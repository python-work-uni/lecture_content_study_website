## **XML** 

- <u>Extensible Markup Language (XML) defines a set of rules for</u> encoding documents. 

- It is a language for describing the rules of other languages. XML allows us to define schemas for tag-based languages. A schema is a contract for communication between client and server. 

- XML is: 

   - a <u>markup language,</u> _not_ a programming language. 

   - human-readable. 

   - machine-readable. 

   - designed to be self-descriptive. 

   - designed to carry and transport data, not to display data.

## **XML Terminology** 

- **Markup** : Elements that define the structure of the document. Usually enclosed by: 

      - **<** and **>** 

      - **&** and **;** 

- **Content** : All the information between _markup_ . 

- **Tag** : A type of _markup_ that begin with **<** and ends with **>,** and comes in three flavours: 

   - _start tag:_ <section> 

   - _end tag:_ </section> 

   - _empty-element tag:_ <img src=“dog.jpg”/> 

- **Attribute** : _Markup_ on a _start tag_ or _empty-element tag_ that defines key-value pairs about that element. 

   - _<img src=“dog.jpg” alt=“woof”/>_

## **HTTP Structure** 

- A HTTP request or responses consists of: 

   - **Header** : Contain meta-data such as cookie and connection information. 

   - – **Body** : Contains the data to be sent with the transmission (optional). 

- There are several types of web requests: 

   - **GET** : A simple request header only 

   - **POST** : A request containing data in the body, e.g. form data, file upload, etc. 

   - **HEAD** : The same as GET, except server omits the body in the response (only sends header) 

   - **PUT** : Replace a target resource on the server 

   - **PATCH** : Partially modify 

   - **DELETE** : Delete a target resource on the server 

   - **OPTIONS** : Ask the server which request types are allowed against a particular resource 

The University of Sydney

## **HTTP Content Type** 

- Generally, a HTTP request uses the _Accept_ header to indicate to the server which data types it will accept in the response. A client can define multiple data types that it supports. 

- A HTTP response defines the _Content-Type_ header, which determines what type of data is contained in the body of the response. This is an indication to the browser as to how it should interpret the response. 

- _<u>Content-Type</u>_ <u>applies to both request and response bodies.</u>

## **HTTP Cookies** 

- A HTTP cookie is a small piece of data, set by a website, which is stored in the user’s browser. 

- Browsers automatically include all the cookies set by a server with every HTTP request sent to that server. 

- There are two HTTP headers which control cookies on the web: 

   - **Requests** : Cookie 

   - Cookie: username=abc123; authToken=4f3e 

   - – **Responses** : Set-Cookie 

      - Set-Cookie: username=abc123 

   - Set-Cookie: authToken=4f3e 

The University of Sydney

## **HTTP Cookies II** 

- Cookies are often used for tracking users and authentication. 

- A typical login flow: 

   - 1.User visits website for first time. 

      - no cookie 

   - 2.User submits login form to server with username + password. 

      - still no cookie 

   - 3.Server generates authentication token (auth-tok). 

      - Server responds with Set-Cookie: token=[auth-tok] 

   - 4.User visits website. 

      - Client sends: Cookie: token=[auth-tok] 

   - 5.Server recognises (auth-tok) and knows request came from User.

## **HTTP Referer**

   - I click on the link to the www.elec3609.com website. 

   - The browser’s request to www.elec3609.com includes a **Referer** header, containing our previous address:

## **Model-View-Controller Architecture** 

- A common way to structure the code of a web application is using the <u>model-view-controller (MVC) architecture.</u> 

- In this pattern, code functionality is separated into three responsibilities: 

   - **Model:** Handles the data. 

   - **View:** Renders data into views (usually HTML). 

   - **Controller:** Interprets requests and encapsulates business logic.
