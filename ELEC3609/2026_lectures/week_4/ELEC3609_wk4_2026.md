## **Cross-Compatibility Testing** 

- If our application must run on a certain browser, we must test it on that browser. **Never assume it will work.** 

- We can test different browsers by using our own local machine. 

- We can test different operating systems by emulating them with virtual machines. Virtualisation can introduce bugs itself. 

## **<mark>Professional Solutions</mark>** 

Many professional tools and services exist for testing cross-compatibility, often with the ability to test on real hardware and devices (e.g., Windows Phone). 

The University of Sydney 

Page 21 

## **You Don’t Need To Support ALL Browsers!** 

### **Strategically choose your supported browsers.** 

- You don’t need to (and probably shouldn’t) support all browsers, versions and operating systems. 

- At the start of your project, make a decision on what you will and won’t support. Base this decision on your intended customer base. 

- Know your intended audience.

## **DOCTYPE Tag** 



- Not a HTML tag. It is an instruction to the browser of the version of HTML used by the page. 

- Must be the **very first** line in your document. 

- This is a HTML5 DOCTYPE declaration, however it will masquerade as HTML4 for older browsers. 

- HTML 4 DOCTYPES are more complex. 

   - _<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN" "http://www.w3.org/TR/html4/strict.dtd">_ 

   - _<!DOCTYPE html>_

## **HEAD Tag** 



- Contains meta information that is separate from the content. 

- Elements are not rendered in the view. 

- CSS files are generally imported here.

- Title tag is mandatory in this section.

## **Single Page Applications** 

- Single page applications load a single HTML document and use JS to update the user’s view without a hard refresh. 

- Single page applications move a lot of work to the client-side (browser) and typically create a smoother, more fluid user experience. They allow for significantly more powerful web applications. 

The University of Sydney 

Page 59 

## **Single Page Applications** 

### **Pros:** 

- Provide a faster interface. 

- Encourage separation of concerns. 

- Reusable 

- Allow for “serverless” browser applications. 

- Simpler binding of data to views. 

- Easy to serve from a CDN, decreasing user load time. 

- Removes load from backend servers. 

### **Cons:** 

- Typically require more work. 

- Typically require more experienced developers due to complexity. 

- New frontier. Frameworks are rapidly evolving. 

- Pushes workload into the browser, bad for low-spec/mobile devices.
