The Internet vs the Web

  • The Internet is "a big network of networks" — a medium that allows computers to talk to each other. The word comes from interconnected networks: linking isolated local area networks (home networks, university networks, enterprise networks) into one global infrastructure.
  • The World Wide Web (WWW) is a way of accessing information over the medium of the Internet.
  • "The Web" is just one of many information-transfer mechanisms on the Internet. Others include Email (SMTP), Instant Messaging, File Transfer (FTP), Media Streaming, SSH, and Usenet.
💡

Why It Matters:

Confusing the Internet with the Web is the most common beginner mistake. The Internet is the road; the Web is one vehicle that drives on it.
🧠

Memory Hook:

Internet = infrastructure and protocols, Web = one service running on top.
02

Websites, URLs & URIs

  • A website is a collection of web pages on the World Wide Web.
  • A single web page can be identified by a Uniform Resource Locator (URL), also known as a Uniform Resource Identifier (URI).
  • A URL has the shape protocol://domain.tld/path/file.ext, for example:
  • https://google.com
  • mailto:jiawen.wen@sydney.edu.au
  • ftp://ftp.google.com
  • Websites are generally made up of HTML, JavaScript, and CSS, and can contain multiple pages and hyperlinks.
  • A URL specifies the transfer protocol (e.g., HTTPS), the domain name, and the resource path. The precise difference between URIs, URLs, and URNs is explored in Week 2.
✅

Exam Tip:

Be ready to identify the protocol, domain, and path inside a URL — and remember that a URL is a type of URI.

Software & System Layers

Software is more than source code. It is a collection of computer programs, consisting of:

  • Compiled code or modules
  • Configuration
  • APIs
  • Services provided by other web or local services
  • Operating systems
  • Hardware drivers
  • Firmware or embedded programs

"It works on my machine" does not mean a software system is ready for production. Software requires systematic testing across environments.
04

Platforms & Infrastructure

Historically, running a software platform meant purchasing physical server hardware (from vendors such as IBM, Dell, HP, and Cisco), installing it in dedicated server racks, and manually maintaining operating systems and networking.

Today, while physical hardware still exists, we manage infrastructure through cloud platforms. We describe it using Infrastructure as Code (IaC) — writing configuration scripts that automatically provision, deploy, scale, and manage resources. An IaC file is just text (for example, a YAML definition of a database table) that a cloud provider turns into real infrastructure.

Major cloud service providers:

  • Microsoft Azure
  • Alibaba Cloud
  • Google Cloud Platform (GCP)
  • Amazon Web Services (AWS)
💡

Why It Matters:

IaC turns infrastructure into version-controlled text, so an environment can be recreated exactly instead of configured by hand.
05

DevOps Lifecycle & Ecosystem

Software engineering is never a one-shot action — it is a continuous, iterative loop.

Plan --> Design --> Build --> Test --> Deploy --> Release --> Monitor --> Gather Feedback --> Redesign

The DevOps continuous lifecycle groups this work into:

  • Development (DEV) — plan and design; build and test (create, verify); package.
  • Operations (OPS) — release and configure; monitor; react and respond (defend).
  • Platform management & governance — manage, secure, and defend.

Key ecosystem tools:

  • Jira — issue tracking and project planning
  • Jenkins — CI/CD build and test automation
  • GitHub — source code control and collaboration
  • Docker — containerisation
🧠

Memory Hook:

DEV builds it, OPS runs it, and governance secures it.
06

System Integration Examples

Example 1: Data Pipeline

A data pipeline moves raw data toward insight through four stages: data ingestion, data processing, data analytics, and data visualisation. Concretely:

  1. Sensor data is collected.
  2. It is ingested in real time, near real time, or batch.
  3. It goes through Extract, Transform, and Load (ETL).
  4. The outcome is visualised to provide insights.

A real-time train station display is a good example: the user sees a simple message ("Train arriving in 2 mins"), but behind it lies a complex pipeline.

Example 2: Industry DevOps at Scale (Qantas)

  • Qantas runs a cloud team of just 12 engineers.
  • The mantra is "automation, automation, and automation".
  • Everything as code: 250+ applications, 5000+ blue/green deployments every month, and over 2.7 million instances launched.
  • Related practices include Site Reliability Engineering (SRE) and the Internet of Things (IoT).
💡

Why It Matters:

A tiny team can operate an enormous estate only by automating almost everything — this is the payoff of the DevOps tools you will use in this unit.

AI, Vibe Coding & Engineering

Why Software Engineering Still Matters

A student once asked: if AI can generate code and build entire websites, why still study software engineering? The answer is that writing code is not the same as being a good software engineer. AI lets students build sophisticated prototypes rapidly, but engineering still requires:

  • Understanding user workflows and product requirements.
  • Architecting resilient, maintainable systems.
  • Prioritising feature backlogs under time and resource constraints.
  • Developing engineering taste and critical judgement.

A Real-World AI Failure (OpenAI Codex, Issue #11022)

  • Git preserves repository history because the .git folder moves with the project.
  • OpenAI Codex, however, bound active chat threads to absolute local file paths rather than relative paths.
  • Moving a project folder therefore broke thread accessibility and caused permission errors, forcing developers to abandon their active thread history.
  • Despite complaints spanning over six months, the eventual patch only allowed attaching new folder paths — not true project-folder migration.

This shows that even state-of-the-art AI developer tools suffer from fundamental software architecture and workflow flaws.

Vibe Coding & Vibe Security

Emerging frameworks and projects address AI-assisted "vibe coding" and its security implications — for example, vibe-security and Meta's Purple Llama safety framework. Generative-AI hotspots include conversational AI and AI platform integrations such as ChatGPT and mobile apps.

⚠️

Common Trap:

AI-generated code that "works" is not automatically correct, secure, or maintainable.
08

Security & Human Responsibility

Because the lecturer's research is in software security, a central message is: never blindly trust AI-generated code. AI is fantastic for prototyping, but a "working" application is not necessarily a "correct" or "secure" one.

  • A generated login page might authenticate users, but is it storing passwords securely using salted password hashes?
  • A payment processing endpoint might execute transactions, but does it leak sensitive PII or suffer from Insecure Direct Object References (IDOR)?

Security requires formal requirements review, static analysis, dynamic testing, and adherence to security standards such as the Web Coding Security Checklist and Meta's Purple Llama safety framework. Ultimately, human engineers — not AI — must take legal and technical responsibility for system integrity.

💡

Why It Matters:

AI can accelerate you, but accountability cannot be delegated to a model. You own the security of what you ship.

Semester Project & Assessment

Over the semester you implement a web development project. You form groups in the first tutorial (max 5 people), then:

  1. Propose an idea.
  2. Identify requirements and use cases.
  3. Design wireframes for the user interface.
  4. Schedule the development and present a project plan.
  5. Design system architecture.
  6. Code.
  7. Deploy the system to the cloud.
  8. Present your final site.

Learning Online

For tips and guides on learning online and the tools you will use, refer to the "Learning while off campus" resources in Canvas.

Academic Integrity

Academic integrity means behaving honestly, ethically, and responsibly in all elements of your study, including assessments. It rests on four core values: honesty, trust, fairness, and respect.

  • Always submit your own work, sit your own tests, and take your own examinations.
  • Acknowledge any contributions in your assignment that are not your original thoughts, ideas, or words.
  • The Academic Honesty Education Module must be completed by all commencing students by census date; continuing students can self-enrol at any time.
  • Strategies: plan and manage your time, use citations and referencing, know your strengths and what you need to develop, and know when and where to ask for help.

Generative AI Policy

Generative AI (such as ChatGPT, Claude Code, GitHub Copilot, OpenAI Codex, and Gemini) is allowed and actively encouraged for your assignments and individual project tasks. However, AI is strictly prohibited in two specific contexts:

  1. The final examination (supervised and closed-book).
  2. Interactive oral check-ins during labs, where tutors assess your individual understanding through direct conversation.
✅

Exam Tip:

You may use AI to build your project, but you must be able to explain and defend your own understanding face-to-face in the lab check-ins.

Glossary

Internet

A global network of networks that lets computers communicate.

World Wide Web (WWW)

A way of accessing information over the medium of the Internet; one of many Internet services.

URL

Uniform Resource Locator — identifies a web page by protocol, domain, and path.

URI

Uniform Resource Identifier — a broader identifier of which a URL is one type.

Software

A collection of computer programs, including code, configuration, APIs, operating systems, drivers, and firmware.

Platform

The infrastructure on which software runs; today usually a cloud platform managed as code.

Infrastructure as Code (IaC)

Managing infrastructure through configuration scripts that provision, deploy, and scale resources.

Cloud service provider

A vendor offering on-demand infrastructure; e.g., AWS, Azure, GCP, Alibaba Cloud.

DevOps

A continuous lifecycle combining development and operations, from planning to monitoring.

DevSecOps

DevOps with security integrated throughout.

SaaS

Software as a Service — software delivered over the internet rather than installed locally.

Data pipeline

A system that ingests, processes, analyses, and visualises data.

ETL

Extract, Transform, and Load — the processing stage of a data pipeline.

IoT

Internet of Things — network-connected physical devices.

SRE

Site Reliability Engineering — applying software engineering to operations reliability.

Generative AI

AI that produces code or content; e.g., ChatGPT, Claude Code, GitHub Copilot, Codex, Gemini.

Vibe coding

Building software rapidly with heavy AI assistance, often with less formal engineering review.

Vibe security

Emerging frameworks/projects addressing the security of AI-assisted coding.

Purple Llama

Meta's AI safety framework referenced for secure AI development.

IDOR

Insecure Direct Object Reference — a flaw letting users access objects they should not.

Salted password hash

A password stored as a slow hash with a unique random salt per user.

Static analysis

Examining code without executing it to find flaws.

Dynamic testing

Testing software while it runs to find flaws.

Django

The Python web framework used as the course's baseline backend tool.

Learning outcome (LO)

A stated capability you should achieve by the end of the unit.

Academic integrity

Behaving honestly, ethically, and responsibly in all study and assessments.

Census date

The date by which commencing students must complete the Academic Honesty Education Module.

Group contract

The document submitted in Week 5 that locks a group.

AWS Academy

The portal providing cloud computational resources for the course.

REST API

An interface the project must call using AJAX requests.

AJAX

Asynchronous JavaScript and XML — updates a page without a full reload.

Wireframe

A low-fidelity layout sketch of the user interface.

Responsive web design

Designing interfaces that adapt across devices and screen sizes.

Supervised exam

The closed-book, invigilated final exam worth 30%; no AI permitted.

Worked Examples & Scenarios

Example 1

Breaking Down a URL

For https://google.com, the protocol is https, the domain is google.com, and there is no path. For ftp://ftp.google.com/files/report.pdf, the protocol is ftp, the domain is ftp.google.com, and the path is /files/report.pdf. A mailto: URL identifies an email address rather than a web resource.

Example 2

A Data Pipeline End to End

Sensors collect readings → the readings are ingested (real time, near real time, or batch) → ETL cleans and transforms them → the results are visualised for insights. A train station display is the visible tip: the passenger sees "Train arriving in 2 mins", while the pipeline does the work behind the scenes.

Example 3

Qantas at Scale

A 12-person cloud team supports 250+ applications, runs 5000+ blue/green deployments every month, and has launched over 2.7 million instances — because everything is automated and defined as code. This illustrates why IaC and CI/CD matter.

Example 4

Why the Codex Bug Matters

When a project folder moved, Git kept working because .git moved too, but Codex lost its chat threads because it stored absolute paths. The lesson: even advanced AI tools have architectural flaws, and engineers must still design for portability and maintainability.

Example 5

Using AI Responsibly

You use an AI agent to scaffold a Django login page. Before shipping, you check that passwords are stored as slow, salted hashes, that the payment endpoint does not leak PII or allow IDOR, and that the code passes static analysis and dynamic tests. The AI wrote the draft; you remain responsible for its security.
