The Internet Is Not the World Wide Web

The Internet is the physical/network medium that lets computers talk; the Web is just one way of using that medium to access information.

Two words get used interchangeably in everyday speech but mean different things. Getting them straight is the foundation for everything else in this course.

Internet — A big network of networks — a medium that allows computers to talk to each other.
World Wide Web (WWW) — A way of accessing information over the medium of the Internet.

The Web is one of many Internet services

"The Web" is just one information-transfer mechanism among several running on the Internet. Others include:

  • Email
  • Instant Messaging
  • File Transfer
  • Media Streaming
  • Usenet
🧠
Memory hook: The Internet is the road system; the Web is one kind of vehicle that drives on it. Email, file transfer and streaming are different vehicles on the same roads.
🤔

Websites and Identifiers: URL, URI and URN

Every web page is a resource with a unique address, and learning to read that address tells you how the page is fetched.

Websites

  • A website is a collection of web pages on the World Wide Web.
  • A single web page is identified by a Uniform Resource Locator (URL) — also referred to as a Uniform Resource Identifier (URI).
  • Websites are generally built from HTML, JavaScript and CSS, and can contain multiple pages and hyperlinks.

Reading a URL

The general shape of a URL is:

URL structure
protocol://domain.tld/path/file.ext

Concrete examples from the lecture:

URLWhat it shows
https://google.comWeb protocol + domain, no path
mailto:jiawen.wen@sydney.edu.auA non-web scheme (email)
ftp://ftp.google.comFile-transfer protocol scheme
  • protocol (or scheme) tells the computer how to communicate — https, mailto, ftp.
  • domain.tld is the host, with the top-level domain (.com, .au, .edu.au).
  • /path/file.ext locates a specific resource on that host.

URL vs URI vs URN

The terms overlap and are worth a moment of thought:

  • URI (Uniform Resource Identifier) is the broad umbrella term for anything that identifies a resource.
  • URL (Uniform Resource Locator) is a URI that also tells you where to find it (a locator).
  • URN (Uniform Resource Name) is a URI that names a resource persistently without saying where it lives.
ℹ️
Note: The lecture treats URL and URI as near-synonyms in practice, but the precise relationship is that every URL is a URI while not every URI is a URL. Broader discussion topics raised include the distinction with URNs and the term Web3.0, coined in 2014.

Software, Platforms and the Stack

Software is not just code — it is a layered collection of programs, configuration, interfaces and services that ultimately rests on hardware.

What counts as "software"

Software is a collection of computer programs, and it consists of more than the code you write:

  • Compiled code or modules
  • Configuration
  • APIs
  • Services provided by other web or local services
  • Operating systems
  • Hardware drivers
  • Firmware or embedded programs

The system architecture hierarchy

Software sits in layers. Requests flow down through the layers and results flow back up:

User→Application Software→Operating System→Hardware
Platform — The environment of software, services and infrastructure on which applications are designed, built, packaged, deployed and run.
💡
Why it matters: Recognising the layers explains why a web app can break at any level — your code, a dependency/API, the OS, or the underlying hardware/network. Debugging means finding which layer failed.

Platform Evolution: From Server Racks to Infrastructure as Code

Platforms used to be physical machines you could touch; today they are described in code and provisioned on demand in the cloud.

Then: traditional on-premises physical hardware

  • Dedicated server racks from vendors such as IBM, Dell, HP, Cisco.
  • You buy, house, power, cool and maintain the metal yourself.

Now: Infrastructure as Code and cloud platforms

Instead of describing hardware in a purchase order, you describe it in a configuration file. This YAML snippet declares a database table in AWS:

resources:
  Resources:
    Results:
      Type: AWS::DynamoDB::Table
      Properties:
        TableName: scheduled_item_results
        BillingMode: PAY_PER_REQUEST
        AttributeDefinitions:
          - AttributeName: id
            AttributeType: S
        KeySchema:
          - AttributeName: id
            KeyType: HASH

Reading it: Type names the cloud resource (AWS::DynamoDB::Table), BillingMode: PAY_PER_REQUEST means you pay only for what you use, and KeySchema with KeyType: HASH makes id the partition key. The whole table exists because it is declared — that is infrastructure as code.

Major cloud service providers

  • Microsoft Azure
  • Alibaba Cloud
  • Google Cloud Platform (GCP)
  • Amazon Web Services (AWS)

Traditional on-premises

  • Physical, dedicated server racks (IBM, Dell, HP, Cisco)
  • Capital expense up front; you own and maintain it
  • Scaling means buying more machines

Cloud + Infrastructure as Code

  • Resources declared in files (YAML), provisioned on demand
  • Pay-per-request / pay-as-you-go billing
  • Scale by editing and re-deploying code

System Integration in the Real World

Two worked examples show what "stitching technologies together" looks like: a data pipeline, and DevOps at industrial scale.

Example 1 — A data pipeline

A data pipeline moves raw data through stages until it becomes insight:

  1. Data ingestion — collect the raw data
  2. Data processing — transform and clean it
  3. Data analytics — compute meaning from it
  4. Data visualisation — present the outcome and provide insights

The pipeline phases in order:

  1. Sensor data
  2. Real-time, near real-time, or batch ingest
  3. Extract, Transform and Load (ETL)
  4. Visualise the outcome and provide insights
ETL — Extract, Transform and Load — the processing step that pulls data from sources, reshapes it, and writes it into a destination store ready for analysis.

Example 2 — Qantas: DevOps at scale

An industry case study of automation taken to its limit:

  • Qantas runs a cloud team of just 12 engineers.
  • Guiding principle: Automation, Automation, and Automation — everything as code.
  • 250+ applications
  • 5000+ Blue/Green deployments every month
  • Over 2.7 million instances launched
  • Site Reliability Engineering (SRE) and Internet of Things (IoT) are core to the approach.
Blue/Green deployment — A release technique that keeps two near-identical environments — "blue" (live) and "green" (new) — so traffic can be switched to the new version with minimal downtime and an easy rollback.
✅
Exam tip: Remember the numbers — 12 engineers, 250+ apps, 5000+ deployments/month, 2.7M+ instances. They are the punchline of the "automation at scale" argument.

Emerging Hotspots: Generative AI, Codex and Vibe Security

Modern development is being reshaped by conversational AI and AI-assisted coding — with new security questions attached.

Conversational AI

  • Emerging trends in conversational AI and AI platform integrations, including ChatGPT, Meeno and mobile apps.

Codex and AI code assistance

  • Developer tools offering AI code completion and codebase management.
  • A real-world example is OpenAI Codex GitHub Issue #11022: "Add ability to update/migrate thread references when projects are moved to new locations."
  • The problem: when project folders relocate, hardcoded absolute path references break thread accessibility in internal databases.
⚠️
Common trap: Hardcoding absolute paths is a classic portability bug. Store references relative to a project root (or in a config/indirection layer) so moving the project does not break it.

Vibe coding and vibe security

  • Emerging Vibe Coding and Vibe Security frameworks/projects.
  • References include the astoj/vibe-security and meta-llama/PurpleLlama repositories.
ℹ️
Note: These are fast-moving hotspots — the point for now is awareness that AI-assisted coding changes how software is written and how it must be secured.

Glossary

Every term you need to speak this week's language.

Internet
A big network of networks — the medium that allows computers to talk to each other.
World Wide Web
A way of accessing information over the medium of the Internet; one of several Internet services.
URL
Uniform Resource Locator — identifies and locates a resource, shaped as protocol://domain.tld/path/file.ext.
URI
Uniform Resource Identifier — the broad term for anything that identifies a resource; every URL is a URI.
URN
Uniform Resource Name — a URI that names a resource persistently without indicating where it is located.
Website
A collection of web pages on the World Wide Web, generally built from HTML, JavaScript and CSS.
Software
A collection of computer programs including compiled code, configuration, APIs, services, OS, drivers and firmware.
Software stack
The layered arrangement of user, application software, operating system and hardware through which requests flow.
Platform
The environment of software, services and infrastructure on which applications are designed, built, packaged, deployed and run.
Infrastructure as Code
Describing and provisioning infrastructure (servers, databases, networks) in configuration files such as YAML instead of physical hardware.
Cloud service provider
A vendor offering on-demand computing infrastructure; major ones are Azure, Alibaba Cloud, GCP and AWS.
DevOps
A continuous lifecycle combining Development and Operations with governance to plan, build, release, monitor and defend software.
DevSecOps
DevOps with security integrated throughout rather than bolted on at the end.
ETL
Extract, Transform and Load — the pipeline stage that pulls, reshapes and writes data ready for analysis.
Data pipeline
A staged flow from data ingestion through processing and analytics to visualisation and insight.
Blue/Green deployment
A release technique using two near-identical environments so traffic can be switched to a new version with minimal downtime.
Site Reliability Engineering (SRE)
A discipline applying software engineering to operations to run large systems reliably at scale.
Internet of Things (IoT)
Networked physical devices that sense and communicate data, feeding pipelines and platforms.
Containerisation
Packaging an application with its dependencies into a portable unit; Docker is the key tool.
SaaS
Software as a Service — software delivered and consumed over the Internet rather than installed locally.
Django
A Python web framework used as the baseline programming tool for this course.
AJAX
Asynchronous JavaScript requests that let a web page exchange data with a server (e.g. a REST API) without reloading.
REST API
An interface exposing resources over HTTP that applications call to read and modify data.
Vibe coding
An emerging AI-assisted coding practice where much code is generated conversationally; vibe security addresses its risks.

No terms in this category.
