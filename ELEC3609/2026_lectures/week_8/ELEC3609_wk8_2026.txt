## **Intro/Recap?** 

- Linux is an open-source UNIX-like operating system, whose defining feature is the Linux kernel. Released in 1991 by Linus Torvalds. 

- A Linux distribution defines a collection of software that comes prepackaged as a complete operating system. 

- For example: 

   - package managers ( `apt-get` or `pacman` ) 

   - window managers ( `GNOME` or `i3` ) 

   - text editors 

- Linux has become the most widely installed general purpose OS due to the proliferation of Android. It is also the most dominant OS for web servers (>90%).

## **Linux Users** 



- The ‘root’ user (aka the ‘Superuser’) is the most privileged user on a Linux system. 

- While the root user can do anything on the system, other users could have a wider variety of privileges. 

- **Programs execute as a particular user.** 

- If a program requires special privileges on the system, it may need to execute as the root user. 

- The output of the command `ps aux` will show you a list of all processes running on the system and the user they are running as. 



Page 6 

The University of Sydney 

## **Program-Specific Linux Users** 

- Usually, a program will not need root access to the system, and so will (or at least, it should) run as a different user. 

- If such a program is somehow compromised, it will only be able to perform malicious actions that its running user could perform. 

- For example: 

   - Web servers (including `nginx` ) usually run as the `www-data` user. 

- MySQL programs (including `mysqld` ) usually run as the `mysql` user. 

- – Linux systems often come with a `nobody` user, which can run programs that require almost no special privileges.

## **Capabilities** 

- Traditional root vs. Capabilities 

   - In a classic UNIX/Linux model: 

      - root (UID 0) has all privileges. 

      - If a process is compromised while running as root, the attacker gains full control of the system. 

   - Capabilities split root privileges into smaller, fine-grained units (like CAP_NET_BIND_SERVICE, CAP_SYS_ADMIN, CAP_DAC_OVERRIDE). 

      - Each process can be assigned only the subset of privileges it really needs. 

- Why it improves security 

   - Least privilege principle 

   - Damage containment 

   - Reduced attack surface

## **Capabilities** 

- Running **nginx** : 

   - Traditionally: needed root just to bind port 80. 

   - With capabilities: run as unprivileged user but grant only CAP_NET_BIND_SERVICE. 

   - If nginx is hacked, the attacker cannot: 

      - Create raw sockets (CAP_NET_RAW). 

      - Mount filesystems (CAP_SYS_ADMIN). 

      - Change ownership of files (CAP_CHOWN).

## **SSH Keys** 

- SSH provides _authentication_ and _encryption_ . 

- The obvious way to log in to SSH is using the password of the remote user. This is bad. 

- Instead, we want to use SSH keys. 

- There are two _sets_ of keys that SSH uses: 

   - **Server host key** : The SSH server has a long-term public/private host key pair. 

      - The host key is used to authenticate the server to the client. 

      - During connection establishment, SSH performs a key-exchange protocol to derive shared symmetric session keys. 

      - The server proves possession of its private host key by signing data associated with the key exchange. 

      - The private host key is never sent to the client. 

   - **Client/user key** : Each user may have a public/private key pair for authentication. 

      - The public key is stored on the server. 

      - The client proves possession of the corresponding private key without sending the private key to the server.

## **SSH Client Keys** 

- To authenticate a particular user on the SSH server, a client proves ownership of a private key, which corresponds to an authorised public key. 

- For example, say we want to connect to a server as the user `myuser` . 

   - On the server, there is a file in `myuser` ’s home directory: 

      - `/home/myuser/.ssh/authorized_keys` 

   - This file contains the public keys of anyone who is authorised to connect to the server as this user. 

   - The SSH server will check that any client trying to connect possesses the private key corresponding to a public key in that file. If they do, then the connection is authorised. 

The University of Sydney 

Page 19 

## **SSH Agent** 

- `ssh-agent` is a useful program for storing the unencrypted SSH private key in memory. 

- SSH typically reads private keys from `~/.ssh/id_rsa` , which is encrypted. Every time SSH is run, it needs the password to use the key. 

- To make things easier, the unencrypted version can be stored in memory by attaching it to a running process. 

- Since we don’t want to store it in every SSH client process, we run `ssh-agent` to store it for us. 

The University of Sydney 

Page 20 

## **SSH Agent Forwarding** 

- `ssh-agent` runs on the client, and as new SSH processes connect to it, they ask it to perform signing operations using the private key. 

- With the `ForwardAgent` option, we can allow remote SSH clients to access our local `ssh-agent` process (and therefore, our unencrypted private key).

## **Network Revision: OSI Model** 

- 7-layer OSI model 

- In particular: 

   - TCP/UDP Ports: Layer 4 

   - Firewalls 

   - Load Balancers 

   - Public Ips: Layer 3 



- We say that applications ‘listen’ on a particular TCP port. – This allows multiple applications to run on the same host, with each listening for TCP connections on a different port. 

   - Any application can choose to listen on any port, but there are standard port numbers used for particular application types. 



The University of Sydney

## **TCP Ports - Listening** 

- Whenever a network service starts on a host, it attempts to listen on a particular port. 

- Only one running application may listen to a port at a time.

## **Firewalls** 

- A firewall is a security system that can allow or disallow network traffic to pass according to a set of rules. 

- Firewalls come in many shapes and sizes: 

   - Your Home Router 

      - Makes decisions about incoming/outgoing traffic and prevents attackers from gaining access to your network. 

   - Software Firewalls 

      - Runs on a host machine and provides rules about the traffic allowed to enter the host. 



The University of Sydney 

Page 34 

## **AWS Security Groups** 

- AWS Security Groups (SGs) are stateful virtual firewalls. 

- When first configuring an EC2 instance, you can either create a new security group or add the instance to an existing security group. 

- To configure a security group, you must specify: – Protocol: TCP/UDP/ICMP 

   - Port(s): The TCP/UDP port(s) the rule applies to. 

   - Source: Which source IP address(es) the rule applies to. 

- The rules are a whitelist, meaning any packets not matching a rule are automatically dropped (disallowed). 

- Bad: SSH 22 ← 0.0.0.0/0 

- Better: SSH 22 ← your IP only 

- Better cloud-native option: AWS Systems Manager Session Manager

- When you start an EC2 instance, AWS assigns it a public IP address. If you stop and start the instance, it can be reassigned to a different IP address.

   - Once assigned, the instance will always have this IP whenever it is created

## **Databases** 

- Most web applications require persistent storage of data. 

- You will most likely need to install a relational database management system (RDBMS) for your project. 

- We recommend using MySQL, since it is feature-rich and relatively easy to use.

   - Configure users (username & password). 

   - Configure application code to use the DB.
