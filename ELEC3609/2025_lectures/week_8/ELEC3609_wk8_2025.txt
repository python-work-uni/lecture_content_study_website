Introduction
– Linux is an open-source UNIX-like operating system, whose 
defining feature is the Linux kernel. Released in 1991 by Linus 
Torvalds.
– A Linux distribution defines a collection of software that comes pre-
packaged as a complete operating system.
– For example:
– package managers (apt-get or pacman)
– window managers (GNOME or i3)
– text editors
– Linux has become the most widely installed general purpose OS due 
to the proliferation of Android. It is also the most dominant OS for 
web servers (>90%).

--- Slide 6 ---
The University of Sydney
Page 6
Linux Users
– The ‘root’ user (aka the ‘Superuser’) is the most privileged 
user on a Linux system.
– While the root user can do anything on the system, other users 
could have a wider variety of privileges.
– Programs execute as a particular user.
– If a program requires special privileges on the system, it may 
need to execute as the root user.
– The output of the command ps aux will show you a list of 
all processes running on the system and the user they are 
running as.

--- Slide 7 ---
The University of Sydney
Page 7
Program-Specific Linux Users
– Usually, a program will not need root access to the system, and 
so will (or at least, it should) run as a different user.
– If such a program is somehow compromised, it will only be 
able to perform malicious actions that its running user could 
perform.
– For example:
– Web servers (including nginx) usually run as the www-data user.
– MySQL programs (including mysqld) usually run as the mysql user.
– Linux systems often come with a nobody user, which can run 
programs that require almost no special privileges.

The University of Sydney

Capabilities
– Traditional root vs. Capabilities
– In a classic UNIX/Linux model:
• root (UID 0) has all privileges.
• If a process is compromised while running as root, the attacker 
gains full control of the system.
– Capabilities split root privileges into smaller, fine-grained units (like 
CAP_NET_BIND_SERVICE, CAP_SYS_ADMIN, 
CAP_DAC_OVERRIDE).
• Each process can be assigned only the subset of privileges it really 
needs.
– Why it improves security
– Least privilege principle
– Damage containment
– Reduced attack surface

--- Slide 9 ---
The University of Sydney
Page 9
Capabilities
– Running nginx:
– Traditionally: needed root just to bind port 80.
– With capabilities: run as unprivileged user but grant only 
CAP_NET_BIND_SERVICE.
– If nginx is hacked, the attacker cannot:
• Create raw sockets (CAP_NET_RAW).
• Mount filesystems (CAP_SYS_ADMIN).
• Change ownership of files (CAP_CHOWN).

Secure Shell (SSH)
– Secure Shell (SSH) is a secure replacement for the old Telnet 
protocol.
– SSH enables a user to access the shell or terminal on a remote 
machine.
– Essential tool for any web master, since Linux is the dominant 
server platform on the internet.

The University of Sydney

SSH Server
– The most common SSH server software is OpenSSH, which 
originates from the OpenBSD project.
– An SSH server:
– Listens for incoming connections on TCP Port 22.
– Authenticates connecting users using:
• Passwords
• Public/Private Keys

SSH Client
– Open SSH also provides an SSH client, which is the client-
side software that connects to the SSH server.
– There are many alternative clients, depending on the platform 
you are using.
– On Linux, you’re best to stick with the default OpenSSH.
– On Windows however, PuTTY might be a better option.

The University of Sydney

SSH Keys
– SSH provides authentication and encryption.
– The obvious way to log in to SSH is using the password of the 
remote user. This is bad.
– Instead, we want to use SSH keys.
– There are two sets of keys that SSH uses:
– Server: The server has its own key pair, which allows initial 
connections to it to be encrypted with its public key. It also allows 
clients to authenticate the server.
• Only the server possessing the private key can read incoming 
connections.
– Client: Each client has their own key pairs, which are used to 
authenticate when connecting to the server.

--- Slide 18 ---
The University of Sydney
Page 18
Public Key Crypto & Signatures
– An encryption and decryption key pair are generated to 
provide effective authentication. This is achieved by 
demonstrating possession of the private key without revealing 
it.
– Private Key
• Held by you, never shared.
• Only you can sign a request 
with your private key.
– Public Key
• Shared publicly.
• Anyone can verify your 
signature with your public key.

--- Slide 21 ---
The University of Sydney

SSH Client Keys
– To authenticate a particular user on the SSH server, a client 
proves ownership of a private key, which corresponds to an 
authorised public key.
– For example, say we want to connect to a server as the user 
myuser.
– On the server, there is a file in myuser’s home directory:
• /home/myuser/.ssh/authorized_keys
– This file contains the public keys of anyone who is authorised to 
connect to the server as this user.
– The SSH server will check that any client trying to connect possesses 
the private key corresponding to a public key in that file. If they do, 
then the connection is authorised.

--- Slide 22 ---
The University of Sydney
Page 22
SSH Agent
– ssh-agent is a useful program for storing the unencrypted 
SSH private key in memory.
– SSH typically reads private keys from ~/.ssh/id_rsa, 
which is encrypted. Every time SSH is run, it needs the 
password to use the key.
– To make things easier, the unencrypted version can be stored 
in memory by attaching it to a running process.
– Since we don’t want to store it in every SSH client process, we 
run ssh-agent to store it for us.

--- Slide 23 ---
The University of Sydney
Page 23
SSH Agent Forwarding
– ssh-agent runs on the client, and as new SSH processes 
connect to it, they ask it to perform signing operations using 
the private key.
– With the ForwardAgent option, we can allow remote SSH 
clients to access our local ssh-agent process (and therefore, 
our unencrypted private key).

TCP Ports
– Most web software communicates via the Transmission 
Control Protocol (TCP).
– TCP establishes an end-to-end connection and ensures delivery 
of packets in the order they were sent.
– We say that applications ‘listen’ on a particular TCP port.
– This allows multiple applications to run on the same host, with each 
listening for TCP connections on a different port.
– Any application can choose to listen on any port, but there are standard 
port numbers used for particular application types.

--- Slide 40 ---
The University of Sydney
Page 40
TCP Ports - Listening
– Whenever a network service starts on a host, it attempts to 
listen on a particular port.
– Only one running application may listen to a port at a time.

--- Slide 41 ---
The University of Sydney
Page 41
UDP Ports
– The User Datagram Protocol (UDP) is a connectionless 
protocol.
– It is a ‘best-effort’ protocol, and makes no guarantees about 
packets being in order, or even being delivered at all.
– UDP has its own set of ports.
– For example, TCP Port 80 is different from UDP Port 80.

Firewalls
– A firewall is a security system that can allow or disallow 
network traffic to pass according to a set of rules.
– Firewalls come in many shapes and sizes:
– Your Home Router
• Makes decisions about incoming/outgoing traffic and prevents 
attackers from gaining access to your network.
– Software Firewalls
• Runs on a host machine and provides rules about the traffic allowed 
to enter the host.

--- Slide 43 ---
The University of Sydney
Page 43
AWS Security Groups
– AWS Security Groups (SGs) are sets of firewall rules that can 
be applied to EC2 instances.
– When first configuring an EC2 instance, you can either create 
a new security group or add the instance to an existing security 
group.
– To configure a security group, you must specify:
– Protocol: TCP/UDP/ICMP
– Port(s): The TCP/UDP port(s) the rule applies to.
– Source: Which source IP address(es) the rule applies to.
– The rules are a whitelist, meaning any packets not matching a 
rule are automatically dropped (disallowed).
– For development, you may find it useful to add a rule for SSH 
access from any source (0.0.0.0/0)

Elastic IPs
– When you start an EC2 instance, AWS assigns it a public IP 
address.
– If you restart the instance, it can be reassigned to a different IP 
address, which can make updating dependent configurations 
very difficult.
– For example, updating the DNS records.
– To maintain a consistent IP address between restarts, you can 
assign the instance an Elastic IP address.
– Once assigned, the instance will always have this IP whenever it is 
created

--- Slide 49 ---

Recommended Web Server Software: nginx
– nginx (pronounced ‘engine-X’) is a fast web server that can 
also act as a reverse proxy.
– Due to its widespread use and ease of configuration, we highly 
recommend you use nginx for your project.
– While nginx can receive and process a HTTP request, it does 
not interpret web application code.
– Instead, we ask nginx to proxy_pass HTTP requests to 
the application interface.

Application Interfaces
– A web application interface provides a simple interface 
between a web server and the application server.
– It runs multiple application ‘workers’ so that the application 
can process requests concurrently.
– WSGI is a specification for such an interface, and it is 
implemented by the uWSGI software.
– uWSGI is designed for Python programs, and has good 
support for Django.

Databases
– Most web applications require persistent storage of data.
– You will most likely need to install a relational database 
management system (RDBMS) for your project.
– We recommend using MySQL, since it is feature-rich and 
relatively easy to use.
– PostgreSQL and MariaDB are acceptable alternatives.
– Regardless of your choice of RDBMS, the rough setup steps 
will be:
– Install the DB software.
– Configure users (username & password).
– Configure application code to use the DB.
• Connect using the username & password.
