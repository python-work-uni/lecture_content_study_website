DHCP
– When you connect to a network, usually your computer is 
configured with the Dynamic Host Configuration Protocol 
(DHCP). This provides your computer with:
– IP address: Identifies you on the local network
– Subnet Mask: Defines what “local” means with regard to your IP 
address
– Default gateway: A host that can route packets to non-local IP 
addresses
– Nameservers: A host which can be used to resolve domain names –
i.e., a DNS server
– First thing to check if you cannot reach any web sites

HTTP Methods
– These are the most commonly used HTTP methods:
– GET: used to request data about a specified resource.
– POST: used to create a resource.
– Many more exist:
– PUT: create/update a resource.
– PATCH: partial modification of a resource.
– DELETE: deletes the specified resource.
– OPTIONS: returns the supported HTTP methods for this resource.
– HEAD: equivalent to a GET request without the response body.
– Consistency is key.

HTTP Cookies
– A HTTP cookie is a small piece of data, set by a website, 
which is stored in the user’s browser.
– Browsers automatically include all the cookies set by a server 
with every HTTP request sent to that server.
– There are two HTTP headers which control cookies on the 
web:
– Requests: Cookie
Cookie: username=abc123; authToken=4f3e
– Responses: Set-Cookie
Set-Cookie: username=abc123
Set-Cookie: authToken=4f3e

HTTP Cookies II
Cookies are often used for tracking users and authentication.
A typical login flow:
– 1.User visits website for first time.
→ no cookie
– 2.User submits login form to server with username + password.
→ still no cookie
– 3.Server generates authentication token (auth-tok).
→ Server responds with Set-Cookie: token=[auth-tok]
– 4.User visits website.
→Client sends: Cookie: token=[auth-tok]
– 5.Server recognises (auth-tok) and knows request came from User.

Load Balancer
– Load balancers (LB) can be added to a server environment to 
improve performance and reliability by distributing the 
workload across multiple servers. If one of the servers that is 
load balanced fails, the other servers will handle the incoming 
traffic until the failed server becomes healthy again.
– Typical implementations use HAProxy, Nginx, and Varnish.

HTTP Accelerator
– A HTTP accelerator, or caching HTTP reverse proxy, can be 
used to reduce the time it takes to serve content to a user 
through a variety of techniques. Typically the response from a 
web or application server is cached for a period of time in 
memory.
– Examples of software capable of HTTP acceleration: Varnish, 
Squid, Nginx.

UML Case Documentation – Flow of Events
–
Create a big table that lists the use cases (see Monopoly example on 
Canvas).
–
Describe each use case using fields such as:
–
Name: Give the use case a short name.
–
Goal: The main goal that the use case is trying to achieve.
–
Actors: Actors which initiate a use case and/or are involved in a use case.
–
Preconditions: A list of conditions that must be met before the use case can 
start.
–
Main flow: A full description of the use case.
–
Subflows: A list of actions or use cases on which the use case depends.
–
Alternative Flows: Any alternative action flows, e.g. ones that might come 
from error scenarios.
–
Priority: An indication of how important the use case is to the functioning 
of the system, or the MVP.

Software Requirements Specification
A Software Requirements Specification (SRS) document details 
exactly what the system does and does not do.
In essence, the SRS is a communication tool between project 
stakeholders and software designers.
It is a very important document that allows you to say the project 
is “finished”, and mitigates scope creep. This forms the primary 
specification document and should capture all information 
regarding the project.
The diagrams should not introduce new information that is not 
contained within the SRS.

Web Request Overview
Client
1. Browser: Parse URL
2. Browser: Check cache
3. OS: Identify network
4. OS: Resolve using DNS
5. OS: Establish TCP connection to web server
6. Browser: Submit HTTP request to web server
Server
1. Load Balancers (LB) establish TCP connection and receive HTTP request.
2. LB software parses HTTP header, then routes requests to an application server.
3. App server executes back-end website logic, probably connecting to a database.
4. App server generates a response, and returns it via the TCP connection.
Client
1. Browser: Parse response
2. Browser: Fetch additional resources:
 
–Fetch assets (CSS, JS, Images)
 
–Establish websocket connection/s
 
–Load browser plugins
3. Render page
