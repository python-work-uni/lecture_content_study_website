2. CORE CONCEPTS: THE INTERNET VS. THE WORLD WIDE WEB (WWW)
--------------------------------------------------------------------------------
[Concept 1: Internet]
- Definition: A global network of networks connecting millions of computing devices.
- Purpose: Provides the physical and logical medium allowing computers to communicate with each other.

[Concept 2: World Wide Web (WWW or "The Web")]
- Definition: An information-sharing system built ON TOP of the Internet.
- Access Method: Information is accessed via documents/pages connected by web links.
- Crucial Distinction: The Web is NOT the Internet! It is just ONE of many applications/services operating over the Internet.
- Other non-Web Internet services include:
  * Email (SMTP / IMAP / POP3)
  * Instant Messaging (WebSocket / XMPP)
  * File Transfer (FTP / SFTP)
  * Media Streaming (RTSP / RTMP)
  * Usenet / SSH / Peer-to-Peer (P2P)

[Concept 3: Websites, URLs, and URIs]
- Website: A collection of related web pages hosted on the Web, constructed using:
  * HTML (HyperText Markup Language): Defines structural content.
  * CSS (Cascading Style Sheets): Defines visual styling.
  * JavaScript: Defines client-side interactivity and logic.
- URI vs. URL:
  * URI (Uniform Resource Identifier): A generic term for all names and addresses that identify a resource.
  * URL (Uniform Resource Locator): A specific TYPE of URI that provides the location and method of accessing a resource (e.g., protocol + domain + path).
  * Rule of Thumb: All URLs are URIs, but not all URIs are URLs!
- Standard URL Structure:
  protocol://domain.tld/path/file.ext
  Example: https://google.com (HTTPS protocol), mailto:user@sydney.edu.au, ftp://ftp.google.com

3. INTERNET SOFTWARE PLATFORMS: THE "STITCHING" CONCEPT
--------------------------------------------------------------------------------
An Internet Software Platform stitches together three foundational pillars:

1. THE INTERNET (Infrastructure & Communication):
   - Networking fundamentals & data transport
   - Protocols (HTTP, TCP/IP, REST)
   - Cybersecurity fundamentals (Encryption, Auth, TLS)

2. SOFTWARE (Engineering & Architecture):
   - Design patterns and architectural principles
   - Coding (Front-end & Back-end, e.g., Django/Python)
   - Packaging & Modularization
   - Human factors (UX/UI, usability, accessibility)

3. PLATFORMS (Cloud & Operations):
   - Cloud technologies (IaaS, PaaS, SaaS)
   - Infrastructure as Code (IaC - managing infrastructure via scripts)
   - DevOps & DevSecOps (Automated pipelines, continuous integration, security integration)

4. SOFTWARE PLATFORM LIFECYCLE & DEVOPS IN PRACTICE
--------------------------------------------------------------------------------
[Software Platform Lifecycle]
The life cycle of an internet software platform alternates continuously between two main phases:

  A. DEVELOPMENT PHASE:
     - Plan & Design (Architecture, DB schemas, wireframes)
     - Build & Test (Coding, Unit testing, Integration testing)
     - Package (Containerization e.g., Docker, building artifacts)

  B. OPERATIONS PHASE:
     - Release & Configure (Deployment to servers/cloud)
     - Monitor (Tracking performance, uptime, latency, logs)
     - React & Respond (Patching bugs, scaling resources, incident response)

[Real-World Data Pipelines (ETL Architecture)]
Modern web platforms handle massive streams of data through pipelines:
1. Data Ingestion: Sensor data or user events ingested in real-time, near real-time, or batch.
2. Data Processing: Extract, Transform, and Load (ETL) processing.
3. Data Analytics: Performing computations or machine learning inference.
4. Data Visualization: Displaying insights to users on web dashboards.

[Industry Spotlight: DevOps & Automation (e.g., Qantas Case Study)]
- Scalability with Automation: A small platform team (e.g., 12 engineers) can manage 250+ applications and millions of server instances using automation.
- Everything as Code: Infrastructure, security, and deployment pipelines are written as code scripts rather than manual setup.
- Blue/Green Deployments: Technique for zero-downtime deployment by running two identical environments (Blue = Live production, Green = Idle/New version). Traffic switches seamlessly to Green once verified.
- Site Reliability Engineering (SRE): Applying software engineering practices to infrastructure and operations problems.

5. KEY CRITERIA WHEN BUILDING WEBSITES/PLATFORMS
--------------------------------------------------------------------------------
Taking an idea from conception to market requires balancing 10 major factors:
1. Cost: Hosting, API usage, computational resources.
2. Performance: Load times, latency, throughput.
3. Hosting: Cloud providers (AWS, GCP, Azure), serverless vs. dedicated.
4. Stability / Reliability: Uptime, failover mechanisms, redundancy.
5. Payment: Payment gateway integration (Stripe, PayPal).
6. Stack / Frameworks: Choosing tools like Django, React, Postgres, Redis.
7. Maintenance: Code quality, modular design, documentation.
8. Security: Data protection, HTTPS, vulnerability prevention (OWASP Top 10).
9. Audience: User scale, internationalization, accessibility.
10. Compliance / Ethics: Privacy laws (GDPR), data governance.

7. SELF-ASSESSMENT QUESTIONS FOR RETENTION
--------------------------------------------------------------------------------
Q1: Explain the fundamental difference between the Internet and the World Wide Web.
    Answer: The Internet is the global network infrastructure connecting machines; the World Wide Web is an application/service running on top of the Internet using HTTP to share hyperlinked web pages.

Q2: What is the relationship between URIs and URLs?
    Answer: Every URL is a URI, but not every URI is a URL. A URI identifies a resource; a URL identifies it and describes how to access it (location + protocol).

Q3: What are the two major phases of an Internet Software Platform's lifecycle?
    Answer: Development (Plan, Build/Test, Package) and Operations (Release/Configure, Monitor, React/Respond).

Q4: What is Blue/Green deployment?
    Answer: A deployment strategy utilizing two identical physical/virtual environments. One serves active traffic (Blue) while the other receives the new version (Green). After testing, live traffic is switched to Green, enabling zero-downtime releases and instant rollbacks.
