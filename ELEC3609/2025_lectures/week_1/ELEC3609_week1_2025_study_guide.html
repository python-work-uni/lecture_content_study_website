The Big Picture: What "Internet Software Platforms" Means

A modern web application is a whole system you design, build, package, deploy and operate — not just code you write.

This unit is called Internet Software Platforms because it stitches together three areas that used to be taught separately. Before you can build anything, you need a shared vocabulary for the pieces.

  • The Internet is a big network of networks — a medium that allows computers to talk to each other.
  • The World Wide Web (WWW) is a way of accessing information over the medium of the Internet.
  • A website is a collection of web pages on the World Wide Web.
  • Software is a collection of computer programs.
  • A platform is the environment on which that software is designed, built, packaged, deployed and run.

The goal of the unit is to take you from idea to market: to design a web-based service, implement it, test it, deploy it to the cloud securely, and operate it. Each week adds one layer to that story.

Why this matters to you

Professional life

Be a techie in the IT industry. Help all organisations with IT. Explore research opportunities. Run a business directly or indirectly dealing with technologies.

Personal life

Better choose and leverage internet software and platforms. Understand the basics so you are not tricked. Be aware of cyber threats and best practices to protect your data. Be a smart investor. Be digitally savvy.

🧠
Memory hook: Software-defined everything + the Internet of everything. That one line is the reason these skills transfer to almost any career.

The Internet vs the World Wide Web

The Internet is the infrastructure; the Web is only one of several services running on top of it.

These two terms are constantly confused, so pin them down precisely.

Internet — A big network of networks. It is the medium that allows computers to talk to each other.
World Wide Web (WWW) — A way of accessing information over the medium of the Internet. "The Web" is just one of many information-transfer mechanisms on the Internet.

The Internet carries many kinds of traffic besides the Web, for example:

  • Email
  • Instant Messaging
  • File Transfer
  • Media Streaming
  • Usenet
🧠
Memory hook: The Internet is the road system; the Web is one type of vehicle on it. Email, chat, file transfer and streaming are other vehicles using the same roads.
🤔
Pause & predict: When you send an email or stream a video, are you "using the World Wide Web"? Explain why or why not before reading on. (Answer: no — those are separate transfer mechanisms on the Internet; the Web is only one of them.)

Websites, URLs and URIs

Every page on the Web is addressed by a URL, which is a specific kind of URI.

A website is a collection of web pages on the World Wide Web. A single web page can be identified by a Uniform Resource Locator (URL), which is also known as a Uniform Resource Identifier (URI).

The general shape of a URL is:

protocol://domain.tld/path/file.ext

Concrete examples from the lecture:

https://google.com
mailto:huaming.chen@sydney.edu.au
ftp://ftp.google.com

Each example uses a different protocol: https for the Web, mailto for email, and ftp for file transfer.

Websites are generally made up of HTML, JavaScript and CSS, and can contain multiple pages and hyperlinks.

URL vs URI

A URL is a URI that locates a resource; URI is the broader term for any identifier. The lecture points to an external reading for the full distinction.

Web 3.0

The term Web3.0 was coined in 2014 — worth knowing as the next-evolution label after the original Web.

✅
Exam tip: If asked "what is the difference between a URL and a URI?", the safe answer is that a URI identifies a resource while a URL locates it — every URL is a URI, but not every URI is a URL.

Software and Platforms: From Desktops to the Cloud

Software is a collection of programs; a platform is where that software lives and runs — and platforms have moved from the desktop to the cloud.

Software — A collection of computer programs. It is not only code — it includes everything the programs depend on to run.

Software consists of:

  • Compiled code or modules
  • Configuration
  • APIs
  • Services provided by other web or local services
  • Operating systems
  • Hardware drivers
  • Firmware or embedded programs
Platform — The environment on which software is designed, built, packaged and deployed. The lecture contrasts how platforms looked in the past (single desktop machines) with how they look now (distributed, cloud-based systems).
ℹ️
Note: A "hotspot" slide in this week's material highlights ChatGPT as an example of the kind of modern internet software platform that shapes how we work.
💡
Why it matters: Recognising that software includes configuration, APIs, services, OS, drivers and firmware explains why "deploying" is harder than "writing code" — you must manage a whole stack, not a single file.

The Life Cycle of an Internet Software Platform

A platform's life splits into a development half (build it) and an operations half (run it).

The life cycle has two phases, each with three stages.

Plan & Design→Build & Test→Package→Release & Configure→Monitor→React & Respond

Development

  1. Plan, Design — decide what you are building and how.
  2. Build & Test — write and verify the code.
  3. Package — prepare the software for release.

Operations

  1. Release & Configure — ship it and set it up in the target environment.
  2. Monitor — watch how it behaves in the real world.
  3. React & Respond — fix, scale and adapt to what monitoring reveals.
🧠
Memory hook: Development = make it; Operations = keep it alive. The loop never stops — monitoring feeds back into the next plan.
💡
Why it matters: This six-stage cycle is the skeleton of the whole course. The three group assessments map onto it: design (early), implementation and testing (middle), then deployment and security (end).

Real-World Evolution: Data Pipelines and the Qantas Story

Modern platforms evolve by integrating pipelines and automating everything — the Qantas cloud team proves how far automation can scale.

Example 1: A data pipeline

A data pipeline moves raw data through stages until it produces insight:

  1. Data ingestion — take in sensor data via real-time, near real-time, or batch ingest.
  2. Data processing — Extract, Transform and Load (ETL).
  3. Data analytics — analyse the processed data.
  4. Data visualisation — visualise the outcome and provide insights.
Data ingestion→Data processing (ETL)→Data analytics→Data visualisation

Example 2: Qantas at cloud scale

Qantas runs a cloud team of just 12 engineers, driven by one principle: Automation, Automation and Automation. Key facts:

  • Everything as code
  • 250+ applications
  • 5000+ Blue/Green deployments every month
  • Over 2.7 million instances launched
  • Uses Site Reliability Engineering (SRE) and Internet of Things (IoT)
🧠
Memory hook: 12 engineers, 250+ apps, 5000+ deployments a month. Small team, enormous automation — that is the payoff of "everything as code".
✅
Exam tip: Be ready to name the four data-pipeline stages in order and to quote at least two Qantas numbers; these are the concrete anchors examiners like.

Building Websites: The Real-World Trade-offs

Websites are complicated, and engineering is the art of balancing many competing factors.

Building a website is not just coding. Many factors must be considered:

  • Cost
  • Performance
  • Hosting
  • Stability / Reliability
  • Payment
  • Languages / Frameworks
  • Maintenance
  • Security
  • Audience

In this course, the approaches and tools needed to take an idea from conception to market (potentially) are discussed.

💡
Why it matters: Every design decision — which framework, which host, how much to spend — is a trade-off among these factors. Naming them is the first step to reasoning about them.
🤔
Pause & predict: You must launch in two weeks on a tiny budget. Which of the nine factors do you sacrifice first, and why? (There is no single right answer — the point is to reason explicitly about trade-offs.)

Course Mechanics and Learning Outcomes

The unit is built around nine learning outcomes that progress from using tools to professional and ethical responsibility.

The unit's learning outcomes (LOs) define what you should be able to do by the end.

Goals I

  • LO1. Use Python and the Django framework as the baseline programming tools.
  • LO2. Develop web-based services from inception to design through to implementation, testing and maintenance, using principles, techniques and methodologies presented.
  • LO3. Use tools and methods employed in web service design, implementation and testing to the extent of the material and projects presented.
  • LO4. Develop real-world web applications using web-based environments and the course's principles and techniques.

Goals II

  • LO5. Deploy applications using basic cloud services and DevOps practices with baseline security measures.
  • LO6. Instigate inquiry and knowledge development into issues of designing and building a web-based service, and synthesise information to draw meaningful, useful conclusions.
  • LO7. Work in a team, assuming different roles (stakeholders), remaining receptive to other inputs and opinions, to deliver real-world web applications on time and within scope.
  • LO8. Proficiently write reports that convey complex and technical concepts, experiments and outcomes in a clear, concise form.
  • LO9. Demonstrate ethical and professional responsibility in software engineering practice, including awareness of privacy, legal issues, accessibility and the societal impact of technology.
🧠
Memory hook: LO1–LO4 are build it; LO5–LO9 are ship it responsibly. Python + Django is the baseline stack named in LO1.

Glossary

Every term you need to speak this week's language.

Internet
A big network of networks; the medium that allows computers to talk to each other.
World Wide Web (WWW)
A way of accessing information over the medium of the Internet; just one of several transfer mechanisms.
Website
A collection of web pages on the World Wide Web, generally built from HTML, JavaScript and CSS.
URL
Uniform Resource Locator — identifies and locates a single web page, e.g. https://google.com.
URI
Uniform Resource Identifier — the broader term for any identifier of a resource; a URL is a type of URI.
HTML
The markup language used to structure web page content.
CSS
The language used to style and lay out web pages.
JavaScript
The programming language used to add interactivity to web pages.
Software
A collection of computer programs, including compiled code, configuration, APIs, services, OS, drivers and firmware.
API
An interface through which one piece of software requests services from another.
Platform
The environment on which software is designed, built, packaged and deployed.
Infrastructure as Code (IaC)
Managing and provisioning infrastructure through machine-readable code rather than manual setup.
SaaS
Software as a Service — software delivered to users over the internet rather than installed locally.
DevOps
A practice that unifies software development and operations to deliver and run software continuously.
DevSecOps
DevOps with security built into every stage of the development and operations pipeline.
Data pipeline
A staged flow that ingests, processes, analyses and visualises data to produce insight.
ETL
Extract, Transform and Load — the standard data-processing stage of a pipeline.
Blue/Green deployment
A release technique that switches traffic between two identical environments to reduce risk.
Site Reliability Engineering (SRE)
A discipline applying software engineering to operations to keep large systems reliable.
Internet of Things (IoT)
Networks of connected physical devices that collect and exchange data.
AJAX
A technique for making asynchronous requests from a web page to a server without reloading the page.
REST API
A web API that follows representational-state-transfer principles, used to exchange data.
Academic integrity
Behaving honestly, ethically and responsibly in all elements of study, including assessments.
AWS Academy
The portal through which this unit provides cloud computational resources.

No terms in this category.
