1. FRONTEND FUNDAMENTALS & USER EXPERIENCE (UX VS UI)
--------------------------------------------------------------------------------
The front-end is the presentation layer of a web application. It executes directly
in the client browser, serving as the bridge between the user and backend services 
(data persistence, business logic, computations).

[Core Usability Philosophy]
- Usability Axiom: "Mobile is a magnifying glass for your usability problems."
- Engineering vs. Art: Building effective user interfaces is NOT art—it is an engineering
  discipline based on structure, sensible defaults, and consistency.
- Steve Jobs on Design: "Design is not just what it looks like and feels like. Design is 
  how it works."

[UX (User Experience) vs. UI (User Interface)]
UX and UI represent two distinct aspects of frontend design:

+-------------------------+----------------------------------------------------+
| Aspect                  | Key Responsibilities & Focus Areas                 |
+-------------------------+----------------------------------------------------+
| UX Designer             | - Focuses on HOW IT WORKS & user interaction flow.  |
| (Interaction Design)    | - Charts user pathways & plans information arch.   |
|                         | - Creates structural wireframes & interactive      |
|                         |   prototypes; conducts user research.              |
+-------------------------+----------------------------------------------------+
| UI Designer             | - Focuses on HOW IT LOOKS & visual aesthetics.     |
| (Visual Design)         | - Selects color palettes, typography, & styling.   |
|                         | - Produces high-fidelity mockups, graphics, and   |
|                         |   pixel-perfect page layouts.                      |
+-------------------------+----------------------------------------------------+
| Technical Artist        | - Bridges the gap between visual artwork and       |
|                         |   frontend code execution/performance.             |
+-------------------------+----------------------------------------------------+

[Golden Rules for Great UX]
1. No Instructions Needed: The interface should be intuitive enough that users do 
   not need a user manual.
2. Simple Common Tasks: Keep the user path for frequent actions as short as possible.
3. Every Click Matters: Minimize unnecessary steps and friction.
4. User Happiness: Design predictable, responsive interactions that reduce user frustration.

2. WEBPAGE DESIGN PIPELINE: WIREFRAMES, MOCKUPS & PROTOTYPES
--------------------------------------------------------------------------------
The webpage design workflow moves sequentially from structural outline to high-fidelity 
interactive behavior:

1. Wireframe (Structural Blueprint):
   - Scope: Structural layout and component positioning.
   - Purpose: Outline what information and UI components will be displayed on each page.
   - Characteristics: Low fidelity, grayscale/skeletal representation; no visual styling.

2. Mockup (Visual Specification):
   - Scope: Visual appearance and aesthetics.
   - Purpose: Show exact colors, typography, spacing, icons, and visual branding.
   - Characteristics: High-fidelity static graphical snapshot of the final page design.

3. Prototype (Functional Experience):
   - Scope: Interaction, motion, and behavior.
   - Purpose: Demonstrate how the page works and responds to user inputs.
   - Characteristics: Interactive model (can be low or high fidelity) allowing users to 
     click through and evaluate real workflow behavior.

[Design Deliverables Summary Table]
+---------------+-----------------------------------+----------------------------------+
| Design Stage  | Primary Focus                     | Key Questions Answered           |
+---------------+-----------------------------------+----------------------------------+
| Wireframe     | Information Architecture & Layout | "Where do components go?"        |
| Mockup        | Visual Style & Graphic Aesthetic  | "What will it look like?"        |
| Prototype     | Interaction & Behavioral Flow     | "How does the user interact?"    |
+---------------+-----------------------------------+----------------------------------+

3. THE BROWSER ECOSYSTEM, INTEROPERABILITY & CROSS-COMPATIBILITY
--------------------------------------------------------------------------------
[Browser Fragmentation Challenges]
Web applications execute in highly heterogeneous runtime environments:
- Browser Engines: Chrome (Blink), Firefox (Gecko), Safari (WebKit), Edge (Blink).
- Versioning: Legacy versions vs. evergreen auto-updating browsers.
- Operating Systems: Windows, macOS, Linux, iOS, Android (each rendering differently).
- Hardware Diversity: Screen resolutions, high-DPI viewports, touch vs. mouse inputs.

[Interoperability Strategy]
- Rule of Support: You do NOT need to support all browsers, versions, or operating systems.
- Strategic Targeting: At project inception, define target supported browsers based 
  strictly on target audience metrics and demographic analytics.
- Compatibility Reference: `caniuse.com` provides up-to-date compatibility tables for 
  HTML5, CSS, and JS APIs across browser versions.

[Testing Methodologies]
1. Local Machine Testing: Native execution in locally installed browser instances.
2. Virtual Machine (VM) Emulation: Running target OS environments inside VMs.
   * Note: Virtualization can introduce its own unique rendering/performance bugs.
3. Professional Cloud Platforms: Automated cross-browser testing services running 
   on real physical hardware/devices (e.g., BrowserStack, Sauce Labs).

4. MODERN DESIGN PRACTICES & WEB COMPONENTS
--------------------------------------------------------------------------------
[Design Best Practices]
1. Responsive Web Design (RWD):
   - Fluid page layouts that dynamically adapt to any screen size or orientation 
     using media queries, flexible grids, and responsive media.
2. Inclusive Design:
   - Creating software accessible to everyone without exclusion.
   - Considers accessibility across: Disability (visual, auditory, motor), age, language, 
     ethnicity, race, religion, gender identity, and sexual orientation.

[Web Components Architecture]
Web Components are a suite of native browser technologies allowing developers to create 
custom, reusable HTML tags (`<user-card>`, `<custom-button>`) containing HTML, CSS, and JS.

[The 4 Pillars of Web Components]
1. Reactivity: Automatically re-rendering or updating UI state when properties/attributes change.
2. Encapsulation: Keeping styles and markup scoped internally so they don't leak out (Shadow DOM).
3. Modularity: Packaging complex UI widgets into standalone, self-contained units.
4. Reusability: Using the custom element repeatedly across pages or projects like native HTML tags.

5. HTML5 MARKUP, DOCUMENT STRUCTURE & THE DOM
--------------------------------------------------------------------------------
[HTML Specification Timeline]
- 1997: HTML 3.2
- 1999: HTML 4.01
- 2007: HTML5 Draft published
- 2014: HTML5 published as official W3C Recommendation (introduced `<audio>`, `<video>`, 
        semantic elements, and input types: `color`, `date`, `email`, `time`).

[The DOCTYPE Declaration]
- Purpose: NOT an HTML tag. It is a directive informing the browser parser which standard 
  or HTML version is being used.
- Placement: Must be the absolute FIRST line in the HTML document.
- HTML5 DOCTYPE: `<!DOCTYPE html>` (Short, case-insensitive, standards-compliant, and 
  masquerades safely for older browsers).
- Legacy HTML4 DOCTYPE (Complex DTD):
  `<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN" "http://www.w3.org/TR/html4/strict.dtd">`

[Minimal HTML5 Document Template]
```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Page Title</title>
    <link rel="stylesheet" href="styles.css">
</head>
<body>
    <h1>Main Heading</h1>
    <p>Paragraph content goes here.</p>
    
    <!-- Scripts placed at end of body to avoid blocking page render -->
    <script src="app.js"></script>
</body>
</html>
```

[Structural HTML Tags Breakdown]
- `<html>`: Root element wrapping the entire document. Defines language attribute (`lang="en"`).
- `<head>`: Stores document metadata, encoding, title, and external CSS style links.
  * Note: Script tags in `<head>` block page parsing/rendering while downloading.
  * Mandatory Tag: `<title>` is required inside `<head>`.
- `<body>`: Contains all visible UI content rendered in the browser viewport.
  * Best Practice: Place `<script>` tags immediately before closing `</body>` tag to ensure 
    DOM elements are parsed before scripts execute.
  * Empty Elements: Self-closing tags without closing tags (e.g., `<br>`, `<img>`).

[HTML Attribute Best Practices]
- Use lowercase for all element names and attributes (`src`, `href`, `title`, `style`).
- Always enclose attribute values in quotes (`href="https://sydney.edu.au"`).

[Document Object Model (DOM)]
- Concept: An in-memory object-oriented tree structure representing the HTML document.
- DOM Manipulation: JavaScript interacts with the DOM to dynamically alter page content, 
  styles, and attributes.

[Common DOM Selection Methods]
+---------------------------------------+-----------------------------------------------+
| DOM Method                            | Description / Return Value                    |
+---------------------------------------+-----------------------------------------------+
| `document.getElementById('id')`       | Returns single matching element by ID.        |
| `document.getElementsByTagName('tag')`| Returns HTMLCollection of elements by tag.    |
| `document.getElementsByClassName('c')`| Returns HTMLCollection of elements by class.  |
| `document.querySelector('selector')`  | Returns first element matching CSS selector.  |
| `document.querySelectorAll('sel')`    | Returns NodeList of all matching elements.    |
+---------------------------------------+-----------------------------------------------+

[Web Component Custom Element Lifecycle Callbacks]
Custom HTML elements hook into browser DOM events via lifecycle callbacks:
- `connectedCallback()`: Invoked when the custom element is attached to the document DOM (`'connected'`).
- `disconnectedCallback()`: Invoked when the custom element is detached/removed from the DOM (`'disconnected'`).

6. CSS ARCHITECTURE, SELECTORS, RESPONSIVE DESIGN & FRAMEWORKS
--------------------------------------------------------------------------------
[Cascading Style Sheets (CSS)]
- Role: Defines presentation and styling of HTML markup, establishing separation of concerns 
  between document content (HTML) and visual appearance (CSS).
- Syntax: `selector { property: value; }`

[Primary Selectors & Specificity]
1. Element Selector: Targets all elements of a specific HTML tag.
   ```css
   body { background-color: #f4f4f4; font-family: Arial, sans-serif; }
   ```
2. Class Selector (`.className`): Targets elements with a specific `class` attribute.
   - Reusable: Can be applied to multiple elements on the same page.
   - Elements can possess multiple classes (`<div class="card shadow primary">`).
   ```css
   .dog { color: blue; font-weight: bold; }
   ```
3. ID Selector (`#idName`): Targets a single element with a specific unique `id`.
   - Uniqueness: Must be unique; an ID can only be assigned to one element per document.
   ```css
   #dog-name { color: red; text-decoration: underline; }
   ```

[Selector Specificity Order (Highest to Lowest Priority)]
Inline Styles (`style=""`) > ID Selector (`#id`) > Class Selector (`.class`) > Element Selector (`tag`)

[Responsive Design & Media Queries]
- Media Queries (`@media`): Apply CSS rules conditionally depending on viewport dimensions, 
  device orientation, or screen resolution.
- Example:
  ```css
  /* Default styles for mobile viewports */
  .container { width: 100%; }

  /* Desktop viewport override */
  @media (min-width: 768px) {
      .container { width: 750px; }
  }
  ```

[CSS Frameworks]
- Philosophy: "The best CSS is written by someone else." Pre-built, battle-tested CSS frameworks 
  accelerate development and ensure cross-browser layout consistency.
- Popular Frameworks: Bootstrap, Foundation, Materialize.
- Framework Selection Criteria: Visual aesthetics, grid layout engine, community support, 
  and cross-browser compatibility.

7. JAVASCRIPT ECOSYSTEM: TYPESCRIPT, SPAS & AJAX
--------------------------------------------------------------------------------
[JavaScript Fundamentals]
- Characteristics: High-level, dynamic, untyped (dynamically typed), interpreted programming language.
- Function: Manipulates the HTML DOM dynamically to create interactive client-side web apps.

[Historical JavaScript Issues]
- Type Coercion: Weird implicit conversions (`5 == "5"` evaluates to true).
- Context Loss: Complex and unintuitive behavior of the `this` keyword.
- Weak Tooling: Absence of static type checking leads to runtime type errors.
- Lack of Native Modules: Early JS lacked standard module importing (`import`/`export`).

[TypeScript]
- Definition: Open-source language developed by Microsoft; a strict superset of JavaScript.
- Transpilation: TypeScript code is transpiled back into standard JavaScript for browser execution.
- Key Additions: Optional static typing, interface contracts, classes, and ES6 module namespaces.
- Target: Designed specifically for engineering large-scale enterprise web applications.

[jQuery]
- Legacy Role: Historical DOM abstraction library ("Swiss army knife") that simplified DOM manipulation 
  and cross-browser compatibility.
- Modern Decline: Declining popularity because modern browsers now natively support clean DOM 
  APIs (`document.querySelector`) and modern JavaScript syntax (ES6+).

[Single Page Applications (SPAs)]
- Concept: Loads a single HTML document; dynamically updates user views client-side using JavaScript 
  without performing full page browser reloads.

+-----------------------------------------------+--------------------------------------------------+
| SPA Advantages (Pros)                         | SPA Disadvantages (Cons)                         |
+-----------------------------------------------+--------------------------------------------------+
| Fluid, fast, app-like user interface          | Higher initial codebase complexity & overhead    |
| Strict separation of frontend UI & backend API| Pushes processing workload into client browser   |
| Easy deployment to static CDNs (fast load)    | Poor performance on low-spec/mobile hardware     |
| Simplified dynamic data binding to views      | SEO indexing challenges & framework churn        |
+-----------------------------------------------+--------------------------------------------------+

[AJAX (Asynchronous JavaScript and XML)]
- Concept: Fetches data asynchronously from backend servers without requiring a full page refresh.
- API Evolution:
  1. `XMLHttpRequest (XHR)`: Original low-level browser API (clunky syntax).
  2. `jQuery $.ajax()`: Simplified library wrapper around XHR.
  3. `Fetch API`: Modern, promise-based native browser API (`fetch('/api/data').then(...)`).

[Popular Frontend Frameworks]
React (Meta), Angular (Google), Vue.js, Ember.js, Backbone.js.

8. FRONTEND TOOLING & BUILD ECOSYSTEM (BOWER, TASK RUNNERS, WEBPACK)
--------------------------------------------------------------------------------
[Package Management (Bower)]
- Function: Front-end package manager dedicated to HTML, CSS, and JS client-side dependencies.
- Runtime: Node.js application installed via `npm`.
- Manifest: Tracks client-side project dependencies inside `bower.json`.

[Task Runners (Grunt & Gulp)]
- Function: Automated task runners (frontend equivalent to a Unix `Makefile`).
- Primary Use Cases:
  1. Minification: Compressing HTML, CSS, JS, and image assets to reduce network transfer sizes.
  2. Concatenation: Combining multiple source files into unified bundles.
  3. Linting: Code style and syntax error checking.
  4. Testing: Automating client-side test execution.

[Module Bundlers (Webpack)]
- Function: Static module bundler for modern JavaScript applications.
- Behavior: Recursively builds a dependency graph of all assets (JS, CSS, images) and packages 
  them into optimized, production-ready bundle files containing only necessary code.
