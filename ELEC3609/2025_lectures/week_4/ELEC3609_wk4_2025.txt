Not All Browsers Are Created Equal
Each browser is different
 
…and so is each version of a browser
 
…and each version is different on each OS
 
…don’t forget different screen resolutions
 
…or mobile devices
– You must consider interoperability between browsers, browser 
versions and operating systems when writing web 
applications.
Can I Use?
caniuse.com provides a quick reference on browser 
compatibility for features and limitations.

--- Slide 21 ---
The University of Sydney
Page 21
Cross-Compatibility Testing
– If our application must run on a certain browser, we must test 
it on that browser. Never assume it will work.
– We can test different browsers by using our own local 
machine.
– We can test different operating systems by emulating them 
with virtual machines. Virtualisation can introduce bugs itself.
Professional Solutions
Many professional tools and services exist for testing 
cross-compatibility, often with the ability to test on real 
hardware and devices (e.g., Windows Phone).

--- Slide 22 ---
The University of Sydney
Page 22
You Don’t Need To Support ALL Browsers!
Strategically choose your supported browsers.
– You don’t need to (and probably shouldn’t) support all 
browsers, versions and operating systems.
– At the start of your project, make a decision on what you will 
and won’t support. Base this decision on your intended 
customer base.
– Know your intended audience.

DOCTYPE Tag
– Not a HTML tag. It is an instruction to the browser of the 
version of HTML used by the page.
– Must be the very first line in your document.
– This is a HTML5 DOCTYPE declaration, however it will 
masquerade as HTML4 for older browsers.
– HTML 4 DOCTYPES are more complex.
–
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN" "http://www.w3.org/TR/html4/strict.dtd">
–
<!DOCTYPE html>

HEAD Tag
– Contains meta information that is separate from the content.
– Elements are not rendered in the view.
– CSS files are generally imported here.
– JS imported here will delay rendering of the page until the 
scripts are loaded. JS can instead be imported in the body to 
speed up page loading times.
– Title tag is mandatory in this section.

--- Slide 37 ---
The University of Sydney
Page 37
BODY Tag
– Contains the HTML elements to be rendered to the view.
– If placing script tags in the section, it is convention to place 
them just before the closing body tag.
– Body is a mandatory tag for a HTML document.
– Never Skip the End Tag
– Empty elements: <br>

Cascading Style Sheets
– Describes the presentation of a HTML document.
– Enables a separation of concerns between “what’s in a 
document” (HTML) and “what a document looks like” (CSS).
– Similar to HTML, CSS has different versions and varying 
support across browsers.
– CSS can be difficult to get right but is 100% worth it.

--- Slide 46 ---
The University of Sydney
Page 46
CSS Syntax
selector { property:value; }
Selector: Points to the HTML element the style should apply to
Property: The attribute that should be modified.
Value: What the value should be updated to.
{}: Declaration block can contain multiple property value pairs.

JavaScript
– JavaScript is a high-level, dynamic, un-typed, interpreted 
programming language.
– JavaScript allows pages to become dynamic by manipulating 
the HTML DOM with code.
– Alongside HTML and CSS, it forms a fundamental core of 
today’s modern web.
– Learning to appreciate JavaScript will improve your 
applications and make you more employable.

--- Slide 56 ---
The University of Sydney

JavaScript Issues
– Early versions were hard to develop in:
– Weird equality/automatic conversion.
– Behaviour of this.
– Lack of a type system.
– Weak static analysis support. Poor tooling.
– Lack of a module system.
– JavaScript is constantly evolving, and the language has 
improved significantly with more recent versions.
JavaScript isn’t perfect but it’s here to stay.

TypeScript
– TypeScript is an open-source programming language that 
implements a superset of JavaScript while adding optional 
static types.
– Developed and maintained by Microsoft and designed for the 
development of large web applications.
– Transpiled back to JavaScript
Adds support for:

– modules/namespaces
– classes

JQuery
JQuery – the Swiss army knife!
– Commonly used on web pages.
– Highly supported and has an active community.
– Likely to have everything you need to interact with the DOM.
– Great for cross platform support.
Becoming less popular due to modern frameworks superseding 
JQuery’s functionality and browsers implementing native 
versions of a lot of the library.

--- Slide 59 ---

Single Page Applications
– Single page applications load a single HTML document and 
use JS to update the user’s view without a hard refresh.
– Single page applications move a lot of work to the client-side 
(browser) and typically create a smoother, more fluid user 
experience. They allow for significantly more powerful web 
applications.

--- Slide 60 ---
The University of Sydney
Page 60
Single Page Applications
Pros:
– Provide a faster interface.
– Encourage separation of concerns.
– Reusable
– Allow for “serverless” browser applications.
– Simpler binding of data to views.
– Easy to serve from a CDN, decreasing user load time.
– Removes load from backend servers.
Cons:
– Typically require more work.
– Typically require more experienced developers due to complexity.
– New frontier. Frameworks are rapidly evolving.
– Pushes workload into the browser, bad for low-spec/mobile devices.

AJAX
Asynchronous JavaScript and XML
– Allows the page to be updated with external data without a full 
refresh.
– AJAX is a fundamental aspect of the modern web.
– Traditionally we would use XHR, which can be clunky and 
cumbersome.
– JavaScript libraries like JQuery improved the situation
– Native browser APIs, such as Fetch, are also an option where 
supported.

Bower
Bower – a package manager for the web.
– Imagine pip but for frontend HTML, JS and CSS libraries.
– A Node.js application – installed via npm.
– Can fetch packages and their dependencies.
– Much easier to update packages.
– Document your dependencies in a bower.json file.

--- Slide 65 ---
The University of Sydney
Page 65
Grunt
Grunt – a JavaScript task runner.
– Similar to a Makefile but for HTML frontends.
– Also a Node.js application – installed via npm.
– Automates boring, repetitive tasks:
– minification of images, CSS, JS, HTML
– dependency linking
– linting (error/style checking)
– testing
Gulp is another popular JS task runner.
