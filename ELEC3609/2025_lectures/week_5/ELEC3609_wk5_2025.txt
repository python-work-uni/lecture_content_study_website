XML
– Extensible Markup Language (XML) defines a set of rules for 
encoding documents.
– It is a language for describing the rules of other languages. 
XML allows us to define schemas for tag-based languages. A 
schema is a contract for communication between client and 
server.
– XML is:
– a markup language, not a programming language.
– human-readable.
– machine-readable.
– designed to be self-descriptive.
– designed to carry and transport data, not to display data.

XML Terminology
– Markup: Elements that define the structure of the document. 
Usually enclosed by:
• < and >
• & and ;
– Content: All the information between markup.
– Tag: A type of markup that begin with < and ends with >, and 
comes in three flavours:
– start tag: <section>
– end tag: </section>
– empty-element tag: <img src=“dog.jpg”/>
– Attribute: Markup on a start tag or empty-element tag that 
defines key-value pairs about that element.
– <img src=“dog.jpg” alt=“woof”/>

XML Document Type
– To define what types of fields are allowed in an XML document, 
and in what structure, a document type declaration (DOCTYPE) is 
provided.
– The DOCTYPE identifies a document type definition (DTD), which 
defines the fields and their structure.
– For our XML book document example, the DTD is:
<!ELEMENT book (title , chapter+)>
<!ELEMENT chapter (heading , paragraph*)>
<!ELEMENT heading (#PCDATA)>
<!ELEMENT paragraph (#PCDATA)>
<!ATTLIST book
language CDATA #REQUIRED
author CDATA #REQUIRED
>

HTTP
– Hypertext Transfer Protocol (HTTP) is designed to allow 
communication between a HTTP client and HTTP server.
– HTTP works as a request-response protocol. A client makes a 
request and the server responds, generally with a web page.

HTTP Methods
– These are the most commonly used HTTP methods:
– GET: used to request data about a specified resource.
– POST: used to create a resource.
– Many more exist:
– PUT: create/update a resource.
– PATCH: partial modification of a resource.
– DELETE: deletes the specified resource.
– OPTIONS: returns the supported HTTP methods for this resource.
– HEAD: equivalent to a GET request without the response body.
– Consistency is key.

HTTP Cookies
– A HTTP cookie is a small piece of data, set by a website, 
which is stored in the user’s browser.
– Browsers automatically include all the cookies set by a server 
with every HTTP request sent to that server.
– There are two HTTP headers which control cookies on the 
web:
– Requests: Cookie
• Cookie: username=abc123; authToken=4f3e
– Responses: Set-Cookie
• Set-Cookie: username=abc123
– Set-Cookie: authToken=4f3e

--- Slide 17 ---
The University of Sydney
Page 17
HTTP Cookies II
– Cookies are often used for tracking users and authentication.
– A typical login flow:
– 1.User visits website for first time.
• no cookie
– 2.User submits login form to server with username + password.
• still no cookie
– 3.Server generates authentication token (auth-tok).
• Server responds with Set-Cookie: token=[auth-tok]
– 4.User visits website.
• Client sends: Cookie: token=[auth-tok]
– 5.Server recognises (auth-tok) and knows request came from User.
HttpOnly, Secure, SameSite

HTTP Content Type
– A HTTP request uses the Accept header to indicate to the 
server which data types it will accept in the response. A client 
can define multiple data types that it supports.
– The HTTP response defines the Content-Type header, which 
determines what type of data is contained in the body of the 
response. This is an indication to the browser as to how it 
should interpret the response.

HTTP Referer
– The HTTP Referer header is sent with requests made by a 
browser. It indicates to the server, the previous page that the 
user was on.
– For example:
– I go to www.google.com and search for “elec3609”.
– I click on the link to the www.elec3609.com website.
– The browser’s request to www.elec3609.com includes a Referer 
header, containing our previous address:
 
 
https://www.google.com/

Models
– A model describes the fields which hold information about a 
particular entity. Each attribute of a model has a designated 
type, such as:
– String
– Numeric
– Boolean
– Date/Time
– An entity is represented by a single table in a database.
– Each table should have an ‘id’ field, which uniquely identifies 
each row, as the primary key.
– Each of the entities in an ERD can be considered a model.

Foreign Keys
– Models rarely exist in isolation, they have relationships with 
other models.
– A relationship to another model is expressed through a Foreign 
Keys (FK).
– Foreign Keys specify a ‘one-to-many’ relationship.
TIL Example

Posts contain a foreign key to their associated User.

Model-View-Controller Architecture
– A common way to structure the code of a web application is 
using the model-view-controller (MVC) architecture.
– In this pattern, code functionality is separated into three 
responsibilities:
– Model: Handles the data.
– View: Renders data into views (usually HTML).
– Controller: Interprets requests and encapsulates business logic.
MVC Overview (source)

Virtual Environments
– To solve this problem, we can use Python Virtual 
Environments.
– Virtual environments allow us to have multiple, isolated 
installations of Python. Each virtual environment can have its 
own Python dependencies without conflicting with each other.
– A virtual environment must be activated before it can be used.
– Do not commit your virtual environment into your repository.
