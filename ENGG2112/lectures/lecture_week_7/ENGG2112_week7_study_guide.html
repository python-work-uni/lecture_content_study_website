Human-AI Interaction with Generative AI

How people use large language models, how prompts steer them, and how far collaboration goes.

Read this first: A generative model is a next-token predictor you direct: its behaviour follows the role and structure you give it, its value follows the initiative you share.

The Big Picture

One story runs through the week: a powerful text predictor you can direct, and a ladder for how much you let it drive.

Generative AI creates new content, not just labels or analysis. Its workhorse is the large language model (LLM), trained on enormous text to predict the next token.

The lecture's six topics: what these models do, how you instruct them, how deep collaboration gets, what input/output they handle, how feedback trains them, and who can access them — Professor Mary Lou Maher's Week 7 lecture.

Common uses→ Structured prompts & roles→ Six levels of interaction→ Input / output modalities→ RLHF training→ Enterprise vs personal access
💡
Why it matters: these six topics answer three engineering questions — What is this tool good for?, How do I control it?, and Can I trust it with my data?

Common Uses of LLMs

Five everyday jobs one language model already does well — and the question they raise about intelligence.

✍️ Content Creation

Generates articles, stories and poems; gives creators drafts to refine.

💬 Chatbots & Virtual Assistants

Powers conversational agents for customer service, assistance and queries.

🌐 Language Translation

Translates text between languages accurately.

🎓 Educational Tools

Creates personalised materials and quizzes, and offers tutoring and coaching.

🔎 Search Engines

Summarises web results into a focused, conversational answer.

Is it AGI?

AGI (Artificial General Intelligence) would mean human-like intelligence across any intellectual task. The lecture poses “Is it AGI?” but does not declare LLMs to be AGI: many tasks is not general understanding.

🧠
Remember: the five common uses as “Content, Chat, Translate, Teach, Search.”

Personal & Professional Uses

The same capability appears in private life and professional work — the context changes, the model does not.

🏠 Personal Uses of AI

  • Personalised Recommendations — preferences shape suggested content, products or advice.
  • Accessibility — text-to-speech and real-time transcription.
  • Email and Communication Assistance — draft, summarise and manage messages.
  • Fake News Detection and Fact-Checking — flag false information.

💼 Professional Uses of AI

  • Programming Assistance — GitHub Copilot and Claude Code generate, debug and test code.
  • Sentiment Analysis — gauge opinion and trends from social media and reviews.
  • Legal and Medical Document Analysis — summarise and analyse documents.
  • Creative Writing and Scriptwriting — prompts, plot ideas or whole scripts.
  • Game Development — dynamic dialogue, narratives and quests.

Structured Prompts & Roles

A structured prompt is a recipe, not a wish — six named parts control what the model does and who it acts as.

A structured prompt uses named components so the model plays a defined role; Context frames it, the other five define who, what and how.

ComponentQuestionWhat it controls
ContextWho am I?Your level, course, problem.
RoleWho should you be?A persona or expertise.
GoalWhat do I want?The target outcome.
ConstraintsWhat are the limits?Length, complexity, format, scope.
Step-by-step instructionsIn what order?Order of reasoning or output.
PersonalisationHow do I work best?Style, analogy, tone, format.

Roles you can assign

A tutor asks guiding questions; a tool produces an artefact. Seven roles: Mentor, Tutor, Coach, Teammate, Student, Simulator, Tool.

C · R · G · C · S · P
“Clearly Role-play Goals, Constraints, Steps, Personalise”
Context, Role, Goal, Constraints, Step-by-step instructions, Personalisation.
⚠️
Common trap: no context or constraints gives a generic, over-long or wrong-level answer.

Worked Example: A Prompt to Learn Recursion

The six components in action — one prompt that teaches recursion, each part labelled.

  1. Context. “I am a second-year CS student taking data structures and algorithms; I can't see how recursion progresses and returns values.”
  2. Constraints. “Keep the explanation under 350 words, use simple Python examples, avoid advanced concepts.”
  3. Role Modelling. “Explain as an experienced CS tutor who builds intuition for algorithmic thinking.”
  4. Step-by-Step Process. “First define recursion; then trace a recursive function (like factorial) call by call; finally explain why this aids debugging.”
  5. Personalisation. “I learn better from visual or real-world analogies, so include one that pictures recursion.”

The Goal (“understand recursion”) is implied, not stated; other parts close failure modes: too long, too advanced, wrong persona, unstructured, or mismatched to how the student learns.

Reusable Template: The Tutor Role

A fill-in-the-blanks prompt that makes the model a tutor who asks first and hints instead of answering.

Opening: “Act as my tutor for [course name/number], topic [specific topic, e.g. “second-order linear differential equations”]. My course uses [textbook/notes/approach, if relevant].”

“Please tutor me using these rules:”

  • Ask the topic for this session.
  • Ask what I already understand.
  • Explain briefly (max 200 words), then offer more depth.
  • Ask guiding questions; let me attempt each step.
  • Check understanding before moving on.
  • If I'm stuck, give a hint, not the solution.
  • Match a second-year engineering level.
  • Note correct reasoning even if my answer is wrong.
  • Do not do my assignment; help me do it.

Six Levels of Human-AI Interaction

Not every LLM interaction is the same — they climb a ladder from minimal lookup to full co-creation.

The lecture arranges interaction into six levels; moving up, the AI takes more initiative and both parties influence each other more. A definition needs only level 1; co-designing needs levels 4–6.

LevelRole of AIHuman–AI relationship
1. Information retrievalLookup toolMinimal interaction
2. Task automationAssistantUser directs, AI executes
3. Guided generationContent generatorIterative refinement
4. Thought partnershipCognitive collaboratorShared sense-making
5. Mixed-initiativeCo-workerBoth take initiative
6. Co-creativityCreative partnerJoint creation, mutual influence
I · T · G · T · M · C
“I Take Great Thought Making Co-creations”
Information retrieval, Task automation, Guided generation, Thought partnership, Mixed-initiative, Co-creativity.

The Six Levels in Detail

The distinctions between levels are the exam core — especially what separates levels 4, 5 and 6.

Level 1 — Information Retrieval

The lowest level: query the LLM like a search engine for facts, definitions or summaries; minimal context.

Level 2 — Task Automation

The AI performs bounded, well-defined tasks — emails, rewriting, code snippets, translation — with constraints set and efficiency the goal.

Level 3 — Guided Generation

You give structured instructions; the AI produces substantial work (essays, images) refined iteratively.

Level 4 — Thought Partnership

The AI helps you reason, brainstorm or explore — project ideas, drafts, dialogue, critiques — sustained shared sense-making that supports but does not lead.

Level 5 — Mixed-Initiative Collaboration

The user and AI both take initiative: the AI proposes steps, flags constraints or suggests alternatives unprompted.

Level 6 — Co-Creative Collaboration

The highest level: human and AI jointly create and build on each other's ideas (co-designing art, stories or interfaces; frameworks like COFI), needing trust, transparency and shared context.

⚠️
Common trap: don't merge levels 5 and 6 — level 5 is turn-taking initiative on a defined task; level 6 is joint creation of the creative direction.

Worked Example: A Thought Partner Prompt

A prompt that holds the AI at level 4 — it helps a team think but refuses to write for them.

The lecture's prompt for a 4–5 person “AI for Good” team. The AI is a thought partner (level 4), not the author; the team must decide the problem, ML techniques, data and one-semester feasibility.

Role line: “Act as a thought partner for my team's “AI for Good” project proposal, not as the author of it.”

“Please follow these rules while working with us:”

  • Don't write our proposal or text; redirect us to think it through.
  • Respond to our ideas, not replace them: strengths, risks, gaps; don't invent unless asked.
  • Push on feasibility — say when something is too ambitious and why.
  • Ask clarifying questions rather than assuming.
  • Flag missing essentials — data, ethics, evaluation.
  • If asked “what do you think”, give reasoning as one input, not a decision.
  • Start by asking us to describe the problem, then help scope it.

Credit: Rezwana & Maher (2022), the COFI co-creative framework (DOI 10.48550/arXiv.2204.07666).

Input & Output Modalities

Many kinds of input go in; text almost always comes out — that asymmetry is the key pattern.

Models take text, images, video and audio, but the default answer is language; other modalities are converted into text-like space, and non-text output needs a separate tool.

Input modalityTypical LLM path (pretrained)Common outputsNotes / examples
TextNative (tokenized text → LLM)Text (language, JSON, code)Core capability.
ImageVision encoder → projector → LLMText (captioning, OCR, VQA)GPT-5.x, Gemini 3 and Claude accept images; generation is separate.
VideoFrame sampling (+ audio) → encoders → LLMText (summaries, timestamps)Gemini 3 native; others sample frames.
Audio (speech)Cascaded ASR → LLM, or end-to-end multimodalText (transcripts, Q&A); audio (TTS)Audio-native models common (GPT-5.x voice, Gemini Live).

How each modality works

Text is the core channel (prompts, documents and code in; language, JSON and code out). Images support captioning, OCR and VQA with text output; video gives summaries and timestamps from sampled frames; audio uses cascaded ASR → LLM → TTS for transcription and translation.

🧠
Remember: inputs are T-I-V-A (Text, Image, Video, Audio); outputs default to text. To make a picture you need a different model.

Rule-Based vs LLM-Based Chatbots

One is narrow but reliable; the other is flexible but can confidently make things up.

A rule-based chatbot follows fixed rules or decision trees (“if X, respond Y”); an LLM-based chatbot generates replies from a language model trained on huge text.

AspectRule-basedLLM-based
Response methodFixed rules / decision treesGenerated by the model
Input handledOnly anticipated patternsOpen-ended questions; typos
PredictabilitySame input → same outputSame question can differ
Failure modeGoes silent or a fallbackConfidently wrong (“hallucinating”)
AuditabilityEasy — paths traceableHard — no decision tree
Cost / buildCheap for narrow tasksCostlier; needs oversight
Example“Check my order status”Troubleshooting a novel problem
💡
Decision rule: how open-ended is the task, and how costly is a wrong answer? A silent bot is annoying; a hallucinating one in medicine or law is dangerous.

LLMs vs Image Generators — and Deepfakes

Both are “generative”, but they learn and represent the world in completely different ways.

Both create new content, but their training data, representation and output differ — so an LLM “sees” an image as text-like features, not truly picturing it.

Trained onTextImages (often with captions)
GenerationLanguage, token-by-tokenVisuals via diffusion or GANs
RepresentationLinguistic embeddingsPixel or latent space
Prompt useReasons with text and structureMaps prompts to visual features
OutputTextImages

Generating deepfakes

A deepfake is hyper-realistic synthetic video, image or audio of a target person. Five-step pipeline:

  1. Collect data — images, video and audio of the target.
  2. Preprocess — face extraction and alignment.
  3. Train — a GAN or similar model on the target's visual and voice patterns.
  4. Generate — face swaps, voice clones, reenactments.
  5. Post-process — improve realism.

Deepfakes rely on GANs, diffusion models and neural rendering; they convince because models learn facial micro-movements, voice tone, rhythm and accent, behavioural patterns and lighting and texture cues, while adversarial training minimises artefacts.

How LLMs Learn to Generate and Debug Code

Code generation reuses next-token prediction from general text, then specialises on code and human preferences.

Pretrain on text→ Fine-tune on code→ Autoregressive training→ Instruction fine-tuning + RLHF
  1. Pretrained Transformer. Pretrained on large text, it learns next-token prediction and representations of patterns, syntax and structure.
  2. Train or fine-tune on large code datasets. For Python: GitHub repos, docs, tutorials, unit tests and competitive datasets — learning syntax, idioms, data structures, libraries and multi-file imports.
  3. Autoregressive training. Feed partial code, predict the next token, compute loss against the ground truth, update parameters via gradient descent. Teaches valid syntax, logical continuation and snippets; Transformers excel at long-range dependencies (e.g. a definition and a distant call).
  4. Instruction fine-tuning and RLHF. Refine on coding-task prompts with correct solutions, improving instruction-following, then tune with RLHF.

RLHF: Learning from Human Preferences

Traditional training copies “the one right answer”; RLHF learns “which is better” — qualities easier to recognise than to write down.

Reinforcement Learning from Human Feedback (RLHF) trains a model using human opinions about quality, instead of only fixed “correct” examples.

Traditional training

Labelled examples pair each input with one “correct” output to reproduce — an answer key each.

RLHF

The model produces candidates; humans say which is better, nudging it toward preferred outputs — preferences, not a gold answer.

Think of it like a code review

A senior engineer doesn't grade against one answer key — they compare a few solutions and say which they'd ship; that judgement is what RLHF learns.

Good code is readable, secure and idiomatic, not just correct — qualities easier to recognise than to encode as rules. Reviewers rate it on four criteria:

C · R · S · E
“Correct, Readable, Secure, Efficient”
The four qualities RLHF reviewers rate code on: Correctness, Readability, Security, Efficiency.

Glossary

Every term you need to speak this week's language.

Generative AI
Models that create new content — text, images, audio or video — rather than only analysing existing data.
Large Language Model (LLM)
A generative model trained on massive text that predicts the next token and so produces language; the backbone of most tools in this lecture.
AGI (Artificial General Intelligence)
A system with human-like, general-purpose intelligence across any intellectual task. The lecture asks whether LLMs qualify and does not declare that they do.
Structured prompt
A prompt assembled from named components (context, role, goal, constraints, steps, personalisation) so the model returns a controlled, useful answer.
Role (for an LLM)
The persona or expertise you assign, such as tutor, coach or tool; it changes how the model behaves.
Human-AI levels of interaction
A six-level ladder from information retrieval (level 1) to co-creativity (level 6), describing how much initiative each party takes.
Thought partnership
Level 4: the AI helps you reason, brainstorm or explore ideas but supports without leading.
Mixed-initiative collaboration
Level 5: both user and AI take initiative — the AI may propose next steps, flag missing constraints or suggest alternatives unprompted.
Co-creative collaboration
Level 6, the highest: human and AI jointly create and mutually influence each other's ideas; needs trust, transparency and shared context.
COFI
Prof Maher's framework for modelling interaction in human-AI co-creative systems (Rezwana & Maher, 2022).
Hallucination
When an LLM-based chatbot confidently produces a wrong answer — its characteristic failure mode.
Deepfake
Hyper-realistic synthetic video, image or audio of a target person, built with GANs, diffusion models and neural rendering.
Open source LLM
A model whose source code is publicly available to access, use, modify and distribute freely; encourages collaboration and transparency.
Closed source LLM
A model whose source code is proprietary, often a commercial product requiring a licence or subscription.
RLHF (Reinforcement Learning from Human Feedback)
Training a model using human opinions about quality — comparing candidate outputs — instead of only a fixed set of “correct” examples.
Instruction fine-tuning
Training on datasets where prompts describe a task and outputs contain correct solutions, improving responsiveness to natural-language instructions.
Autoregressive training
Training where the model predicts the next token from a partial sequence, computes loss against the ground truth, and updates parameters via gradient descent.
GAN (Generative Adversarial Network)
A model trained adversarially to generate realistic synthetic media; used to build deepfakes and to generate images.
Correctness
The first RLHF review criterion: does the generated code actually do the right thing?
Readability, security & efficiency
The remaining RLHF review criteria — qualities that are easier for a human to recognise than to write down as strict rules.

Practice Questions

Look away from the page first — retrieval is what builds memory.

Answer, reveal, then tick “Mastered”. Your progress is saved.
Q1

Name the five common uses of LLMs.

Answer: Content creation, chatbots and virtual assistants, language translation, educational tools, and search engines.
Q2

The topic is titled “Is it AGI?” — why does the lecture pose the question instead of answering it?

Answer: AGI means human-like, general-purpose intelligence across any task. One model drafting, chatting, translating, tutoring and searching shows broad capability, but doing many tasks is not the same as general human-like intelligence — so the lecture raises the question without declaring LLMs to be AGI.
Q3

List the six components of a structured prompt and what each one controls.

Answer: Context (your background and situation), Role (the persona or expertise to adopt), Goal (the target outcome), Constraints (limits on length, complexity, format, scope), Step-by-step instructions (the order of reasoning or output), and Personalisation (style, analogy, tone, format adapted to you).
Q4

In the recursion prompt, classify each of these: “under 350 words”; “explain as an experienced CS tutor”; “include an analogy”.

Answer: “Under 350 words” is a constraint; “explain as an experienced CS tutor” is a role; “include an analogy” is personalisation. (The step-by-step part is the ordered “first… then… finally…” instruction.)
Q5

In the tutor prompt, what should the AI do when you are stuck, and why does it refuse to do your assignment?

Answer: It should give you a hint, not the solution. It refuses to do the assignment because the goal is to help you do it — keeping you in the learning loop so you do the thinking that builds understanding.
Q6

List the six levels of human-AI interaction in order, with the human–AI relationship at each.

Answer: 1 Information retrieval (minimal interaction); 2 Task automation (user directs, AI executes); 3 Guided generation (iterative output refinement); 4 Thought partnership (shared sense-making); 5 Mixed-initiative (both take initiative); 6 Co-creativity (joint creation and mutual influence).
Q7

Distinguish level 4, level 5 and level 6 in one sentence each.

Answer: Level 4 (thought partnership): the AI supports your sense-making but does not lead. Level 5 (mixed-initiative): both parties take initiative — the AI introduces ideas autonomously, like a colleague making suggestions. Level 6 (co-creativity): human and AI jointly create and mutually influence the creative direction.
Q8

Which input modality is the core capability of all LLMs, what is the default output, and how does an image actually reach the model?

Answer: Text is the core input channel and text remains the default output. An image passes through a vision encoder and a projector into the LLM, which then answers in text — generating a new image needs a separate model or tool.
Q9

How do rule-based and LLM-based chatbots fail differently, and what two questions decide which to use?

Answer: Rule-based chatbots fail by going silent or giving a generic fallback; LLM-based chatbots can fail by confidently giving a wrong answer (“hallucinating”). The decision comes down to: how open-ended is the task, and how costly is a wrong answer?
Q10

How do LLMs differ from image generators, and how are deepfakes built and made convincing?

Answer: LLMs are trained on text, generate language token-by-token, represent meaning in linguistic embeddings, reason with text, and output text; image generators are trained on images, use diffusion or GANs, work in pixel/latent space, map prompts to visual features, and output images. Deepfakes are built by: collecting target data → preprocessing (face extraction, alignment) → training a GAN or similar model → generating synthetic media (face swaps, voice clones, reenactments) → post-processing. They convince because models learn facial micro-movements, voice tone/rhythm/accent, behavioural patterns, and lighting/texture cues, and adversarial training minimises giveaway artefacts.
Q11

Name the four stages used to train code-generating LLMs, and explain autoregressive training.

Answer: (1) Pretrain a Transformer on large text corpora; (2) fine-tune on large code datasets; (3) autoregressive training; (4) instruction fine-tuning and RLHF. Autoregressive training feeds the model a partial code sequence, has it predict the next token, computes loss against the ground-truth next token, and updates parameters via gradient descent — teaching valid syntax, logical continuation, indentation, and functional snippets.
Q12

Contrast traditional training with RLHF, name the four review criteria, and state the default training behaviour for enterprise vs personal accounts.

Answer: Traditional training studies labelled examples — each input paired with one “correct” output — and reproduces the pattern. RLHF has the model produce several candidates, humans compare them, and the model is nudged toward the preferred ones. Reviewers rate code on correctness, readability, security and efficiency. Enterprise/Business/Team inputs and outputs are excluded from training by default unless an admin opts in; personal (Free, Plus, Pro) conversations may be used unless the user opts out, and data is retained for abuse monitoring even if history is deleted.
