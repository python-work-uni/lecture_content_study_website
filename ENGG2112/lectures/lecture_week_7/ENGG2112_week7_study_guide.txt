ENGG2112 Week 7 – Study Guide
Human-AI Interaction with Generative AI
================================================

OVERVIEW
--------
This lecture examines how people interact with generative AI and large language models (LLMs): their common, personal, and professional uses, and whether this breadth amounts to AGI. It teaches structured prompts that assign a role, presents a six-level ladder of human-AI interaction, and explains input/output modalities, training with reinforcement learning (RLHF), chatbots, deepfakes, and enterprise vs personal access.

SECTION 1: Common Uses of Generative AI
------------------------------------------------

**Generative AI** creates new content (text, images, audio, video). An **LLM (Large Language Model)** is a generative model trained on massive text that predicts and produces language. Its **five common uses** are:

- **Content Creation** — articles, stories, poems; a draft a human refines.
- **Chatbots and Virtual Assistants** — natural agents for service and queries.
- **Language Translation** — accurate translation between languages.
- **Educational Tools** — personalised materials, quizzes, tutoring, coaching, language learning.
- **Search Engines** — summarising web results into focused answers.

### Is Generative AI AGI?

**AGI (Artificial General Intelligence)** means human-like, general-purpose intelligence across any task. The lecture poses "Is it AGI?" as an open question: one model drafts, chats, translates, tutors, and summarises, yet the lecture does not declare LLMs to be AGI.

💡 **Why It Matters:** One model doing many tasks explains both its usefulness and the AGI debate — doing many tasks is not automatically human-like general intelligence.

🧠 **Memory Hook:** The five uses are **"Content, Chat, Translate, Teach, Search"**.

------------------------------------------------
SECTION 2: Personal and Professional Uses
------------------------------------------------

The same LLM capability serves two contexts: personal life and professional work.

**Personal uses:** **Personalised Recommendations** (user preferences in context), **Accessibility** (text-to-speech, real-time transcription), **Email and Communication Assistance** (drafting, summarising), and **Fake News Detection and Fact-Checking** (flagging false information).

**Professional uses:**

- **Programming Assistance** — **GitHub Copilot** and **Claude Code** generate/debug code and run unit tests from natural-language descriptions.
- **Research and Sentiment Analysis** — gauging public opinion, satisfaction, and trends from social media and reviews.
- **Legal and Medical Document Analysis** — summarising and analysing documents to save time and improve accuracy.
- **Creative Writing and Scriptwriting** — generating prompts, plot ideas, or scripts.
- **Game Development** — generating dialogue, narratives, and quests.

✅ **Exam Tip:** When giving examples, name the category (personal or professional), then the use, then one concrete tool or output.

------------------------------------------------
SECTION 3: Structured Prompt Roles
------------------------------------------------

A **structured prompt** is assembled from named components so the LLM plays a defined role and returns a controlled, useful answer. The lecture lists **six components**:

| Component | Question | What it does |
|---|---|---|
| **Context** | Who am I? | Background (course, level, problem) |
| **Role** | Who should you be? | Assigns a persona or expertise |
| **Goal** | What do I want? | The target outcome |
| **Constraints** | What are the limits? | Caps length, complexity, format, scope |
| **Step-by-step instructions** | In what order? | Sequences the reasoning or output |
| **Personalisation** | How do I learn best? | Adapts style, analogy, tone, format |

The **roles for LLMs** are **Mentor, Tutor, Coach, Teammate, Student, Simulator, and Tool**. The role changes behaviour: a "tutor" asks guiding questions; a "tool" just produces an artifact.

💡 **Why It Matters:** The role you set decides whether the AI helps you learn or replaces your thinking.

⚠️ **Common Trap:** A prompt with no context or constraints produces a generic, over-long, or wrong-level answer.

🧠 **Memory Hook:** **"C-R-G-C-S-P"** — **C**ontext, **R**ole, **G**oal, **C**onstraints, **S**teps, **P**ersonalisation.

------------------------------------------------
SECTION 4: Worked Prompt for Recursion
------------------------------------------------

The lecture builds one prompt for **learning about recursion**, labelling each part. The **Goal** ("understand recursion") is implied by the context; the rest are explicit.

**1. Context** — "I am a second-year computer science student taking a course on data structures and algorithms. I'm learning about recursion, and I find it difficult to understand how a recursive function progresses and returns values."

**2. Constraints** — "Keep the explanation under 350 words, use simple Python examples, and avoid introducing advanced concepts."

**3. Role Modelling** — "Explain this as an experienced CS tutor who specialises in helping students build intuition for algorithmic thinking."

**4. Step-by-Step Process** — "First, define recursion in clear terms. Then walk through a simple recursive function (like computing factorial), showing each call and return step-by-step. Finally, explain why this step-wise breakdown helps with debugging and tracing."

**5. Personalisation** — "I often understand concepts better when they are connected to visual or real-world analogies, so include an analogy that helps me picture the recursive process."

💡 **Why It Matters:** Each part closes one failure mode — too long, too advanced, wrong persona, unstructured, or mismatched to the learner.

✅ **Exam Tip:** "Under 350 words" is a **constraint**; "explain as an experienced CS tutor" is a **role**; "include an analogy" is **personalisation**.

SECTION 5: Example Prompt for a Tutor Role
------------------------------------------------

The lecture's reusable template for a **Tutor** role; square brackets are filled by the user.

"You are acting as my tutor for **[course name/number]**, specifically for the topic of **[specific topic, e.g., "second-order linear differential equations"]**. My course uses **[textbook/lecture notes/specific approach, if relevant]**."

"Please tutor me using these rules:"

- Ask me what topic we are covering in this session.
- Start by asking me what I already understand about this topic.
- Briefly explain the topic first (max 200 words), and ask if I want more depth.
- Ask guiding questions about the major concepts and let me attempt each step.
- Check my understanding before moving to the next concept.
- If I'm stuck, give me a hint, not the solution.
- Match your explanations to the level of a 2nd year engineering student.
- Point out if my reasoning is correct even if my final answer is wrong.
- Do not do an assignment for me. Instead help me do it.

💡 **Why It Matters:** The rules keep the human in the learning loop — the tutor asks first, hints instead of answering, and refuses to do the assignment.

⚠️ **Common Trap:** Setting a tutor role but then adding "just give me the answer" defeats the purpose.

SECTION 6: Human-AI Levels of Interaction
------------------------------------------------

Not every LLM interaction is the same. The lecture arranges them into **six levels**, from minimal lookup to full co-creation.

| Level | Role of AI | Human–AI Relationship |
|---|---|---|
| 1. Information retrieval | Database / lookup tool | Minimal interaction |
| 2. Task automation | Utility / assistant | User directs, AI executes |
| 3. Guided generation | Content generator | Iterative output refinement |
| 4. Thought partnership | Cognitive collaborator | Shared sense-making |
| 5. Mixed-initiative | Co-worker | Both take initiative |
| 6. Co-creativity | Creative partner | Joint creation and mutual influence |

As you move up, the AI takes more initiative and the two parties influence each other more. Interaction is **not always text based** — it can involve images, audio, and other modalities.

💡 **Why It Matters:** Match the level to your goal. A definition needs only level 1; co-designing a project needs level 4–6.

🧠 **Memory Hook:** **"I Take Great Thought Making Co-creations"** — Information, Task, Guided, Thought, Mixed, Co-creativity.

------------------------------------------------
SECTION 7: The Six Levels in Detail
------------------------------------------------

**Level 1 — Information Retrieval.** The **lowest level**; query the LLM like a conversational search engine (factual questions, definitions, summaries). One-off prompts, minimal context, AI as a lookup tool.

**Level 2 — Task Automation.** The AI performs **bounded, well-defined tasks** (drafting emails, rewriting text, code snippets, translating). The user sets constraints, the AI delivers with little negotiation, and **efficiency is the goal**.

**Level 3 — Guided Generation.** The user gives **structured instructions**; the AI produces substantial work (essays from outlines, images from prompts, multiple variations). Back-and-forth refinement; the AI acts as a generator not just a tool.

**Level 4 — Thought Partnership.** The AI **helps users reason, brainstorm, or explore ideas**. Sustained conversation, shared sense-making, and the **AI supports but does not lead**.

**Level 5 — Mixed-Initiative Collaboration.** The **user and AI both take initiative** (AI proposing next steps, identifying missing constraints, suggesting alternatives unprompted). The AI introduces ideas autonomously and interaction is two-directional, like a colleague.

**Level 6 — Co-Creative Collaboration.** The **highest level**; human and AI jointly create, influence each other, and build on each other's ideas (co-designing artworks, stories, or interfaces; frameworks like **COFI**). Fluid collaboration; AI contributes original directions; requires **trust, transparency, and shared context**.

💡 **Why It Matters:** The distinctions are the exam core — level 4 "supports but does not lead"; level 5 "both take initiative"; level 6 "joint creation and mutual influence".

⚠️ **Common Trap:** Do not merge levels 5 and 6. Level 5 is turn-taking initiative on a defined task; level 6 is joint creation where the creative direction is shared.

SECTION 8: Example Prompt for Thought Partner
------------------------------------------------

The lecture's full prompt sets the AI as a **thought partner (level 4)**, explicitly *not the author*, for a team of 4–5 engineering students deciding (1) the problem, (2) the ML techniques, (3) available data, and (4) one-semester feasibility.

"You are acting as a thought partner for my team's **"AI for Good"** project proposal, **not as the author of it**."

"Please follow these rules while working with us:"

- **Don't write our proposal, problem statement, or sections of text for us.** If we ask you to write something outright, redirect us back to thinking it through ourselves — offer a structure or questions instead of finished text.
- **Respond to our ideas rather than replacing them.** Point out strengths, risks, gaps, or things we haven't considered — don't generate a new idea from scratch unless we ask for options.
- **Push on feasibility.** If something is too ambitious for one semester, say so directly and explain why, rather than being agreeable.
- **Ask us clarifying questions** when our idea is vague, instead of assuming what we mean.
- **Flag when we're missing something important**, e.g., data availability, ethical concerns, or how we'd evaluate success.
- If we ask "what do you think," give an opinion with reasoning, framed as one input to weigh, not a decision.
- Start by asking us to describe the problem, and help us think about scope and direction before moving to ML techniques or data.

The lecture credits the co-creativity idea to **Rezwana, Jeba & Maher, Mary (2022)**, "Designing Creative AI Partners with COFI."

💡 **Why It Matters:** The rules hold the AI at level 4 — it supports sense-making but does not lead.

⚠️ **Common Trap:** Without the "do not write for us" rule, an LLM will write your whole proposal. The role holds only if the prompt forbids taking over.

SECTION 9: Input and Output Modalities
------------------------------------------------

AI interaction is **not always text based**. The key pattern: **many input modalities, but text remains the standard output**, with other modalities handled by separate tools or "live" runtimes.

| Input modality | Typical LLM path (pretrained) | Common outputs | Notes |
|---|---|---|---|
| Text | Native (tokenized text → LLM) | Text (NLG, JSON, code) | Core capability; other modalities align into text space |
| Image | Vision encoder → projector → LLM | Text (captioning, OCR, VQA); image via paired generator | GPT-5.x, Gemini 3, Claude accept images; image generation uses a separate tool (DALL·E) |
| Video | Frame sampling (+ audio) → encoders → LLM | Text (summaries, timestamps); audio (live) | Gemini 3 native video/audio; GPT-5.x and Claude via frame-sampling |
| Audio | Cascaded ASR → LLM, or end-to-end multimodal | Text (transcripts, QA); Audio (TTS) | Audio-native models common (GPT-5.x voice, Gemini Live) |

**Text** is where LLMs are strongest and most mature; surveys still treat text as the "central" channel. Inputs include plain/structured prompts, long documents, and code; outputs include natural language, structured text (JSON, tables), code, and citations — and even for multimodal tasks such as captioning an image, **text output stays the default**. Image inputs support captioning and OCR; video inputs are sampled into frames plus audio; audio inputs are speech for transcription, often via a pipeline **ASR → LLM → TTS**.

💡 **Why It Matters:** An LLM "sees" an image by encoding it into text-like space and still answers in words — generating a picture needs a different model.

🧠 **Memory Hook:** Inputs are **"T-I-V-A"** (Text, Image, Video, Audio); outputs default to **text**.

SECTION 10: Rule-Based vs LLM Chatbots
------------------------------------------------

A **rule-based chatbot** follows fixed pre-written rules or decision trees ("if user says X, respond with Y"). An **LLM-based chatbot** generates replies from a language model trained on huge amounts of text.

| Aspect | Rule-Based | LLM-Based |
|---|---|---|
| Response method | Fixed rules / decision trees | Generated by the model |
| Input handled | Only anticipated patterns | Open-ended, varied phrasing, typos, context |
| Predictability | Same input → same output | Same question can get different answers |
| Failure mode | Goes silent or generic fallback | Confidently wrong ("hallucinating") |
| Auditability | Easy — every path traceable | Hard — no fixed tree to inspect |
| Cost / build | Cheap, fast for narrow tasks | More expensive, needs oversight and guardrails |
| Example | "Check my order status" | Troubleshooting a novel problem |

**Key differences:** rule-based = narrow but reliable (fails by going silent); LLM-based = flexible but less predictable (can confidently give a wrong answer, "hallucinating"). **The choice comes down to: how open-ended is the task, and how costly is a wrong answer?**

💡 **Why It Matters:** A silent bot is annoying; a hallucinating bot can be dangerous in medicine or law, where a confident wrong answer has real cost.

✅ **Exam Tip:** "Narrow task and very costly error" → rule-based. "Open-ended task and tolerable errors" → LLM-based.

SECTION 11: LLMs vs Image Generators and Deepfakes
------------------------------------------------

Both are "generative", but they learn and represent the world differently.

| Aspect | LLMs | Image Generation Models |
|---|---|---|
| Trained on | Text | Images (often with captions) |
| Generation | Token-by-token language | Diffusion or GAN processes |
| Representation | Linguistic embeddings | Pixel or latent space |
| Prompt use | Reason with text and structure | Map text prompts to visual features (not linguistic reasoning) |
| Output | Text | Images |

### Generating Deepfakes

**Deepfakes** are hyper-realistic synthetic videos, images, and audio of a target person:

```
Collect Data → Preprocess → Train GAN → Generate → Post-process
```

1. Collect images, video, and audio of the target.
2. Preprocess (face extraction, alignment).
3. Train a GAN or similar model to learn the target's visual/voice patterns.
4. Generate synthetic media (face swaps, voice clones, reenactments).
5. Post-process to improve realism.

They rely on **GANs, diffusion models, and neural rendering**. They look realistic because the models learn **facial micro-movements**, **voice tone, rhythm and accent**, **behavioral patterns**, and **lighting and texture cues**. **Adversarial training** teaches generators to minimise the artifacts that give fakes away.

💡 **Why It Matters:** The same generative machinery that creates art can create convincing fakes; understanding how deepfakes are built is the first step to defending against them.

SECTION 12: Training LLMs for Code
------------------------------------------------

How does an LLM learn to generate and debug code? The lecture gives a four-stage process (stage 4 is covered next).

```
Pretrain → Fine-tune on Code → Autoregressive Training → RLHF
```

**Step 1 — Pretrained Transformer Model.** Begin with a Transformer pretrained on large text corpora. It learns to predict the next token, building representations of patterns, syntax, and structure — the foundation for code specialisation.

**Step 2 — Fine-Tune on Large Code Datasets.** Expose the model to Python corpora: GitHub repositories, documentation, tutorials, unit tests, and competitive programming datasets. It learns Python syntax, idioms, data structures and libraries, error-checking, and multi-file/import structure.

**Step 3 — Autoregressive Training.** The model receives a partial code sequence, predicts the next token, computes loss against the ground truth, and updates parameters via gradient descent. This teaches valid Python, logical continuation, indentation, and functional snippets, and Transformers excel at **long-range dependencies** such as matching definitions to later calls.

**Step 4 — RLHF and Instruction Fine-Tuning.** Modern systems are refined by **instruction fine-tuning** (task prompts paired with correct solutions) and **RLHF**, detailed next.

💡 **Why It Matters:** Code generation reuses next-token prediction from general text models, then specialises on code and human preferences.

✅ **Exam Tip:** List the four stages in order: pretrain, fine-tune on code, autoregressive training, RLHF (with instruction fine-tuning).

SECTION 13: RLHF and Human Feedback
------------------------------------------------

**Reinforcement Learning from Human Feedback (RLHF)** trains a model using human **opinions** about quality, instead of only a fixed set of "correct" examples.

| Traditional Training | RLHF |
|---|---|
| Studies labeled examples — each input paired with one "correct" output — and reproduces the pattern | Produces several candidate outputs; humans say which is better; the model is nudged toward preferred outputs |
| Needs an answer key per input | Needs only human preferences between candidates |
| Good when there is one right answer | Good for qualities easier to recognise than to write as rules |

**The code-review analogy:** a senior engineer doesn't grade code against one answer key; they look at a few working solutions and say which they'd rather ship — RLHF learns from that comparative judgement.

**Why it matters:** good code isn't just correct; it is **readable, secure, and idiomatic**, qualities easier to recognise than to encode as rules. Reviewers rate code on **correctness, readability, security, and efficiency**, prioritising correct, high-quality output.

💡 **Why It Matters:** Traditional training copies "the one right answer"; RLHF learns "which is better", capturing subjective qualities like readability and security.

🧠 **Memory Hook:** Reviewers judge code on **"C-R-S-E"** — **C**orrectness, **R**eadability, **S**ecurity, **E**fficiency.

⚠️ **Common Trap:** RLHF is not supervised learning on labelled pairs — it uses *comparisons* between candidate outputs, not a single gold answer.

SECTION 14: Access Models for Generative AI
------------------------------------------------

Who can use an LLM, and who owns the data you enter? Two comparisons answer this.

**Open vs closed source models:**

- **Open Source LLMs** — source code is publicly available; anyone can access, use, modify, and distribute them. They encourage collaboration, transparency, and community involvement.
- **Closed Source LLMs** — source code is proprietary; often commercial products requiring licences or subscriptions.

**Enterprise vs personal subscriptions:** the tier determines who owns the data, how it is stored and shared, whether it trains the model, and what security guarantees exist.

| Aspect | Enterprise / Business / Team | Personal (Free, Plus, Pro) |
|---|---|---|
| Used for training? | Not used by default | May be used unless the user opts out |
| Inputs and outputs | Fully excluded unless an admin opts in | — |
| Plans covered | Business, Enterprise, Healthcare, Edu, Teachers, Team | Free, Plus, Pro |
| Data retention | — | Retained for abuse monitoring even if history is deleted |

💡 **Why It Matters:** On a personal account your conversations may train the model unless you opt out, and data is retained for abuse monitoring even after deletion. Enterprise accounts exclude inputs and outputs from training by default. For sensitive data, the tier is a data-governance decision.

✅ **Exam Tip:** The default is the answer — enterprise excluded by default (admin opt-in); personal included by default (user opt-out).

KEY TAKEAWAYS
================================================

1. **Five common uses of LLMs** — content creation, chatbots/virtual assistants, translation, educational tools, and search engines.
2. **Is it AGI?** — the lecture poses the question rather than answering it; breadth of tasks is not automatically general intelligence.
3. **Six prompt components** — Context, Role, Goal, Constraints, Step-by-step instructions, and Personalisation; roles include Mentor, Tutor, Coach, Teammate, Student, Simulator, and Tool.
4. **The recursion prompt** — context, constraints (<350 words, simple Python), role (CS tutor), steps (define → trace factorial → explain), and personalisation (an analogy).

6. **Six levels of interaction** — information retrieval, task automation, guided generation, thought partnership, mixed-initiative, co-creativity; level 4 supports but does not lead, level 5 both take initiative, level 6 is joint creation with mutual influence.
7. **Inputs multimodal, outputs text** — text, image, video, and audio inputs align into text space, but text stays the default output; rule-based chatbots are narrow but reliable, LLM chatbots flexible but able to hallucinate.
8. **Training and access** — code models are pretrained, fine-tuned on code, trained autoregressively, then tuned with instruction fine-tuning and RLHF (rated on correctness, readability, security, efficiency); enterprise excludes data from training by default, personal does not.

TERMS TO KNOW
================================================

Generative AI: Models that create new content such as text, images, audio, or video rather than only analysing data.
Large Language Model (LLM): A generative model trained on massive text that predicts and produces language.
AGI (Artificial General Intelligence): A system with human-like, general-purpose intelligence across any intellectual task.
Information retrieval: The lowest interaction level, where a user queries an LLM like a conversational search engine.
Task automation: The level where the AI performs bounded, well-defined tasks with efficiency as the goal.
Guided generation: The level where structured instructions yield substantial work with back-and-forth refinement.
Thought partnership: The level where the AI helps users reason or explore ideas but does not lead.
Mixed-initiative collaboration: The level where both the user and the AI take initiative.
Co-creative collaboration: The highest level, where human and AI jointly create and mutually influence each other's ideas.
COFI: Prof Maher's framework for modelling interaction in human-AI co-creative systems.
RLHF (Reinforcement Learning from Human Feedback): Training a model using human opinions about quality instead of only fixed correct examples.
Deepfake: Hyper-realistic synthetic video, image, or audio of a target person.
GAN (Generative Adversarial Network): A model trained adversarially to generate realistic synthetic media.
Open Source LLM: A model whose source code is publicly available to use, modify, and distribute freely.
Closed Source LLM: A model whose source code is proprietary and often sold through licences or subscriptions.
