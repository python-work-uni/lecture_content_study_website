Generative AI: How Deep Learning Models Actually Work

This week opens the black box behind ChatGPT, Copilot and every other modern AI tool — from a single artificial neuron all the way up to a language model that writes text one token at a time.

Read this first: A deep learning network is a big machine that learns by trial and error. It makes a prediction, measures how wrong it was, then nudges millions of internal dials called weights so it does better next time. Stack that idea into layers, wrap it in a Transformer, and train it on a huge pile of text — that is a large language model.

The Big Picture

One idea runs through the whole lecture: learning is just repeatedly adjusting numbers until the errors shrink.

Your lecturer, Professor Mary Lou Maher, builds the week in three layers. First, the tiny machinery: nodes, layers and weights. Second, how those parts learn through training and backpropagation. Third, how that machinery is scaled up into large language models — pretraining, tokenization, Transformers and generation — and finally into the family of foundation models such as GPT and BERT.

If you hold onto one mental model, hold onto this: an AI model is not a database of facts. It is a vast set of numbers that have been tuned so that, given some input, it produces a useful output. Everything else this week is a detail of that sentence.

Deep Learning Networks: The Core Idea

A deep learning network is many connected processing units that learn patterns from data by adjusting numerical weights.

A deep learning network is a type of neural network made up of many connected processing units. It does not follow hand-written rules. Instead, it learns patterns from data by adjusting numerical values called weights.

The learning recipe has three moves that repeat over and over: pass data through layers of nodes, measure the error, then use backpropagation to adjust the weights so predictions improve over time.

The six key terms for this topic

Nodes (neurons)

The basic computational units that transform inputs into outputs.

Layers

How nodes are organised: input, hidden and output layers.

Weights

The dials on the connections between nodes that get tuned.

Training

The process of teaching the network to make accurate predictions.

Backpropagation

The algorithm that updates the weights using the error.

Learning over time

The repeated cycle that steadily reduces error.

🧠
Remember: A deep network is a machine that learns by trial and error — predict, measure the mistake, nudge the weights, repeat.

Inside a Node

A node is a tiny calculator that weighs its inputs, adds them up, and decides how strongly to fire.

Nodes, also called neurons, are the basic computational units of the network. Each node does the same small job again and again, which is exactly why networks can scale to millions of units.

Every node does five things

  1. Receives numerical inputs. Raw numbers arrive from the previous layer (or from the data itself).
  2. Multiplies them by weights. Each input is scaled by its own weight — bigger weight, bigger influence.
  3. Sums the results. All the weighted inputs are added into a single number.
  4. Applies an activation function. A rule that decides how strongly the node fires, adding the non-linear twist that lets networks model complex patterns.
  5. Produces an output. That number flows forward to the next layer.
What one node computes
output = f( w₁·x₁ + w₂·x₂ + … + b )

Here x₁, x₂ … are the inputs, w₁, w₂ … are their weights, b is a bias term, and f is the activation function.

Worked example: walking a value through one node

Suppose a node receives two inputs, 2 and 3, and its connection weights are 0.5 and 0.4.

  1. Multiply. 2 × 0.5 = 1.0 and 3 × 0.4 = 1.2.
  2. Sum. 1.0 + 1.2 = 2.2.
  3. Activate. Apply the activation function to 2.2 to get the node's output.
  4. Learn. If the final answer was wrong, backpropagation adjusts 0.5 and 0.4 slightly so the next prediction is better.

That tiny calculation, repeated across millions of nodes and billions of weights, is all a deep network is really doing.

Nodes represent learned features of the data: early nodes tend to pick up simple patterns, while later nodes combine them into more complex concepts.

“Receive, Multiply, Sum, Activate, Produce”

Layers and Depth

“Deep” literally means many hidden layers stacked between the input and the output.

Deep learning networks are organised into layers. Each layer passes information forward to the next, so the network is really a pipeline of transformations.

LayerWhat it does
Input layerReceives the raw input data — for example pixel values or token IDs.
Hidden layersPerform intermediate processing and feature extraction. Having many hidden layers is what makes the network “deep”.
Output layerProduces the final prediction or output.
Input layer→ Hidden layers→ Output layer
⚠️
Common trap: “Deep” does not mean complicated maths. It means many hidden layers stacked up. Depth is about how many layers sit between input and output.
🧠
Remember — IHO: read the layers left to right like an assembly line: Input feeds Hidden, which feeds Output.

Weights and Parameters

Weights are the dials on every connection; learning is simply finding better values for them.

Weights are numerical values on the connections between nodes. They control how strongly one node influences another — think of each weight as the volume dial on a wire between two units. Learning in a neural network is essentially finding better values for these weights; the architecture stays fixed while training tunes only those numbers.

Large models (like LLMs) can have millions or billions of weights.

“Parameters” is just another word for weights

When OpenAI says it trained a model with 400B parameters and Google says it trained one with 600B parameters, both are counting the number of weights in the network. A model with more parameters can potentially have more capacity — a larger potential ability to fit a more complex set of patterns in its training data.

  • More parameters means the model can be more complex and perform more tasks.
  • The parameters are the model's features — for example the ability to generate different types of text, translate languages, and summarise text.
⚠️
Common trap: Parameters are not documents or examples stored inside the model. They are learned numbers (weights) on the connections. The training text is not saved as-is — its patterns are absorbed into the weights.
Capacity — the rough ceiling on how complex a set of patterns a model can represent. More parameters usually means more capacity, but capacity is a potential, not a guarantee that the model will be accurate.

Training, Loss and Backpropagation

Training is trial and error with a scoreboard: show an example, let the network guess, then tell it how wrong it was.

What training involves

Training is the process of teaching the network to make accurate predictions. It involves:

  • Providing input data.
  • Producing an output (a prediction).
  • Comparing the prediction to the correct answer.

The goal is to minimise error, which is measured using a loss function — a score for how far the prediction is from the truth. The smaller the loss, the better the model. Training happens over many examples and many repetitions.

The core learning cycle

  1. Forward pass. Feed the input through the network to make a prediction.
  2. Loss calculation. Measure how wrong the prediction is.
  3. Backpropagation. Adjust the weights to reduce that error next time.

How backpropagation works

Backpropagation is the algorithm used to update the weights. Once the network has made a prediction and the loss is known, it needs to know which weights are to blame, and by how much. It works by:

  • Calculating how much error each weight contributed to the final output.
  • Sending this error information backwards through the network (from the output layer back toward the input).
  • Using this information, adjusting each weight slightly to reduce future error.

In simple terms: backpropagation tells each weight how to change to make the network better.

ℹ️
Key idea: The forward pass and the backward pass are two directions of the same network. Data flows forward to make a prediction; blame flows backward to fix the weights.
⚠️
Common trap: Backpropagation does not change the architecture or add neurons. It only nudges the existing weights a little at a time.

Learning over time

Learning is not a single step. Training consists of repeated cycles of the three stages above. Over time:

  • Errors decrease.
  • The network learns useful representations of the data.
  • Predictions become more accurate.
F · L · B
“Forward, Loss, Back”
The repeated training cycle: forward pass, loss calculation, backpropagation — then do it again.
✅
Exam tip: If asked what training optimises, the answer is the loss function. The network adjusts weights to make the loss as small as possible.

The Two Phases of a Large Language Model

Every LLM lives two lives: it trains once, then generates forever.

Large Language Models work through a two phase process: training and generating. The Transformer model used here is the same family of model that powers ChatGPT.

Phase 1 — Training

  • Data collection.
  • Tokenization.
  • Format tokenized data into input–output pairs.
  • Train a Transformer model to predict output from input.
  • Fine-tune using specific tasks.

Phase 2 — Generating

  • Tokenize the input text.
  • Predict the next tokens.
  • Sample a token from this distribution.
  • Append the token and repeat.
  • Continue until a stopping criterion is met.
Training (learn the weights)→ Generating (use frozen weights to produce text)
ℹ️
Key idea: Training is where the weights change. Generating is where the weights are held fixed and the model simply uses what it learned. A prompt never changes the model — it only steers the output.

Pretraining: The Eight Steps

Pretraining is where the model soaks up general language from massive amounts of text before it is adapted to any specific task.

Pretraining is the phase where a model learns general language patterns from massive amounts of text, before being adapted to specific tasks. It runs through eight steps.

  1. Data collection. Gather very large, diverse text corpora.
  2. Data cleaning and filtering. Remove junk so training is stable and quality is high.
  3. Tokenization. Convert text into tokens and numerical IDs.
  4. Creating training objectives. Decide what the model is asked to predict.
  5. Transformer model initialisation. Define the architecture and set weights randomly.
  6. Training with backpropagation. Run the forward/loss/backward loop at scale.
  7. Learning language representations. The model forms internal understanding of language.
  8. Pretrained model output. A general-purpose pretrained model is produced.

Step 1 — Data collection

Goal: expose the model to a wide range of language use, styles and domains by gathering very large, diverse text corpora. Examples include:

Sources

  • Web pages
  • Books
  • Wikipedia
  • Articles and documents

Why breadth matters

A model that only ever sees one style of writing will only ever be good at that style. Diversity in the corpus is what lets the pretrained model generalise later.

Step 2 — Data cleaning and filtering

Goal: improve training stability and model quality. The pipeline removes:

  • Duplicates.
  • Very low-quality text.
  • Corrupted or non-linguistic data.

Optional filtering may also be applied for language, length and formatting consistency.

⚠️
Common trap: Garbage in, garbage out. Cleaning is not optional tidying — the lecture links it directly to training stability and model quality.

“Collect, Clean, Tokenize, Objectives, Initialise, Train, Learn, Produce”
The eight pretraining steps in order.

Tokenization: Turning Text into Numbers

Computers cannot multiply words, so tokenization chops text into pieces and gives each piece a number.

Goal: convert text into a format that can be processed mathematically by the model. Tokenization works like this:

  • Convert raw text into tokens.
  • Tokens may be words, subwords, or character sequences.
  • Build a vocabulary of tokens.
  • Each token is mapped to a numerical ID.

This works particularly well because it connects text → symbols → numbers. Think of it like chopping a sentence into LEGO bricks: the same idea can be rebuilt from differently sized bricks, but each brick still has a catalogue number.

Example of tokenization

The user provides input text (a prompt), and it is converted into tokens (numbers) using the same tokenizer used during training. Those tokens become the input sequence to the Transformer.

A prompt becomes a list of token IDs
“Large language models work by…” → [1987, 10234, 845, 563, …]
ℹ️
Key idea: The same data can be split into different token sets (“alternative tokens for the same data”). As long as training and generation use the same tokenizer, the model stays consistent.

Training Objectives: What the Model Is Asked to Predict

No humans label the data — the text supervises itself.

The model is trained using unsupervised learning. That means no human labels are required: the text itself provides the supervision. The lecture names two training objectives.

ObjectiveUsed byTask
Next-token predictionGPT-style modelsGiven previous tokens, predict the next one.
Masked-language modellingBERT-style modelsPredict missing tokens in a sentence.
💡
Why it matters: Because the answer is already sitting in the text, you can train on essentially unlimited data without paying humans to label it. That is the trick that made LLMs possible.

The Transformer and Self-Attention

The Transformer is the architecture that lets a model weigh every word against every other word at once.

Before training, the model's architecture is defined. The Transformer is built from four kinds of component:

Embedding layers

Map each token to a vector that represents its meaning.

Positional encoding

Adds order and distance information so the model knows where each token sits.

Multi-head self-attention

Lets every token weigh its relationship to other tokens, from several perspectives at once.

Feed-forward layers

Transform each position's representation to build richer meaning.

At initialisation, the parameters (weights) are set randomly. The number of parameters can range from millions to hundreds of billions. Structurally, a Transformer is still a deep network:

  • Layers: input → multiple hidden layers → output.
  • Neurons (nodes) as computation units.
  • Weighted connections between layers.

Self-attention: how tokens relate

The self-attention mechanism is the core of how Transformers work. For each token, the model:

  • Compares it with all other tokens in the input.
  • Computes attention scores indicating which tokens are most relevant.
  • Weights information from important tokens more heavily.

This allows the model to track long-range dependencies, resolve ambiguity (for example, what “it” refers to), and use context dynamically. Picture a spotlight: for every word, the model shines light on the few other words that matter most right now.

Training the Transformer with backpropagation

Backpropagation is the process of adjusting a neural network's weights by propagating error backward through the network. For each batch of tokenized text:

  1. Tokens are passed through the Transformer.
  2. The model predicts token probabilities.
  3. A loss function measures prediction error.
  4. Gradients are computed using backpropagation.
  5. Parameters are updated using an optimizer.

This is repeated over many epochs and massive datasets.

What the model learns along the way

Through training, the model implicitly learns:

Grammar and syntax

How words are allowed to fit together.

Semantics and meaning

What words and sentences actually refer to.

Long-range context

Dependencies between words far apart in the text.

Patterns across domains

Science, fiction, instructions and more.

Fine-Tuning After Pretraining

Pretraining teaches general language; fine-tuning points that skill at one specific job.

After pretraining, the model can be fine-tuned — adapted to specific tasks. The lecture gives two primary approaches.

Feature extraction (repurposing)

  • The pretrained LLM is treated as a fixed feature extractor.
  • The model has already learned significant language features that can be repurposed for the task.
  • The final layers are trained on task-specific data while the rest of the model stays frozen.
  • Cost-effective and efficient.

Full fine-tuning

  • Trains the entire model on the task-specific data.
  • All model layers are adjusted during training.
  • Best when the task dataset is large and significantly different from the pretraining data.
  • Can give a more profound adaptation, but requires more resources.

What is trainedFinal layers onlyEntire model
Rest of modelFrozenAll layers updated

CostLowerHigher

Generating Text with a Pretrained LLM

When you prompt an LLM, it turns your words into tokens and predicts what comes next, one token at a time.

Here is the full generation pipeline for a pretrained model.

  1. Tokenize the prompt. Convert text into tokens (numbers).
  2. Embed the tokens. Add meaning and position information.
  3. Apply attention. Focus on relevant tokens in context.
  4. Process with Transformer layers. Refine meaning across layers.
  5. Predict the next token. Output probabilities for possible tokens.
  6. Repeat autoregressively. Append the token and generate text step by step.

Input is tokenized

The user provides input text (a prompt). It is converted into tokens (numbers) using the same tokenizer used during training, and these tokens become the input sequence to the Transformer. For example, “Large language models work by…” becomes [1987, 10234, 845, 563, …].

Tokens are embedded and positioned

Inside the Transformer:

  1. Each token is mapped to a vector embedding that represents its meaning.
  2. Positional encoding is added so the model knows the word order and the distance between tokens.

This step gives the model both what the tokens are and where they occur.

Attention, then Transformer layers

The self-attention mechanism compares each token with all others and weights the most relevant ones more heavily. The input then passes through multiple Transformer layers, each consisting of multi-head self-attention and feed-forward neural networks. Across these layers the model builds rich semantic representations and higher-level abstractions. Crucially, no learning occurs here — the weights are fixed (pretrained).

Predicting the next token

At the output of the Transformer, the model computes a probability distribution over the vocabulary. Each possible next token has an associated probability. For example:

Example distribution over the vocabulary
“model” → 0.42 “system” → 0.21 “process” → 0.11

Sampling a token

The model selects the next token using a sampling strategy, such as:

  • Greedy decoding — always take the highest-probability token.
  • Temperature scaling — flatten or sharpen the distribution.
  • Top-k or top-p sampling — choose from the most likely candidates.

This balances coherence (safe, predictable tokens) against creativity (more varied outputs). Greedy decoding would always pick “model” and favour coherence; temperature or top-k/top-p sampling might pick “system” or “process” and add creativity.

The autoregressive generation loop

The selected token is:

  • Appended to the input sequence.
  • Fed back into the Transformer.
  • Used to predict the next token.

This loop repeats until a stop token is reached or a maximum length is exceeded. This is why LLMs are called autoregressive models.

Tokenize→ Embed→ Attend→ Transform layers→ Predict→ Sample→ Append & repeat

“Tokenize, Embed, Attend, Predict, Repeat”
The autoregressive generation pipeline for a pretrained LLM.

GPT vs BERT: Generate or Understand

Same Transformer DNA, opposite goals — one writes forward, the other reads both ways.

GPT — Generative Pre-trained Transformer

  • Autoregressive.
  • Each token can only see earlier tokens.
  • Trained using Next-Token Prediction.
  • Predicts the next token given all previous tokens.
  • Goal: generate language.

BERT — Bidirectional Encoder Representations from Transformers

  • Fully bidirectional.
  • Every token attends to all other tokens.
  • Trained using Masked Language Modelling.
  • Random tokens are hidden, and the model predicts the missing words.
  • Goal: understand language.
ℹ️
Key idea: GPT's one-directional view is what lets it generate fluently, because it is always predicting forward. BERT's two-directional view is what lets it understand context deeply, because it can see the whole sentence at once — but it cannot generate text the way GPT does.
⚠️
Common trap: GPT is not “better” than BERT — they are built for different jobs. Next-token prediction drives generation; masked language modelling drives understanding.

Foundation Models, Implementations and Copilot

A foundation model is a large general model that can be adapted to many tasks — and Copilot is not a model at all, but an orchestrator.

A foundation model is a large general model that can be adapted to many tasks. The lecture names several types of foundation models: GPT, BERT, GAN, VAE and RNN.

concept GAN

Generative Adversarial Network — a generative model listed among the foundation-model types.

concept VAE

Variational Autoencoder — an autoencoder-based generative model; the lecture includes an Autoencoder Neural Network slide.

concept RNN

Recurrent Neural Network — a sequence-processing network type also listed among the foundation models.

ℹ️
Key idea: GPT and BERT are Transformer-based. GAN, VAE and RNN are other foundation-model types the lecture names. Different goals matter — GPT generates language while BERT understands it.

Transformer model implementations

  • Google's BERT was one of the first LLMs based on transformers.
  • OpenAI's GPT followed, with iterations including GPT-2, GPT-3, GPT-3.5, GPT-4 and ChatGPT.
  • Meta's Llama achieves comparable performance with models 10 times its size.
  • Google's Pathways Language Model generalises and performs tasks across multiple domains, including text, images and robotic controls.
  • OpenAI's DALL-E creates images from a short text description.
  • The University of Florida and Nvidia's GatorTron analyses unstructured data from medical records.
  • DeepMind's AlphaFold 2 describes how proteins fold.
  • AstraZeneca and Nvidia's MegaMolBART generates new drug candidates based on chemical structure data.

Where is Copilot?

Unlike GPT or BERT, Copilot isn't just one neural network. It is a coordination layer that retrieves data, chooses models, applies reasoning and produces a grounded response.

User Request→ Retrieval→ Model Selection→ Reasoning→ Grounded Response
  • User Request starts outside the model.
  • Retrieval pulls in relevant documents, emails, files and context.
  • Model Selection dynamically chooses an appropriate GPT-class model.
  • Reasoning applies depth and multi-step inference.
  • Grounded Response is produced using retrieved enterprise data.

The whole pipeline is enclosed within Copilot, emphasising orchestration. The lecture closes with a survey for the class to complete.

Key Takeaways

If you remember nothing else, remember this.

1

Deep learning networks learn by adjusting weights — connected processing units that improve predictions over time.

2

Nodes compute in five steps — receive, multiply, sum, activate, produce (RMSAP).

3

Depth means many hidden layers — input layer takes raw data, hidden layers extract features, output layer predicts.

4

Weights are the learned dials, and “parameters” means weights — more parameters means more capacity.

5

Training minimises a loss function — give input, get a prediction, compare to the correct answer, measure the error.

6

Backpropagation assigns blame backwards — it finds each weight's error contribution and nudges weights to reduce future error.

7

Learning over time is a loop — forward pass, loss, backpropagation, repeated; errors fall and predictions improve.

8

LLMs have two phases — training (data collection, tokenization, Transformer training, fine-tuning) and generating.

9

Pretraining has eight steps — collect, clean, tokenize, set objectives, initialise, train with backprop, learn representations, output.

10

Objectives need no human labels — next-token prediction (GPT) and masked-language modelling (BERT) draw supervision from the text.

11

The Transformer stack is embeddings, positional encoding, multi-head self-attention and feed-forward layers — weights start random and training tunes them.

12

Generation is autoregressive — tokenize, embed, attend, predict a distribution, sample, append, repeat until a stop token.

Glossary

Every term you need to speak this week's language.

Deep learning network
A type of neural network made of many connected processing units that learn patterns from data by adjusting weights.
Node (neuron)
The basic computational unit: it receives inputs, multiplies them by weights, sums, applies an activation function and produces an output.
Activation function
The rule applied inside a node that decides how strongly it fires after summing its weighted inputs.
Weight (and parameter)
A number on a connection between nodes that controls how strongly one node influences another; “parameter” is a synonym for weight.
Token
A chunk of text — a word, subword or character sequence — that the model converts into a numerical ID.
Positional encoding
Information added to embeddings so the model knows word order and the distance between tokens.
Self-attention
The mechanism that compares each token with all others, computes attention scores, and weights the most relevant tokens more heavily.
Transformer
The model architecture built from embedding layers, positional encoding, multi-head self-attention and feed-forward layers.
Next-token prediction
The training objective where the model predicts the next token given previous tokens; used by GPT-style models.
Masked-language modelling
The training objective where random tokens are hidden and the model predicts the missing words; used by BERT-style models.
Autoregressive model
A model that generates text by appending each predicted token and feeding it back to predict the next.
Training
The process of teaching a network to make accurate predictions by comparing its outputs to correct answers.
Backpropagation
The algorithm that updates weights by propagating error backward through the network.
Pretraining
The phase where a model learns general language patterns from massive amounts of text before task adaptation.
Fine-tuning
Adapting a pretrained model to specific tasks by training either the final layers or the whole model.
Feature extraction (repurposing)
Treating the pretrained model as a fixed feature extractor and training only the final layers while the rest stays frozen.
Full fine-tuning
Training the entire model on task-specific data so all layers are adjusted; used when the dataset is large and very different.
Sampling strategy
The rule for picking the next token — greedy decoding, temperature scaling, or top-k / top-p sampling.
Loss function
The measure of prediction error that training aims to minimise; smaller loss means a better model.
Capacity
The rough potential of a model to fit complex patterns, related to its number of parameters.

Q3

What makes a network “deep”, and what are the three layer roles?

Answer: Having many hidden layers between input and output is what makes it deep. The input layer receives raw data (such as pixel values or token IDs), hidden layers perform intermediate processing and feature extraction, and the output layer produces the final prediction. Each layer passes information forward.
Q4

Why is “parameter” a synonym for “weight”, and what does having more parameters buy a model?

Answer: A parameter is a weight — a learned number on a connection between nodes. So a model trained on “400B parameters” has 400 billion weights. More parameters means more potential capacity: a larger ability to fit complex patterns, which lets the model be more complex and perform more tasks. The parameters are the model's features, such as generating text, translating and summarising.
Q5

Walk through one training cycle. What role does the loss function play?

Answer: A cycle is: forward pass (feed input and make a prediction), loss calculation (measure how wrong the prediction is using the loss function), then backpropagation (adjust weights to reduce that error next time). The loss function is the scoreboard — training's goal is to minimise it, over many examples and many repetitions.
Q6

Explain backpropagation to a friend who has never heard of it.

Answer: After the network makes a prediction, backpropagation works out how much error each weight contributed to the final output, sends that error information backwards through the network (from output toward input), and adjusts each weight slightly to reduce future error. In plain terms, it tells each weight how to change to make the network better. It never changes the architecture — it only nudges existing weights.
Q7

What are the two phases of an LLM, and what happens in each?

Answer: Training and generating. Training: data collection, tokenization, formatting tokenized data into input–output pairs, training a Transformer to predict output from input, then fine-tuning on specific tasks. Generating: tokenize the input text, predict the next tokens, sample a token from the distribution, append it and repeat until a stopping criterion is met. The Transformer is the model used by ChatGPT.
Q8

List the eight pretraining steps in order.

Answer: (1) Data collection; (2) data cleaning and filtering; (3) tokenization; (4) creating training objectives; (5) Transformer model initialisation; (6) training with backpropagation; (7) learning language representations; (8) pretrained model output. Mnemonic: CCTOITLP.
Q9

Why is pretraining called “unsupervised”, and how do the two training objectives differ?

Answer: It is unsupervised because no human labels are required — the text itself provides the supervision. Next-token prediction (GPT-style) takes previous tokens and predicts the next one. Masked-language modelling (BERT-style) hides random tokens in a sentence and predicts the missing words.
Q10

What are the four components of the Transformer, and why is positional encoding needed?

Answer: Embedding layers, positional encoding, multi-head self-attention and feed-forward layers. Positional encoding is needed because embeddings capture what a token means but not where it occurs; adding position tells the model the word order and the distance between tokens. At initialisation the parameters are random, and their number can range from millions to hundreds of billions.
Q11

Describe self-attention and give one ambiguity it can resolve.

Answer: For each token, self-attention compares it with all other tokens in the input, computes attention scores indicating which tokens are most relevant, and weights information from important tokens more heavily. This lets the model track long-range dependencies, use context dynamically, and resolve ambiguity — for example, working out what “it” refers to in a sentence.
Q12

What happens between the Transformer outputting probabilities and you seeing text?

Answer: A sampling strategy (greedy decoding, temperature scaling, or top-k / top-p sampling) selects a token, balancing coherence against creativity. The chosen token is appended to the input sequence, fed back into the Transformer, and used to predict the next token. This autoregressive loop repeats until a stop token is reached or a maximum length is exceeded. Example distribution: “model” → 0.42, “system” → 0.21, “process” → 0.11.
Q13

Compare feature extraction and full fine-tuning. When would you pick each?

Answer: Feature extraction (repurposing) treats the pretrained model as a fixed feature extractor: only the final layers are trained on task-specific data while the rest stays frozen — cost-effective and efficient. Full fine-tuning trains the entire model, adjusting all layers; it is best when the task-specific dataset is large and significantly different from the pretraining data, giving a more profound adaptation but requiring more resources.
Q14

How is Copilot different from GPT or BERT?

Answer: Copilot is not just one neural network. It is a coordination layer that retrieves data, chooses models, applies reasoning and produces a grounded response. Its pipeline is: User Request → Retrieval (documents, emails, files, context) → Model Selection (an appropriate GPT-class model) → Reasoning (depth and multi-step inference) → Grounded Response (using retrieved enterprise data). The whole pipeline sits inside Copilot, emphasising orchestration.
