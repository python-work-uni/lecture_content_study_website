What Is an Engineering Model?

An engineering model is a mathematical representation of a real-world system or sub-system that lets us simulate, analyse, and design before building. Unlike a physical scale model (like a model car), engineering models are usually equations or algorithms.

🌐 Whole-System Models

Digital twins, full building or airframe models. Primarily used for visualisation and high-level, limited experimentation.

⚙️ Sub-System Models

The real engineering workhorse. Break down complex systems into manageable physics/mathematics:

  • Auditory system → filter that suppresses or emphasises specific frequencies.
  • Water hose flow → fluid dynamics equation accounting for nozzle diameter.
💡
Why It Matters: Every engineering discipline relies on sub-system models. You cannot design a high-performance car engine without modelling combustion, heat transfer, and fluid dynamics separately.
02

Input-Output Systems & The General Model

A System takes input(s) and produces output(s). Systems come in two distinct flavours:

1. Deterministic System

Same input $ ightarrow$ always same output. No randomness or variance.

Examples: Weighing scale, ideal audio amplifier, car engine response to throttle pedal.

2. Stochastic System

Same input $ ightarrow$ possibly different outputs. Contains inherent randomness.

Examples: Natural atmospheric processes, stock market, Large Language Models (LLMs).

The Universal Engineering Model
$$y = f_ heta(x)$$

$x$ = input vector  |  $y$ = output vector  |  $ heta$ = learnable parameters  |  $f$ = model structure / function

Training is simply the process of finding the optimal parameter vector $ heta$ for your system using observed data.

🧠
Memory Aid: "X goes in, Y comes out, Theta makes it work" — X, Y, $ heta$.
03

Three Concrete Model Examples

Example 1 • Linear

Discrete-Time FIR Filter

$$y[n] = \sum_{k=0}^2 w[k] x[n-k]$$
  • $x[n]$: input signal samples (e.g. audio at 44.1 kHz)
  • $y[n]$: output filtered audio samples
  • Parameters $ heta$: $\{w[0], w[1], w[2]\}$
  • Goal: Choose weights to attenuate specific high frequencies.
Example 2 • Non-Linear

Power Amplifier Model

$$y[n] = A \cdot anh(g \cdot x[n])$$
  • Models a memory-less saturating power amplifier.
  • Parameters $ heta$: $A$ (amplitude scaling) and $g$ (gain).
  • Learning $ heta$: Excite system with known $x$, record $y$, fit $A$ and $g$ via regression.
Example 3 • Deep Learning

Neural Network (MLP)

$$y = \sigma(W_2 \sigma(W_1 x + b_1) + b_2)$$
  • Multi-Layer Perceptron: Universal approximator.
  • Parameters $ heta$: All weights matrices $W$ & bias vectors $b$.
  • Optimization: Gradient descent via backpropagation.
💡
Model Spectrum: These three examples illustrate the spectrum of machine learning: from simple Linear FIR Filters $ ightarrow$ Non-linear Parametric Equations $ ightarrow$ Deep Neural Networks & LLMs (increasing flexibility and expressive power).

Datasets & Supervised Learning Terminology

In supervised learning, we learn a mapping from input features to known target labels using historical observations.

Dataset Component Notation Description Role in Supervised Learning
Sample (Record / Row) $i \in \{1, \dots, N\}$ A single observation or instance. Individual training example.
Features (Columns) $x = [x_1, x_2, \dots, x_k]^T$ Input variables / measurements. Fed into model to generate prediction $\hat{y}$.
Ground Truth Label $y$ The verified true output or target. Compared against prediction to compute loss.
Inference / Prediction $\hat{y} = f_ heta(x)$ The model's estimation for a given $x$. Used in deployment on unseen data.
🧠
Memory Aid: "Features Feed Forward, Labels Look Back" — Features flow into the model forward; labels are what you look back to for error checking.

5.1 Data Preparation

  • Collection: Garbage In, Garbage Out. Use verified datasets and review documentation.
  • Cleaning: Handle missing values, outliers, sensor noise, and incompatible formats.
  • Feature Engineering: Transform raw signals into meaningful predictors (e.g. Fourier transform, polynomial combinations).

5.2 Data Split (80 / 10 / 10)

  • Training Set (80%): Optimize model parameters $ heta$.
  • Validation Set (10%): Tune hyperparameters (learning rate, layer count, regularization).
  • Test Set (10%): Final unbiased evaluation. NEVER touch during development!
  • Data Leakage: Using test data in training/selection inflates metrics falsely.

5.3 Training & Optimization

  • Loss Function: Quantifies prediction error. Must be differentiable w.r.t. $ heta$.
    • Regression $ ightarrow$ MSE (Mean Squared Error)
    • Classification $ ightarrow$ Cross-Entropy
  • Gradient Descent: $ heta \leftarrow heta - \eta abla_ heta \mathcal{L}( heta)$
  • SGD (Stochastic GD): Computes gradients over mini-batches for efficiency.

5.4 Deployment & Monitoring

  • Hardware Constraints: Edge compute, memory budgets, and real-time latency limits.
  • Distribution Shift: Real-world sensors are noisier than clean lab training data.
  • Static Nature: Deployed models do not learn on-the-fly. They are static weights and require scheduled periodic retraining.

Classification vs Regression

Supervised learning tasks are bifurcated by the mathematical nature of their target output space $\mathcal{S}_y$.

Characteristic Classification 🏷️ Regression 📈
Output Space ($\mathcal{S}_y$) Finite / Discrete set of categories $\{C_1, C_2, \dots, C_K\}$ Continuous / Uncountable real values ($\mathbb{R}$ or $\mathbb{R}^d$)
Core Objective Assign input sample to the correct discrete class. Predict an exact numerical quantity.
Engineering Examples • Fault diagnosis (Normal vs Faulty)
• Emergency brake trigger (Brake / No Brake)
• Defect inspection on manufacturing line 		• Temperature & weather forecasting
• Battery State of Charge (SoC %)
• Aircraft airspeed & altitude estimation
Output Type Discrete label or probability distribution (Soft) Continuous scalar or probability density
ℹ️
Soft Estimates > Point Estimates: Predicting probability distributions (e.g., $P( ext{Rain}) = 0.85$ or $ ext{Price} \sim \mathcal{N}(\mu, \sigma^2)$) provides critical uncertainty quantification that single point estimates cannot convey.
🧠
Memory Aid: "Class = Category, Regress = Real number"

Classification Performance Metrics & Confusion Matrix

7.1 Binary Confusion Matrix

The ground-truth comparison table evaluating classifier decisions:

Predicted Positive (+) Predicted Negative (-)
Actual Positive (+) True Positive (TP) False Negative (FN) (Miss)
Actual Negative (-) False Positive (FP) (False Alarm) True Negative (TN)

7.2 Core Formulas

Accuracy
$$ ext{Accuracy} = rac{TP + TN}{TP + TN + FP + FN}$$

Overall correctness. Severely misleading on imbalanced datasets!

Precision (Positive Predictive Value)
$$ ext{Precision} = rac{TP}{TP + FP}$$

"Of all predicted positives, how many were actually correct?"

Recall (Sensitivity / True Positive Rate)
$$ ext{Recall} = rac{TP}{TP + FN}$$

"Of all actual positives that existed, how many did we catch?"

F1 Score (Harmonic Mean)
$$ ext{F1} = 2 \cdot rac{ ext{Precision} \cdot ext{Recall}}{ ext{Precision} + ext{Recall}}$$

Harmonic mean balances precision & recall. Only high if both are high.

7.3 The Accuracy Trap (Example 1)

Imagine a dataset with 94.5% Negative samples and only 5.5% Positive samples. A dumb classifier that blindly predicts "Negative" for every sample achieves:

  • Accuracy = 94.5% (Looks outstanding on paper!)
  • Recall = 0.0% (Caught zero actual positive events!)
  • Precision = Undefined (0/0)

⚠️ CRITICAL RULE: Never evaluate a model using accuracy alone on imbalanced datasets.

7.4 Cost Asymmetry — Choose the Right Metric

In the real world, the financial and human costs of False Positives and False Negatives are rarely equal:

Application Scenario False Negative (FN) Cost False Positive (FP) Cost Optimization Target
Medical Cancer Screening High (Missed treatment / Death) Low (Extra follow-up test) Maximize Recall
Aircraft Engine Failure / Intrusion High (Catastrophic crash / Breach) Medium (Precautionary inspection) Maximize Recall
Phone Face Unlock / Biometric Auth Low (User re-attempts unlock) High (Unauthorized device access) Maximize Precision
General Balanced Classification Equal / Unknown Equal / Unknown Maximize F1 Score

7.5 Multi-Class Confusion Matrices

For $K$ classes, the matrix is $K imes K$ where Rows represent Actual classes and Columns represent Predicted classes.

  • The Diagonal elements $\sum M_{ii}$ represent all correct predictions.
  • $ ext{Accuracy} = rac{\sum ext{Diagonal}}{ ext{Total Samples}}$.
  • Compute Precision, Recall, and F1 per-class using One-vs-Rest, then aggregate via Macro-average (unweighted mean) or Micro-average.

Regression Performance: Mean Squared Error (MSE)

Unlike discrete classification, in regression problems the model output is continuous ($\mathbb{R}$). Exact matches occur with probability zero ($P(\hat{y} = y_0) = 0$). Error is inevitable; we must measure its magnitude.

Regression Loss Formulation
$$ ext{Error: } e = \hat{y} - y_0$$ $$ ext{MSE: } \zeta = \mathbb{E}[(\hat{y} - y_0)^2] = rac{1}{N} \sum_{i=1}^N (\hat{y}_i - y_i)^2$$ $$ ext{RMSE: } ext{RMSE} = \sqrt{ ext{MSE}}$$

Where $\mathbb{E}[\cdot]$ denotes statistical expectation (sample average).

🧠
Memory Aid: "MSE = Mean Squared Error = Average of (guess minus truth) squared."

Terms to Know (Glossary)

Engineering Model Model
Mathematical representation of a real-world system or sub-system used for simulation, analysis, and design.
Deterministic System Model
A system where identical inputs always yield the exact same output without randomness.
Stochastic System Model
A system where identical inputs can yield different outputs due to inherent randomness (e.g. LLMs).
Parameters ($ heta$) Model
Internal learnable values (weights, biases, gains) within a model that are optimized using data.
Training Pipeline
The algorithmic process of finding the optimal parameters $ heta$ that minimize the loss function.
Ground Truth Pipeline
The empirically verified true target value or label ($y$) for a specific training observation.
Features ($x$) Pipeline
The measured input variables or observational vector passed into the model.
Label / Response ($y$) Pipeline
The ground truth target output variable that the model is tasked with predicting.
Inference Pipeline
Using a trained model with fixed parameters $ heta$ to make predictions on novel, unseen data.
Supervised Learning Pipeline
Machine learning regime where models learn patterns from paired $(x, y)$ input-label examples.
Data Leakage Trap
Contamination where information from validation/test sets leaks into training, causing false optimism.
Loss Function Pipeline
A differentiable mathematical function quantifying prediction error used by optimization algorithms.
Gradient Descent Pipeline
Iterative first-order optimization algorithm that updates $ heta$ opposite the gradient of the loss.
SGD Pipeline
Stochastic Gradient Descent: updates parameters using mini-batch estimates of the true gradient.
Hyperparameters Pipeline
Structural configurations set prior to training (learning rate, layer depth, batch size).
Validation Set Pipeline
Data split reserved exclusively for hyperparameter tuning and model selection.
Test Set Pipeline
Held-out data split used strictly for final, unbiased performance verification.
Confusion Matrix Metric
Table tabulating True Positives, False Positives, True Negatives, and False Negatives.
Precision Metric
Ratio $ rac{TP}{TP + FP}$. Measures the reliability and purity of positive predictions.
Recall (Sensitivity) Metric
Ratio $ rac{TP}{TP + FN}$. Measures the proportion of actual positive events successfully detected.
F1 Score Metric
Harmonic mean of Precision and Recall: $2 \cdot rac{P \cdot R}{P + R}$. Robust against class imbalance.
MSE Metric
Mean Squared Error: average squared difference between predictions $\hat{y}$ and true continuous targets $y$.
Deployment Production
Integrating trained models into production environments (REST API, embedded firmware, mobile apps).
Monitoring Production
Tracking live performance and input distributions in production to detect model degradation and drift.

Worked Scenarios & Calculations

Scenario 1 • Signal Processing

Designing a Simple FIR Filter

Given an audio input sampled at $44.1 ext{ kHz}$ ($x[n]$), we want to design a 3-tap discrete-time filter to suppress high-frequency hiss:

$$y[n] = w[0]x[n] + w[1]x[n-1] + w[2]x[n-2]$$

Here, the learnable parameter vector is $ heta = \{w[0], w[1], w[2]\}$. We can solve for $ heta$ analytically using filter design methods (e.g. windowing) or learn $ heta$ from recorded input/output pairs using least-squares optimization.

Scenario 2 • Medical Diagnosis Selection

Choosing Between Two Cancer Screening Classifiers

Disease prevalence is rare ($2\%$ positive, $98\%$ healthy). We evaluate two candidate models:

Model Accuracy Precision Recall F1 Score Verdict
Classifier A (Trivial) 98.0% 0.0% 0.0% 0.00 Rejected (Useless)
Classifier B (Tuned) 97.0% 80.0% 90.0% 0.85 Selected for Production

Even though Classifier A has higher nominal accuracy ($98\%$ vs $97\%$), it misses $100\%$ of sick patients. Classifier B catches $90\%$ of disease cases with strong precision ($80\%$) and an $F_1$ of $0.85$.

Scenario 3 • Regression Math

House 2 $750 ext{k} $730 ext{k} $-20 ext{k} $400 ext{M}$ ($k^2$)

Potential Exam Focus & Practice (15 Questions)

Progress: 0 / 15 Mastered
Q1
Define and distinguish between a deterministic system and a stochastic system, giving one example of each.
Answer:
  • Deterministic System: Given identical input conditions, it always produces the exact same output without randomness (e.g. weighing scale, audio FIR filter, ideal mechanical gear train).
  • Stochastic System: Given identical inputs, it can produce different outputs due to inherent randomness or probabilistic dynamics (e.g. weather systems, stock prices, Large Language Models).
Q2
Given the model equations: (a) $y[n] = A \cdot anh(g \cdot x[n])$ and (b) $y[n] = w_0 x[n] + w_1 x[n-1]$, state explicitly what the learnable parameters $ heta$ are for each.
Answer:
  • (a) For $y[n] = A \cdot anh(g \cdot x[n])$, the learnable parameters are $ heta = \{A, g\}$ (Amplitude scaling factor and Gain).
  • (b) For $y[n] = w_0 x[n] + w_1 x[n-1]$, the learnable parameters are $ heta = \{w_0, w_1\}$ (the filter weights).
Q3
Arrange the following steps in their correct chronological engineering pipeline order: Hyperparameter tuning, Data cleaning, Final evaluation, Parameter training, Deployment, Data collection.
Answer:
  1. Data collection
  2. Data cleaning
  3. Parameter training (on training set)
  4. Hyperparameter tuning (on validation set)
  5. Final evaluation (on test set)
  6. Deployment (into production)
Q4
Leakage scenario: "A student uses test set accuracy to choose between two candidate neural network architectures. What is methodologically wrong with this procedure?"
Answer: This is a severe violation called Test Set Leakage. The test set must be strictly held out for final unbiased evaluation of the finished model. Architecture selection and hyperparameter tuning must be performed exclusively on the Validation set; otherwise, the test metric becomes biased and over-optimistic.
Q5
"Design a classifier for detecting imminent aircraft engine failure. False Negative = catastrophic crash. False Positive = precautionary maintenance inspection. Which performance metric matters most?"
Answer: Recall (Sensitivity) matters most. Because a False Negative results in loss of life and aircraft destruction, the system must detect virtually $100\%$ of real engine failures ($TP / (TP + FN) ightarrow 1.0$), even if it incurs occasional False Positive maintenance checks.
Q6
Given confusion matrix counts $TP = 45$, $FP = 5$, $TN = 85$, and $FN = 15$, compute Accuracy, Precision, Recall, and F1 score step-by-step.
Answer:
  • $ ext{Total} = 45 + 5 + 85 + 15 = 150$
  • $ ext{Accuracy} = rac{TP + TN}{ ext{Total}} = rac{45 + 85}{150} = rac{130}{150} pprox \mathbf{86.67\%}$
  • $ ext{Precision} = rac{TP}{TP + FP} = rac{45}{45 + 5} = rac{45}{50} = \mathbf{90.00\%}$
  • $ ext{Recall} = rac{TP}{TP + FN} = rac{45}{45 + 15} = rac{45}{60} = \mathbf{75.00\%}$
  • $ ext{F1} = 2 \cdot rac{0.90 imes 0.75}{0.90 + 0.75} = rac{1.35}{1.65} pprox \mathbf{0.818 ext{ (81.82\%)}}$
Q7
Explain the "Accuracy Trap": A cancer screening test reports 99% accuracy on a population where 1% have cancer, but the model predicts "healthy" for every patient. What are its Precision and Recall?
Answer:
  • $TP = 0, FP = 0, FN = 1\%, TN = 99\%$
  • $ ext{Precision} = rac{TP}{TP + FP} = rac{0}{0}$ (Undefined / 0%)
  • $ ext{Recall} = rac{TP}{TP + FN} = rac{0}{0 + 1\%} = \mathbf{0\%}$
  • Explanation: The model has 99% nominal accuracy simply by mirroring the dominant negative majority class, but it catches zero disease cases, rendering it totally useless.
Q8
Categorize each task as classification or regression, and justify: (a) "Predicting tomorrow's temperature in °C", (b) "Predicting whether it will rain tomorrow (Yes/No)".
Answer:
  • (a) Regression: Temperature is a continuous, uncountable real number ($\mathbb{R}$).
  • (b) Classification: The output is a finite discrete binary set of mutually exclusive categories: $\{ ext{Rain}, ext{No Rain}\}$.
Q9
Given true values $y = [10, 20, 30]$ and predictions $\hat{y} = [12, 18, 33]$, calculate the Mean Squared Error (MSE) step by step.
Answer:
  1. Errors $e_i = \hat{y}_i - y_i$: $[12-10, 18-20, 33-30] = [+2, -2, +3]$
  2. Squared errors $e_i^2$: $[2^2, (-2)^2, 3^2] = [4, 4, 9]$
  3. Mean Squared Error: $ ext{MSE} = rac{4 + 4 + 9}{3} = rac{17}{3} pprox \mathbf{5.67}$
Q10
List three reasons why the real-world deployment environment differs from the training environment and why monitoring is essential.
Answer:
  • 1. Hardware & Latency Constraints: Edge devices have limited RAM, CPU/battery budgets, and strict real-time response deadlines.
  • 2. Sensor Noise & Quality: Real-world production sensors suffer from drift, calibration error, and harsher noise than curated training datasets.
  • 3. Data Distribution Drift: User behaviour and operating conditions change over time. Monitoring detects when model predictions decay, triggering scheduled retraining.
Q11
True or False: "A deployed machine learning model continues learning and updating its parameters autonomously from new live user data." Justify your answer.
Answer: FALSE. Standard deployed ML models are static after training (their weights $ heta$ are fixed). They perform pure inference. Adapting to new data requires collecting new samples, passing them through validation/safety pipelines, and redeploying an updated model version.
Q12
When is the F1 score a superior evaluation metric compared to Accuracy?
Answer: F1 score is superior whenever there is class imbalance (e.g. $95\%$ negative, $5\%$ positive) or when False Positives and False Negatives carry asymmetric real-world costs. Because F1 is the harmonic mean of Precision and Recall, it requires strong performance on both metrics to score well.
Q13
In a 3×3 multi-class confusion matrix, how are per-class Precision and Recall extracted, and how is the overall diagonal related to Accuracy?
Answer:
  • For Class $i$: $TP_i = M_{ii}$ (diagonal cell).
  • $ ext{Precision}_i = rac{M_{ii}}{\sum_j M_{ji}}$ (diagonal element divided by its column sum).
  • $ ext{Recall}_i = rac{M_{ii}}{\sum_j M_{ij}}$ (diagonal element divided by its row sum).
  • $ ext{Overall Accuracy} = rac{\sum_{i=1}^3 M_{ii}}{ ext{Total Samples}}$ (sum of main diagonal divided by total matrix sum).
Q14
Why might an engineer engineer polynomial features (e.g. $x_1^2$, $x_1 x_2$) for a linear regression model?
Answer: To enable a linear model structure to fit and capture non-linear curvature and feature interactions in the underlying data without altering the closed-form or convex linear optimization solver.
Q15
What critical mathematical property must a loss function possess in order for Gradient Descent optimization to work?
Answer: The loss function $\mathcal{L}( heta)$ must be continuous and differentiable with respect to the model parameters $ heta$ (i.e. the partial derivatives $ rac{\partial \mathcal{L}}{\partial heta_j}$ must exist everywhere) so that gradient vectors can be calculated to guide parameter updates.
