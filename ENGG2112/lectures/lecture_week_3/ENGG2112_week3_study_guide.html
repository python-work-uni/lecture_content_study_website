What a Model Is, and How We Judge It

This week answers four questions. What is a model in engineering? How do we describe one mathematically? What makes a model an "AI" model? And how do we measure whether it is any good? Along the way you meet the single equation that runs through the whole unit, the full AI/ML pipeline, and the metrics that decide whether a model is useful or dangerous.

Read this first: Hold onto one mental model — a model is a function that turns inputs into outputs, and training finds the numbers inside that function. We write it as y = f_θ(x): x goes in, y comes out, and θ is the set of tunable parameters that training adjusts. Everything else this week — datasets, the pipeline, classification versus regression, confusion matrices — is either how we feed that function or how we judge what it returns.

The Big Picture

Everything this week hangs off one idea: a model is a function, and training is how we find its parameters.

Engineers rarely design a whole machine in one go. They build models of the parts — the combustion inside an engine, the airflow over a wing, the filtering inside a hearing aid — and then assemble the parts into a system. This week's lecture, delivered by Professor T. J. Lim, starts there and builds all the way up to "AI models", the pipeline that produces them, and the numbers we use to judge them.

The lecture is organised around four questions. Keep them in mind as signposts:

🗂️ 1. What is a model?

In engineering, a representation of a thing that is useful for design — and for sub-systems, that representation is mathematical.

🧮 2. How do we describe it?

As an input-output function, y = f_θ(x), with inputs x, outputs y and parameters θ.

🤖 3. What makes it "AI"?

An AI model is still y = f_θ(x) — but f is very flexible (a neural network) and θ is learned from data rather than derived by hand.

📏 4. Is it any good?

We measure it: the confusion matrix, accuracy, precision, recall, F1 for classification, and MSE for regression.

Notice that the last question is where most of the risk lives. A model can look superb on one number (94.5% accuracy!) and still be useless. Learning to read the metrics is as important as learning to build the model.

The journey, in order

Define the model→ Collect & clean data→ Engineer features→ Split→ Train→ Validate & test→ Deploy & monitor

What Is an Engineering Model?

A model is a representation of a thing that must be useful for engineering design — usually a mathematical one.

Start with the everyday meaning. A dictionary gives two senses of "model":

  1. A scaled representation. A three-dimensional representation of a person, thing or proposed structure, typically smaller than the original — for example, "a model of St Paul's Cathedral".
  2. An example to imitate. A thing used as a standard to follow — for example, "the project became a model for other schemes".

Engineering models are closer to the first definition: a representation of a thing. But there is a crucial extra requirement — the representation must be useful in engineering design. A pretty replica that cannot help you predict or decide anything is not doing an engineer's job.

Engineering model — a representation of a system or sub-system that supports engineering design. Familiar examples include model cars, model buildings and digital twins (software replicas of a physical asset). These allow visualisation and a limited amount of design refinement and experimentation.

Whole systems vs sub-systems

Some models represent a whole complex "thing" — a car, a building, a manufacturing process. But engineers also rely heavily on models of the sub-systems inside that thing. Those sub-system models let us design the parts through computer simulation, mathematical analysis and lab experiments, and confirm that each part works before we commit to building it.

Sub-system models are necessarily mathematical. Two examples from the lecture:

👂 The human auditory system

Modelled as a filter that suppresses frequencies outside our hearing range and emphasises or de-emphasises certain frequencies inside that range.

🚿 Water flow through a hose

A model of how the flow rate into a hose affects the force of water at the other end — and it must account for the diameter of the nozzle.

💡
Why it matters: almost every engineering discipline designs through sub-system models. You cannot design an engine without separately modelling combustion, heat transfer and fluid flow — and each of those is a model in its own right.

Inputs, Outputs and Systems

A system maps inputs to outputs; a deterministic system always gives the same answer, a stochastic one does not.

In engineering, a system takes in one or more inputs and produces one or more outputs in response to those inputs. Think of the input as an excitation and the output as the response.

Deterministic system — a system that always responds the same way to a given input. Feed it the same thing twice and you get the same output twice.
Stochastic system — a system that does not necessarily give the same output for a given input. It contains randomness, so the same input can produce different outputs on different runs.

Deterministic

Same input → same output, every time. The behaviour is repeatable and predictable.

Examples: a weighing scale or other measuring device; the audio amplifier in a TV; a car engine responding to the gas pedal.

Stochastic

Same input → possibly different output. Randomness is built in.

Examples: natural systems with inherent randomness; large language models (LLMs) and other engineered systems that mimic natural randomness.

ℹ️
Key idea: stochastic does not mean "broken". Randomness is a feature when you are modelling something genuinely random — the weather, human behaviour, or the next word in a sentence.

The Universal Model: y = f_θ(x)

One equation covers every model in this unit — from a simple filter to a giant language model.

Every system we have looked at can be described by the same compact idea, which you first met in the opening lecture:

General mathematical model
y = f_θ(x)

Read it left to right: the model takes inputs x, applies a function f that depends on parameters θ, and produces outputs y. Breaking it down:

  • x is the input. It is usually multi-dimensional — a whole vector of numbers, not a single value.
  • y is the output. It may also be multi-dimensional (for example, several predicted values at once).
  • f_θ is the function itself — linear, non-linear, a neural network, anything.
  • θ (theta) is the set of parameters — the numbers we are allowed to tune.
Parameters (θ) — the tunable numbers inside the model function. Choosing the function f fixes the structure; choosing θ fixes the behaviour.

So where does learning come in? We need to find the best parameter θ for the system we are modelling. That search is exactly what we call training.

Training — the process of finding the best value of θ for a given model and data set, so that the model's outputs match reality as closely as possible.
🧠
Remember XYT: "X goes in, Y comes out, Theta makes it work." If you can say which part is x, which is y, and which is θ, you can analyse any model in this unit.

Three Worked Model Examples

The same equation y = f_θ(x) climbs a ladder of flexibility: a linear filter, a non-linear curve, then a neural network.

Abstract equations become real once you see them applied. These three examples all fit y = f_θ(x), but the function form gets more powerful each time — and, crucially, the set of parameters θ changes.

Example 1 — Discrete-time feedforward model

Feedforward filter (a "finite impulse response" filter)
y[n] = Σ_{k=0}^{2} w_k · x[n−k]

Here x[n] is a sequence of samples of a signal — for instance, audio sampled at 44.1 kHz (44,100 samples per second) — and y[n] are the samples of the output signal. The model combines the current sample and the two previous samples, each scaled by a weight.

  • By designing the weights w₀, w₁, w₂, we can accomplish various functions — for example, suppressing high frequencies (a low-pass filter).
  • We can also use the same structure to model an unknown input-output system: observe its inputs and outputs, then fit the weights.
  • So the parameters are θ = {w₀, w₁, w₂} — the three weights.

Example 2 — Non-linear model

Memory-less power amplifier
y[n] = A · tanh(g · x[n])

This models a memory-less power amplifier — "memory-less" means the output depends only on the current input, not on past samples. The shape of the curve is a hyperbolic tangent (tanh), which flattens out at large inputs, just as a real amplifier saturates.

We do not know the characteristics of this amplifier — but we have the physical device. So we control its input and measure the corresponding output, then fit the curve. The parameters we need to learn are A (the amplitude, or how tall the curve is) and g (the gain, or how sharply it bends). An interactive HTML demo of this is available on Canvas.

✅
Do this: when asked "what is θ?" for a model, separate the known structure from the unknown numbers. Filter → the weights; tanh amplifier → A and g; neural network → all weights and biases.

Example 3 — Neural network model

The simplest neural network is a multi-layer perceptron (MLP): layers of simple units, each connected to the next by weighted links. Its parameters are all the weights and biases across every layer — often a very large set of numbers. Two questions the lecture asks about it:

  • How would we make the model more powerful? Add more layers or more neurons per layer, or change the activation functions (the non-linearities between layers).
  • How do we find the best weights? By training — the same "minimise a loss" process we meet later this week.

How do LLMs fit in?

Large language models (LLMs) are the most flexible form of y = f_θ(x) — enormous neural networks with huge parameter counts. In class you watch a short video, "Large Language Models explained briefly", and jot down any terms you do not fully understand into a Menti poll. The key point for this unit: because they generate text by sampling from probabilities, LLMs behave as stochastic systems — the same prompt can yield different answers.

Datasets and Basic Terminology

Training data is just a spreadsheet: each row is a sample, each column is a feature or a label.

To train a model we need data. In the training phase, the objective is to find the best value of θ using the training data available. That data is organised into rows of the form (x₁, …, x_K, y), assuming K scalar inputs (features) and one scalar output (the response or label). In practice it is often stored as a CSV or Excel file.

The cleanest way to picture it is a spreadsheet with N rows and K columns:

ConceptWhat it isIn the spreadsheet
Sample / data recordOne complete observationOne row
FeatureAn input variable the model reads (also called an observation)A column of inputs
Label / responseThe output the model tries to predictThe final column

Depending on the problem, some columns are features and some are responses (labels). The machine's job is to estimate or predict the label from the features. Inference is just another word for estimation and prediction — running a trained model to get an output.

Feature — an input value x fed into the model. Also called an observation or attribute.
Label (response) — the output value y that the model predicts. In supervised learning it is the thing you compare the prediction against.
Inference — using a trained model to estimate or predict an output from new inputs.

Labelled data and supervised learning

In supervised learning, the model is trained on labelled data: every training record has a true y value corresponding to its x values. That true value is called the ground truth label. The x values are fed into the model and are known as the features or observations.

🧠
Memory hook: "Features Feed Forward, Labels Look Back." Features go into the model; labels are what you look back at to check the prediction.

The AI/ML Pipeline

AI/ML applications are a chain of stages — and because of feedback, the chain is really a cycle.

AI/ML applications are often described as a "pipeline" of functions, one leading into the next: data processing at the front, deployment at the back. But with the monitoring and feedback step, it is more of a cycle than a straight line — a model that fails in the field sends you back to the start to redesign.

  1. Data collection. Gather the right data for the application.
  2. Cleaning and preprocessing. Fix missing, corrupted, wrongly formatted or noisy data.
  3. Feature engineering. Extract the relevant attributes for processing, manually or automatically.
  4. Data split. Divide the data into training, validation and test sets.
  5. Training. Adjust the parameters θ for a given model and hyper-parameter setting.
  6. Validation. Tune the hyper-parameter settings.
  7. Testing. Assess the final model and settings on unseen data.
  8. Deployment. Put the model into production (an API, an app, firmware on a chip).
  9. Monitoring. Watch performance after deployment; if it fails, loop back and redesign.
Collect→ Clean→ Engineer features→ Split→ Train→ Validate→ Test→ Deploy→ Monitor↺
💡
Why it matters: the pipeline is the map of this course. Skip a stage — especially the validation/test separation or monitoring — and the model quietly fails in the real world even though it looked fine in the lab.
🧠
Remember the order: "Don't Cheat, Find Sweet Training Values, Then Deploy Monitored." Data, Clean, Feature-engineering, Split, Train, Validate, Test, Deploy, Monitor.

Data Preparation: Collection, Cleaning, Features

Before any model, the data has to be right — garbage in, garbage out.

Data collection

You need to collect the right data for the application. The governing rule is "Garbage In, Garbage Out": if the inputs are bad, no amount of clever modelling will save the outputs.

  • In this unit you probably will not run your own experiments to collect data — you will rely on publicly available data sets.
  • Be sure to read the overview and description of any data set you download, so you understand what it actually contains.
  • Academic papers often provide their data sets freely too. In that case, read the paper to understand what the authors did with the data.

Cleaning and preprocessing

Real data is messy. It may be missing, corrupted, in the wrong format, or noisy. You usually need to do something to clean it up before using it for training and testing. (The lecture notes "more on this later" — it returns in Week 4.)

Feature engineering

Feature engineering means extracting the relevant attributes of the data for processing. It can be done manually (you decide which columns and transformations matter) or automatically (the AI architecture learns useful representations itself). Good features make learning easy; poor or irrelevant features make it much harder.

⚠️
Common trap: never start training before checking your data. No amount of hyper-parameter tuning fixes corrupted, missing or unrepresentative inputs — you will simply fit the mess.

Splitting Data and Avoiding Leakage

Training needs data — but not all of it. Hold some back or you will fool yourself.

Think of a dataset as a spreadsheet with N rows and K columns. Each row is a sample; each column is a feature or a label. In an image application, for example, each sample represents one image in the dataset, the k-th column may be a pixel value at some position, and the final column may be a label such as "dog", "car" or "bicycle".

Training requires some samples of data but not all of them:

  • If you use all the samples for training, you have none left for validation — the data that tells you whether the current model is good or should be changed.
  • You also need some for testing — the final step where the finished model is assessed on other, unseen data to see how well it generalises.
SplitPurpose
Training setAdjust the parameters θ for a given model and hyper-parameter setting.
Validation setAdjust the hyper-parameter settings (the choices made before training).
Testing setEvaluate the final model and settings on unseen data; if the result is unacceptable, redesign from the start.
Data leakage — if you reuse data across training, validation or testing, information "leaks" from the validation and test sets into training, yielding better-than-normal results that will not hold up in the real world.

To avoid leakage, split the available data into training, validation and test sets — a common choice is 80/10/10 (80% train, 10% validation, 10% test).

ℹ️
Note: hyper-parameters are chosen before training; θ is learned during training. Keeping those two ideas straight is what makes the training/validation/test distinction click.
✅
Exam tip: "A student uses test accuracy to pick between two models — what is wrong?" That is test-set leakage. Model selection belongs to the validation set; the test set is used once, at the very end, for final evaluation.

Training, Loss Functions and Gradient Descent

Training = define a loss, then nudge θ downhill until the loss is small.

Training an ML model is conceptually easy to understand but mathematically intricate. The idea is simple: measure how wrong the model is, then change θ to make it less wrong. The machinery that does this is where the maths lives.

Step 1 — Define a loss function

A loss function captures statistically how well the model is predicting the labels. The right loss depends on the task:

Regression

Some variant of mean squared error (MSE) works well — errors are continuous, so we penalise their squares.

Classification

We need a cross-entropy function — it compares predicted class probabilities with the true classes.

Loss function — a function that measures how poorly the model predicts the labels, aggregated over the data. The model "learns" by making this number as small as possible.

One crucial technical requirement: the loss function must be differentiable with respect to the model parameters θ. Differentiability is what lets us compute a gradient and know which way to nudge each parameter.

Step 2 — Minimise it with gradient descent

The goal
minimise L(θ) → best parameters θ*

We use some variant of gradient descent to minimise the loss with respect to θ — repeatedly stepping "downhill" on the loss surface. There is a subtlety, though:

  • The loss is formally defined in terms of a statistical expectation, written E[…], which is not knowable with precision (you would need infinite data).
  • So we approximate it using averages over the training samples. This practical variant is called stochastic gradient descent (SGD).
Gradient descent — an iterative method that repeatedly adjusts θ in the direction that reduces the loss.
Stochastic gradient descent (SGD) — gradient descent where the true expectation is approximated by averages over training samples (often small batches), making it practical on real data.
🧠
Remember: "Regression → MSE, Classification → Cross-entropy." Match the loss to the task and the rest of training follows.
ℹ️
Where each set is used: the training set adjusts parameters θ for a given model and hyper-parameter setting; the validation set adjusts the hyper-parameter settings; the testing set evaluates the final model and settings — and if that is unacceptable, you redesign from the start. Performance in all of this is judged with accuracy, precision, recall, F1 and related metrics, which we meet shortly.

Deployment and Monitoring

A model is worthless until it runs in the real world — where the rules change.

An AI application eventually needs to be deployed. That might mean an API, an app on a phone, or firmware on a microcontroller or DSP chip. Each of these places the model under different constraints from the training, validation and testing environment:

💾 Memory

The device may have far less memory than the machine you trained on.

⚡ Processing speed

Inference must be fast enough for the hardware that runs it.

⏱️ Real-time needs

Some systems must respond within a hard time budget.

There can also be a mismatch between the training and deployment environments. For example, the sensors used in deployment may be noisier than the clean sensors used in the lab for testing. A model tuned on tidy data can degrade badly on messy real-world data.

Because of this, monitoring of performance after deployment is critical. If it does not work, you go back to the first step and re-design the system — this is the feedback loop that turns the pipeline into a cycle.

ℹ️
Favourite exam fact: contrary to popular belief, AI systems generally do not learn on-the-fly. The model is static after training and is re-trained periodically. "It just keeps learning from users" is a myth.
🤔

Classification vs Regression

Classification picks a category; regression estimates a number. The difference is the set of possible outputs.

There are two basic types of problem in ML, and they are distinguished by the set of all possible outputs the model can produce. Call that set S_y.

AspectClassificationRegression
Output set S_yFinite — a fixed set of classesUncountable (and therefore infinite)
TaskDecide which class the observed features belong toEstimate the value of the response to the inputs
ExamplesDo sensor readings indicate a problem? Should a car brake based on proximity sensors? Should a robot arm pick up an object?Predicting tomorrow's rainfall from today's weather; estimating 5 pm traffic volume from 4 pm measurements; estimating someone's age from a photo

In both cases, the model y = f_θ(x) applies. And in both cases, machines are often capable of producing the output probability distribution rather than a single value:

  • A point estimate is a single output value — "the label is A".
  • A soft estimate is a range of outputs with probabilities — "A with 70%, B with 20%, C with 10%".

The distribution is very useful because it conveys uncertainty, not just a decision. A point estimate hides how confident the model is; a soft estimate exposes it.

Where classifications live: observation space

We can visualise input vectors as points lying in a geometrical observation space. Think of a 2D slice of that multi-dimensional space and you get a picture: a cloud of points, each belonging to one of several classes. In the lecture's example there are three classes.

An ML model — any classifier — divides the observation space into three non-overlapping decision regions, one per class. The surface that separates them is the decision boundary.

Observation space — the geometrical space in which each input vector is a point; nearby points tend to have similar labels.
Decision region — the region of observation space that a classifier assigns to one class. Decision regions do not overlap.

Classifiers make errors

No classifier is perfect — think of how often your phone fails to recognise your face. In the lecture's two-class illustration, the crosses belong to the blue class and the stars to the yellow class, and a slanted line is the decision boundary: points to the right are classified "blue", points to the left "yellow". Because the classifier is imperfect (perhaps it can only draw straight-line boundaries), some points land on the wrong side:

  • 1 of the 6 crosses is incorrectly labelled yellow.
  • 1 of the 7 stars is incorrectly labelled blue.

That raises the central question of the rest of the week: how do we quantify the performance of a classifier?

🧠
Remember: "Class = Category, Regress = Real number." If the answers are labels, it is classification; if they are quantities on a continuous scale, it is regression.

The Confusion Matrix and Core Metrics

The confusion matrix turns a classifier's errors into four counts, and those four counts into four metrics.

To judge a classifier we first count what it got right and wrong. For a two-class ("binary") problem, every prediction falls into one of four buckets, collected in a confusion matrix:

Actual \ PredictedPredicted PositivePredicted Negative
Actual PositiveTrue Positive (TP)False Negative (FN)
Actual NegativeFalse Positive (FP)True Negative (TN)
  • True Positive (TP): actually positive, and predicted positive. Correct hit.
  • False Negative (FN): actually positive, but predicted negative. A missed positive.
  • False Positive (FP): actually negative, but predicted positive. A false alarm.
  • True Negative (TN): actually negative, and predicted negative. Correct rejection.

The four core metrics, in words

Each metric asks a different question. Read the plain-English version first, then the formula.

Accuracy — out of all predictions, what fraction were correct? It mixes positives and negatives together, which is why it can be misleading when one class dominates.
Accuracy
Accuracy = (TP + TN) / (TP + TN + FP + FN)
Precision — of everything the model flagged as positive, what fraction really was positive? High precision means few false alarms.
Precision
Precision = TP / (TP + FP)
Recall — of all the cases that were truly positive, what fraction did the model catch? High recall means few missed positives. Recall is also called sensitivity.
Recall (sensitivity)
Recall = TP / (TP + FN)
F1 score — a single number that balances precision and recall. It is the harmonic mean of the two, so it can only be high when both are high.
F1 score
F1 = 2 × (Precision × Recall) / (Precision + Recall)
✅
Intuition for the harmonic mean: a plain average can be dragged up by one strong score. The harmonic mean punishes imbalance — if precision is 0.9 but recall is 0.1, the F1 is close to 0.18, not 0.5. That is exactly what you want: "high only if both are high."

The Accuracy Trap and the Cost of Errors

High accuracy can hide a useless classifier, and not all mistakes cost the same.

Example 1 — accuracy high, but…

The lecture's first worked example is a classifier that "does a bad job but appears from its accuracy to do a terrific job":

📊 Accuracy = 94.5%

Looks excellent at first glance.

🎯 Precision = 33%

Only 1 in 3 of the cases it predicted positive were actually positive.

🔍 Recall = 10%

Only 1 in 10 of the truly positive cases were ever detected.

The problem is that the dataset is heavily skewed towards negative. When the negatives vastly outnumber the positives, a lazy classifier can simply output "negative" almost all the time, regardless of the input, and still score high accuracy. Accuracy is dominated by the majority class and tells you almost nothing about how well the rare class is found.

⚠️
Common trap: never trust accuracy alone on imbalanced data. Always look at precision, recall and F1 alongside it. A high accuracy with terrible recall is a red flag, not a triumph.

The relative cost of false negatives and false positives

In many applications, an FN and an FP do not cost the same. The designer must therefore look at the metric that matches the real risk:

ApplicationCost of a False NegativeCost of a False PositivePrioritise
Medical diagnosisPatient does not receive timely treatmentPatient goes for additional testsRecall (FN more costly)
Intrusion detectionA security breach goes undetected, with major costsHuman experts are called in for further checksRecall (FN more costly)
Phone face unlockYou have to try againAn unauthorised user is allowed to unlock your phonePrecision (FP more costly)

This is why the F1 score exists: it is the harmonic mean of recall and precision, balancing the two. It can only be high if both are high, making it a sensible default when the two error types are roughly equally costly — or when you do not yet know the costs.

🧠
Remember MF: "Medical Miss" is bad → prioritise recall. "Facial False" alarm is dangerous → prioritise precision. One phrase, two opposite metric choices.

Example 2 — all metrics agree, but…

Now consider balanced data: 500 positive and 500 negative samples. A classifier correctly identifies both positive and negative cases at a 70% rate. Because the data is balanced and the error rate is symmetric, every metric lands on the same value:

Balanced but mediocre
Recall = Precision = Accuracy = F1 = 0.70

Is 0.70 good enough? It depends on the application — but this is a classifier that is mediocre in both directions, and a good candidate for re-design. Agreement among metrics does not mean quality; it just means the errors are symmetric.

More Than Two Classes

With more than two classes the confusion matrix grows, and the metrics go class-by-class.

In non-binary classification the confusion matrix takes the form below. Rows are the actual class, columns are the predicted class, and the diagonal holds the correct predictions (shown as the "green" cells in the lecture's coloured version):

Actual \ PredictedABCD
A852103
B19513
C121825
D22393

Accuracy is defined as the proportion of correct decisions — the sum of the diagonal divided by the total:

Multi-class accuracy
(85 + 95 + 82 + 93) / 400 = 355 / 400 = 0.8875 ≈ 88.75%

Recall, precision and F1 are now defined on a class-by-class basis, or "one-vs-rest": to score class A, treat A as the positive class and all other classes together as the negative class, then use the same binary formulas. Repeat for B, C and D, and you get a per-class report rather than a single number.

One-vs-rest — a way to extend binary metrics to many classes: score each class as if it were the only positive class and everything else were negative.
ℹ️
Worked per-class check (class A): TP = 85 (correct A predictions). FN = 2 + 10 + 3 = 15 (A's that went elsewhere), so Recall_A = 85 / 100 = 0.85. FP = 1 + 12 + 2 = 15 (other classes predicted as A), so Precision_A = 85 / 100 = 0.85, giving F1_A = 0.85.

Regression Errors and MSE

In regression, every prediction is slightly wrong — so we measure the average squared error.

Classification and regression fail differently. In classification, a correct prediction is an exact match of a class label. In regression, that is essentially impossible:

ℹ️
Key idea: regression errors occur with probability one. The model output and the ground-truth label are both continuous, so there is zero probability of the two being exactly identical. There is always some error.

Denoting the true label as y₀ and the model output as ŷ (y-hat), the error is simply their difference:

Prediction error
e = ŷ − y₀

Since we want the error to be small, our goal is often to select the model and the corresponding θ that minimise the mean squared error (MSE):

Mean squared error
ζ = E[(ŷ − y₀)²]

Here E[·] denotes the statistical mean operator — just think of it as the average/mean you already know. Squaring does two useful things: it makes every error positive (so a −5 and a +5 do not cancel out), and it penalises large errors much more heavily than small ones.

Unlike the classification task, regression tasks generally use only the MSE as a performance measure — there is no regression equivalent of the precision/recall split.

🧠
Remember: "MSE = the average of (guess minus truth), squared." E[·] is the average; the inside is the difference between prediction and truth; the square keeps it positive and punishes big misses.

Key Takeaways

If you remember nothing else, remember this.

1

An engineering model is a representation of a thing — and for sub-systems it is mathematical, because it must be useful for design, simulation and analysis.

2

Deterministic vs stochastic — a deterministic system always gives the same output for a given input; a stochastic system (including LLMs) may not.

3

The universal model is y = f_θ(x) — the function form is the design, and θ is what training learns. It spans an FIR filter, a tanh amplifier, an MLP and an LLM.

4

Know your θ: FIR filter → the weights w₀, w₁, w₂; tanh amplifier → A and g; MLP → all weights and biases.

5

Supervised learning uses labelled data — features x go in, the model predicts a label, and the ground truth measures the error. Datasets are spreadsheets: rows are samples, columns are features and labels.

6

The AI/ML pipeline is a cycle — collect, clean, engineer features, split, train, validate, test, deploy, monitor, then redesign if needed.

7

Split the data properly (often 80/10/10): training fits θ, validation tunes hyper-parameters, testing is a one-time final check — reusing data causes leakage.

8

Training needs a differentiable loss — regression uses MSE, classification uses cross-entropy, and gradient descent (in practice SGD) minimises it.

9

Models are static after training — they do not learn on the fly; they are re-trained periodically and must be monitored after deployment.

10

Accuracy alone is dangerous — on imbalanced data a high-accuracy model can have terrible precision and recall; choose the metric that matches the real FN/FP costs.

11

Classification vs regression — classification has a finite output set, regression an uncountable one; soft (probability) estimates beat point estimates.

12

Regression errors are certain — with continuous outputs, MSE = E[(ŷ − y₀)²] is the standard performance measure.

Glossary

Every term you need to speak this week's language.

Engineering model
A representation of a system or sub-system that is useful for engineering design. Sub-system models are usually mathematical, supporting simulation, analysis and lab experiments.
Deterministic system
A system that always responds the same way to a given input. Example: a weighing scale, a TV audio amplifier, a car engine versus the gas pedal.
Stochastic system
A system that does not necessarily give the same output for a given input because of inherent randomness. Examples: natural systems, and LLMs that mimic natural randomness.
Parameters (θ)
The tunable numbers inside a model function f_θ. The function form fixes the structure; θ fixes the behaviour, and training finds the best θ.
Training
The process of finding the best parameter θ for a system using the available training data, by minimising a loss function.
Feature
An input variable x fed into a model. Also called an observation or attribute. In a dataset, a feature is a column of inputs.
Label (response)
The output variable y that the model predicts. In supervised learning it is the value you compare the prediction against.
Ground truth
The true, correct label corresponding to a set of features. The benchmark your prediction is measured against.
Data leakage
Information from the validation or test sets contaminating training (through reuse), producing better-than-normal results that do not hold up in the real world.
Loss function
A differentiable function that statistically measures how poorly a model predicts its labels. Regression uses MSE; classification uses cross-entropy.
Gradient descent
An iterative optimisation method that adjusts the parameters θ in the direction that minimises the loss.
Stochastic gradient descent (SGD)
Gradient descent that approximates the true (unknowable) statistical expectation with averages over training samples, making it practical on real data.
Classification
An ML task whose output set is finite: decide which of a fixed set of classes the observed features belong to. Example: brake or not brake?
Regression
An ML task whose output set is uncountable (and therefore infinite): estimate the value of a continuous response. Example: tomorrow's rainfall, 5 pm traffic volume, age from a photo.
Confusion matrix
A table of TP, FP, FN and TN counts that summarises a classifier's decisions; for multiple classes, rows are actual and columns are predicted.
Accuracy
The proportion of all predictions that are correct: (TP + TN) / total. Misleading on imbalanced data because it is dominated by the majority class.
Precision
Of the cases the model flagged positive, the fraction that truly were positive: TP / (TP + FP). High precision means few false alarms.
Recall (sensitivity)
Of the truly positive cases, the fraction the model caught: TP / (TP + FN). High recall means few missed positives.
F1 score
The harmonic mean of precision and recall: 2 × (P × R) / (P + R). It can only be high when both precision and recall are high.
Mean squared error (MSE)
The expectation of the squared difference between model output and true label, ζ = E[(ŷ − y₀)²]; the standard regression performance measure.

Practice Questions

Look away from the page first — retrieval is what builds memory.

Answer, reveal, then tick "Mastered". Your progress is saved.
Q1

In your own words, what is an engineering model, and how does it differ from the dictionary's first meaning of "model"?

Answer: An engineering model is a representation of a thing or sub-system that must be useful for engineering design — and for sub-systems it is mathematical, so you can simulate and analyse it. The dictionary's first meaning (e.g. "a model of St Paul's Cathedral") is a scaled visual replica. An engineering model does more: it lets you predict behaviour and make design decisions.
Q2

A weighing scale and an LLM both take an input. Which is deterministic and which is stochastic, and what does that mean?

Answer: The weighing scale is deterministic — the same weight gives the same reading every time. The LLM is stochastic — the same prompt can produce different outputs because it samples from probabilities. "Stochastic" means the same input does not necessarily give the same output.
Q3

For the feedforward model y[n] = Σ_{k=0}^{2} w_k·x[n−k], what exactly is θ?

Answer: θ = {w₀, w₁, w₂} — the three weights. The structure (a weighted sum of the current and two previous samples) is fixed; the weights are the numbers training must find.
Q4

A power amplifier is modelled as y[n] = A·tanh(g·x[n]). What are the parameters, and how would you learn them if you cannot see inside the device?

Answer: The parameters are A (amplitude) and g (gain). We have the physical device, so we feed it controlled inputs and measure the corresponding outputs, then fit A and g so the tanh curve matches the measured input-output pairs. This is a memory-less model — the output depends only on the current input.
Q5

What is a multi-layer perceptron's parameter set, and name two ways to make it more powerful.

Answer: Its parameters are all the weights and biases across every layer. To make it more powerful, add more layers or more neurons per layer, and/or change the activation functions. The best weights are then found by training.
Q6

Put the AI/ML pipeline in order, and say which stage feeds back into the start.

Answer: Data collection → cleaning/preprocessing → feature engineering → data split → training → validation → testing → deployment → monitoring. Monitoring feeds back: if performance drops, you go back to the first step and re-design. This feedback is why the "pipeline" is really a cycle.
Q7

A classmate uses the test set to choose between two models. What is wrong, and which set should they use?

Answer: This is test-set leakage. The test set must stay unseen and be used only once, at the very end, for a final unbiased evaluation. Model selection belongs to the validation set, which exists precisely to tune choices before the final test.
Q8

Why must a loss function be differentiable, and why is SGD used instead of plain gradient descent on the expectation?

Answer: Gradient descent needs the gradient of the loss with respect to θ to know which way to adjust each parameter, so the loss must be differentiable. The true loss is a statistical expectation E[…], which is not knowable exactly; SGD replaces it with averages over training samples — a practical approximation.
Q9

Given TP = 45, FP = 5, TN = 85, FN = 15, compute accuracy, precision, recall and F1.

Answer: Total = 150. Accuracy = (45 + 85)/150 = 130/150 ≈ 0.867. Precision = 45/(45 + 5) = 45/50 = 0.90. Recall = 45/(45 + 15) = 45/60 = 0.75. F1 = 2 × (0.90 × 0.75)/(0.90 + 0.75) ≈ 0.818.
Q10

A classifier reports 94.5% accuracy, 33% precision and 10% recall. Explain how this happens and what you would do about it.

Answer: The dataset is heavily skewed towards negative, so a classifier that predicts "negative" almost all the time rides the majority class and scores high accuracy while missing nearly all positives. Look at precision, recall and F1 (not accuracy), and consider rebalancing the data, changing the decision threshold, or using a cost-sensitive design.
Q11

Compare phone face unlock with medical diagnosis. Which error is worse in each, and which metric would you prioritise?

Answer: Face unlock: a false positive (an unauthorised user gets in) is far worse, so prioritise precision. Medical diagnosis: a false negative (a patient misses timely treatment) is far worse, so prioritise recall. The right metric depends on the relative cost of FN versus FP.
Q12

Using the four-class confusion matrix from the lecture, compute the accuracy.

Answer: Accuracy is the sum of the diagonal divided by the total: (85 + 95 + 82 + 93)/400 = 355/400 = 0.8875, about 88.75%. Recall, precision and F1 for each class are computed one-vs-rest (treat that class as positive, all others as negative).
Q13

Why do regression errors occur with probability one, and what performance measure do we use?

Answer: Both the model output ŷ and the ground-truth label y₀ are continuous, so the probability of them being exactly equal is zero — some error e = ŷ − y₀ always remains. Regression generally uses only the mean squared error, ζ = E[(ŷ − y₀)²], where E[·] is the statistical mean (average) operator.
Q14

Classify each task as classification or regression: (a) predicting tomorrow's rainfall amount, (b) predicting whether it will rain, (c) estimating a person's age from a photo, (d) deciding whether a robot arm should pick up an object.

Answer: (a) regression — rainfall amount is continuous/uncountable. (b) classification — a finite set {rain, no rain}. (c) regression — age is a continuous value. (d) classification — a finite decision {pick up, do not pick up}.
