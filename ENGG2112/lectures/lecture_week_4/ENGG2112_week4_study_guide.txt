SECTION 1: Data Pre-Processing Overview
------------------------------------------------
**Data pre-processing** (data cleaning) turns a raw table of rows and columns into something an algorithm can learn from. In the lecture's table, columns are **features** (the inputs, $K$ of them) and the target is the **label**. The workflow is a sequence of decisions made before training.

- **Importing data:** load the table (CSV/Excel) into a pandas DataFrame.
- **Missing data:** some cells are blank because the data was not recorded properly.
- **Data types:** features may be numeric or categorical; signals may be long time series.
- **Class balance:** one class may vastly outnumber another.
- **Scale:** features may have wildly different numeric ranges.

💡 **Why It Matters:** The lecture's theme is "Let's keep it clean!" Pre-processing decides whether a model generalises or silently learns from noise and missingness.

```text
Import → Clean → Engineer Features → Encode → Balance → Train → Validate → Test
```

------------------------------------------------
SECTION 2: Missing Data Handling
------------------------------------------------
Loading a file with pandas converts any missing entry to **NaN (Not a Number)**. A danger is that NaN is frequently treated as zero during summing and averaging, which may or may not be sensible.

- `isna` reports missing entries (its opposite is `notna`).
- `dropna` removes any row containing missing data.
- `fillna` fills missing values by a chosen method.

### Strategies
- **Drop the row** with `dropna()` — simple, but you lose data, possibly including a rare class.
- **Fill with a constant** via `fillna()` — e.g. filling NaN in a `Power(kW)` column with `200`.
- **Forward fill** — carry the last known value forward.
- **Backward fill** — carry the next known value backward.

⚠️ **Common Trap:** Filling a power reading with `200` assumes every missing reading really was 200 kW, which is probably wrong. Forward fill assumes the signal did not change since the last reading — better for steady signals.

### Other Pre-Processing
Engineering data often arrives as **signals measured at regular time intervals**, and important information is often in the **frequency domain**, where class differences appear as frequency artefacts.

- It is common to **transform between time and frequency domain** using the **Fourier transform** (or another transform).
- A long sequence is broken into short, appropriately sized **windows**.
- Extracting dominant features from signals is described as "more an art than a science".

------------------------------------------------
SECTION 3: Feature Engineering and Selection
------------------------------------------------
**Feature engineering** turns raw, high-dimensional data into informative, lower-dimensional inputs. The lecture stresses it is often **the step that takes the most time in an ML project**.

| Technique | What it does |
|---|---|
| Feature Selection | Picks the best inputs, i.e. highest correlation with the output |
| Variance Threshold | Removes nearly-constant features |
| Decision Tree / Random Forest first | Trains a tree model to reveal which features separate classes |
| PCA (Principal Component Analysis) | Projects data onto directions of maximum variance |
| Manual feature engineering | Uses human insight into the data |

💡 **Why It Matters:** Good features beat fancy models, and reducing dimensionality speeds every later step.

------------------------------------------------
SECTION 4: Imbalanced Datasets
------------------------------------------------
When one class is far more prevalent, training is skewed. **This is called imbalanced data**, and the trained model becomes optimised for the majority case.

- If 95% of the data is "blue" and the metric is **accuracy**, a model can output "blue" regardless of input and still score 95%.
- It is not learning — it is exploiting the metric, so imbalance must be handled deliberately.

**Accuracy** = fraction of predictions correct — misleading when one class dominates, because a trivial "always majority" model scores high.

### Resampling Methods
- **Oversampling the minority** — replicate minority samples or synthesise new ones with **SMOTE (Synthetic Minority Oversampling Technique)**.
- **Undersampling the majority** — discard some majority samples.

### Other Approaches
- **Cost-Sensitive Learning** — assign higher penalties to costly errors during training.
  - Define a new **loss function** reflecting the relative costs of a **false positive (FP)** and a **false negative (FN)**.
  - The model **shifts its decision boundary** to reduce the more expensive error.
  - Goal: **minimise overall cost**, not just accuracy.
- **Data augmentation** — create synthetic but realistic minority-class data.

🧠 **Memory Hook:** **SMOTE = Synthetic Minority Oversampling TEchnique** — it makes *new* minority points, not just copies.

------------------------------------------------
SECTION 5: One-Hot Encoding
------------------------------------------------
Many features are not numbers (airport names, airlines, gender), yet most ML algorithms expect numerical inputs (otherwise you cannot multiply, etc.). **One-hot encoding** is the most basic conversion.

1. Find how many values the categorical variable can take — call it $M$.
2. Create $M - 1$ "dummy" 0/1 variables, with a 1 in the position for the category.

### Worked Encoding: Gender
Suppose Gender has values **Male / Female / Not Given** and we want to estimate shop spending.

- Generate $x_1$ for Male and $x_2$ for Female.
- No third dummy is needed, because $x_1 = x_2 = 0$ already means Not Given.

| Customer | $x_1$ | $x_2$ | Meaning |
|---|---|---|---|
| 1 | 1 | 0 | Male |
| 2 | 1 | 0 | Male |
| 3 | 0 | 1 | Female |
| 4 | 0 | 1 | Female |
| 5 | 0 | 0 | Not Given |

**Question:** could we assign 0 to Male, 1 to Female, 2 to Unknown? **Answer:** No — it would be risky and imply an **ordinal relationship** (Male < Female < Unknown), which is meaningless.

⚠️ **Common Trap:** Using $M$ dummies makes one column perfectly predictable from the others (the **dummy variable trap**). Never give a label-encoded 0,1,2 category to a linear model, SVM, or neural network — they read the numbers as distances.

### Python
- `sklearn.preprocessing.OneHotEncoder` returns a NumPy array, convertible to a DataFrame.
- pandas can also build a DataFrame with one-hot columns.

SECTION 6: Probabilistic Foundations
------------------------------------------------
Classical ML starts from probability. Assume we don't know the true relationship between input $x$ and output $y$ (otherwise the model would already be known!). For a given $x$, the output $y$ has some chance of taking each value — e.g. if $x$ is "The quick brown fox", then $P[y = \text{"jumps"} \mid x] = 0.4$, $P[y = \text{"walks"} \mid x] = 0.1$, $P[y = \text{"is"} \mid x] = 0.05$.

**Maximum a posteriori (MAP) detection** answers "which output would we pick?": choose the $y$ that maximises $P[y \mid x]$.

- For **discrete $y$ (classification)**, MAP minimises decision error, i.e. it **maximises accuracy**.
- **Bayes' rule** computes it: $P(y \mid x) = \dfrac{P(x \mid y)\,P(y)}{P(x)}$.
- For a fixed observed $x$, the denominator $P(x)$ is a normalising constant, so we compare only $P(x \mid y)P(y)$ across labels.

💡 **Why It Matters:** Probabilistic thinking shaped AI. **Naïve Bayes** is MAP detection with simplifying assumptions, and the "soft" outputs of **softmax** are another indirect manifestation.

### Where Does P(x | y) Come From?
1. **A physical model.** Over a noisy channel, a bit 0/1 is received as 0/1 with probability of bit error $p$, i.e. $P[0 \text{ received} \mid 1 \text{ transmitted}] = P[1 \text{ received} \mid 0 \text{ transmitted}] = p$. If $p$ is measured, we have the conditional distribution.
2. **Learned from training data.** Often no simple model matches reality — especially when mimicking cognition, where we don't understand the process well enough. Hence general AI/ML models that "sort of" work.

------------------------------------------------
SECTION 7: Gaussian Naïve Bayes
------------------------------------------------
Assume $K$ features $x_1,\dots,x_K$ and one discrete label $y$. Bayes' rule gives $P(y \mid x_1,\dots,x_K) \propto P(x_1,\dots,x_K \mid y)\,P(y)$.

- The denominator is irrelevant (a normalising constant).
- $p(y)$ is found from training data.
- But the **joint** $p(x_1,\dots,x_K \mid y)$ is hard: with binary features there are $2^K$ frequencies to estimate, and there is usually not enough data.

### The Two "Naïve" Assumptions
1. **Conditional independence** — features are independent given the label:
   - $p(x_1,\dots,x_K \mid y) = \prod_{i=1}^{K} p(x_i \mid y)$, a product of 1-D densities instead of one K-dimensional joint.
2. **Gaussian features** — each $p(x_i \mid y)$ is Gaussian.
   - A Gaussian is fully specified by its **mean** $\mu_{i,y}$ and **variance** $\sigma^2_{i,y}$, so finding those for each feature and class gives the distribution.

```text
p(x_i | y) = K · exp( − (x_i − μ_{i,y})² / (2 σ²_{i,y}) )
```

### Training and Inference
- **Training:** estimate each feature's conditional mean and variance per class. These are the **parameters**.
- **Inference:** for each class, combine $p(y)$ with the product of per-feature Gaussians and pick the maximiser.
- Structure depends only on $K$ and the number of classes, so Gaussian NB has **no hyper-parameters**.

### Worked Means Example
With $y \in \{0,1\}$ and two features:

| $y$ | $x_1$ | $x_2$ |
|---|---|---|
| 0 | 0.2 | 0.9 |
| 0 | −0.6 | 1.2 |
| 1 | 2.4 | −1.0 |
| 1 | 3.1 | −0.6 |
| 1 | 2.8 | −1.4 |

The conditional means are $\mu_{1,0} = -0.2$, $\mu_{2,0} = 1.05$, $\mu_{1,1} = 2.77$, $\mu_{2,1} = -1.0$. Variances are estimated from the data the same way.

### Python
```python
from sklearn.naive_bayes import GaussianNB
nb = GaussianNB()                 # name the model
nb.fit(X_train, y_train)          # train
y_pred = nb.predict(X_test)       # predict
probs = nb.predict_proba(X_test)  # P(y|x)
```

💡 **Why It Matters:** Gaussian NB is fast, needs no tuning, and is a strong baseline — but if features are highly correlated the independence assumption makes its probability estimates poor.

SECTION 8: Random Forest Basics
------------------------------------------------
Unlike Gaussian NB, the Random Forest comes from a **computer-science** perspective, built on the **decision tree**:

- At each level we ask a question that splits the data into two parts.
- Traversing from the top (**root**) to the bottom (**leaf**) yields the leaf's final decision.
- A **random forest** runs several trees in parallel and takes a **majority decision**.

### The Ideal Split and the Criterion
The ideal split puts only one class label on each branch — then no further splitting is needed. We look for the feature and threshold closest to that ideal, measured by the `criterion`:

- **Gini impurity** — how mixed the classes are in a node; lower is purer.
- **Entropy** — the information-theory version.

### Parameters vs Hyper-Parameters
- **Set by us humans (hyper-parameters):** `max_depth` (maximum tree depth), `max_features` (features considered per node), `criterion` (splitting quality measure), `n_estimators` (number of trees).
- **Optimised by the machine (parameters):** which feature to split on at each node, and the threshold at each node.

### Python
```python
from sklearn.ensemble import RandomForestClassifier
RF = RandomForestClassifier(n_estimators=100, max_depth=5)
RF.fit(X_train, y_train)
y_pred = RF.predict(X_test)
```

💡 **Why It Matters:** Random Forest is a robust off-the-shelf classifier. `max_depth` too large lets trees memorise; `max_features` controls how many candidate features each split may inspect.

------------------------------------------------
SECTION 9: Random Forest Randomisation
------------------------------------------------
A single tree may **overfit** — excelling on training data but failing to generalise. The Random Forest avoids this with many trees, each **randomised** so it differs from the others:

- **Bagging (bootstrap sampling):** each tree trains on a different resampled dataset.
- **Random feature subsets at each split:** every node investigates only $m$ of $p$ features, chosen randomly and independently.

The randomisation stops trees turning out the same and defeating the purpose of having many. The lecture calls this "rather clever!"

```text
Bootstrap sample → grow tree on random feature subsets → repeat T times → majority vote
```

⚠️ **Common Trap:** Bagging samples **rows** with replacement; random feature subsets sample **columns** at each node. Random Forest does **both**.

------------------------------------------------
SECTION 10: K-Nearest Neighbours
------------------------------------------------
**K-Nearest Neighbours (KNN)** classifies a new point by looking at the nearest training points. We have $N$ samples $(x_i, y_i)$, $i=1,\dots,N$, where the $y_i$ are **class labels** and the $x_i$ are **feature vectors** (in the example two-dimensional, e.g. "bee," "cat," "dragonfly").

### The Algorithm
1. Set parameter $K$ to an odd value, say 5 (avoids ties).
2. Denote training vectors $x_i^m$, where $m \in \mathcal{M}$ is the class label and $i$ the sample index.
3. For a new vector $x$, compute all $N$ distances: $d_i(x) = \| x - x_i^m \|_2$, $i=1,\dots,N$.
4. Sort smallest to largest, note the $K$ smallest and their labels.
5. Output the class label with the highest count.

### Choice of K
- In the example, $K=3$ gives "triangle" but $K=5$ gives "square".
- There is **no formulaic way** to choose $K$ for a dataset.
- $K$ does **not** affect computational complexity (all $N$ distances are always computed) but **does** affect accuracy. Complexity grows with $N$, so avoid "too many" training samples.

### Distance Measures
Distances need not be **L2 (Euclidean)**; they may be **L1 (Manhattan)**, **Hamming** (= number of positions where two vectors differ), etc.

⚠️ **Common Trap:** Always normalise features before KNN (Section 12), or one large-scale feature dominates every distance.

------------------------------------------------
SECTION 11: Weighted KNN and Probability
------------------------------------------------
KNN has an imbalanced-data problem: if 90% of training points are class 0 and 10% class 1, the vote is biased. If the test point is the yellow triangle, it may look like it sits in the orange class, yet KNN returns **blue** because there are more blue neighbours. The fix is to **give nearer neighbours higher weight**.

### Weighted Nearest Neighbour (WNN)
1. Find the $K$ closest points and their distances $d_i(x)$, $i \in \mathcal{I}_K(x)$ (the K indices with smallest distance).
2. Group by class. For class $n$, compute $N_n = \sum_i \dfrac{1}{d_i(x)}$, summing only over class-$n$ points.
3. Output the value of $n$ that **maximises** $N_n$.

### Worked Example
With $K = 5$:

| Point | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| Class | 0 | 0 | 1 | 1 | 1 |
| Distance | 0.5 | 0.4 | 1.0 | 0.8 | 1.5 |
| Inverse | 2.0 | 2.5 | 1.0 | 1.25 | 0.67 |

- **KNN:** $N_0 = 2$, $N_1 = 3$ ∴ output class = 1.
- **WNN:** $N_0 = 2 + 2.5 = 4.5$, $N_1 = 1 + 1.25 + 0.67 = 2.92$ ∴ output class = 0.

WNN flips the answer because the closer class-0 points earn larger weights.

### Probability Estimates
We want $P[C_i \mid x]$ — the **conditional probability** of class $C_i$ **given** features $x$. In KNN and WNN:

```text
P[C_i | x] = N_i / Σ_k N_k
```

where $N_i$ is the weighted or unweighted neighbour count for class $C_i$.

- **WNN:** $P[C_0 \mid x] = 4.5/(4.5+2.92) = 0.606$ and $P[C_1 \mid x] = 0.394$.
- **KNN:** $P_{knn}[C_0 \mid x] = 2/5 = 0.4$ and $P_{knn}[C_1 \mid x] = 3/5 = 0.6$.

ℹ️ **Note:** Another classifier gives different estimates again; it is hard to argue one is more accurate — these are estimates, not ground truth.

------------------------------------------------
SECTION 12: Feature Normalisation
------------------------------------------------
One feature's dynamic range may be vastly different from another:

1. Engine capacity (cc) versus model year.
2. Age (years) versus height (cm).
3. Bit rate (bps) versus transmitted power (mW).

Raw distance is then dominated by the larger-range feature, so we **normalise to a standard scale**. **Min-max normalisation** maps values to [0,1]:

```text
x' = (x − min) / (max − min)
```

The slides note this is implemented in scikit-learn's preprocessing module (named `sklearnnormalize`; the standard equivalent is `MinMaxScaler`).

### KNN and WNN in Python
```python
from sklearn.neighbors import KNeighborsClassifier
knn = KNeighborsClassifier(n_neighbors=5)                     # KNN
wnn = KNeighborsClassifier(n_neighbors=5, weights="distance") # WNN
knn.fit(X_train, y_train)
y_pred = knn.predict(X_test)
```

### KNN/WNN in the General ML Model
- A model is a function $f_\theta(x)$ outputting a class label, where $\theta$ is the parameter vector.
- In KNN/WNN there are **no obvious parameters to optimise**; the training data creates decision regions.
- The **decision boundaries** (borders between regions) can be considered the "parameters".
- $K$ is a **hyper-parameter** shaping the model. Hyper-parameters are **not learned or updated** during optimisation — they are fixed before training and set the architecture.

⚠️ **Common Trap:** With KNN, "training" mostly means storing the data; all the work happens at prediction time.

------------------------------------------------
SECTION 13: Validation and Testing
------------------------------------------------
After training, judge the model on labelled data **not** used in training — and remember validation and testing are different.

- **Training** fits the model parameters.
- **Validation** judges how good the current model is; hyper-parameters and even the model are adjusted in a **training–validation cycle** until the designer is satisfied.
- **Testing** is the final step on data used at no earlier stage.

### Cross-Validation
Validation is often **averaged over multiple splits**, called **cross-validation**.

- Most commonly, **K-fold cross-validation**: train on $K-1$ folds, validate on the held-out fold, repeat so every fold is validated once.
- For imbalanced data use **stratified** K-fold so each fold keeps class proportions.

```python
from sklearn.model_selection import StratifiedKFold
cv = StratifiedKFold(n_splits=5)
```

### Testing After Validation
- The performance of the validated model on the **test set** is what should be reported.
- This estimates performance **after deployment**, on data unseen in training or validation.

⚠️ **Common Trap:** A single validation split has high variance; K-fold averaging is far more stable. And if you tune on the test set, it is no longer an honest estimate.

------------------------------------------------
SECTION 14: Scikit-Learn ML Workflow
------------------------------------------------
Almost every supervised model in `sklearn` follows the same five steps:

1. **Create an object** of the algorithm class, setting its hyper-parameters.
2. **`fit`** to train the model.
3. **`predict`** to estimate test-sample classes.
4. **`predict_proba`** to estimate each class's probability given the features.
5. **Test accuracy** using one or more `metrics`.

```text
Create object → .fit(X_train, y_train) → .predict(X_test) → .predict_proba(X_test) → metrics
```

💡 **Why It Matters:** This uniform interface lets you swap Gaussian NB, Random Forest, or KNN by changing only the class name and hyper-parameters.

⚠️ **Common Trap:** `predict` returns hard labels; `predict_proba` returns per-class probabilities. Accuracy uses labels; thresholding and cost-sensitive decisions need probabilities.

------------------------------------------------
KEY TAKEAWAYS
================================================
1. **Pre-processing is not optional** — missing values, differing scales, categorical variables, and class imbalance silently break a model if ignored.
2. **Handle missing data deliberately** — pandas turns blanks into NaN; `isna`/`notna` find them, `dropna` removes rows, `fillna` (forward/backward) replaces them.
3. **Feature engineering often matters more than model choice** — use feature selection, variance threshold, tree-based importance, PCA, and domain features.
4. **Imbalanced data fools accuracy** — a 95% majority lets a trivial model score 95%; fix with oversampling (SMOTE), undersampling, cost-sensitive learning, or augmentation.
5. **One-hot encoding uses M − 1 dummies** — the last category is implied by all-zero dummies; 0,1,2 encoding falsely implies ordering.
6. **MAP detection is the probabilistic core** — choose the label maximising $P(y \mid x)$; $P(x)$ is a constant, so only $P(x \mid y)P(y)$ matters.
7. **Gaussian NB = MAP + two assumptions** — conditional independence and Gaussian features; it has parameters (means, variances) but no hyper-parameters.
8. **Decision trees split toward purity** — the `criterion` (Gini impurity or entropy) measures closeness to one class per branch.
9. **Random Forest = many randomised trees** — bagging (bootstrap rows) plus random feature subsets decorrelate trees, combined by majority vote.
10. **KNN votes among the K nearest neighbours** — K has no formulaic best value, affects accuracy but not computational complexity; distances can be L2, L1, or Hamming.
11. **Weighted KNN uses inverse-distance weights** — $N_n = \sum 1/d_i$ over class-$n$ neighbours, fixing the imbalance bias.
12. **Normalise, then validate before testing** — min-max scaling stops one feature dominating distance, and stratified K-fold CV tunes the model before the test set is touched once.

CONCRETE EXAMPLES / WORKED SCENARIOS
================================================
### Example 1: One-Hot Encoding Gender
Gender has three categories (M = 3), so create 2 dummies: $x_1 = 1$ for Male, $x_2 = 1$ for Female. Customers 1–2 male → (1,0); 3–4 female → (0,1); 5 unknown → (0,0). Assigning 0/1/2 instead would imply Male < Female < Unknown — meaningless — so the dummies feed regression or classification.

### Example 2: Gaussian NB Means
With $y \in \{0,1\}$: class 0 rows (0.2, 0.9), (−0.6, 1.2) give $\mu_{1,0} = (0.2-0.6)/2 = -0.2$ and $\mu_{2,0} = (0.9+1.2)/2 = 1.05$. Class 1 rows (2.4, −1.0), (3.1, −0.6), (2.8, −1.4) give $\mu_{1,1} = (2.4+3.1+2.8)/3 = 2.77$ and $\mu_{2,1} = (-1.0-0.6-1.4)/3 = -1.0$. A new point near (2.6, −0.9) sits closest to class 1's means, so Gaussian NB predicts class 1.

### Example 3: KNN versus Weighted KNN
With K = 5: two class-0 points at distances 0.4 and 0.5; three class-1 points at 0.8, 1.0, 1.5.
- **KNN** votes: class 0 = 2, class 1 = 3 → class 1.
- **WNN** sums inverse distances: $N_0 = 1/0.4 + 1/0.5 = 2.5 + 2.0 = 4.5$; $N_1 = 1/0.8 + 1/1.0 + 1/1.5 = 1.25 + 1.0 + 0.67 = 2.92$ → class 0.
The closer class-0 points outweigh the more distant class-1 points. Probabilities: WNN $P[C_0|x] = 4.5/7.42 = 0.606$, $P[C_1|x] = 0.394$; KNN $P[C_0|x] = 2/5 = 0.4$, $P[C_1|x] = 3/5 = 0.6$.

POTENTIAL EXAM FOCUS
================================================
1. Why is accuracy a poor metric on a 95%-majority dataset? → Answer: A model that always predicts the majority scores 95% while learning nothing, so it is optimised for the majority case.
2. Why does one-hot encoding use M − 1 dummies instead of M? → Answer: The last category is implied when all dummies are 0, so M − 1 suffice; all M creates redundancy (the dummy variable trap).
3. What is wrong with encoding categories as 0, 1, 2? → Answer: It implies a false ordinal relationship such as Male < Female < Unknown, which the model treats as real.
4. State the two assumptions of Gaussian Naïve Bayes. → Answer: Conditional independence lets the joint factorise into per-feature distributions; Gaussian features mean each is specified by a mean and variance.
5. Why can Gaussian NB ignore the Bayes' rule denominator? → Answer: For a fixed x, P(x) is a constant, so comparing P(x|y)P(y) across labels gives the same maximising y.
6. Why does Gaussian NB have no hyper-parameters? → Answer: Its structure depends only on the feature and class counts; training estimates only means and variances.
7. Parameter versus hyper-parameter in Random Forest? → Answer: Split feature and threshold are learned parameters; `max_depth`, `max_features`, `criterion`, `n_estimators` are set before training.
8. What two randomisations make Random Forest trees differ? → Answer: Bagging (bootstrap resampling of rows) and random feature subsets (each node investigates only m of p features).
9. Does K affect KNN's computational complexity? → Answer: No — all N distances are computed regardless; K affects accuracy, not distance cost.
10. How does Weighted KNN fix the imbalance problem? → Answer: Nearer neighbours get higher weight via inverse-distance summation, so a few close minority points can outweigh many distant majority points.
11. How are class probabilities estimated in KNN and WNN? → Answer: P[C_i|x] = N_i / Σ_k N_k, with N_i the weighted (WNN) or unweighted (KNN) count for class i.
12. Why normalise features before KNN, and what is the formula? → Answer: One large-range feature would dominate distance; min-max normalisation is x' = (x − min)/(max − min), mapping values to [0,1].
13. Difference between validation and testing? → Answer: Validation tunes hyper-parameters and chooses the model; testing reports final performance on data unseen before, estimating post-deployment behaviour.
