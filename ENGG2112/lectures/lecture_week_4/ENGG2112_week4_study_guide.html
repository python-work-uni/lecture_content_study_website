Clean the Data, Then Learn From It

Before any model can predict anything, the data has to be trustworthy. This week covers how to clean a raw table, then how three classical (non-neural-network) methods actually make predictions: Gaussian Naïve Bayes, Random Forest and K-Nearest Neighbours.

Read this first: Machine learning is a pipeline. Pre-processing decides what the model is allowed to see; the algorithm decides how it turns that into a decision. Most real-world failures happen in the first half — missing values, skewed classes, mismatched scales and text features — so this lecture spends just as long on cleaning as on modelling.

By the end you will be able to

The Big Picture

A model is only as good as the data you feed it, and the journey from a raw table to a trustworthy prediction has a fixed shape.

You already have the vocabulary: data lives in a table where each row is one sample and each column is one property. The columns you use as inputs are the features (the lecture counts K of them), and the column you want to predict is the label. A model is just a function that maps a row of features to a label or a number.

The lecture agenda lists a lot at once — data pre-processing (cleaning), stochastic gradient descent, and classical machine learning methods (K-Nearest Neighbours, random forest, naïve Bayes), plus training, parameters versus hyper-parameters, and Python implementation. Stochastic gradient descent is the optimisation engine that many models use to learn; it appears on the agenda as context, while this deck spends its time on cleaning data and the three classical classifiers.

Classical machine learning is the lecture's shorthand for everything but neural networks. The three methods below — Gaussian Naïve Bayes, Random Forest and K-Nearest Neighbours — are older, lighter and easier to reason about than deep networks, yet they still power real systems and they are the groundwork for the neural networks coming next week.

The pipeline you should picture

Every ML project follows roughly the same sequence. Notice how much of it happens before the model is trained — that is the whole point of "Let's keep it clean!".

Import data→ Handle missing values→ Engineer features→ Encode categories→ Balance classes→ Train→ Validate→ Test
💡
Why it matters: Garbage in, garbage out. A perfectly tuned classifier fed blank cells, lopsided classes and unscaled features will happily learn the wrong thing — and it will look successful while doing it.

Data Pre-Processing

Pre-processing is the deliberate set of decisions that turns a raw table into something an algorithm can actually learn from.

Recall that we have a table of data — rows of samples, columns of features or labels. Some items might be missing, some columns might be text, some might be enormous time-series signals. The lecture's framing question is blunt: what do we do? The answer is a checklist of fixes applied before training.

Data pre-processing — also called data cleaning: every transformation applied to raw data so that a learning algorithm receives usable inputs. It covers missing values, feature scaling, categorical encoding, class balance and signal handling. It is not optional polish; it changes what the model can learn.

🗂️ What "raw" looks like

  • Missing cells — data that was not recorded properly.
  • Categorical text — airport names, airlines, gender.
  • Signals — measurements at regular time intervals.
  • Class imbalance — one label dominates the table.
  • Mismatched scale — one feature spans thousands, another spans 0–1.

recall Features & labels

Each column is a feature (an input) except the one you predict, which is the label. If a table has K feature columns, a single sample is a vector of K numbers (once cleaned and encoded).

ℹ️
Key idea: Importing data is step one, but it is rarely clean. pandas is the tool of choice, and its default behaviour for a blank cell is important enough to have its own section next.

Handling Missing Data

Blank cells are the most common defect in real data, and the way you fill or drop them quietly shapes every prediction that follows.

When analysing real data, we very often encounter missing data: some cells are blank because the value was not recorded properly. You cannot just ignore them, because arithmetic on a blank is undefined. pandas solves this by giving every missing entry a marker.

NaN (Not a Number) — the placeholder pandas inserts for any missing value when it loads a file. It is a specific floating-point sentinel, not the number zero, but many operations treat it as if it were zero — for example summing or averaging a column may silently skip or zero-out NaNs. The lecture warns this "may or may not be sensible", so you must decide deliberately.

The pandas toolkit

FunctionWhat it doesWhen to use it
isna()Reports which entries are missing (returns True/False).To find the gaps before deciding.
notna()The exact opposite of isna() — True where data exists.To keep or count the valid entries.
dropna()Removes any row that contains a missing value.When a partial row is useless to you.
fillna()Replaces missing values with a chosen value or method.When the row still carries useful information.

Four strategies for a blank cell

  1. Drop the row. Call dropna() to ignore any row with missing data. Simple and safe, but you lose data — and if the blanks cluster in a rare class, you can delete exactly the examples you needed.
  2. Fill with a constant. Call fillna() with a fixed value. The lecture's worked example fills the NaN values in the Power(kW) column with 200.
  3. Forward fill. Carry the last known value forward into the gap — sensible for a signal that changes slowly.
  4. Backward fill. Carry the next known value backward into the gap.
⚠️
Common trap: Filling a power reading with 200 asserts that every missing reading really was 200 kW — usually false. Forward fill asserts the signal did not change since the last reading, which is better for steady signals but wrong across a sudden step. There is no free lunch; each choice is an assumption.
D · F · F
“Drop, Fill, Forward”
Drop the row, Fill with a constant, or Forward/backward Fill. (Add "Find" first — use isna/notna to locate the gaps.)

Signals & Feature Engineering

Raw signals are huge and awkward; feature engineering is the craft of squeezing the few numbers that actually separate the classes.

Engineering data often arrives not as tidy columns but as signals measured at regular intervals of time — vibration traces, voltages, audio. The important information is often not in the raw time-domain shape but in the frequency domain, where the main differences between two classes show up as frequency artefacts. So it is common to transform between the time domain and the frequency domain using the Fourier transform (or some other transform).

A long sequence is also broken into short, appropriately sized windows, because analysing the whole recording at once is both unwieldy and wasteful. The lecture is candid that extracting dominant features from signals to differentiate classes is "more an art than a science", and that using the entire signal is inefficient — we can often reduce dimensionality through feature engineering.

💡
Why it matters: Feature engineering is often the step that takes the most time in an ML project. Better features usually beat a fancier model, and fewer features make every later step faster.

Five ways to engineer features

TechniqueWhat it does
Feature selectionPicking the best inputs — looking for the highest correlation with the output.
Variance thresholdRemoving nearly-constant features, which carry almost no information.
Decision Tree / Random Forest firstUsing a tree model to reveal which features actually separate the classes during training.
PCA (Principal Component Analysis)Projecting the data onto new directions that capture maximum variance.
Manual feature engineeringUsing human insight into the data to construct meaningful new features.
Feature engineering — turning raw, high-dimensional data into informative, lower-dimensional inputs. It ranges from automatic methods (variance threshold, PCA) to purely human design based on domain knowledge.

Imbalanced Datasets

When one class vastly outnumbers the others, a model can score highly by learning nothing at all.

Sometimes one class is much more prevalent than the others, which skews training. This is called imbalanced data. The trained model becomes optimised for finding the majority case, because that is the cheapest way to reduce the average error.

⚠️
The classic example: if 95% of the data is "blue" and the performance metric is accuracy, a model can output "blue" for every single input and score 95%. It has learned nothing, yet it looks excellent. Therefore we need to prevent that.

This is why accuracy alone is a poor judge on imbalanced data. You have to change either the data or the cost of mistakes.

Resampling methods

  • Oversampling the minority class — replicate minority-class samples, or synthesise new ones. The lecture names SMOTE (Synthetic Minority Oversampling Technique).
  • Undersampling the majority class — discard some majority samples so the classes are more even.

Other ways to handle imbalance

⚖️ Cost-Sensitive Learning

  • Assign higher penalties to costly errors during training.
  • Define a new loss function that reflects the relative costs of a false positive (FP) and a false negative (FN).
  • The model adapts by shifting its decision boundary to reduce the more expensive error.
  • Goal: minimise overall cost, not just improve accuracy.

🧪 Data Augmentation

Create synthetic but realistic minority-class data. Unlike blind replication, augmentation aims to add genuinely new, plausible examples so the minority class is better represented.

S · M · O · T · E
“Synthetic Minority Oversampling TEchnique”
It makes new minority points, not just copies — and it fixes the imbalance by growing the small class rather than shrinking the big one.

One-Hot Encoding

Most algorithms can only multiply numbers, so text categories must become numeric — but the obvious way to number them is a trap.

Features may not be numerical: airport names, airlines, or a category like gender. Most ML algorithms expect numerical inputs though — otherwise you cannot multiply, add or compute distances. The most basic method for converting a categorical variable into a numeric representation is one-hot encoding.

  1. Count the categories. Look at how many values the categorical variable can take — call it M.
  2. Create M − 1 dummy variables. Each is a 0/1 column, with a 1 in the position corresponding to the category.
  3. Encode each row. A sample gets a 1 in its own dummy column, and 0 elsewhere; the leftover all-zeros row represents the final category.
Number of dummies
M categories → M − 1 dummy 0/1 variables

Worked example: encoding Gender

Suppose Gender is one of the features and its allowable values are Male / Female / Not Given. The problem is to estimate the amount spent in a given shop, using gender as one of the features. Because M = 3, we generate two dummy variables, x_1 for Male and x_2 for Female. There is no need for a third dummy, because x_1 = x_2 = 0 already means Gender is in the third category (Not Given).

In the lecture's table, customers 1 and 2 are male, 3 and 4 are female, and 5 is unknown:

Customerx_1 (Male)x_2 (Female)Meaning
110Male
210Male
301Female
401Female
500Not Given

With this, we can now perform regression or classification using the new dummy variables.

⚠️
The lecture's question: could we simply have assigned 0 to Male, 1 to Female and 2 to Unknown? Answer: No — that would be risky and imply an ordinal relationship between the genders, i.e. Male < Female < Unknown. A model reading those numbers as distances would treat "Unknown" as more than "Female", which is meaningless.
ℹ️
Dummy variable trap: using all M dummies makes one column perfectly predictable from the others (it is redundant). Dropping one category — the M − 1 rule — avoids the redundancy, and the omitted category is recovered from the all-zero row.

Probability Foundations

Underneath every classifier is one question: given what I have seen, which output is most probable?

Classical machine learning starts from probability. Assume we don't know the relationship between the input x and the output y — otherwise the model would already be known! For a given input x, there is some chance that the output y takes a certain value.

Consider the lecture's language example: x encodes the words "The quick brown fox", and y is the next word in the sentence. We might have:

Conditional probabilities of the next word
P[y = "jumps" | x] = 0.4  ·  P[y = "walks" | x] = 0.1  ·  P[y = "is" | x] = 0.05

If we knew these conditional probabilities, which output y would we choose if forced to choose only one? Clearly, a detector that knows P[y | x] can output the y that maximises this function. In detection theory this is known as the maximum a posteriori (MAP) detector.

Maximum a posteriori (MAP) detector — the rule that outputs the label y which maximises the posterior probability P[y | x]. For discrete y (classification), MAP minimises the probability of making a decision error — that is, it maximises accuracy.
MAP decision rule
ŷ = argmax_y P(y | x)

Bayes' rule: how to compute it

The posterior is computed from the likelihood, the prior and a normalising constant:

Bayes' rule
P(y | x) = P(x | y) · P(y) / P(x)

For a fixed observed x, the denominator P(x) is the same for every candidate label, so it is just a normalising constant — we can compare only P(x | y) · P(y) across labels and pick the largest.

Where does P(x | y) come from?

Either it must be learned from training data, or derived mathematically from knowledge or assumptions about the system being modelled.

From a physical model

Consider transmitting a bit over a noisy channel. The bit value is 0 or 1 and is received as 0 or 1, but there is a probability of bit error p:

P[0 received | 1 transmitted] = P[1 received | 0 transmitted] = p

If p is known through measurements, we already have the required conditional distribution.

Learned from data

In many applications — especially those mimicking human cognitive ability — we don't understand the underlying process well enough to design a simple, accurate model.

That is why we have general AI/ML models that (sort of) work in many scenarios, and learn P(x | y) from training data instead.

💡
Did probability shape AI design? Short answer: yes. It is applied explicitly in the Naïve Bayes model, which is basically computing the MAP decision with several major simplifying assumptions. It is manifested indirectly in the "soft" outputs created by the softmax function — a function that turns a model's raw scores into probabilities that sum to 1. The long answer is more nuanced: AI/ML was also developed from a computer-science algorithms angle, as we will see with random forest and K-Nearest Neighbours — but even those are designed to output probabilities.
🤔
Pause & predict: If two next words have posteriors 0.4 and 0.35, what does MAP pick? Does the value of the denominator P(x) change your answer?

Gaussian Naïve Bayes

Gaussian Naïve Bayes is MAP detection made practical by two bold assumptions that collapse an impossible estimation problem into simple averages.

Assume K features x_1, …, x_K and one discrete label y — this is a classification problem. Bayes' rule applied here says the posterior is proportional to the likelihood times the prior. For a given vector of observed features, we want to calculate the distribution of the label y and then pick the value that maximises it. The denominator is irrelevant (just a normalising constant), and p(y) can be found from the training data.

The hard part is p(x_1, …, x_K | y), the joint distribution of the features given the label. In theory we would have to estimate the relative frequency of every possible feature combination. If the features are binary, there are 2^K such relative frequencies — and there is usually not enough data to get good estimates. That is the wall Naïve Bayes breaks through.

The two "naïve" assumptions

assumption a Conditional independence

All features are conditionally independent given the label. This lets the joint factorise into a product of one-dimensional pieces:

p(x_1, …, x_K | y) = ∏_{i=1}^{K} p(x_i | y)

So instead of one enormous K-dimensional distribution, we only need K simple ones.

assumption b Gaussian features

Each individual conditional feature distribution p(x_i | y) is Gaussian. A Gaussian is fully specified by its mean and variance, so finding those for each feature conditioned on y gives us its distribution.

Gaussian conditional density
p(x_i | y) = K · exp( −(x_i − μ_{i,y})² / (2 σ²_{i,y}) )

Here μ_{i,y} and σ²_{i,y} are the mean and variance of feature i conditioned on class y, and the leading constant (written K on the slide) is just the normalising factor — not the number of features.

Worked example: estimating the means

For each class y ∈ S_y, find the mean and variance of each corresponding feature. If y ∈ {0, 1}, we may have:

Conditional variances can be estimated from the data too. Thus we have the Gaussian distributions needed for inference.

Training, parameters and Python

  • Training: from the training data, estimate the conditional means and variances of every feature conditioned on each class label. These are the parameters of the Gaussian NB model.
  • No hyper-parameters: the structure of the Gaussian NB model is entirely determined by the number of features and the number of classes the label can take — there is nothing for a human to tune.
✅
The scikit-learn pattern: from sklearn.naive_bayes import GaussianNB, then nb = GaussianNB() to name the model, nb.fit(X_train, y_train) to train on training data, and y_pred = nb.predict(X_test) to generate predictions from test data. That's it really — in scikit-learn, almost all ML models are trained using <xyz>.fit and make inference using <xyz>.predict, where <xyz> is your model's name. On first definition, <xyz> needs the right hyper-parameter values — in Gaussian NB there happen to be none.
💡
Why it matters: Gaussian NB is fast, needs no tuning and is a strong baseline. But if features are strongly correlated, the independence assumption is false and its probability estimates become poor — it may still classify well while its probabilities mislead you.

Random Forests

A Random Forest grows many deliberately different decision trees and lets them vote — a computer-science idea that beats any single tree.

Unlike Gaussian Naïve Bayes, the random forest is a model derived from a computer-science perspective. It is built on the concept of a decision tree.

The decision tree concept

  • At each level of the tree, we ask a question that splits the data into two parts.
  • For a given data sample, traversing the whole tree from the top (root) to the bottom (leaf) yields the final decision at the leaf node.
  • In a random forest, we run a number of trees in parallel, then take a majority decision.

Specifications: who sets what

Hyper-parameters — set by us humans

  • max_depth — the maximum depth (number of levels) of the tree.
  • max_features — how many features to choose from at each node.
  • criterion — the quality measure used in splitting.

Parameters — optimised by the machine

  • Which feature to split on at each node.
  • The threshold value to use for the split at each node.

The main idea: at each node, the ideal split results in only one class label per branch — in that case, no further splitting is needed. We just need to find which feature and which threshold would bring us as "close" to that ideal as possible. The measure of closeness is the criterion hyper-parameter — either a Gini impurity or entropy. The lecture illustrates this in class with a worked example.

ℹ️
Two criteria, one job: both Gini impurity and entropy measure how mixed the classes are in a node. Lower is purer. Gini comes from probability, entropy from information theory — in practice they often give similar trees.

Randomisation is key

The problem with relying on a single tree is that it may overfit the training data — performing very well on the training data but failing to generalise. A random forest avoids this by using many decision trees, each one randomised (and so different from the others) in two ways:

  • Bagging (bootstrap sampling) — each tree trains on a different resampled dataset.
  • Random feature subsets at each split — every node is allowed to investigate only m out of p features, chosen randomly and independently.

The randomisation prevents different trees from turning out the same as each other, which would defeat the purpose of introducing multiple trees. The lecture calls this "rather clever!".

BAG · FS
“Bag rows, subset features”
Bagging samples rows with replacement; random feature subsets sample columns at each node. Random Forest does both.

Random Forest in Python

Create the model with your chosen hyper-parameters, fit it, then predict:

✅
from sklearn.ensemble import RandomForestClassifier
RF = RandomForestClassifier(n_estimators = 100, max_depth = 5)
RF.fit(X_train, y_train) → train with training data
Y_pred = RF.predict(X_test) → infer labels on test data
Then compute performance, plot charts, etc.

Here n_estimators = 100 means 100 trees, and max_depth = 5 caps each tree at 5 levels.

K-Nearest Neighbours

KNN classifies a new point by asking its K closest training neighbours to vote — no equation, just proximity.

We have N training samples (x_i, y_i) for i = 1 … N. The y_i are class labels: they take on a limited number of possible values. In the lecture's illustration, each point belongs to a category such as "bee," "cat," or "dragonfly." The x_i are feature vectors; in this case each has two dimensions, so we can represent them on a 2D Cartesian plane.

The algorithm, step by step

  1. Set the parameter K to an odd value, say 5 — an odd K avoids tied votes.
  2. Denote the training feature vectors by x_i^m, where m ∈ M is the class label (or category) and i is the sample index.
  3. For a new feature vector x, compute the N distances, where N is the number of training data records.
  4. Sort from smallest to largest, and note the K smallest values and their class labels.
  5. The classifier output is the class label with the highest count.
Distance from the new point to each training point
d_i(x) = ‖x − x_i^m‖₂,  i = 1, …, N

Choosing K (and why it is fiddly)

  • In the illustrated example, when K = 3 the classifier output is "triangle"; but when K = 5 the output is "square". The same test point flips class depending on K.
  • Choice of K is important, but there is no formulaic way to choose it well for any given data set.
  • K does not impact computational complexity — we always have to compute all N distances. It does impact classifier accuracy.
  • As complexity grows with N, it is best not to use "too many" training samples.

Distance need not be Euclidean

The distance measure need not be L2 (Euclidean). It may also be Hamming distance (= the number of positions where two vectors differ), L1, etc. Your choice of distance defines what "near" means.

⚠️
Common trap: KNN is sensitive to feature scale, because raw distance is dominated by whichever feature has the largest numeric range. Always normalise before KNN — see the Feature Normalisation section.

Weighted KNN & Probabilities

Plain KNN lets many far-away majority points outvote a few very close minority points; weighting by distance fixes that bias.

KNN has an imbalanced-data problem: one class can dominate the training set. For example, 90% of the training data may be class 0 and only 10% class 1. Suppose the test feature is the yellow triangle — though visually it looks like it sits in the orange class, KNN may return an output of blue, simply because there are more blue neighbours around it.

The solution: give nearer neighbours higher "weight" in the count. That is Weighted Nearest Neighbour (WNN).

Weighted Nearest Neighbour, precisely

  1. Find the K training points closest to the test point and their distances to the test point, d_i(x) for i ∈ I_K(x), where I_K(x) is the set of K training indices having the smallest distance to x.
  2. Group those K points according to class. For class n, compute the sum of inverse distances — summing only over the points in class n.
  3. The classifier output is the value of n that maximises N_n.
Weighted neighbour score for class n
N_n = Σ_{i ∈ class n} 1 / d_i(x)

Worked example (K = 5)

Suppose K = 5, and the distances from the test point to the 5 nearest neighbours are as follows:

Point12345
Class00111
Distance0.50.41.00.81.5
Inverse of distance2.02.51.01.250.67
  • KNN: N_0 = 2; N_1 = 3 ∴ output class = 1.
  • WNN: N_0 = 2 + 2.5 = 4.5; N_1 = 1 + 1.25 + 0.67 = 2.92 ∴ output class = 0.

The closer class-0 points earn larger weights, so WNN flips the answer to class 0 — even though class 1 has more neighbours.

Turning neighbours into probabilities

We are also interested in the probability that a given input belongs in each possible class. More formally, we would like to know P[C_i | x], where C_i denotes the i-th class and x is the vector of input features. This is read as "the probability of the correct class being C_i given that the observed features are x". It is what is called a conditional probability. In both KNN and WNN we can argue that:

Class probability estimate
P[C_i | x] = N_i / Σ_k N_k

where N_i is either the weighted or unweighted count of the nearest neighbours in class C_i.

Continuing the worked example, the WNN estimates are P[C_0 | x] = 4.5 / (4.5 + 2.92) = 0.606 and P[C_1 | x] = 0.394. The KNN estimates of the same events are P_{knn}[C_0 | x] = 2/5 = 0.4 and P_{knn}[C_1 | x] = 3/5 = 0.6.

ℹ️
These are estimates, not truth. If we use some other classifier, the estimated probabilities will be different again, and it is hard to argue that one result is more accurate than another. The value of KNN/WNN probabilities is that they are cheap and intuitive, not that they are calibrated.

Feature Normalisation

When one feature spans thousands and another spans single digits, distance-based models only hear the loud one.

Another problem is that the dynamic range of one feature may be vastly different from that of another. The lecture's examples:

  1. Engine capacity (in cc) versus model year.
  2. Age (in years) versus height (in cm).
  3. Bit rate (in bps) versus transmitted power (in mW).

In each pair the units and magnitudes are wildly mismatched, so a raw distance calculation would be dominated by the larger-range feature. So we should normalise to a standard scale, e.g. min-max normalisation.

Min-max normalisation
x′ = (x − min) / (max − min)

This maps the original values to a new range, usually between 0 and 1. The lecture notes the function preprocessing.sklearnnormalize implements this normalisation algorithm. In modern scikit-learn the equivalent is the preprocessing.MinMaxScaler.

⚠️
Common trap: fit the scaler on the training set only, then apply the same min and max to validation and test data. If you compute the range over all data, information leaks from test into training.

KNN and WNN in Python

In sklearn, we can easily execute KNN and WNN using the KNeighborsClassifier function. The workflow is always: import the required libraries, define the classifier object, then fit the model on training data and test it on test data.

✅
from sklearn.neighbors import KNeighborsClassifier
knn = KNeighborsClassifier(n_neighbors = 5) → plain KNN
wnn = KNeighborsClassifier(n_neighbors = 5, weights = "distance") → weighted KNN
knn.fit(X_train, y_train) then knn.predict(X_test)

Parameters vs Hyper-Parameters

One set of numbers is learned by the machine; the other is chosen by you before learning starts — mixing them up is a classic exam slip.

Remember that an ML model is a function f_θ(x) that outputs the class label corresponding to the input variables x, where θ is the parameter vector.

In KNN and WNN, there are no obvious parameters to optimise. Instead, the training data is used to create decision regions, and we can consider the decision boundaries (the borders between adjacent decision regions) to be the "parameters". The parameter K (number of nearest neighbours) is a hyper-parameter that determines the exact form of the model.

Hyper-parameters — values that are not learned or updated during the optimisation process. They are set before training begins, and are fixed values that determine the overall architecture and behaviour of the model. Examples: K in KNN, max_depth and n_estimators in a Random Forest.
Parameters — values learned from the training data during fitting. Examples: the means and variances in Gaussian NB, or the split feature and threshold at each Random Forest node.
ModelParameters (learned)Hyper-parameters (chosen)
Gaussian NBConditional means and variances per feature per classNone — structure is fixed by K and the number of classes
Random ForestSplit feature and threshold at each nodemax_depth, max_features, criterion, n_estimators
KNN / WNNDecision boundaries / decision regions (stored training data)K (and the distance measure / weighting)
🧠
Remember: Hyper = set by hand, before training, controls the architecture. Parameter = found by the machine, during training, controls the fit. If you could compute it from the training data, it is a parameter.

Validation & Testing

Training tells you what the model memorised; validation tells you how to tune it; only testing tells you what to expect in the real world.

Data is split three ways: training, validation and testing. Each has a different job, and confusing them is the most common way to fool yourself about performance.

Validation

  • In this step, labelled data that has not been used in training is used to determine how good the current model is.
  • The hyper-parameters of the model, and even the model itself, are adjusted and iterated in a training–validation cycle until the designer is satisfied.
  • Often validation is not done just once for each setting — instead, performance is averaged over multiple validation steps, called cross-validation.
  • Most commonly we use K-fold cross-validation (the lecture illustrates five-fold): train on K−1 folds, validate on the held-out fold, and repeat so every fold is validated once.
✅
In scikit-learn: from sklearn.model_selection import StratifiedKFold then cv = StratifiedKFold(n_splits = 5). The stratified version keeps the class proportions in each fold, which matters for imbalanced data.

Testing after validation

  • Once the right model is chosen after validation, the final step is to test it on the final set of data that has not been used — the test set.
  • The performance of the trained and validated model on the test dataset is what should be reported.
  • This is the performance we expect after deployment, when data that has not been seen in training or validation is presented to the model.

Validation

Uses held-out labelled data repeatedly to tune hyper-parameters and choose the model. It is part of the design loop, so it can influence the final model.

Testing

Used once, at the very end, on data untouched by training or validation. It estimates post-deployment performance and is the number you report.

⚠️
Common trap: a single validation split has high variance, so K-fold averaging is far more stable. And if you tune on the test set, it is no longer an honest estimate — you have quietly turned it into a validation set.

The Scikit-Learn Workflow

Almost every supervised model in scikit-learn follows the same five steps, so learning one model teaches you the interface for all of them.

  1. Create an object for the desired ML algorithm using the appropriate class — this is where you set the hyper-parameters.
  2. Use the fit method to train the model.
  3. Use the predict method to estimate the class of the test data samples.
  4. Use the predict_proba method to estimate the probability of each class given the input features.
  5. Test the accuracy of the algorithm using one or more of the metrics.
Create object→ .fit(X_train, y_train)→ .predict(X_test)→ .predict_proba(X_test)→ metrics
💡
Why it matters: this uniform interface lets you swap Gaussian NB, Random Forest or KNN by changing only the class name and hyper-parameters. The fit / predict / predict_proba pattern is the same for almost all models.
⚠️
Know the difference: predict returns hard labels; predict_proba returns per-class probabilities. Accuracy uses labels, but thresholding and cost-sensitive decisions need the probabilities.
🧠
Remember: "Create, fit, predict, proba, metrics." Every classical model this week plugs into that same five-step loop.

Exam & Assignment Focus

These are the distinctions most likely to be tested, with the crisp answer for each.

🎯 Accuracy on imbalanced data

Q: Why is accuracy poor on a 95%-majority dataset?
A: A model that always predicts the majority scores 95% while learning nothing — it is optimised for the majority case, so use resampling or cost-sensitive learning.

🎯 M − 1 dummies

Q: Why M − 1 dummies rather than M?
A: The last category is implied when all dummies are 0, so M − 1 suffice; using all M creates redundancy (the dummy variable trap).

🎯 The 0/1/2 trap

Q: What is wrong with encoding categories as 0, 1, 2?
A: It implies a false ordinal relationship (e.g. Male < Female < Unknown) that the model treats as real distance.

🎯 Gaussian NB assumptions

Q: State the two assumptions.
A: (a) Features are conditionally independent given the label, so the joint factorises; (b) each conditional feature distribution is Gaussian, specified by a mean and variance.

🎯 Why ignore the denominator?

Q: Why can Gaussian NB ignore P(x)?
A: For a fixed x it is the same constant for every label, so the label maximising P(x|y)P(y) is unchanged.

🎯 No hyper-parameters?

Q: Why does Gaussian NB have no hyper-parameters?
A: Its structure depends only on the number of features and classes; training estimates only means and variances.

🎯 Random Forest randomisation

Q: What two randomisations make the trees differ?
A: Bagging (bootstrap resampling of rows) and random feature subsets (each node investigates only m of p features).

🎯 Does K affect complexity?

Q: Does K change KNN's computational complexity?
A: No — all N distances are computed regardless; K affects accuracy, not distance cost.

🎯 Why normalise?

Q: Why normalise before KNN, and what is the formula?
A: A large-range feature would dominate distance; min-max normalisation is x′ = (x − min)/(max − min), mapping to [0,1].

🎯 Validation vs testing

Q: What is the difference?
A: Validation tunes hyper-parameters and selects the model; testing reports final performance once, on data unseen before, estimating post-deployment behaviour.

Key Takeaways

If you remember nothing else, remember this.

1

Pre-processing is not optional — missing values, mismatched scales, categorical variables and class imbalance silently break a model if ignored.

2

Handle missing data deliberately — pandas turns blanks into NaN; isna/notna find them, dropna removes rows, fillna (constant, forward or backward) replaces them. Every choice is an assumption.

3

Feature engineering often matters more than model choice — feature selection, variance threshold, tree-based importance, PCA and manual domain features. It is often the most time-consuming step.

4

Imbalanced data fools accuracy — a 95% majority lets a trivial model score 95%. Fix it with oversampling (SMOTE), undersampling, cost-sensitive learning or data augmentation.

5

One-hot encoding uses M − 1 dummies — the last category is implied by the all-zero row; encoding 0/1/2 falsely implies an ordinal relationship.

6

MAP detection is the probabilistic core — choose the label maximising P(y|x); P(x) is a constant, so only P(x|y)P(y) matters across labels.

7

Gaussian NB = MAP + two assumptions — conditional independence and Gaussian features. It has parameters (means, variances) but no hyper-parameters.

8

Decision trees split toward purity — the criterion (Gini impurity or entropy) measures closeness to one class per branch.

9

Random Forest = many randomised trees — bagging (bootstrap rows) plus random feature subsets decorrelate the trees, which are combined by majority vote to avoid overfitting.

10

KNN votes among the K nearest neighbours — K has no formulaic best value, affects accuracy but not computational complexity, and distances can be L2, L1 or Hamming.

11

Weighted KNN uses inverse-distance weights — N_n = Σ 1/d_i over class-n neighbours, so a few close minority points can outweigh many distant majority points.

12

Normalise, then validate before testing — min-max scaling stops one feature dominating distance, and stratified K-fold cross-validation tunes the model before the test set is touched once.

Glossary

Every term you need to speak this week's language.

Data pre-processing
Cleaning and transforming raw data — missing values, scaling, encoding, balance — so an algorithm can learn from it.
NaN (Not a Number)
pandas' marker for a missing value. Frequently treated as zero in sums and averages, which may or may not be sensible.
pandas missing-data tools
isna / notna find missing entries; dropna removes rows containing them; fillna replaces them.
Feature engineering
Turning raw high-dimensional data into informative, lower-dimensional inputs. Often the most time-consuming ML step.
PCA (Principal Component Analysis)
A dimensionality-reduction method that projects data onto directions capturing maximum variance.
Imbalanced data
A dataset where one class is far more prevalent, skewing training so the model optimises for the majority case.
SMOTE
Synthetic Minority Oversampling Technique — creates new synthetic minority-class samples to rebalance a dataset.
Cost-sensitive learning
Assigning higher penalties to costly errors so the model shifts its decision boundary to minimise overall cost, not just accuracy.
One-hot encoding
Converting an M-category variable into M − 1 binary dummy columns, with 1 marking the category.
Dummy variable trap
The redundancy from including all M dummies, since one column is perfectly predictable from the others.
MAP detector
Maximum a posteriori: the rule outputting the label that maximises P(y|x). For classification it maximises accuracy.
Bayes' rule
The identity P(y|x) = P(x|y)·P(y)/P(x) used to compute posterior probabilities; the denominator is a normalising constant.
Conditional independence
The assumption that features are independent given the label, so the joint factorises into a product of per-feature distributions.
Gaussian Naïve Bayes
A classifier combining MAP detection with conditional-independence and Gaussian-feature assumptions. Parameters: per-class means and variances. No hyper-parameters.
Gini impurity & entropy
Decision-tree split criteria measuring how mixed the classes are in a node; lower values mean purer nodes.
Bagging (bootstrap sampling)
Training each tree on a different resampled dataset (rows drawn with replacement) so the trees differ.
K-Nearest Neighbours (KNN)
An instance-based classifier that computes the distance to all N training points and takes a majority vote of the K closest.
Weighted KNN (WNN)
KNN where each neighbour is weighted by the inverse of its distance, so closer neighbours count more.
Min-max normalisation
Scaling a feature to [0,1] via x′ = (x − min)/(max − min), so no feature dominates distance.
Parameter vs hyper-parameter
A parameter is learned from training data (Gaussian means/variances, tree split thresholds); a hyper-parameter is set before training and not learned (K, max_depth, n_estimators).
Cross-validation (stratified K-fold)
Averaging validation performance over multiple splits, most commonly K-fold: train on K−1 folds, validate on the held-out fold. The stratified version preserves class proportions in each fold.
Accuracy
The fraction of predictions that are correct. Misleading on imbalanced data, where always predicting the majority scores high.

No terms in this category.

Practice Questions

Look away from the page first — retrieval is what builds memory.

Answer, reveal, then tick "Mastered". Your progress is saved.
Q1

Why is accuracy a poor metric on a dataset where 95% of samples are "blue"?

Answer: A model that always predicts "blue" scores 95% while learning nothing about the input. Training is optimised for the majority case, so the model exploits the metric instead of the data. You must handle imbalance deliberately — oversampling (SMOTE), undersampling, cost-sensitive learning or augmentation.
Q2

What does pandas do with missing cells, and which functions let you find, drop and fill them?

Answer: Missing cells become NaN (Not a Number). isna finds missing entries (opposite: notna), dropna removes rows containing missing data, and fillna replaces them — e.g. filling a Power(kW) column with 200, or using forward/backward fill.
Q3

A categorical feature has M = 4 possible values. How many dummy variables does one-hot encoding create, and why not M?

Answer: M − 1 = 3 dummies. The fourth category is implied when all three dummies are 0, so a fourth would be redundant (the dummy variable trap): one column would be perfectly predictable from the others.
Q4

Why is encoding Male/Female/Unknown as 0/1/2 a bad idea?

Answer: It implies an ordinal relationship — Male < Female < Unknown — which is meaningless. Algorithms that read numbers as distances would treat "Unknown" as further from "Male" than "Female" is. One-hot dummies avoid imposing a false order.
Q5

State the two simplifying assumptions behind Gaussian Naïve Bayes and say what each one buys you.

Answer: (a) Conditional independence — features are independent given the label, so the hard joint p(x₁,…,x_K|y) factorises into a product ∏ p(x_i|y). (b) Gaussian features — each p(x_i|y) is Gaussian, so it is fully specified by a mean μ_{i,y} and variance σ²_{i,y} estimated from data.
Q6

Why can Bayes' rule ignore the denominator P(x)?

Answer: For a fixed observed x, P(x) is the same for every candidate label. It is just a normalising constant, so comparing P(x|y)·P(y) across labels gives the same maximising y as comparing the full posteriors.
Q7

What are the parameters of Gaussian NB, and why does it have no hyper-parameters?

Answer: The parameters are the conditional means and variances of every feature conditioned on each class label, estimated from training data. There are no hyper-parameters because the model's structure is entirely determined by the number of features and the number of classes — nothing is left for a human to set.
Q8

In a Random Forest, which quantities are parameters and which are hyper-parameters?

Answer: Parameters (learned by the machine): which feature to split on at each node, and the threshold at each node. Hyper-parameters (set by humans): max_depth, max_features, criterion, and n_estimators (the number of trees).
Q9

What two forms of randomisation make Random Forest trees differ from one another, and why does that matter?

Answer: (1) Bagging (bootstrap sampling) — each tree trains on a different resampled dataset. (2) Random feature subsets — each node investigates only m of p features, chosen randomly and independently. Randomisation stops the trees turning out the same, which would defeat the point of having many; combined by majority vote, they reduce the overfitting of a single tree.
Q10

Does the choice of K affect KNN's computational complexity? Does it affect anything else?

Answer: No — we always compute all N distances regardless of K, so complexity is unchanged. K does affect classifier accuracy. Complexity grows with N, so it is best not to use "too many" training samples, and there is no formulaic way to choose K well.
Q11

With K = 5, two class-0 neighbours are at distances 0.5 and 0.4, and three class-1 neighbours are at 1.0, 0.8 and 1.5. What class does plain KNN pick, what class does Weighted KNN pick, and what is the WNN probability of class 0?

Answer: KNN: N_0 = 2, N_1 = 3 → class 1. WNN: N_0 = 1/0.5 + 1/0.4 = 2.5 + 2.0 = 4.5; N_1 = 1/1.0 + 1/0.8 + 1/1.5 = 1.0 + 1.25 + 0.67 = 2.92 → class 0. Probability: P[C_0|x] = 4.5/(4.5+2.92) = 0.606 (and P[C_1|x] = 0.394). The closer class-0 points outweigh the more numerous class-1 points.
Q12

Why must you normalise features before running KNN, and what is the min-max formula?

Answer: A feature with a much larger dynamic range (e.g. engine capacity in cc versus model year) would dominate every distance, drowning out the others. Min-max normalisation maps each feature to [0,1]: x′ = (x − min)/(max − min).
Q13

What is the difference between validation and testing, and what role does K-fold cross-validation play?

Answer: Validation uses held-out labelled data, repeatedly, to tune hyper-parameters and choose the model in a training–validation cycle. Testing happens once at the end on data untouched by either, and its result is what you report as expected post-deployment performance. K-fold cross-validation averages validation over K splits (train on K−1 folds, validate on the held-out fold) for a more stable estimate; use the stratified version for imbalanced data.
Q14

Using the MAP rule, if P[y = "jumps" | x] = 0.4, P[y = "walks" | x] = 0.1 and P[y = "is" | x] = 0.05, which next word do you output — and what does MAP guarantee for classification?

Answer: Output "jumps", the label that maximises P(y|x). For discrete y, the MAP detector minimises the probability of a decision error, i.e. it maximises accuracy. To use it you need P(y|x), computed via Bayes' rule P(y|x) = P(x|y)·P(y)/P(x) or learned from training data.
