One Key to Lock Them All: The Machinery of Symmetric Cryptography

Symmetric cryptography is where sender and receiver share one secret key. This week covers the maths that makes it possible (sets, groups, rings, fields, primes, modular arithmetic, discrete logs), the ancient ciphers and why they failed, Shannon's design principles, and the modern algorithms that protect the internet: one-time pads, stream ciphers, DES, AES and the block cipher modes that glue them together.

Read this first: under Kerckhoffs's Principle the algorithm is public and only the key is secret, so the security of a symmetric cipher reduces to two questions: how big is the key space, and how much does the ciphertext leak about the plaintext?
~35 min read 16 teaching sections 15 practice questions 30 key terms

By the end you will be able to

  • Define plaintext, ciphertext, key, encryption and decryption, and separate symmetric from asymmetric cryptography.
  • State Kerckhoffs's Principle and explain the GSM A5/1 and DVD CSS failures.
  • Break a monoalphabetic cipher by frequency analysis and outline the Kasiski method.
  • Explain confusion and diffusion and map them onto S-boxes and P-boxes.
  • Describe the four adversary models and give an example of each.
  • Prove why the one-time pad is perfectly secure yet impractical, and how key reuse breaks it.
  • Trace a Feistel round and an SPN round through DES and AES.
  • Compare ECB, CBC and CTR, state the rules for IVs and nonces, and explain authenticated encryption.
  • Do modular arithmetic, run the extended Euclidean algorithm, compute Euler's totient, and explain the discrete logarithm problem.

Why Cryptography Matters

Cryptography is the tool that gives secure systems their confidentiality, integrity and authentication, and it is easier to get dangerously wrong than it looks.

Cryptography is indispensable in secure protocols and systems because it delivers four guarantees:

🔒 Data confidentiality

Through encryption: only a key holder can read the data.

🧾 Data integrity

Through signatures and Message Authentication Codes (MACs): changes are detectable.

🪪 Authentication & origin

Through signatures and MACs: you can verify who created a message.

🚫 Non-repudiation

Through signatures: a sender cannot deny sending.

This unit teaches cryptography functionally rather than proof-first, but you still need the maths. The lecture assumes you have read the separate number theory and abstract algebra handouts, and those ideas are assessable.

A double-edged sword

Cryptography is subtle and complex. Careless use produces insecure systems, and worse, systems that look secure to their developers while attackers quietly break them. The attacker does not know the system is "supposed" to be secure, and will take it apart. The GSM A5/1 stream cipher is the classic case: it used a 64-bit secret key, and weaknesses found in 1994 led by the late 1990s to practical attacks, including a ciphertext-only attack in which an eavesdropper recovered the key from a sequence of consecutive encrypted frames using moderate computing power.

⚠️
Common trap: do not implement your own cryptography for real applications. Use known, standardised methods. Proficiency takes practice, a mentor and discussion with other implementers; it is a long path with no shortcuts.

A definition of cryptography

Cryptography is the science of securely transmitting data over space and time.

Two dimensions
spatially: secure over physical distance  |  temporally: secure far into the future

Spatially means securing data across distance, such as a browser tab talking to www.google.com. Temporally means keeping data secure for decades, so archival data encrypted today stays unreadable despite future computing power.

The Symmetric Cipher Model

A cipher is just two functions, encryption and decryption, parameterised by keys, and symmetric cryptography is the case where those keys are the same.

Plaintext — the unprotected data p, built from an alphabet R = {r1, …, rn} (for English, {A–Z, a–z, 0–9}).
Encryption — encodes plaintext with the cipher function Enc and key ke to produce ciphertext c.
Ciphertext — the output c, from a possibly different alphabet S = {s1, …, sm} of possibly different size.
Decryption — recovers plaintext with the decipher function Dec and key kd.
The two halves of a cipher
Encke(p) = c      Deckd(c) = p

Symmetric (shared-key)

  • ke = kd, or kd is derivable from ke.
  • One shared secret key.
  • Shuffles symbols around and maps them to others.
  • AES, DES, ChaCha20. Fast, for bulk data.

Asymmetric (public-key)

  • ke ≠ kd, and deriving kd from ke is infeasible.
  • Encryption key can be public, decryption key private.
  • Security rests on a hard maths problem.
  • RSA, ECC. Slower, used for keys and signatures.

The picture to hold

A sender encrypts plaintext with a shared secret key; the ciphertext crosses an insecure channel watched by an opponent; the receiver decrypts with the same key. Sender and receiver must already share that key over a secure channel, which is the key distribution problem and the main practical weakness of symmetric cryptography.

Plaintext p→ Encrypt, key k→ Ciphertext c (insecure)→ Decrypt, key k→ Plaintext p
✅
Key idea: encryption does not hide the message in a scrambled envelope that a clever attacker opens; it makes the plaintext-to-ciphertext mapping depend so heavily on a secret parameter that, without the parameter, no efficient algorithm recovers the message.

Kerckhoffs's Principle

A cipher must stay secure even when the attacker knows exactly how it works, because only the key should be secret.

Kerckhoffs's Principle
Security depends only on the secrecy of the KEY, never on the secrecy of the mechanism.

Almost every mainstream algorithm is public. We know exactly how AES and RSA work; their security depends purely on the keys. This is deliberate, for the many-eyes argument: when a design is public, many experts can find flaws before attackers exploit them. That is why standards bodies such as NIST run open competitions, inviting the global cryptographic community to submit and scrutinise algorithms. The winning designs, such as AES, have survived worldwide analysis.

Two famous failures of secrecy

case study GSM A5/1

A proprietary, secret stream cipher with a 64-bit key. Weaknesses found in 1994 led to practical ciphertext-only attacks by the late 1990s. Secrecy did not save it.

case study DVD CSS

The DVD Content Scrambling System restricted regions and copying, and relied on its algorithm staying secret. Once it was reverse-engineered and published, the whole copy-protection scheme collapsed.

💡
Why it matters: Kerckhoffs's Principle lets us publish, standardise and audit algorithms while keeping systems secure through keys alone. Learn the statement and at least two historical violations; it is a recurring exam theme.
K · E · Y
"Keep Everything Yours, except the algorithm"
Keep only the key secret · Expect full disclosure of the algorithm · Your security must survive it.

Historical Ciphers and How They Break

All classical ciphers are built from substitution or transposition, and every one of them leaks the statistics of natural language.

Transposition — shifting the positions of symbols by a rule, altering their order without changing the symbols.
Substitution — replacing symbols with other symbols by a rule.

Caesar cipher and frequency analysis

The Caesar cipher shifts every letter by a fixed amount (shift 3: a → d, b → e). It is monoalphabetic: a plaintext symbol always maps to the same ciphertext symbol. Suetonius claimed Caesar used it, though similar methods came earlier. A Caesar shift has only 25 useful keys, so it falls to brute force in seconds, but the deeper flaw is frequency analysis.

⚠️
Common trap: every natural language has characteristic letter frequencies (English: E is most common). Substitution preserves them, so an attacker finds the most frequent ciphertext symbol, guesses it is E, and works outward, often with a dictionary.

Vigenère cipher: polyalphabetic substitution

The Vigenère cipher uses a different Caesar shift per position, chosen by a repeating keyword. With A = 0, …, Z = 25:

Vigenère encryption and decryption
Ci = (Pi + Ki mod |K|) mod 26      Pi = (Ci − Ki mod |K| + 26) mod 26

Key CRYPTO (C = 2, R = 17, Y = 24, P = 15, T = 19, O = 14) with plaintext THISISAGREATDAY:

PlainTHISISAGREATDAY
KeyCRYPTOCRYPTOCRY
CipherVYGHBGCXPTTHFRW

First letter: C = 2, T = 19, so 2 + 19 = 21 = V. Decrypting V: 21 − 2 = 19 = T. Note the positions where the same key character meets the same plaintext character: plaintext T, A and D all line up with key C and all yield ciphertext F.

Breaking Vigenère

If the key length is known, split the ciphertext into groups by key position. Each group is now a Caesar cipher, so frequency analysis applies. If the most common symbol in a group is G and E is the likely plaintext letter, solve 6 − c ≡ 4 (mod 26), giving c = 2, so the key letter is C. Repeat for each position. If the key length is unknown, guess lengths, or use the Kasiski examination: repeated plaintext sequences encrypted by the same repeated key produce repeated ciphertext sequences, so the distances between repeats are multiples of the key length.

Kasiski worked example

  1. First repeat — distance 33, so the key size is a factor: 1, 3, 11 or 33.
  2. Second repeat — distance 27, so the key size is 1, 3, 9 or 27.
  3. Intersect — common factors are 1 and 3; discard 1 as too weak.
  4. Conclude — likely key size 3, then frequency-analyse each group.

Rail fence cipher: transposition

The rail fence cipher writes the plaintext diagonally across several rails, then reads row by row. Depth 2 turns "MEET ME AFTER THE TOGA PARTY" into MEMATRHTGPRYETEFETEOAAT. Because transposition preserves which letters appear, it is vulnerable to anagram-style attacks.

Exam drill (lecture practice Q2)
Ciphertext "BWGWBHQSJBBKNF", Vigenère with a two-letter key, plaintext position 2 = "I". Answer: SIXISTHEANSWER.

Identical key letters on identical plaintext letters give identical ciphertext letters, so positions 2 and 4 must both be "I", and positions 1, 5 and 11 must share one plaintext letter. Only SIXISTHEANSWER fits.

Confusion and Diffusion

Claude Shannon reduced good cipher design to two goals: scramble the link between key and ciphertext, and spread the influence of every plaintext bit.

Confusion

  • Makes the ciphertext–key relationship complex.
  • Each ciphertext symbol depends on several key symbols.
  • Stops an attacker recovering the key from ciphertext.
  • Achieved by substitution (S-boxes).

Diffusion

  • Spreads each plaintext bit across many ciphertext bits.
  • Every ciphertext symbol depends on many plaintext symbols.
  • Erases patterns; one input bit flip changes about half the output bits.
  • Achieved by transposition / permutation (P-boxes).
C · D
"Confusion scrambles the KEY; Diffusion spreads the PLAINTEXT."
Confusion hides the key through substitution · Diffusion hides the plaintext through permutation.
🤔
Pause & predict: if a cipher used substitution only, which goal would it miss? What about permutation only?

Attacks on Cryptographic Systems

The strength of an attack is defined by what the adversary may see or ask for, and the four standard models form a ladder from weakest to strongest.

A system is compromised if an adversary can obtain plaintexts for certain ciphertexts, or obtain the decryption key kd given ke. Cryptanalysis is decrypting without the key.

Attack modelWhat the attacker getsLecture example
Ciphertext-onlyOnly ciphertexts.Intercepted WWII communications decrypted from ciphertext alone.
Known plaintextSome plaintexts with their ciphertexts.Bletchley Park broke Enigma using likely wording such as weather reports.
Chosen plaintextChooses plaintext, sees the ciphertext.The BEAST attack on SSL/TLS. Standard model for asymmetric crypto.
Chosen ciphertextChooses ciphertext, sees the decryption (an oracle).Bleichenbacher's attack on PKCS#1 v1.5.
⚠️
Common trap: known plaintext means the attacker happens to have plaintext–ciphertext pairs; chosen plaintext means the attacker picks the plaintext and demands the ciphertext. Chosen ciphertext is stronger still, because it targets the decryption path. A cipher secure against chosen ciphertext is the gold standard, and authenticated encryption aims there.

Stream Ciphers versus Block Ciphers

Symmetric ciphers split by how they consume data: one symbol at a time, or one fixed-size block at a time.

Stream ciphers

  • Encrypt one bit or byte at a time, continuously.
  • Combine each plaintext symbol with a keystream symbol derived from the key.
  • Examples: RC4 (insecure), Salsa20 / ChaCha20.
  • No padding; ideal for continuous data.

Block ciphers

  • Encrypt fixed-size blocks, typically 64 or 128 bits.
  • Output a ciphertext block of the same size.
  • Pad the plaintext if it is shorter than a block.
  • Examples: DES (insecure), AES.

A stream cipher applies a pseudo-random function f to the key to get a keystream b = b0, b1, …, bn, then combines it with the plaintext:

Stream cipher core
c = p ⊕ b    where b = f(k)

The challenge is that the keystream must be as unpredictable as possible without knowing k: an attacker must not be able to distinguish a truly random keystream from one generated deterministically from the key. If they can spot a pattern, security collapses, so the pseudo-random function is everything.

ℹ️
Context: the One-Time Pad is a stream cipher whose keystream is completely random rather than pseudo-random. That difference makes it perfectly secure, and entirely impractical.

The One-Time Pad and Perfect Secrecy

The one-time pad is the only cipher proven unbreakable, and it is almost useless in practice because of one word: distribution.

The One-Time Pad (OTP) assumes a random key per message, at least as long as the message. It is not the one-time password used in multi-factor authentication. Encryption and decryption are both XOR:

One-Time Pad
c = p ⊕ k      p = c ⊕ k

XOR is not mandatory; modular arithmetic such as mod 26 works too. The OTP is perfectly secure if and only if three conditions hold:

  1. The key is truly random, not pseudo-random.
  2. The key is at least as long as the plaintext: |k| ≥ |p|.
  3. The key is never reused, not even in part.
Perfect secrecy — given the ciphertext, every possible plaintext is equally likely, so the ciphertext carries no information about the plaintext content.

Equivalently, the probability distribution of possible plaintexts is independent of the ciphertext. It can be proved that any perfectly secret scheme must use at least as much key material as there is plaintext to encrypt.

💡
Why it matters: if k is uniformly random then p = c ⊕ k is uniformly random for any fixed ciphertext, so the ciphertext gives no clue which plaintext was sent. That is why the key can never be reused: reuse reintroduces structure.

Why it is impractical

  • Key distribution: how do Alice and Bob securely share a key as long as the message? If they had such a channel, they would not need the OTP.
  • Key generation: producing that volume of truly random material is hard and cannot keep up with frequent communication.

OTPs have been used only in extremely high-value settings such as the red telephone, because the key conditions are usually too hard to meet.

Reusing the key: the many-time pad

The attack
C1 = P1 ⊕ K,   C2 = P2 ⊕ K   ⇒   C1 ⊕ C2 = P1 ⊕ P2

The key cancels because K ⊕ K is all zeros. Since P1 = (P1 ⊕ P2) ⊕ P2, guessing one plaintext reveals the other. This is crib dragging: guess a likely word ("the"), try it at every offset, XOR with the combined string, and look for readable output.

⚠️
Common trap: key reuse is not a small shortcut, it is a complete break. If an attacker has one message in both plaintext and ciphertext form, a known-plaintext attack recovers the key, and every other message under that key falls too.

Pseudo-Random Number Generators

Cryptography runs on randomness, and a cryptographically secure generator is one whose output an attacker cannot distinguish from chance and whose seed cannot be guessed.

Random numbers introduce unpredictability. In cryptography they generate keys, Initialization Vectors (IVs) and nonces, keep session keys unique, and provide the keystream for stream ciphers. If an attacker could predict or reproduce these values, they could decrypt messages or forge signatures.

PRNG — a pseudo-random number generator: it outputs a deterministic sequence from an initial seed, and the whole sequence depends on that seed.
CSPRNG — a PRNG that is cryptographically secure: it is computationally infeasible to brute-force the seed to predict the output, and computationally infeasible to distinguish the output from true randomness.

The only option left to an attacker is to know or discover the seed.

modern ChaCha20 & Salsa20

Related stream ciphers by DJ Bernstein, the current de-facto standard for stream ciphers and the basis of the CSPRNG in OpenBSD and Linux.

legacy RC4

Once the TLS/SSL standard. Feasibly broken in 2013. Avoid it today.

✅
Do this: whenever you see a "random" value in a crypto protocol, ask where its seed came from. A strong generator seeded with something guessable, like the current time, is still broken.

Inside a Block Cipher: S-boxes, P-boxes and Feistel Networks

Block ciphers build confusion and diffusion from two tiny components arranged into repeating networks.

Substitution is implemented with Substitution boxes (S-boxes) and permutation with Permutation boxes (P-boxes). They run across multiple rounds, arranged in structures called networks.

S-box — a lookup table mapping input bits to output bits, carefully chosen and vetted. Changing one input bit usually flips about half the output bits. DES uses eight 6-to-4-bit S-boxes; AES uses one 8-to-8-bit S-box.
P-box — a simple index permutation of bits. Chained with S-boxes, it spreads one S-box's output across as many later S-boxes as possible.

Feistel networks

The Feistel cipher is the most common structure, used in DES, Blowfish, Twofish and RC6. It splits the block in half and applies the same round repeatedly:

One Feistel round
Li+1 = Ri      Ri+1 = Li ⊕ F(Ri, Ki)

The right half passes through a keyed function F; its output is XORed with the left half to become the new right half, and the halves swap.

Split L | R→ F(R, K) XOR L→ Swap halves→ Repeat n rounds

The alternative: substitution-permutation network

An SPN applies substitution and permutation layers to the whole block each round, and is what AES uses. Every stage must be invertible for decryption to work.

In short: a Feistel network splits the block and needs no invertible F, while an SPN transforms the whole block and every stage must be invertible. DES is Feistel; AES is SPN.

DES, 3DES and Block Cipher Design Principles

DES is the classic Feistel cipher that taught the world to build block ciphers, and its short key is why AES exists.

The Data Encryption Standard (DES) was published in 1977 and standardised in 1979. Each round derives a subkey from the main key. DES has eight S-boxes feeding one P-box (to spread bits across the next round's S-boxes), uses a Feistel structure, and it can be shown that its 16 rounds are necessary for security.

Using an S-box: DES S[0]

For input bits (b0, b1, b2, b3, b4, b5):

  1. Row — outer bits b0 and b5.
  2. Column — inner bits (b1, b2, b3, b4).
  3. Read the cell — interpret it as binary.

Input 110111: row (11)2 = 3, column (1011)2 = 11, cell value 14, so output (14)10 = 1110. Practice drill input 010000: row 0, column 8, cell value 3, so output 0011.

The full DES operation

DES takes 64-bit blocks and a 56-bit key, and the round-key generator produces sixteen 48-bit round keys.

64-bit block → L | R (32+32)→ Expand R 32 → 48→ XOR round key→ 8 S-boxes: 48 → 32→ Feistel, ×16

Each S-box takes 6 bits and emits 4, so eight boxes return 32 bits, and the process repeats sixteen times.

Why DES is no longer secure

DES has 256 keys, about 7.2 × 1016. A multicore machine tries about 109 per second and a supercomputer about 1013. On average we try half the keys, 255:

Average brute-force time
255 / 109 ≈ 36,028,797 s ≈ 1.2 years   |   255 / 1013 ≈ 3,600 s ≈ 1 hour

This is why AES uses 128-, 192- or 256-bit keys.

3DES: the interim fix

3DES applies DES three times: two keys (K1, K2) give 112-bit effective security, three keys (K1, K2, K3) give 168-bit.

3DES: Encrypt–Decrypt–Encrypt
C = EK3( DK2( EK1(p) ) )

Why EDE and not EEE? Backward compatibility: when all three steps use the same key, 3DES collapses back into DES. The middle decryption with a different key does not recover plaintext; it just makes the composition non-trivial.

💡
Meet-in-the-middle: two DES encryptions with independent keys should need 2112 trials, but an attacker stores the intermediates after the first encryption and matches them against values decrypted from the ciphertext, cutting the work to about 256 per half. That is why double encryption is insufficient and careful constructions were needed.

Block cipher design principles

🔁 Rounds

More rounds make cryptanalysis harder even if F is weak, supplying confusion in a Feistel cipher.

🧮 Function F

Should be nonlinear with strong avalanche properties: SAC and BIC.

🗝️ Key schedule

Generates one subkey per round, made hard to deduce individually or reverse to the main key. SAC and BIC are desired here too.

Strict Avalanche Criterion (SAC) — when one input bit is complemented, each output bit changes with probability 50%.
Bit Independence Criterion (BIC) — output bits j and k change independently when any single input bit i is inverted, for all i, j, k.

The Advanced Encryption Standard (AES)

AES is the de-facto block cipher of the internet, and unlike DES it is not a Feistel cipher: it is a substitution-permutation network built on finite-field arithmetic.

Advanced Encryption Standard (AES) is the current de-facto block cipher and DES's successor. It uses 128, 192 or 256-bit keys, always a 128-bit block, and an SPN rather than a Feistel network.

ℹ️
Fun fact: AES is not itself a cipher. The Rijndael cipher was selected in an open competition (Kerckhoffs's Principle in action) to become the Advanced Encryption Standard.

Finite field arithmetic

AES computes in GF(28) with irreducible polynomial m(x) = x8 + x4 + x3 + x + 1:

Byte arithmetic in GF(28)
Addition = bitwise XOR   |   Multiplication = polynomial multiplication mod m(x)

For A = (a7…a0) and B = (b7…b0), the sum has each bit ci = ai XOR bi. Using a field guarantees every non-zero byte has a multiplicative inverse, which the S-box exploits.

Key expansion

AES expands the key into 32-bit words. For AES-128, a 16-byte key (4 words) becomes a 176-byte array (44 words), giving 11 round keys of 128 bits. The round key is 4 words for AES-128, 6 for AES-192 and 8 for AES-256, which drives the round counts: 10, 12 or 14.

The four operations in a round

substitution SubBytes

The S-box substitutes bytes one by one, mapping each byte to its multiplicative inverse in GF(28) plus an affine transformation. This is the source of non-linearity.

permutation ShiftRows

A simple permutation that shifts rows of the state.

substitution MixColumns

A substitution using arithmetic over GF(28), transforming each column and providing diffusion.

key mix AddRoundKey

A bitwise XOR of the block with a portion of the expanded key.

S · S · M · A
"SubBytes, ShiftRows, MixColumns, AddRoundKey"
Substitute bytes · Shift rows · Mix columns · Add round key = one AES round.

AES's S-boxes describe a mathematical function believed to give excellent diffusion and confusion; attempts to describe it in simpler terms have all failed. AES does not use Feistel; each round applies the four functions above.

✅
Exam tip: be ready to compare in one line. DES: 64-bit block, 56-bit key, 16 Feistel rounds, eight 6-to-4 S-boxes. AES: 128-bit block, 128/192/256-bit keys, 10/12/14 SPN rounds, one 8-to-8 S-box over GF(28).

Modes of Operation: ECB, CBC and CTR

A mode of operation defines how blocks are chained, and a badly chosen mode can destroy an otherwise strong cipher.

Real messages are arbitrary length, but a block cipher handles one fixed block. The mode splits the message into blocks and processes them. If modes are not carefully designed and used, they introduce new vulnerabilities.

Classic (confidentiality only)

  • Electronic Codebook (ECB)
  • Cipher Block Chaining (CBC)
  • Counter (CTR)
  • Also Cipher Feedback (CFB) and Output Feedback (OFB)

Modern (authenticated)

  • Encryption plus integrity.
  • Called AE or AEAD.
  • Galois Counter Mode (GCM)
  • Counter-with-CBC-MAC (CCM)

ECB: Electronic Codebook

Each block is encrypted independently: Ci = Ei(Pi). Identical plaintext blocks give identical ciphertext blocks, so repeated patterns (such as an image's background) stay visible. ECB is not used at all these days.

CBC: Cipher Block Chaining

CBC encryption and decryption
Ci = Ek( Ci−1 ⊕ Pi ), C0 = IV      Pi = Dk( Ci ) ⊕ Ci−1

Chaining makes each block depend on the previous, masking patterns. Encryption is therefore sequential (not parallelisable), though decryption is parallelisable.

Initialization Vector (IV) — a random or pseudo-random first input that makes identical plaintext blocks encrypt differently.
  • The IV need not be secret; it is often sent with the ciphertext.
  • Its role is unpredictability, not secrecy.
  • It must never repeat under the same key, or identical blocks encrypt identically again and the ECB leak returns.

WEP: IV reuse in the wild

Wired Equivalent Privacy (WEP) used RC4 with a secret key plus a 24-bit IV. That is so small that IVs repeat quickly on busy networks. Reusing an IV with the same key makes RC4 reproduce the same keystream; an attacker who captures multiple packets with that IV can study the keystream, recover plaintext where it is predictable, deduce the keystream, and eventually recover the key.

CTR: Counter mode

CTR mode
keystreami = Ek( nonce ‖ counteri )      Ci = Pi ⊕ keystreami

A counter increments per block, and the nonce-plus-counter is encrypted to give a keystream that is XORed with the plaintext. The nonce is like the CBC IV: not secret, but never reused with the same key. Reuse reproduces the keystream, with the same catastrophic effect as an OTP reuse. CTR turns a block cipher into a stream cipher, is fully parallelisable, and needs no padding.

CFB feeds previous ciphertext back into the cipher to act stream-like; OFB repeatedly encrypts an IV to generate a keystream. Modes such as ECB and CBC require padding when the message is not a block multiple; CTR and other stream-like modes do not.

ModeChainingIV / nonceParallel encryptPaddingMain weakness
ECBNoneNoYesYesIdentical blocks leak patterns.
CBCPrevious ciphertextIV, uniqueNoYesSequential; IV reuse is fatal.
CTRCounter + nonceNonce, uniqueYesNoNonce reuse leaks the keystream.

Authenticated Encryption and Key Management

Encryption alone hides the message but does not stop tampering, so modern modes combine confidentiality with integrity.

Classic modes only encrypt. They give confidentiality but not integrity: an attacker may flip bits, or use a decryption oracle to learn the key (as in Bleichenbacher's chosen-ciphertext attack). Modern modes provide authenticated encryption (AE), or AEAD when associated data is also protected, combining encryption with integrity.

AEAD Galois Counter Mode (GCM)

CTR-mode encryption with a Galois-field authentication tag. The modern standard, used in TLS 1.3.

AEAD Counter with CBC-MAC (CCM)

A CBC-MAC authenticator combined with CTR-mode encryption.

💡
Why it matters: AEAD is the practical answer to chosen-ciphertext attacks. A tag verifies the ciphertext, so tampering is detected before the plaintext is trusted, and the attacker never gets a useful oracle.

Key management basics

  • The key is the only secret. Losing it loses everything.
  • Symmetric keys must be distributed securely, the OTP's core impracticality.
  • Keys need sufficient size: DES's 56 bits was brute-forceable, hence AES's 128, 192 or 256 bits.
  • Never reuse a key the mode forbids. IVs and nonces are not secret but must be unique per key.
  • Session keys should be fresh and random, supplied by a CSPRNG.
⚠️
Common trap: "encrypted" and "secure" are not synonyms. Data can be confidential yet forgeable. If you must trust that data was not altered, you need integrity too: an AEAD mode or a separate MAC.

Number Theory for Cryptography

Divisibility, primes, modular arithmetic and the discrete logarithm are the raw material of nearly every cryptographic algorithm.

Divisibility

Divisibility — non-zero b divides a if a = mb for some integer m; written b | a, and b is a divisor of a.

Key properties: if a | 1 then a = ±1; if a | b and b | a then a = ±b; any b ≠ 0 divides 0; if a | b and b | c then a | c; and if b | g and b | h then b | (m·g + n·h) for any integers m, n.

Division, GCD and the Euclidean algorithm

Division algorithm
a = q n + r    with   0 ≤ r < n    and   q = ⌊a / n⌋

The Greatest Common Divisor gcd(a, b) is the largest integer dividing both. We set gcd(0, 0) = 0 and gcd(a, 0) = |a|; also gcd(a, b) = gcd(|a|, |b|) and gcd(60, 24) = 12. Two integers are relatively prime when gcd(a, b) = 1, as with 8 and 15. The Euclidean algorithm finds the GCD by repeated division until the remainder is zero.

Modular arithmetic

Modulus — for integer a and positive integer n, a mod n is the remainder when a is divided by n; n is the modulus.
Congruence — a ≡ b (mod n) when a mod n = b mod n. Note a ≡ 0 (mod n) means n | a.

Examples: −11 mod 7 = 3 (result kept positive); 73 ≡ 4 (mod 23); 21 ≡ 31 (mod 10). Congruence is reflexive, symmetric and transitive, but a ≡ b and b ≡ c (mod n) does not mean a = c: e.g. 26 ≡ 11 ≡ 16 (mod 5).

Modular arithmetic respects +, − and ×
[(a mod n) + (b mod n)] mod n = (a + b) mod n
[(a mod n) − (b mod n)] mod n = (a − b) mod n
[(a mod n) · (b mod n)] mod n = (a · b) mod n

The set Zn = {0, 1, …, (n − 1)} holds the residues; each integer represents a residue class [r] = {a : a ≡ r mod n}, represented by its smallest non-negative member.

Exponentiation by squaring

Modular powers are computed by repeated squaring. For 117 mod 13: 112 ≡ 4, 114 ≡ 3, so 117 = 11 × 4 × 3 = 132 ≡ 2 (mod 13). For large exponents, write the exponent in binary and combine the needed powers of two. The lecture computes 5117 mod 19 (117 = 1110101): squaring gives 5, 6, 17, 4, 16, 9, 5 for exponents 1, 2, 4, 8, 16, 32, 64, so 5 × 17 × 16 × 9 × 5 = 61200 ≡ 1 (mod 19). This returns in Diffie-Hellman.

Extended Euclidean algorithm and modular inverses

Bezout identity
a x + b y = gcd(a, b)

For a = 240, b = 46, the algorithm gives x = −9, y = 47, so 240 × (−9) + 46 × 47 = 2 = gcd(240, 46). Its key use is the modular inverse: for 3−1 mod 11, apply the algorithm to 3 and 11 and read the coefficient of 3, which is 4, since 3 × 4 = 12 ≡ 1 (mod 11).

⚠️
Common trap: a modular inverse of a modulo n exists only when gcd(a, n) = 1. For example 2 has no inverse mod 10, since every multiple of 2 mod 10 is even and never 1. This fact decides whether Zn is a field.

Primes, Fermat, Euler and the discrete logarithm

Prime number — a number whose only divisors are 1 and itself; it cannot be written as a product of other numbers.

The fundamental theorem of arithmetic says any integer a > 1 factors uniquely as a product of primes, e.g. 360 = 23 × 32 × 5.

Fermat's Little Theorem
For a not divisible by prime p:   ap−1 ≡ 1 (mod p)

Example: p = 7, a = 3 gives 36 = 729 ≡ 1 (mod 7), or via squaring 32 ≡ 2 ⇒ 2 × 2 × 2 = 8 ≡ 1.

Euler's totient φ(n) — the count of positive integers below n relatively prime to n.

For prime p, φ(p) = p − 1, so φ(37) = 36. For two distinct primes:

Totient of a product of primes
φ(pq) = (p − 1)(q − 1)    e.g. φ(21) = 6 × 2 = 12
Euler's Theorem (generalises Fermat)
For coprime a and n:   aφ(n) ≡ 1 (mod n)    e.g. 34 = 81 ≡ 1 (mod 5)

A primitive root of n is a number whose order modulo n reaches the maximum φ(n) = p − 1. The primitive roots of 19 are 2, 3, 10, 13, 14 and 15.

Discrete Logarithm Problem (DLP) — given prime p, primitive root g, and y, find x with gx ≡ y (mod p).

Forward is easy: with p = 19, g = 2, x = 7, exponentiation by squaring gives y = 14. Backward is hard: given p = 19, g = 2, y = 8, there is no efficient algorithm to find x; you essentially try values. For large p this is infeasible, and that hardness secures Diffie-Hellman, DSA and related schemes.

Abstract Algebra: Groups, Rings and Fields

Groups, rings and fields form a ladder of structures, and cryptography lives on the top rung: finite fields and their polynomial arithmetic.

Abstract algebra studies algebraic structures such as groups, rings and fields, and underpins the design and security of cryptographic systems. Each rung adds requirements to the one below.

Set→ Group→ Ring→ Field→ Finite field

A set is a collection of elements with no operations. A group adds one associative operation with closure, an identity and inverses; an Abelian group also commutes. A ring adds a second operation and distributivity. A field is a commutative ring with unity in which every non-zero element has a multiplicative inverse.

Groups

A group G with an operation satisfies four properties:

  1. Closure — a + b ∈ G for all a, b ∈ G.
  2. Associativity — (a + b) + c = a + (b + c).
  3. Identity — there is a 0 with 0 + a = a + 0 = a.
  4. Inverses — each a has −a with a + (−a) = 0.

Add commutativity (a + b = b + a) for an Abelian group. The operation need not be addition. The integers Z under addition are a canonical Abelian group: sums stay integers, zero is the identity, and each integer has its negative as inverse.

Rings and their specialisations

A ring adds multiplication, requiring closure and associativity for both operations, additive identity and inverses, commutative addition, and the distributive laws. Multiplication need not commute, and there need not be a multiplicative identity.

A commutative ring has commutative multiplication (a · b = b · a); a ring with unity has a multiplicative identity 1; an integral domain is a commutative ring with unity and no zero divisors (a · b = 0 implies a = 0 or b = 0). A field goes further: every non-zero element has a multiplicative inverse.

The integers Z form a commutative ring but not a field: 4 would need the inverse 1/4, not an integer. The rationals Q are a field, since 1/4 is rational.

Finite fields (Galois fields)

Prime fields GF(p)

  • p elements, p prime.
  • Elements {0, 1, …, p − 1} with arithmetic mod p.
  • Characteristic p.
  • Example: GF(7) = {0,…,6}.

Extension fields GF(pn)

  • pn elements, n > 1.
  • Extend GF(p) with roots of degree-n irreducible polynomials.
  • Finding the polynomial and elements is out of scope this unit.

Verify the field properties on GF(7): closure (5 + 6 ≡ 4, 5 · 6 ≡ 2), additive identity 0, additive inverses (5 + 2 ≡ 0), multiplicative inverses (5 · 3 ≡ 1, 6 · 6 ≡ 1).

⚠️
Common trap: Zn is a finite field only when n is prime. For composite n it is merely a commutative ring. For n = 8, no multiple of 2 gives remainder 1, so 2 has no inverse. The same issue means GF(23) under plain mod-8 arithmetic is not a field, which is why extension fields need polynomial arithmetic modulo an irreducible polynomial.

Polynomial arithmetic and GF(23)

Irreducible polynomial — a polynomial that cannot be factored into lower-degree polynomials over the given field.

To build GF(23): start with GF(2) = {0, 1}, choose the irreducible p(x) = x3 + x + 1, and take the eight elements 0, 1, x, x2, x + 1, x2 + 1, x2 + x, x2 + x + 1 (binary 000–111), with arithmetic mod 2 and multiplication also mod p(x). Addition: (x2 + x) + (x + 1) = x2 + 1 since x + x = 0. Multiplication: x(x + 1) = x2 + x; if a product exceeds degree 2, reduce it, e.g. x2(x + 1) = x3 + x2 and, since x3 ≡ x + 1, the remainder is x2 + x + 1. In mod-2 arithmetic subtraction equals addition because 1 + 1 = 0.

GF(28): the field AES lives in

GF(28) balances efficiency and security and matches digital systems. Its elements are degree-<8 polynomials over GF(2):

General element of GF(28)
a7x7 + a6x6 + … + a1x + a0,   ai ∈ {0, 1}

AES uses the irreducible polynomial x8 + x4 + x3 + x + 1 (binary 100011011), and addition is XOR. For a = x6 + x4 + x2 (01010100) and b = x7 + x4 + x3 + x (10011010), the sum XORs to 11001110. Multiplication by x is a left shift plus reduction: 11000000 shifts to 110000000, and XOR with the aligned polynomial gives 010011011.

Where these structures appear

  • GF(28) — AES, in the SubBytes step.
  • Zn ring — RSA, with n = pq the product of two large primes.
  • Cyclic groups — the DLP: one generator (the primitive root) builds the whole group, and given g and h we must find x with gx = h.
  • Elliptic curves over finite fields — ECC, with smaller keys than RSA for comparable security.
  • Finite fields and modular arithmetic — DSA/ECDSA signatures and Diffie-Hellman/ECDH key exchange.
  • Algebraic structures — hash functions, designed for collision and preimage resistance.
💡
Why it matters: AES is invertible and non-linear because GF(28) is a field, and RSA is secure because factoring n is hard while computing φ(pq) is easy once you know p and q.

Key Takeaways

If you remember nothing else from this week, remember these twelve points.

1

Symmetric cryptography uses one shared key for encryption and decryption. It is fast, used for bulk data, but needs a secure way to distribute that key.

2

Kerckhoffs's Principle: security must depend only on the key, never the algorithm. GSM A5/1 and DVD CSS show what happens otherwise.

3

Substitution and transposition are the building blocks of every cipher. Classical ciphers fall to frequency analysis and the Kasiski examination because they preserve language statistics.

4

Confusion and diffusion are Shannon's goals: S-boxes confuse (hide the key), P-boxes diffuse (spread plaintext, producing the avalanche effect).

5

Adversary power defines the attack model: ciphertext-only, known plaintext, chosen plaintext, chosen ciphertext. Chosen ciphertext is strongest, which is why authenticated encryption exists.

6

The one-time pad is the only perfectly secret cipher, but only with a truly random key at least as long as the message, used once. That makes it impractical.

7

Reusing an OTP key is catastrophic: two ciphertexts XOR to the XOR of the plaintexts, so the key cancels and crib dragging recovers the messages.

8

Stream ciphers XOR plaintext with a keystream that must look random; block ciphers process fixed 64- or 128-bit blocks, padding as needed.

9

A Feistel round needs no invertible F (Li+1 = Ri, Ri+1 = Li ⊕ F(Ri, Ki)). DES uses it; AES instead uses an SPN.

10

DES is broken by its 56-bit key (about an hour at 1013 keys per second). 3DES's EDE gives 112 or 168 bits; AES's 128, 192 or 256 bits is the modern standard.

11

Modes matter: ECB leaks patterns, CBC chains with an IV, CTR acts as a parallel stream. IVs and nonces need not be secret but must never repeat under the same key.

12

Authenticated encryption (GCM, CCM) adds integrity to confidentiality, and groups, rings and finite fields are what make it all work, especially GF(28) in AES and Zn in RSA.

Glossary

Every load-bearing term from this week, grouped so you can filter to what you need.

Plaintext
The original, unencrypted message, written p. Built from symbols of an alphabet R.
Ciphertext
The encrypted output, written c. It may use a different alphabet S from the plaintext.
Symmetric cryptography
Encryption and decryption share the same key (ke = kd, or kd derives from ke). Also called shared-key cryptography.
Asymmetric cryptography
Encryption and decryption use different keys, and deriving the decryption key from the encryption key is infeasible. Also called public-key cryptography.
Kerckhoffs's Principle
Security must depend only on the secrecy of the key, never on the secrecy of the mechanism.
Confusion
Making the ciphertext-key relationship complex, so each ciphertext symbol depends on several key symbols. Achieved by substitution.
Diffusion
Spreading each plaintext bit's influence across many ciphertext bits so patterns vanish. Achieved by transposition or permutation.
Avalanche effect
A one-bit change in the input flips about half of the output bits, on average. The practical test of good diffusion.
Perfect secrecy
Given the ciphertext, every possible plaintext is equally likely, so the ciphertext reveals nothing about the plaintext.
Initialization Vector (IV)
A random or pseudo-random first input in a mode such as CBC. Not secret, but never reused under the same key.
Authenticated encryption (AEAD)
A mode that combines confidentiality with integrity protection, such as GCM or CCM, so tampering is detected.
Caesar cipher
A monoalphabetic substitution shifting every letter by a fixed amount. Broken instantly by frequency analysis or brute force.
Vigenère cipher
A polyalphabetic substitution applying a different Caesar shift per position, chosen by a repeating keyword.
One-time pad (OTP)
c = p ⊕ k with a truly random key at least as long as the message, used once. Perfectly secure but impractical.
Stream cipher
Encrypts one bit or byte at a time by XORing the plaintext with a pseudo-random keystream derived from the key. Examples: RC4, ChaCha20.
Block cipher
Encrypts fixed-size blocks, typically 64 or 128 bits, padding short plaintexts. Examples: DES, AES.
Feistel network
A round structure splitting the block in half, XORing one half with a keyed function of the other, then swapping. The round function need not be invertible. Used by DES.
Substitution-permutation network (SPN)
A round structure transforming the whole block with alternating substitution and permutation layers. Used by AES.
S-box
Substitution box: a vetted lookup table mapping input bits to output bits, providing non-linearity and confusion. DES uses eight; AES uses one over GF(2^8).
P-box
Permutation box: a re-ordering of bits that spreads one S-box's output across many later S-boxes, providing diffusion.
DES
Data Encryption Standard. 64-bit blocks, 56-bit key, 16 Feistel rounds, eight S-boxes. Published 1977, standardised 1979, now insecure because the key is too short.
3DES
Triple DES using Encrypt-Decrypt-Encrypt with two keys (112-bit effective) or three keys (168-bit effective). A deprecated stopgap.
AES
Advanced Encryption Standard (the Rijndael cipher). 128-bit blocks, 128/192/256-bit keys, 10/12/14 SPN rounds, arithmetic in GF(2^8). The internet's de-facto block cipher.
Frequency analysis
Breaking a substitution cipher using the characteristic letter frequencies of natural language, such as E being most common in English.
Kasiski examination
Finding a Vigenère key length from the distances between repeated ciphertext patterns, whose common factors are candidate key lengths.
Crib dragging
Attacking a reused one-time pad by guessing a likely word at each offset in P1 ⊕ P2 to reveal fragments of the other plaintext.
Mode of operation
The rule for applying a block cipher to a message longer than one block, such as ECB, CBC, CTR or an authenticated mode like GCM.
Greatest common divisor
The largest integer dividing both a and b, found by the Euclidean algorithm. gcd(a,b)=1 means a and b are relatively prime.
Euler's totient function
φ(n) counts the positive integers below n relatively prime to n. For distinct primes, φ(pq) = (p−1)(q−1).
Discrete logarithm problem
Given primitive root g, prime p and y, finding x with g^x ≡ y (mod p) is hard, while computing y from x is easy.

No terms in this category.

Practice Questions

Cover the answer, write your own version first, then reveal and compare.

Answer, reveal, then tick "Mastered". Your progress is saved.
Q1

Define plaintext, ciphertext, encryption and decryption, then distinguish symmetric from asymmetric cryptography by their keys.

Answer: Plaintext p is the original data from alphabet R; ciphertext c is the encrypted output, possibly from a different alphabet S. Encryption is Encke(p) = c; decryption is Deckd(c) = p. Symmetric (shared-key): ke = kd, or kd derives from ke, so one secret key works both ways, the algorithm shuffling and mapping symbols. Asymmetric (public-key): ke ≠ kd and deriving kd from ke is infeasible, with security based on a hard maths problem.
Q2

State Kerckhoffs's Principle and give two historical violations, explaining what went wrong.

Answer: Security must depend only on the secrecy of the keys, never on the mechanism being secret. GSM A5/1: a proprietary 64-bit-key stream cipher; 1994 weaknesses led to practical ciphertext-only attacks by the late 1990s that recovered the key from intercepted frames. DVD CSS: relied on its algorithm staying secret; once reverse-engineered and published, the copy-protection scheme collapsed.
Q3

Distinguish transposition from substitution, and say which of Shannon's goals each mainly serves.

Answer: Transposition shifts the positions of symbols by a rule, reordering them without changing the symbols; it mainly serves diffusion. Substitution replaces symbols with other symbols by a rule; it mainly serves confusion. Both are key-parameterised and often combined in one cipher.
Q4

A Vigenère ciphertext shows repeated patterns separated by 33 and 27 characters. What is the likely key length and what next?

Answer: This is the Kasiski examination. Factors of 33 are 1, 3, 11, 33; factors of 27 are 1, 3, 9, 27. Common factors are 1 and 3; discard 1 as too weak. The likely key length is 3. Next, split the ciphertext into three groups by key position and frequency-analyse each as a Caesar cipher, using the most common letter (likely E) to recover each key character.
Q5

Why does the one-time pad provide perfect secrecy, and why is it impractical?

Answer: c = p ⊕ k with a truly random key, at least as long as the plaintext, used once. Because k is uniformly random, p = c ⊕ k is uniformly random for any ciphertext, so every plaintext is equally likely and the ciphertext reveals nothing. It is impractical because the key must be distributed securely, and a key as long as the message is hard to generate and cannot sustain frequent communication; it is used only in exceptional settings.
Q6

Show algebraically what happens if an OTP key is reused, and explain crib dragging.

Answer: With C1 = P1 ⊕ K and C2 = P2 ⊕ K, XORing gives C1 ⊕ C2 = (P1 ⊕ K) ⊕ (P2 ⊕ K) = P1 ⊕ P2, since K ⊕ K is all zeros. The attacker now knows P1 ⊕ P2, and because P1 = (P1 ⊕ P2) ⊕ P2, guessing one plaintext reveals the other. Crib dragging guesses a likely word ("the"), tries it at every offset, XORs with P1 ⊕ P2, and looks for readable fragments.
Q7

List the four attack models from weakest to strongest, with an example of each.

Answer: (1) Ciphertext-only: sees only ciphertexts, e.g. intercepted WWII traffic. (2) Known plaintext: has some plaintext-ciphertext pairs, e.g. Bletchley Park's Enigma work using known weather reports. (3) Chosen plaintext: chooses plaintexts and sees ciphertexts, the standard asymmetric model, e.g. BEAST on SSL/TLS. (4) Chosen ciphertext: submits ciphertexts and sees decryptions (an oracle attack), e.g. Bleichenbacher on PKCS#1 v1.5.
Q8

Compare a stream cipher and a block cipher, and explain the role of the keystream.

Answer: A stream cipher encrypts one bit or byte at a time, deriving a keystream b = f(k) from the key and combining it with the plaintext, typically c = p ⊕ b; the keystream must be unpredictable and indistinguishable from true randomness (RC4 broken; Salsa20/ChaCha20 current). A block cipher encrypts fixed-size blocks (64 or 128 bits), returning a same-size ciphertext block and padding short plaintexts (DES insecure; AES current). The keystream is the key-dependent material a stream cipher combines with the message; in a block cipher the round transformations play that role.
Q9

Explain a Feistel round and an SPN round, and say why a Feistel cipher does not need an invertible F.

Answer: A Feistel round splits the block into halves and computes Li+1 = Ri, Ri+1 = Li ⊕ F(Ri, Ki), then swaps; decryption reuses the structure with reversed subkeys. Because F's output is only XORed and the halves are only swapped, F never needs inverting, only good confusion and diffusion. An SPN transforms the whole block through alternating substitution and permutation layers each round, as AES does, so every stage must be invertible.
Q10

Describe a DES round and compute the S-box output for input 010000 using the S[0] rule.

Answer: DES takes 64-bit blocks and a 56-bit key, and the round-key generator makes sixteen 48-bit round keys. The block splits into two 32-bit halves; the right half expands from 32 to 48 bits, XORs with the round key, then splits across eight S-boxes (6 bits in, 4 bits out) to return 32 bits, combined in the Feistel arrangement for sixteen rounds. For input 010000: row = b0 b5 = 00 = 0; column = b1 b2 b3 b4 = 1000 = 8; the cell reads 3, so the output is 0011.
Q11

Calculate the average brute-force time to break DES at 109 and 1013 keys per second.

Answer: DES has 256 keys, about 7.2 × 1016. On average a search finds the key after half the keys, 255. At 109 keys/s: 255 / 109 ≈ 36,028,797 s ≈ 1.2 years. At 1013 keys/s: 255 / 1013 ≈ 3,600 s ≈ 1 hour. Hence DES is insecure and AES uses larger keys.
Q12

Describe AES: block and key sizes, rounds, the four round operations, and the field it uses.

Answer: AES uses a 128-bit block and 128-, 192- or 256-bit keys, giving 10, 12 or 14 rounds, and is a substitution-permutation network, not Feistel. Its rounds are SubBytes (S-box byte substitution), ShiftRows (a permutation), MixColumns (a GF(28) substitution) and AddRoundKey (XOR with the expanded key). It computes in GF(28) with irreducible polynomial x8 + x4 + x3 + x + 1, where addition is XOR, and the S-box maps each byte to its multiplicative inverse plus an affine transformation. Strictly, AES is the standard and Rijndael the cipher.
Q13

Compare ECB, CBC and CTR. Why is ECB unsafe, what does the IV do, and why is CTR parallelisable?

Answer: ECB encrypts each block independently, Ci = Ek(Pi), so identical plaintext blocks give identical ciphertext blocks and repeating patterns stay visible. CBC XORs each plaintext block with the previous ciphertext before encryption, Ci = Ek(Ci−1 ⊕ Pi) with C0 = IV; the IV adds randomness so repeated plaintext encrypts differently, but must never repeat under the same key, and CBC encryption is sequential. CTR encrypts a nonce plus an incrementing counter to make a keystream, so each block is independent and encryption is fully parallelisable and needs no padding; nonce reuse reproduces the keystream and is catastrophic.
Q14

What is authenticated encryption, why is it needed, and what does WEP teach about IV reuse?

Answer: Authenticated encryption (AE), or AEAD when associated data is protected, combines confidentiality with integrity so tampering is detected. Classic modes (ECB, CBC, CTR) only encrypt, leaving them open to oracle and chosen-ciphertext attacks; GCM and CCM fix this. WEP used RC4 with a secret key and a 24-bit IV; the tiny space caused rapid IV reuse, and when the same IV and key recur, RC4 reproduces the same keystream, so an attacker capturing such packets can analyse the keystream, recover plaintext, and eventually the key. Nonces and IVs must never repeat under the same key.
Q15

Explain primitive roots and the discrete logarithm problem, and why the asymmetry matters.

Answer: For a prime p, the highest order of an element modulo p is φ(p) = p − 1; an element of that order is a primitive root (the primitive roots of 19 are 2, 3, 10, 13, 14, 15). The DLP asks: given p, primitive root g, and y, find x with gx ≡ y (mod p). Computing y from x is easy even for large values (exponentiation by squaring), but finding x has no efficient algorithm. That one-way asymmetry secures Diffie-Hellman, DSA and related schemes.
