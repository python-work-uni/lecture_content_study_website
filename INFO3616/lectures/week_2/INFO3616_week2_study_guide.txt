INFO3616 Week 2 – Study Guide
Usability and Security
================================================

OVERVIEW
--------
This week's lecture explores the critical intersection of usability and security, focusing on how human psychology affects security effectiveness. It covers the Principle of Psychological Acceptability, cognitive biases, social engineering techniques, and practical challenges with passwords. The lecture emphasizes that security must be usable to be effective, as humans are often the weakest link in security chains.

------------------------------------------------
SECTION 1: Principle of Psychological Acceptability
------------------------------------------------

Security mechanisms must be easy to use correctly, or users will avoid them or use them incorrectly. A security mechanism should not make accessing a resource more difficult than if no mechanism existed.

Key concept: "A security mechanism should not make a resource more difficult to access than if the mechanism were not present."

Example: File permissions - programmers find them easy to configure, but secretaries may struggle without proper training, leading to either insecure configurations or workarounds that bypass security.

💡 Why it matters: If security is too cumbersome, users will find ways around it, creating worse security than having no mechanism at all.

------------------------------------------------
SECTION 2: Categories of Human Errors
------------------------------------------------

Human errors in security contexts fall into three categories:
1. Manual skill fails: Routine actions performed incorrectly due to distraction/fatigue (e.g., typing errors leading to typosquatting)
2. Following the wrong rule: Correctly following outdated or incorrect procedures (e.g., trusting HTTPS blindly)
3. Cognitive reasons: Not understanding, pretending to understand, or ignoring advice due to perceived inconvenience

Example: Typo squatting - users mistype URLs (like "glthub.com" instead of "github.com"), allowing attackers to register similar domains to steal credentials.

💡 Why it matters: Understanding error types helps design systems that anticipate and mitigate common mistakes.

------------------------------------------------
SECTION 3: Cognitive Biases Affecting Security
------------------------------------------------

Several biases significantly impact security decisions:

• Prospect Theory/Loss Aversion: People fear losses more than they value equivalent gains (e.g., "Your account is frozen!" is more effective than "Get a reward!")
• Anchoring Effect: Initial information disproportionately influences decisions (e.g., fake high prices make real prices seem like bargains)
• Availability Heuristic: People judge likelihood based on how easily examples come to mind (e.g., recent shark attack documentary makes beach visits seem dangerous)
• Clustering Illusion: Seeing patterns in random data (e.g., "hot hands" fallacy in basketball)
• Confirmation Bias: Favoring information that confirms existing beliefs
• Present Bias: Overvaluing immediate rewards over future benefits (e.g., skipping updates to avoid interruption)
• Zero-Risk Bias: Preferring to eliminate one risk completely rather than reducing overall risk more

Example: Privacy paradox - users say they care about privacy but accept cookies without reading policies due to present bias (wanting immediate content access).

💡 Why it matters: Security designs must account for these predictable human tendencies rather than assuming rational behavior.

------------------------------------------------
SECTION 4: Techniques to Influence People
------------------------------------------------

Attackers exploit psychological principles to manipulate behavior:

1. Reciprocity: Feeling obligated to return favors (e.g., fake IT helper asking to install malware)
2. Commitment/Consistency: Wanting to appear consistent with prior commitments
3. Social Proof: Following what others do (e.g., fake survey using coworker names)
4. Like Bias: Complying with people we like
5. Authority: Obeying perceived authority figures (e.g., fake IRS calls)
6. Scarcity: Valuing scarce items more (fear of missing out)

Example: 2007 IRS audit where 62/102 employees provided credentials and changed passwords to a known value when asked by someone claiming to be an auditor.

💡 Why it matters: Recognizing these techniques helps users resist manipulation and designers create better defenses.

------------------------------------------------
SECTION 5: User Conditioning
------------------------------------------------

Repeated exposure to security prompts can create automatic, thoughtless responses ("click-whirr reaction") that undermine security.

Examples:
- Habitually dismissing certificate warnings because most are benign
- Automatically confirming file deletion prompts without reading warnings
- Ignoring update notifications due to frequency

This conditioning can cause users to ignore legitimate warnings when they appear.

💡 Why it matters: Security communications must be designed to avoid creating dangerous automatic responses.

------------------------------------------------
SECTION 6: Passwords - Usability vs. Security
------------------------------------------------

Passwords face three core usability challenges:
1. Entry correctness: Complex passwords are hard to type accurately
2. Memorability: Users forget complex passwords or choose weak ones
3. Disclosure: Users may share passwords accidentally or through deception

Outdated advice to avoid:
- Forcing regular password changes (leads to weaker passwords)
- Simple complexity rules (e.g., "6-12 chars, 1 special, 2 numbers") that reject strong passwords while accepting weak ones

Better approaches:
- Passphrases (Dice method, sentence-first-letters, PAO method)
- Password managers (with awareness of drawbacks)
- Context-appropriate password writing (acceptable for home use, not offices)
- Don't expire passwords unless compromised

Example: Dice method - roll 5d6 to get numbers, map to words from wordlist, create memorable story ("The sizable bowl of tapioca pudding was undoing my patience as I scalded my tongue, cursing my nemesis").

💡 Why it matters: Usable passwords that users will actually use correctly provide better security than theoretically strong passwords that users circumvent.

------------------------------------------------
SECTION 7: UX/UI Design for Security
------------------------------------------------

Effective security design incorporates usability principles:

• Mental Models: Leveraging users' existing understanding of how things work
• Affordance: Design elements that suggest correct use (buttons that look pressable)
• Constraints: Preventing wrong choices through design
• Conventions: Using familiar symbols and patterns
• Defaults: Pre-configuring secure settings (users rarely change them)
• Nudges: Subtle prompts encouraging secure behavior (update reminders, 2FA prompts)

Key principle: Don't blame users when security fails - examine whether the design accounted for human psychology.

💡 Why it matters: Security that works with human psychology rather than against it is more effective in real-world deployments.

================================================
KEY TAKEAWAYS
================================================

• Security must be usable to be effective - if it's too hard to use correctly, users will bypass it
• Psychological acceptability means security shouldn't make access harder than without security
• Human errors fall into manual skill failures, following wrong rules, and cognitive reasons
• Cognitive biases like loss aversion, anchoring, and present bias significantly affect security decisions
• Attackers exploit psychological principles (reciprocity, authority, social proof, etc.) to manipulate users
• User conditioning can create dangerous automatic responses to security prompts
• Passwords face usability challenges in entry, memorability, and disclosure
• Better password approaches include passphrases, password managers, and context-appropriate writing
• Effective security UX/UI design uses mental models, affordance, constraints, and smart defaults
• Security is a systems problem requiring both technical controls and understanding of human behavior
• The best security designs make secure behavior the easy and natural choice for users
