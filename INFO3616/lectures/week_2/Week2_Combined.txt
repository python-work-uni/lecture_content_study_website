## 1. Usability of Security

### Core Concepts
- People are the weakest link in the cybersecurity chain (80%-90% of breaches caused by human error)
- Example: Twitter bitcoin scam 2020 - attacker breached system using admin credentials from Twitter Slack channel
- Users behave in ways engineers/developers don't expect due to varying tech savviness and task focus
- **Usability of Security**: Field exploring solutions that seamlessly help users while ensuring system security
- Connected to usability engineering in human-computer interaction

### Theoretical vs. Effective Security
- Security community historically focused on theoretically secure solutions that weren't user-friendly
- Example: Smart cards vs. Passwords
  - **Smart cards**: Higher security but require additional hardware, complex implementation
  - **Passwords**: Cryptographically weaker but no hardware dependency, low deployment friction
  - Users find passwords "easy to use" - conceptual model matches intuition

## 2. Principle of Psychological Acceptability
*(Defined by J. Saltzer and M. Schroeder)*

**Definition**: A security mechanism should not make a resource more difficult to access than if the mechanism were not present.

**Alternative Definition**: Security mechanisms must account for users' abilities, knowledge, and mental models. Developers often design based on their own expectations, which differs from user reality.

### Examples of Acceptability Challenges

#### Passwords
- Administrators understand need for strong passwords (live "under attack")
- Users often choose predictable passwords (names, places, dictionary words)
- Attack methods: Social engineering, dictionary attacks, brute-force
- **Tension**: Unpredictability (security) vs. Memorability (usability)

#### Patching
- Critical for security but presents user complications:
  - Disruptions: Requires halting work, restarting applications
  - Complexity: Technical knowledge needed
  - Notification Fatigue: Overwhelming frequency of alerts
  - Compatibility Issues: Unexpected errors/malfunctions
- **Solution**: Streamlined processes (e.g., iPhone overnight charging updates)

#### Security Configurations
- Building secure systems isn't enough - must be properly configured
- Users often lack expertise to configure intricate settings
- **Solution**: Default settings that provide desired security levels

## 3. Categories of Human Errors
From safety research community - predictable forms stemming from cognition:

1. **Manual Skill Fails**
   - Actions become skill-based but failures cause accidents/vulnerabilities
   - Examples: Distracted machinery operation, URL typing errors exploited by typo squatters

2. **Following the Wrong Rule**
   - Actions based on rules become erroneous when rules are incorrect
   - Examples: Malfunctioning safety light systems, flawed HTTPS trust assumption

3. **Cognitive Reasons**
   - Users don't understand, pretend to understand, or ignore advice
   - Examples: Finding new protocols cumbersome, viewing updates as disruptive workflow

## 4. Biases in the Human Mind

### Decision-Making Theories
- **Rational Choice Theory**: Maximize utility/satisfaction
- **Expected Utility Theory**: Decisions under uncertainty/risk
- **Limitations**: Humans don't always act rationally - need additional theories:
  - Prospect Theory and Risk Misperception
  - Behavioural Economics

### Prospect Theory & Risk Misperception
(Kahneman & Tversky)
- **Loss Aversion**: Losses felt more intensely than equivalent gains
- **Framing Effects**: Choices influenced by presentation
- **Risk Misperception**: Like activity = high benefit/low risk; Dislike = low benefit/high risk
- **Anchoring Effect**: Initial guess influences judgment (e.g., discounted prices, lottery scams)
- **Availability Heuristic**: Easily recalled information seen as optimal basis for predictions
  - Examples: Shark attack documentaries affecting beach visits, "spray and pray" SMS scams

### Behavioural Economics
Integrates psychology with economic theory to understand actual decision-making:

#### Present Bias & Hyperbolic Discounting
- **Present Bias**: Preference for immediate rewards over delayed larger benefits
  - Examples: Postponing security updates, accepting cookie pop-ups without review
- **Hyperbolic Discounting**: Future deeply discounted, immediate gratification preferred
- **Privacy Discrepancy**: Express privacy concerns but share information online

#### Cognitive Biases
- **Clustering Illusion**: Seeing patterns in random data
  - Examples: "Hot hands" basketball belief, gambler's fallake, phishing email legitimacy
- **Confirmation Bias**: Favoring information that confirms existing beliefs
  - Examples: Flat Earth beliefs, phishing email trust extension
- **Zero-Risk Bias**: Prefer options eliminating specific risk (0%) over greater overall risk reduction
  - Examples: Hazard site cleanup preferences, absolute security solution preference

### Defaults and Nudges
- **Defaults**: Pre-selected settings applied unless actively changed
  - Powerful due to present bias - people choose path of least resistance
  - Security application: Auto-updates, default encryption, privacy restrictions, minimal privileges
  - **Control Paradox**: More privacy controls can lead to less privacy-conscious behavior
- **Nudges**: Subtle, non-coercive prompts guiding better decisions
  - Examples: Update reminders, 2FA prompts, privacy setting suggestions
  - **Caution**: Excessive nudges can cause user conditioning

## 5. Techniques to Influence People
(Robert Cialdini's six categories - can be considered cognitive biases)

1. **Reciprocity**: Tendency to return favors
   - Exploit: Helpful IT caller → suggest installing "new tool" (potential malware)

2. **Commitment and Consistency**: Stick to previous decisions/commitments
   - Exploit: Get security policy commitment → request password for "verification" → ask for "better" guessable password

3. **Social Proof/Validation**: Seek approval of others
   - Exploit: Fake survey with colleague names → victim participates and shares data

4. **Like Bias**: Comply with requests from people we like
   - Exploit: Attacker befriends victim over shared interests → request software trial

5. **Respect to Authority**: Defer to authority figures
   - Exploit: Fake hospital physician call → nurses comply with medication requests (95% compliance)

6. **Scarcity**: Value items perceived as scarce (fear of missing out)
   - Exploit: SMS ads for "limited edition" products → high scam success rate

## 6. User Conditioning
Process of habituating users to react automatically to specific situations ("click-whirr reaction"):

- **Warning Dialogues**: Repeated exposure leads to hasty dismissal without reading
- **Certificate Errors**: Benign errors condition users to ignore all warnings
- **File Deletion**: Recycle Bin prompts create habitual confirmation of permanent deletion

---

## 7. User Education
Efforts to educate users have mixed results:

- **Ineffective**: Mere policy distribution
- **Effective**: Training with feedback and iterations
- **Limitations**:
  - Security language differs from user language (significant learning cost)
  - Users lack intrinsic motivation (focused on primary job responsibilities)
- **Approach**: Design inherently intuitive systems rather than relying solely on education
  - Training should complement, not replace, strong technical/systemic controls

## 8. Deception in Practice

### Social Engineering
Targets humans to disclose credentials, grant access, or compromise security:
- **ATM PIN Scam**: Steal card, pose as bank rep to extract PIN
- **IRS Audit (2007)**: 62/102 employees provided IDs and changed passwords to known value when requested

### Phishing
Predominant 21st century tactic (replaced phone-based social engineering):
- Execute via deceptive emails/messages/websites from reputable sources
- Goal: Trick recipients into providing confidential information
- Examples:
  - 1996: 336 USYD CS students emailed for password validation after suspected break-in
  - Bank attacks: Reuse genuine emails with changed URLs or fake login windows

## 9. Usability and Security of Passwords
Passwords intersect usability, psychology, and security - but may not be optimal due to memory limitations:

### Three Broad Concerns
1. Will user enter password correctly with high probability?
2. Will user remember password (or write it down/choose guessable one)?
3. Will user disclose password to third party (accidentally/purposefully/deception)?

#### Concern 1: Password Entry
- Long/complex passwords difficult to enter correctly
- Since 2010: Rules require lowercase, uppercase, number, special character
- Particularly cumbersome on mobile devices
- **Preference**: Simple passwords for easy entry/error minimization

#### Concern 2: Remembering Passwords
- Standard advice: "Choose a password you can't remember, and don't write it down"
- **Context Matters**:
  - Open office/public place: Strongly discouraged
  - Private space (e.g., bedroom): May be advisable for complex passwords

#### Concern 3: Disclosing Passwords
- Extraction methods: Social engineering, phishing, password entry/storage vulnerabilities
- **Password Entry**: Interface flaws (uncovered PINs), timing attacks on retry counters
- **Password Storage**: If accessed, attackers use brute-force, dictionary attacks, cracking tools
- **Password Managers**: Tools like Keychain, Chrome/Firefox managers - but have limitations

### Outdated Advice
- **Regular Password Changes** (every 30/60/90/180 days): Bad advice because
  - Correctly stored strong passwords remain strong
  - Humans remember few strong passwords → choose weaker ones when forced
  - Passwords become more similar over time as ideas run out
  - **Better**: "Do not expire passwords unless suspected compromised" (UK: 2015, AU: 2017)
  
- **Complexity Rules** (6-12 chars, 1+ special char, 2+ numbers): Inadequate because
  - Accepts weak passwords like "Password123!"
  - Rejects strong passwords like "geyps5aykj0q71c637n9gf4ycg"
  - **Better Approach**: 
    - Check against dictionaries (any language)
    - Check against attacker-tried password lists
    - Check for common substitutions (4→A/R, 3→e, 7→L, etc.)
    - Check for date-like number combinations
  - **Rationale**: Attackers try dictionaries first (cost-efficient); brute-force is last resort

### Balancing Unpredictability and Memorability
Passwords need both properties - creating inherent tension:

#### Solutions to Bridge the Gap
1. **Password Managers**
   - Concept: Strong master password protects encrypted database
   - Benefits: Generate complex passwords, browser integration, copy/paste, mobile availability, cross-device sync
   - Drawbacks: Master password loss = total loss, mobile portability issues, longer workflow, some sites block copy/paste

2. **Passphrases via Dice Method**
   - Concept: Randomly choose 7-12 words from dictionary
   - Benefits: Words easier to memorize, especially when linked to a story
   - Process: 
     - Get word list (e.g., EFF's Long Wordlist)
     - Roll 5 dice → 5-digit number → match to word
     - Repeat for desired word count
     - Combine words into passphrase
   - Example: "54452 61644 63545 53161 42142" → "sizable tapioca undoing scalded nemesis"
   - Mnemonic: "The sizable bowl of tapioca pudding was undoing my patience as I scalded my tongue, cursing my nemesis."
   - **Note**: Word list needs 6^5 = 7,776 entries (all 5-dice combinations)
   - **Drawback**: Significant typing required

3. **Letters-from-a-Sentence Method**
   - Concept: Choose memorable sentence; pick 1-2 letters from each word
   - Example: "Wow! 62 students, all in this memorable class of 2024!" → "W!62s,aitmco2025!"
   - Ideal traits: Upper/lower case, digits (dates/amounts), special characters
   - Extensible: "W!62s,aitmc02o25!"

4. **Person-Action-Object (PAO) Method**
   - Concept: Use visual cues/unusual imagery to stimulate memory recall
   - Process:
     - Choose random place and person
     - Visualize random action/object involving them
     - Establish rule to form password from scenario
   - Example: "Darth Vader riding a pony on Mt Everest" → "DVrapoMtE!"
   - Extensible: "DVr4poMt3!"

### Password Practicalities
- **Theory**: Use different passwords for every site
  - Rationale: Breach on one site can expose credentials reused elsewhere
- **Practice**: Most people have dozens of accounts - impossible to memorize all
- **Password Managers** ideal when:
  - Don't need all passwords constantly (mobility concerns)
  - Understand concepts behind them well
- **Writing Passwords Down**:
  - OK for: Home-only logins, WiFi passwords
  - Not suitable for: Office situations, admin duties (unless family is attacker or many unknown visitors)
- **Hybrid Approach**: Password managers + handful of strong passwords for always-accessible sites

### Future of Passwords
- Alternatives being explored: SMS authentication, authentication tokens, biometrics
- **Example**: Apple, Microsoft, Google promoting "passkeys"
- **Resource**: https://www.smartcompany.com.au/technology/apples-passkeys-update-passwords/

## 10. Creating Secure and Memorable Passwords
### Passphrase and Dice Method
- **Concept**: Randomly choose 7-12 words from dictionary
- **Benefits**: Words easier to memorize, story-linkable, character-substitutable
- **Process**: Standard dictionary + dice for random selection
- **Security**: Reasonably high
- **Drawback**: Requires significant typing

### Letters-from-a-Sentence
- **Concept**: Choose memorable sentence; pick 1-2 letters to create password
- **Example**: "Wow! 62 students, all in this memorable class of 2026!" → "W!62s,aitmc02o26!"
- **Ideal**: Upper/lower case, digits (dates/amounts), special characters
- **Extensible**: "W!62s,aitmc02o26!"

### PAO (Person-Action-Object) Method
- **Concept**: 
  - Use visual cues and unusual imagery to jog memory
  - Choose images of place and person
  - Imagine random action on random object involving them (e.g., Darth Vader riding pony on Mt Everest)
  - Establish rule to form password (e.g., DVrapoMtE!)
  - Easily extended: DVr4poMt3!

### Password Practicalities
- **Different Passwords Per Site**: 
  - Theory: Should use unique passwords everywhere
  - Reality: Site protection methods opaque; one breach risks multiple accounts
- **Writing Passwords Down**:
  - Risk Assessment: Evil actor getting password vs. forgetting and choosing easy one
  - Acceptable when: Home-only logins, WiFi passwords (unless family attacker or many unknown visitors)
  - Generally Not Suitable: Office situations, admin duties
- **Hybrid Solutions May Be Best**:
  - Password managers where effective
  - Handful of strong passwords for always-accessible sites

## 11. Password Complexity Calculations

### Combinatorics: Number of Possible Passwords
Calculate by: (Character Set Size)^(Password Length)

**Example 1**: 6-char lowercase only
- Length (L): 6
- Character Set (C): 26 lowercase letters
- Total: 26^6 = 308,915,776 possible passwords

**Example 2**: 8-char diverse set
- Length (L): 8  
- Character Set (C): 26 lowercase + 26 uppercase + 10 digits + 10 special = 72 characters
- Total: 72^8 ≈ 720 trillion possible passwords

### Entropy: Measuring Password Strength
Entropy (H) = log₂(N) where N = total possible passwords
- Measures uncertainty/randomness in bits
- Higher entropy = more complex/secure password

**Example Calculations**:
- 6-char lowercase: log₂(308,915,776) ≈ 28.2 bits
- 8-char diverse set: log₂(720 trillion) ≈ 49.4 bits

### Dice Method Entropy Calculation
- 6^5 = 7,776 word possibilities per dice roll
- 6-word passphrase: 7,776^6 ≈ 2.21 × 10²³ possibilities
- Entropy: log₂(2.21 × 10²³) ≈ 77.55 bits

## 12. Summary and Key Takeaways

### Core Principles
1. **Psychological Acceptability**: Security must align with user capabilities and expectations
2. **Human-Centered Design**: Security solutions should minimize user burden while maintaining protection
3. **Bias Awareness**: Understanding cognitive biases enables better security design and user protection

### Effective Security Strategy
- **Defaults**: Secure pre-configured settings (updates, encryption, privacy)
- **Nudges**: Subtle prompts for secure behaviors (updates, 2FA, privacy review)
- **Design Process**: Integrate stakeholder perspectives - don't rely solely on user education
- **Password Strategy**: Balance unpredictability and memorability through:
  - Password managers (understanding limitations)
  - Passphrase methods (Dice, sentence-based, PAO)
  - Context-appropriate password recording

### Critical Reminders
- Don't blame users when security fails - examine system design
- Avoid assuming users have developer-level experience/stress tolerance
- Psychological factors must inform security feature design
- User education complements but doesn't replace strong technical/systemic controls
