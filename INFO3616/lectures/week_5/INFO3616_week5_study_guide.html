Two Keys, One Secret: How Public-Key Cryptography Solves What Symmetric Cannot

Symmetric cryptography gave us fast, strong ciphers, but it left a hole: two strangers who have never met must still agree on one shared secret key, over a channel an attacker may be watching. This week we change the paradigm. Each person gets a public key anyone can use and a private key only they hold, built from mathematical problems we believe are one-way unless you hold a trapdoor. We derive RSA from scratch, break it in every way the lecture lists, repair it with padding, glue it to symmetric ciphers as hybrid encryption, exchange keys with Diffie-Hellman, watch that exchange fall to a person in the middle, survey elliptic-curve cryptography, and finish on the quantum cliff edge: Shor, Grover and post-quantum cryptography.

Read this first: public-key cryptography is a trapdoor one-way function in disguise. Going forwards is easy (encrypt, verify, compute a key) and going backwards is believed to be computationally infeasible, unless you possess a secret extra piece of information, the trapdoor. Hold that single idea and every scheme this week, RSA, Diffie-Hellman and ECC, is just a different hard problem wearing the same coat.

The Key-Distribution Problem

Symmetric cryptography works beautifully once two parties share a key, and falls apart precisely because they have to get that key to each other first.

Last week we built symmetric cryptography: one shared key does both encryption and decryption, and the cipher scrambles the message using two classic tricks, substitution (which creates confusion) and permutation (which creates diffusion). This is efficient and it protects the bulk of the internet's traffic. But it leaves an awkward gap.

Enter public-key cryptography, also called asymmetric cryptography. It is a genuine change of paradigm in two respects:

Symmetric cryptography

  • One shared key for both directions.
  • Built from substitution (confusion) and permutation (diffusion).
  • Fast, ideal for bulk data.
  • Assumes the key is already shared over a secure channel.

Public-key cryptography

  • Two distinct keys: one to encrypt, one to decrypt.
  • Built from mathematical functions with special properties beyond substitution and permutation.
  • Slower, used to establish keys and to sign.
  • Lets strangers who never met communicate securely.

The key insight is that each participant holds a public key, which is distributed freely, and a private key, which is kept secret. Anyone may use the receiver's public key to encrypt a message, but only the receiver, the owner of the matching private key, can decrypt it. You no longer have to arrange a secret meeting first; you can publish the half of the key pair that is safe to publish.

💡
Why it matters: every time your browser opens an https connection it solves the key-distribution problem this way. It fetches the server's public key, uses it to agree on a symmetric session key, and then switches to fast symmetric encryption for the rest of the conversation. Public-key cryptography is the key-exchange machinery, not usually the bulk cipher.

One honest caveat runs through this whole week. Public-key cryptography rests on mathematical problems that are believed to have the required properties. A number of candidate problems are believed to be hard, but there is no proof yet. We build on computational assumptions, not mathematical certainty.

Public-Key Cryptography: Two Keys, Two Jobs

A key pair does two different jobs, and the direction you apply the keys in is what decides whether you get secrecy or proof of origin.

The essential steps of using public-key cryptography are simple to state:

  1. Generate a pair of keys per user: a private key and a public key.
  2. Publish the public key as a publicly accessible file. Keep the companion private key confidential.
  3. Confidentiality — if Bob wants to send a secret to Alice, he encrypts with Alice's public key, and Alice decrypts with her private key. Only Alice has that private key, so only Alice can read it.
Confidentiality — protect the message
encrypt with the receiver's PUBLIC key  →  only the receiver's PRIVATE key can decrypt
Origin authentication — prove the sender
encrypt with the sender's PRIVATE key  →  anyone with the sender's PUBLIC key can decrypt/verify

Notice how clever the mirror image is. In confidentiality, anyone can encrypt but only the receiver can decrypt. In origin authentication, anyone can decrypt but only the sender could have encrypted. That second property is exactly what a digital signature gives you, and signatures are a key application of public-key cryptography. In the authentication case, not only Alice but anyone holding Bob's public key can verify the origin of the message.

⚠️
Common trap: those two uses are conceptual. In practice we do not simultaneously use the same key pair for both confidentiality and origin authentication. Real systems use separate key pairs for encryption and for signing, and real signatures hash the message first rather than encrypting it whole.

🧠
Remember: Diffie-Hellman is the odd one out. It is famous, but it is not used for encryption and cannot sign. Its one job is key exchange. DSS is the other specialist: signature only.

Requirements and Trapdoor One-Way Functions

For a scheme to count as public-key cryptography, six conditions must hold, and together they describe a single object: a trapdoor one-way function.

These are the conditions an algorithm must meet to be usable in public-key cryptography. Read them as a contract between the legitimate users and the adversary.

  1. Easy key generation — it is computationally easy for a party B to generate a key pair (public key PUb, private key PRb).
  2. Easy encryption — it is computationally easy for a sender A, knowing the public key and the message M, to produce the ciphertext C = E(PUb, M).
  3. Easy decryption — it is computationally easy for the receiver B to decrypt using the private key: M = D(PRb, C) = D[PRb, E(PUb, M)].
  4. Private key stays private — it is computationally infeasible for an adversary who knows the public key PUb to determine the private key PRb.
  5. Recovering the message is hard — it is computationally infeasible for an adversary who knows the public key and a ciphertext C to recover M without the private key.
  6. Optional: order freedom — the two keys can be applied in either order. This is beneficial but not essential for all applications.

Requirements 1 to 5 aggregate into one demand: we want a trapdoor one-way function. Before defining that, meet its simpler cousin.

One-way function — a function mapping a domain into a range such that every function value has a unique inverse, with the property that calculating the function is easy while calculating the inverse is infeasible. In symbols, Y = f(X) is easy, but finding X from Y is not.
Trapdoor one-way function — a function that is relatively easy to compute in one direction but computationally difficult to invert without additional information called the trapdoor. With the trapdoor, inversion becomes easy again.
The three faces of a trapdoor function
Y = fk(X)  →  easy when k and X are known
X = fk−1(Y)  →  easy when k and Y are known
X = fk−1(Y)  →  infeasible when k is unknown

Here k is the trapdoor, which in every scheme this week is simply the private key. The corollary is immediate and worth stating plainly: it must be computationally infeasible to compute the private key from the public key, without the trapdoor information.

✅
Key idea: the six requirements are not six separate features. They are the two directions of one function: forward easy for everyone, backward easy only for the holder of the trapdoor, and backward infeasible for the attacker. Every scheme we meet is just a concrete choice of such a function.

The Two Classic Trapdoor Problems

Cryptography keeps proposing hard problems; this week's two candidates are the discrete logarithm problem and the RSA problem, and both flip from infeasible to easy the moment you hold the private key.

1. Discrete logarithms in modular arithmetic

Diffie and Hellman, back in 1976, observed that it is computationally infeasible to compute a discrete logarithm modulo p, for certain primes p.

Discrete Logarithm Problem (DLP) — given y, p and g satisfying y = gx mod p, where p is a prime number and g is a primitive root of p, how do we find x?

Going forwards is easy: pick x, compute gx mod p. Going backwards is the hard part: see y, and work out which exponent x produced it. There is no known efficient method for large primes.

2. The RSA problem

Independently, it is believed computationally impossible to compute the eth root of an integer modulo n, for certain n.

RSA problem — when c = me mod n and the values c, e and n are known, can you find the original message m?
The two candidates side by side
Forward: y = gx mod p     Backward: find x  (discrete log)
Forward: c = me mod n     Backward: find m  (eth root)

Both share the property that "computationally infeasible" becomes "easy to compute" once you have the additional information, the private key. That is what makes them trapdoors rather than plain one-way functions: the house has a back door, and only the legitimate owner carries its key.

🧠
Remember the pairing: Diffie-Hellman relies on the discrete logarithm problem. RSA relies on the difficulty of finding an eth root, which is equivalent in effort to factoring the modulus. When an exam asks which scheme rests on which problem, this is the pair to reach for.

Maths Toolkit: Coprime Numbers, ℤ*ₙ and Euler's Totient

Three small ideas, coprimality, the multiplicative group ℤ*ₙ, and Euler's totient function, are all the number theory RSA actually needs.

You cannot read RSA's key generation without these. The good news is that each one is small and concrete.

Coprime numbers

Two numbers are coprime if they share only one divisor, and that divisor is 1. In other words, their greatest common divisor is 1, written gcd(a, b) = 1.

Worked example
8 = 2 · 2 · 2     27 = 3 · 3 · 3     no shared factor → 8 and 27 are coprime

The group ℤ*ₙ

We define ℤ*n as all non-negative integers less than n that are coprime to n. This half-open set has a lovely property: it forms an Abelian group under multiplication (modulo n). Being a group means you can multiply any two members, get another member, and every member has a multiplicative inverse inside the set.

Example: n = 12
ℤ*12 = {1, 5, 7, 11}     (the integers below 12 that share no factor with 12)

Euler's totient function

Euler's Phi function, also called the totient function, simply counts the elements of ℤ*n. For n = 12 we saw four elements, so ɸ(12) = 4.

Counting elements one by one would be hopeless for the enormous numbers RSA uses, but there is a shortcut that RSA leans on entirely. When n is the product of two distinct primes p and q with p ≠ q, then:

Euler's totient for a product of two primes
ɸ(n) = (p − 1)(q − 1)

This is why RSA can compute ɸ(n) instantly for a modulus with hundreds of digits: knowing the two prime factors is enough. An attacker who cannot factor n cannot compute ɸ(n), and that gap is the whole game.

Fast exponentiation, and the modular inverse

Two computational facts keep RSA practical. First, exponentiation in ℤ/nℤ is fast. Using the technique of exponentiation by squaring, you can compute a number as enormous as me mod n with only a few hundred multiplications, even when the exponents have thousands of bits.

Second, you can always find a modular inverse. If e is coprime to ɸ(n), there exists a unique d with d ≡ e−1 mod ɸ(n), meaning e · d ≡ 1 mod ɸ(n). Finding that d is easy once you know ɸ(n), and hard otherwise, again because it needs the factorisation.

RSA Key Generation

RSA keys are made from two secret primes, and the instant you multiply them into a modulus the primes themselves must be destroyed.

The Rivest-Shamir-Adleman (RSA) scheme was developed by Ron Rivest, Adi Shamir and Len Adleman at MIT in 1977, and it remains the most widely accepted and implemented general-purpose approach to public-key encryption. RSA is defined for a particular class of functions and lets us build a trapdoor function. It encrypts plaintext in blocks, with each block having a binary value less than some number n.

Here is the full key-derivation recipe. In practice we use very large numbers, but the shape is exactly this.

  1. Choose two distinct primes p and q, with p ≠ q.
  2. Compute the modulus n = p · q. We call n the modulus.
  3. Compute Euler's totient ɸ(n) = (p − 1)(q − 1).
  4. Choose the public exponent e with 1 < e < ɸ(n) and gcd(e, ɸ(n)) = 1, i.e. e is coprime to ɸ(n). One convenient way: choose e > max(p, q) to be prime. Testing whether an integer is prime is fast.
  5. Compute the private exponent d such that d ≡ e−1 mod ɸ(n), i.e. d is the modular inverse of e.
  6. Now we have the keys: (e, n) is the public key, and (d, n) is the private key. At this point we delete p, q and ɸ(n) permanently.
  7. Encryption: c = me mod n.
  8. Decryption: m = cd mod n.
The keys RSA produces
Public key = (e, n)      Private key = (d, n)      Secret, then destroyed: p, q, ɸ(n)
⚠️
Common trap: "delete p, q and ɸ(n) permanently" is not a throwaway line. If any of them leaks, an attacker can compute ɸ(n), then d, and decrypt everything. The security of the whole scheme lives in the secrecy of the factorisation.

How RSA Encrypts and Why It Works

RSA works because raising to a power modulo n is cheap in one direction and believed hopeless in reverse, and because the two exponents cancel inside the ring of integers modulo n.

RSA encryption is defined as a function from ℤ/nℤ to ℤ/nℤ. Recall that ℤ/nℤ is a commutative ring. Crucially, n is not prime, but a product of two primes. That choice of playground is deliberate:

⚡ Forwards is fast

Exponentiation in ℤ/nℤ is fast (exponentiation by squaring), so computing c = me mod n is very efficient. This satisfies the requirement that encryption be easy.

🧱 Backwards is hard

Getting the eth root of c to recover m, without d, is believed to be infeasible. This satisfies the requirement that recovery be hard.

Why does decryption recover the message? Because of how d was chosen. We set e · d ≡ 1 mod ɸ(n), so e · d = 1 + k·ɸ(n) for some integer k. Applying both exponents in turn therefore returns the message to its starting point:

Correctness of RSA
(me)d = me·d = m1 + k·ɸ(n) ≡ m1 ≡ m  (mod n)
🧠
Remember: the encryption exponent and the decryption exponent are modular inverses of each other modulo ɸ(n). That single congruence, e · d ≡ 1 mod ɸ(n), is the heart of RSA. Everything else is bookkeeping.

Two honest limitations

First, RSA cannot uniquely encrypt values greater than n. Such values are reduced modulo n, so decryption returns a value less than n, not the original input. This is why RSA encrypts in blocks smaller than n.

Second, by its mathematical nature RSA can encrypt only numbers, more specifically only numbers in ℤ/nℤ. That means sender and receiver must agree on a mapping of numbers to characters to make it useful: a ⇒ 1, b ⇒ 2, and so on. This is an inconvenience the lecture returns to when it explains why we use padding and hybrid encryption.

Worked RSA Examples

Numbers make RSA click, so walk through all four examples the lecture gives, including the one that hides in the quiz.

Toy example: p = 7, q = 11

🔧 Build the keys

1) p = 7, q = 11.
2) n = p · q = 77.
3) ɸ(n) = (7 − 1)(11 − 1) = 6 × 10 = 60.
4) Pick e = 13: it is less than 60 and coprime with 60.
5) Find d with 13d mod 60 = 1, so d = 37.

🔐 Encrypt and decrypt

Keys: public (13, 77), private (37, 77).
Let the plaintext be 3 and the ciphertext c.
7) Encryption: c = 313 mod 77 = 38.
8) Decryption: m = 3837 mod 77 = 3. ✓

Lecture notes example: p = 17, q = 11, M = 88

Key generation
n = 17 × 11 = 187    ɸ(n) = (17 − 1)(11 − 1) = 16 × 10 = 160
Choose e = 7 (coprime to 160, and e < ɸ(n))
Solve d × 7 ≡ 1 mod 160:   23 × 7 = 161 = (1 × 160) + 1 → d = 23
PU = {7, 187}    PR = {23, 187}
Encrypt then decrypt
Encryption: C = 887 mod 187 = 11
Decryption: M = 1123 mod 187 = 88 ✓

Quiz-style example: p = 11, q = 17, e = 7

Given p = 11, q = 17 and e = 7, find the ciphertext for plaintext M = 88.

Encryption without needing d
n = pq = 187    ɸ(n) = (11 − 1)(17 − 1) = 160
C = Me mod n = 887 mod 187 = 11

You can encrypt knowing only the public key, so you do not need d or even ɸ(n).

Recover a private key: e = 31, n = 3599

Here the question runs backwards and is the best test of whether you understand the machinery.

  1. Factor the modulus. 3599 = 59 × 61, so p = 59 and q = 61.
  2. Compute the totient. ɸ(n) = (59 − 1)(61 − 1) = 58 × 60 = 3480.
  3. Solve the congruence. We need ed ≡ 1 mod ɸ(n), i.e. 31d ≡ 1 mod 3480.
  4. Check candidates. 31 × 3031 mod 3480 = 1, so d = 3031. As a sanity check, 31 × 2412 mod 3480 = 1692, not 1.
✅
Do this in the exam: for "find the private key" questions, always start by factoring n into two primes, then compute ɸ(n) = (p − 1)(q − 1), then solve ed ≡ 1 mod ɸ(n). Factorisation is the only hard step, which is exactly why real RSA uses primes with hundreds of digits.

The Security of RSA

RSA's security rests on two believed-hard problems, finding the eth root and factoring the modulus, and both crumble if the primes are chosen carelessly.

The security of RSA rests on two facts:

🌱 The eth root

Obtaining the eth root of a number in ℤ/nℤ is computationally infeasible unless you know d.

🧩 Factoring n

Factoring n = pq, for very large p and q, is computationally infeasible. If it were easy, d could be calculated trivially from ɸ(n).

That is true for now. The lecture flags the quantum risk: Australia plans to get rid of RSA by 2030. Keep that in your back pocket for the post-quantum section.

Key size is a balance

The defence against brute-forcing d is to use a large key space. The larger the number of bits in d, the more secure the system becomes. But increasing key size slows everything down, because key generation, encryption and decryption all get more computationally complex. Security and performance pull in opposite directions.

Rules for choosing p and q

RuleReason
p and q must be very largeSo that factoring n = pq is computationally infeasible.
Encoding n needs thousands of bitsRSA key lengths of 2048 bits and more are the secure norm today.
p and q must not be too close togetherClose primes allow forms of fast factoring.
Never choose small primesSmall factors fall instantly to trial division and related attacks.

In practice there are many more limiting factors, and not every key is a good key. The lecture is blunt about the consequence: it is not recommended to implement RSA yourself for use in production environments. Use a vetted library written by people who have already been bitten by the corner cases.

⚠️
Common trap: students often say "RSA is secure regardless of key size". That is false. A 512-bit RSA key is breakable today; only key sizes above 2048 bits are considered safe. Security is a function of key size, not an intrinsic property of the algorithm.

Attacks on RSA

There are five recognised families of attack on RSA, and only one of them is the obvious brute force you might guess first.

The lecture lists five possible approaches to attacking RSA. Learn them as a set, because exam questions tend to ask you to name or distinguish them.

💥 Brute force

Try all possible private keys. Feasible only against smaller keys, which is exactly why key size matters.

➗ Mathematical attacks

Several approaches exist, but they are all equivalent in effort to factoring the product of two primes. Breaking the maths means factoring n.

⏱️ Timing attacks

These depend on the running time of the decryption algorithm. Tiny variations in how long operations take can leak information about the key.

🔌 Hardware fault-based attacks

Involves inducing hardware faults in the processor that is generating digital signatures, then exploiting the faulty outputs.

🎯 Chosen ciphertext attacks

Exploits properties of the RSA algorithm itself, such as malleability, which the next section unpacks in detail.

🧠
Memory hook: Brute, Mathematical, Timing, Hardware, Chosen ciphertext. "Big Maths Teachers Have Class." Five families, one mnemonic.

Never Use RSA Without Padding

Textbook RSA leaks structure, so an attacker can tamper with a ciphertext and predict the effect, and it produces identical ciphertexts for identical plaintexts, which is exactly what padding fixes.

Malleability: tampering with a predictable outcome

Malleability — an attacker can modify a ciphertext in a predictable way so that the decrypted plaintext is also changed in a related, predictable way, all without knowing the private key.

Here is the attack, step by step.

  1. Intercept. The attacker, Eve, listens for a ciphertext c that she wants to crack.
  2. Modify predictably. She computes a modified ciphertext and sends it to the receiver: c' ≡ c · re mod n, for example using r = 2, so c' ≡ c · 2e mod n.
  3. Collect the decryption. The receiver decrypts c' and obtains r·m (for example 2m):
Why the tampering works
(c')d mod n ≡ (c · re mod n)d mod n ≡ r·m

The result looks valid, not random. The receiver cannot detect that the message was altered. The detailed derivation in the notes shows why:

Full derivation
(c')d = (c × re)d = (me × re)d = me×d × re×d = m × r

since (me)d mod n must equal m1 mod n. Eve then obtains the original plaintext by simply dividing the result by r.

ℹ️
Context: note the Chosen Ciphertext Attack (CCA) assumption here. We are assuming the attacker has the ability to get c' decrypted by the victim. This is a realistic model: think of an attacker who can submit tampered ciphertexts to a server and observe whether decryption succeeds.
🧠
Key idea: vanilla RSA preserves structure, so tampering yields a predictable, manipulated plaintext rather than garbage. This is a generic result: the multiplier can be any number, not just 2.

No semantic security

RSA has a second, deeper problem.

Textbook RSA has none. An attacker can forward-compute likely messages and see whether they match a given ciphertext. And because RSA is deterministic, the same plaintext encrypted with the same public key always produces the same ciphertext, an adversary can encrypt likely messages and compare the results. Deterministic encryption with a public key means the scheme is open to Chosen Plaintext Attacks (CPA). The root cause is a lack of randomness.

The solution: padding

Modern RSA implementations incorporate sophisticated padding, which adds randomness on encryption and removes it on decryption. With padding, the same plaintext encrypted multiple times produces different ciphertexts, restoring semantic security. The padding is crucial, but non-trivial to get right. Today we use OAEP (Optimal Asymmetric Encryption Padding).

The fix in one line
textbook RSA is deterministic → add random padding → encrypt the padded block → strip padding after decryption

Hybrid Encryption

Public-key encryption is slow and clumsy, so almost every real system uses it only to deliver a symmetric key and then switches to a fast symmetric cipher.

RSA has two key problems that stop us using it for bulk data:

🐌 Problem 1: it is slow

Public-key cryptography is slow, especially with the long keys needed for security. RSA is roughly 100 to 1000 times slower than AES.

🔤 Problem 2: it needs a mapping

It requires a mechanism to map characters to numbers for practical use, adding complexity to every message.

The solution is hybrid encryption. Public-key encryption like RSA quickly establishes a symmetric key, and subsequent communication is secured with symmetric encryption. Almost all public-key encryption in practice uses hybrid encryption, so this is one of the most practically important ideas of the week.

  1. Generate a random symmetric key k.
  2. Encrypt the actual message with the symmetric key: cm = Enck(m).
  3. Encrypt the key with the receiver's public key: ck = EncPK(k).
  4. Send the pair (ck, cm). The receiver decrypts ck with the private key to recover k, then decrypts cm.
Random key k→ Enck(message) = cm→ EncPK(k) = ck→ Send (ck, cm)
✅
Exam tip: the classic true/false statement is "Hybrid cryptography uses asymmetric cryptography to establish a symmetric key between two parties that can be used for subsequent communications." The answer is TRUE. It assumes the receiver's public key is already shared with the sender.

Diffie-Hellman Key Exchange

Two people who share nothing secret can each combine a public value with their own private value and arrive at the same secret number, and an eavesdropper who sees everything still cannot.

There are many public-key cryptosystems besides RSA, and one of the best known is not used for encryption at all. It answers a sharper question: can Alice and Bob establish a shared symmetric key without a purely listening attacker being able to obtain it? Finite fields come to our aid.

Diffie-Hellman is the first published algorithm that implemented the public-key (trapdoor) principle, published by Diffie and Hellman in 1976. Its best-known application is secure key exchange, which can then feed symmetric encryption. It also became the basis for ElGamal encryption/decryption and the Digital Signature Standard (DSA/DSS).

Its security relies on the difficulty of computing discrete logarithms. It is considered computationally infeasible to compute a discrete logarithm over a finite field, provided the prime defining the field is sufficiently large. With additional information, the private key, the computation becomes feasible. And we have already met the problem it rests on.

Recap: Discrete Logarithm Problem (DLP)
Given y, p, g with y = gx mod p, where p is prime and g a primitive root of p, find x.

Finite fields revisited: primitive roots

Let p be prime. We know ℤ/pℤ is a finite field, whose elements are {0, 1, …, p − 1}. You can define a new group over the non-zero numbers, ℤ*p = {1, …, p − 1}, with multiplication. There is a special element g ∈ ℤp such that every number a ∈ ℤ*p is a power of g. So:

Primitive root (generator)
ℤ*p = {g0 = 1, g1, g2, …, gp−2}    g is called a primitive root of ℤp

The Diffie-Hellman algorithm

Alice and Bob have already agreed on two publicly known values: a prime p, and a primitive root g of p. Then:

Alice

  • Choose a random value a < p (kept private).
  • Compute X = ga mod p.
  • Send X to Bob.
  • Compute the shared key k = Ya mod p.

Bob

  • Choose a random value b < p (kept private).
  • Compute Y = gb mod p.
  • Send Y to Alice.
  • Compute the shared key k = Xb mod p.

Both sides obtain the same k value, and the algebra shows exactly why:

Why both sides agree
Ya mod p = (gb)a = g(ab) = (ga)b = Xb mod p

The numbers a and b are the private keys of A and B, kept secret. The values X and Y are publicly exchanged, so they act as the public keys. Each user selects a random integer less than p and computes their public value. After the exchange, each independently calculates the same key K = Ya mod p = Xb mod p, typically used as a symmetric key.

Why a passive attacker fails

An adversary who can only passively observe the exchange knows p, g, X and Y, and is forced to take a discrete logarithm to recover one of the private keys. For instance, to find b the adversary needs to solve Y = gb mod p, which is the DLP. For large primes this is computationally infeasible, so the shared secret K is considered secure from a passive observer. DH key exchange therefore allows key establishment over an insecure channel, under a passive attacker.

The Person-in-the-Middle Attack

Diffie-Hellman never checks who is on the other end, so an active attacker can quietly run two separate exchanges and sit in the middle reading everything.

While Diffie-Hellman is secure against passive eavesdroppers, it is vulnerable to a person-in-the-middle attack (often called man-in-the-middle). When the attacker is active, standard DH key exchange is not secure.

The attacker first observes the publicly shared values of p and g, then generates two separate sets of private and public key pairs. Positioning themselves between Alice and Bob, the attacker intercepts and replaces the messages transmitted during the key exchange:

  1. Attacker sets up two identities. Choose random values c, d < p; compute X' = gc mod p and Y' = gd mod p; send X' to Alice and Y' to Bob.
  2. Alice thinks she is talking to Bob. She chooses random a < p, computes X = ga mod p, sends X, and computes k1 = (X')a mod p.
  3. Bob thinks he is talking to Alice. He chooses random b < p, computes Y = gb mod p, sends Y, and computes k2 = (Y')b mod p.
  4. Attacker completes both exchanges. The attacker computes k1 = Xc mod p and k2 = Yd mod p.

By doing this, the attacker performs two independent key exchanges, one with Alice and one with Bob. At the end, the attacker shares a separate secret key with each of them, K2 with Alice and K1 with Bob, and can use these keys to intercept, read, and replace messages on future communications.

The structural flaw
the protocol does NOT authenticate the participants  →  Alice cannot tell Bob's key from the attacker's key

The key exchange protocol is vulnerable because it does not authenticate the participants. Nothing in the messages proves who generated X or Y, so a forged value is indistinguishable from a genuine one.

The fix: authentication, signatures and certificates

The solution is digital signatures and public-key certificates. Each party signs their public key with their private key, so the other party can verify the authenticity of the exchanged key with the corresponding public key. That guarantees the exchanged values have not been tampered with by an attacker. The result is called signed Diffie-Hellman, and the machinery of certificates, a public key plus a trusted signature binding it to an identity, is the basis of Public Key Infrastructure (PKI), which the lecture discusses next time.

Elliptic Curve Cryptography (Non-Examinable)

ECC keeps the public-key idea but swaps the group: instead of multiplying numbers modulo a prime, it adds points on a curve, and the same discrete-log hardness returns with far shorter keys.

This section is non-examinable and for information only. Elliptic curves E(a, b) are defined by y2 = x3 + ax + b. Over a finite field they produce a finite set of points, and a group can be defined on those points using point addition, giving a Discrete Logarithm Problem for elliptic curves (ECDLP). Because ECDLP is harder per bit than the classical DLP, ECC reaches the same security with much shorter keys, typically 256 bits (very common) or 384 bits (high security).

Diffie-Hellman (classical)

  • Group: ℤ*p.
  • Operation: multiplication mod p.
  • Computation: ak mod p.
  • Security from the DLP.

ECC (same idea, new group)

  • Elements: points on a curve over ℤp.
  • Operation: point addition, kP = P + P + ⋯ + P.
  • Given P and Q = kP, recovering k is infeasible.

The idea, and a worked check

Add an imaginary point O, the point at infinity, as the identity. To add points P and Q, draw the line through them, find where it meets the curve a third time, and reflect that point across the x-axis. The negative of a point is its reflection, −P = (x, −y), and three points on a line sum to zero, P + Q + R = 0. When P = Q, use the tangent at P to get 2P; repeated doubling computes kP efficiently.

Over a finite field the curve is Ep(a,b): y2 = x3 + ax + b (mod p). On E23(1,1): y2 = x3 + x + 1 (mod 23), the point (9,7) lies on the curve because 72 ≡ 93 + 9 + 1, i.e. both sides equal 3 (mod 23). The curve is all such pairs plus O. ECC also works over binary fields GF(2m) (recall AES), where elements are polynomials, arithmetic is modulo an irreducible polynomial, and the curve is y2 + xy = x3 + ax2 + b.

For the ECDLP, take Q = kP with P, Q ∈ Ep(a,b) and k < p; finding k is hard. On E23(9,17) the discrete log of Q = (4,5) to base P = (16,5) can only be brute-forced:

Walking the group to reach Q
P=(16,5) → 2P=(20,20) → 3P=(14,14) → 4P=(19,20) → 5P=(13,10)
→ 6P=(7,3) → 7P=(8,7) → 8P=(12,17) → 9P=(4,5) ⇒ k = 9

ECDH and EC ElGamal

In ECDH the parameters a, b, q, G, n are system-wide; G is a base point and n its order (nG = O). Each side computes a public point PA = nA × G or PB = nB × G and keeps the scalar secret; an attacker with PA and G cannot compute nA. Both reach the same key:

ECDH shared secret
nA ∗ PB = nA ∗ (nB ∗ G) = nB ∗ (nA ∗ G) = nB ∗ PA

EC ElGamal encrypts a message encoded as a curve point Pm: Alice sends Cm = {kG, Pm + kPB} with a fresh random k, and Bob recovers Pm = (Pm + kPB) − nB × (kG). The term kPB is a one-time mask, the embedded ECDH shared secret, and it cancels because nB × (kG) = k × (nBG) = kPB. Reusing k lets an attacker combine two ciphertexts and strip the mask, so k is fresh per message.

ECC's security depends on the hardness of finding k given kP and P, and its keys are far shorter than RSA's for the same strength, so "a considerably larger key size can be used for ECC compared to RSA" is FALSE.

✅
Key idea: ECC is the same trapdoor story in a richer group. The hard problem is the elliptic-curve discrete log, the payoff is small keys, and it powers ECDH and EC ElGamal. It is non-examinable, so focus on the big picture.

Post-Quantum Cryptography

Quantum computers do not break all cryptography equally: they gut the asymmetric schemes this whole week is built on, while only halving the strength of symmetric ciphers.

Post-Quantum Cryptography (PQC) focuses on developing algorithms that remain secure even in the presence of quantum computational power. The threat splits neatly along the symmetric/asymmetric fault line.

Asymmetric: badly broken

  • Shor's algorithm can efficiently factor large numbers and compute discrete logarithms.
  • So RSA, Diffie-Hellman key exchange and ECC will be vulnerable.
  • The hard problems we relied on all week stop being hard.

Symmetric: merely weakened

  • Grover's algorithm gives only a quadratic speedup for brute-forcing symmetric keys.
  • A symmetric key's effective security level is halved.
  • A 256-bit key offers security comparable to 128 bits against a quantum adversary.
  • Doubling key sizes is the solution.
The quantum scoreboard
Shor: factor + discrete log → RSA / DH / ECC broken
Grover: quadratic speedup → symmetric security halved → double key size

This is why the lecture says Australia plans to get rid of RSA by 2030, and why "this is for now" was attached to RSA's security. A record of encrypted traffic captured today could be decrypted later once a capable quantum computer exists.

The candidate replacements

🔷 Lattice-based

Based on the hardness of problems related to lattice structures in high-dimensional spaces.

🧱 Code-based

Relies on the hardness of decoding random linear codes.

#️⃣ Hash-based

Leverages the security properties of hash functions for cryptographic tasks.

🧠
Remember: Shor kills the asymmetric world (factorisation, discrete logs, elliptic curves) and Grover merely tires the symmetric world (halve the security level, double the keys). If an exam asks which is more vulnerable to quantum computing, the answer is asymmetric cryptography.

Key Takeaways

If you remember nothing else from this week, hold on to these twelve points.

1

Public-key cryptography solves the key-distribution problem. Two parties who have never met can communicate securely because a public key can be published while the private key stays secret.

2

One key pair, two jobs. Encrypt with the receiver's public key for confidentiality; encrypt with your own private key for origin authentication (digital signatures). Do not use the same pair for both in practice.

3

Everything rests on a trapdoor one-way function: easy forwards for everyone, easy backwards only with the trapdoor (the private key), infeasible backwards without it.

4

Two classic hard problems: the discrete logarithm problem (Diffie-Hellman) and the RSA problem, finding the eth root (RSA), which is equivalent to factoring.

5

Busy maths toolkit: coprime numbers, the group ℤ*n, Euler's totient ɸ(pq) = (p − 1)(q − 1), exponentiation by squaring, and the modular inverse.

6

RSA key generation: pick primes p, q; set n = pq and ɸ(n) = (p − 1)(q − 1); choose e coprime to ɸ(n); set d ≡ e−1 mod ɸ(n); delete p, q, ɸ(n). Public (e, n), private (d, n).

7

RSA encryption is c = me mod n, decryption is m = cd mod n. Correct because e·d ≡ 1 mod ɸ(n), so (me)d ≡ m. It encrypts numbers in blocks below n.

8

RSA security needs large, well-chosen primes: 2048 bits and above, p and q far apart in size. Never implement RSA yourself for production.

9

Five attack families: brute force, mathematical (equivalent to factoring), timing, hardware fault-based, and chosen ciphertext (malleability).

10

Never use RSA without padding. Vanilla RSA is deterministic and malleable, vulnerable to CPA and CCA. Modern RSA uses OAEP to add randomness and restore semantic security.

11

Almost all real use is hybrid: RSA establishes a random symmetric key, which then encrypts the bulk data. This sidesteps RSA's slowness (100–1000× slower than AES) and its character-to-number mapping problem.

12

Diffie-Hellman exchanges a key but authenticates nobody. It is secure against passive attackers (who must solve the DLP) but falls to an active person-in-the-middle attack, fixed by digital signatures and public-key certificates. Quantum computing, via Shor and Grover, threatens all of it.

Glossary

Every load-bearing term from this week, grouped so you can filter to what you need.

Public-key cryptography
A paradigm using two distinct keys, one published and one secret, instead of one shared key. Also called asymmetric cryptography.
Public key
The half of a key pair distributed freely and used to encrypt, or to verify a signature.
Private key
The half of a key pair kept confidential. It decrypts what the public key encrypted and signs to prove origin. Also called the trapdoor.
Digital signature
A key application of public-key cryptography giving origin authentication: the sender signs with their private key and anyone verifies with the public key.
Hybrid encryption
Using public-key encryption to establish a random symmetric key, then using that key to encrypt the bulk data. Used by almost all practical systems.
Key-distribution problem
Getting a shared symmetric key to both parties securely over an insecure channel; public-key cryptography is the standard solution.
RSA
The Rivest-Shamir-Adleman public-key scheme (1977): keys from two primes, encrypt c = m^e mod n, decrypt m = c^d mod n. Security rests on factoring n and the e-th root.
OAEP
Optimal Asymmetric Encryption Padding: modern RSA padding that adds randomness on encryption and removes it on decryption, so the same plaintext encrypts differently each time.
Diffie-Hellman key exchange
The first published public-key algorithm (1976). Two parties combine public values with private exponents to derive the same shared key over an insecure channel.
Elliptic Curve Cryptography (ECC)
Public-key cryptography over point addition on elliptic curves. Same ideas as RSA and DH but with much shorter keys (256 or 384 bits). Non-examinable.
ECDH
Elliptic Curve Diffie-Hellman: each side computes a public point nG and both reach n_A·P_B = n_B·P_A, secure under the ECDLP.
Post-quantum cryptography (PQC)
Algorithms designed to stay secure against quantum computers, drawn from lattice-based, code-based and hash-based cryptography.
Person-in-the-middle attack
An active attack on Diffie-Hellman in which the adversary runs two separate key exchanges, one with each party, and relays messages between them.
Malleability
An attacker modifies a ciphertext predictably (c' = c·r^e mod n) so the decrypted plaintext changes predictably (to r·m), without knowing the private key.
Chosen ciphertext attack (CCA)
An attack in which the adversary submits chosen ciphertexts and observes their decryptions. Vanilla RSA is vulnerable because of malleability.
Chosen plaintext attack (CPA)
An attack in which the adversary encrypts chosen plaintexts and compares the results. Deterministic textbook RSA is vulnerable.
Discrete logarithm problem (DLP)
Given prime p, primitive root g and y, find x with g^x ≡ y (mod p). Easy forwards, believed infeasible backwards for large p. Underpins Diffie-Hellman.
RSA problem
Given c = m^e mod n along with c, e and n, find m. Believed infeasible for suitable n, and equivalent in effort to factoring n.
Coprime
Two numbers are coprime when their only shared divisor is 1, i.e. gcd(a, b) = 1. For example, 8 and 27.
ℤ*n
The non-negative integers below n that are coprime to n. It forms an Abelian group under multiplication modulo n; e.g. {1, 5, 7, 11} for n = 12.
Euler's totient function
φ(n) counts the elements of the multiplicative group. For distinct primes, φ(pq) = (p − 1)(q − 1). RSA depends on this shortcut.
Primitive root
An element g of the multiplicative group modulo prime p whose powers generate the whole group: {g^0, g^1, …, g^(p−2)}. Also called a generator.
ECDLP
The Elliptic Curve Discrete Logarithm Problem: given P and Q = kP on a curve, find k. Harder per bit than the classical DLP, so ECC keys can be shorter.
Trapdoor one-way function
A function easy to compute forwards and infeasible to invert, unless you hold secret extra information (the trapdoor). The idea behind RSA, DH and ECC.

No terms in this category.

Practice Questions

Cover the answer, write your own version first, then reveal and compare.

Answer, reveal, then tick "Mastered". Your progress is saved.
Q1

What is the key-distribution problem, and in what two respects is public-key cryptography a change of paradigm?

Answer: The key-distribution problem: symmetric cryptography needs both parties to share one secret key, yet delivering it over an insecure channel exposes it, and every pair of users needs its own key. Public-key cryptography changes the paradigm twice: each user has a freely distributed public key and a secret private key, so anyone can encrypt with the receiver's public key while only the receiver decrypts; and it uses two distinct keys built on mathematical functions with special properties, not only substitution and permutation.
Q2

Explain how a key pair is used for confidentiality and for origin authentication, and state the practical caveat.

Answer: Confidentiality: Bob encrypts with Alice's public key and Alice decrypts with her private key, so anyone can encrypt but only Alice can read it. Origin authentication: Bob encrypts with his own private key and Alice verifies with Bob's public key, so anyone can verify but only Bob could have produced it; this is the basis of digital signatures. Caveat: these are conceptual uses; in practice we do not use the same key pair for both, and signatures normally hash the message first.
Q3

State the discrete logarithm problem and the RSA problem, and say which scheme depends on which.

Answer: The Discrete Logarithm Problem (DLP): given y, p and g with y = g^x mod p, where p is prime and g a primitive root of p, find x. The RSA problem: when c = m^e mod n and c, e and n are known, find m, i.e. compute the e-th root, which is equivalent in effort to factoring n. Diffie-Hellman (and DSA/ElGamal) rely on the DLP; RSA relies on the difficulty of the e-th root and of factoring n. Both become easy once the private key is known, which makes them trapdoors.
Q4

Write out RSA key generation step by step, and say which values are public, which are private, and which are destroyed.

Answer: (1) Choose distinct primes p and q. (2) Set the modulus n = p·q. (3) Compute φ(n) = (p − 1)(q − 1). (4) Choose e with 1 < e < φ(n) and gcd(e, φ(n)) = 1; a convenient method is a prime e > max(p, q). (5) Compute d ≡ e^−1 mod φ(n), the modular inverse of e. (6) The public key is (e, n); the private key is (d, n); p, q and φ(n) are then deleted permanently. (7) Encryption: c = m^e mod n. (8) Decryption: m = c^d mod n.
Q5

In an RSA system the public key is e = 31, n = 3599. Find the private key.

Answer: Factor n: 3599 = 59 × 61, so p = 59 and q = 61. Then φ(n) = (59 − 1)(61 − 1) = 58 × 60 = 3480. Solve ed ≡ 1 mod φ(n), i.e. 31d ≡ 1 mod 3480. Checking candidates, 31 × 3031 mod 3480 = 1, so d = 3031. (By contrast 31 × 2412 mod 3480 = 1692, not 1.) The bottleneck is finding the prime factors; for real 2048-bit moduli that is infeasible.
Q6

What does the security of RSA rest on, and what rules must p and q satisfy?

Answer: RSA's security rests on two assumed-hard facts: obtaining the e-th root of a number in the integers mod n is infeasible unless you know d, and factoring n = pq is computationally infeasible for very large p and q (otherwise d follows easily from φ(n)). To keep factoring hard, p and q must be very large, n must need thousands of bits (RSA keys of 2048 bits and more), and p and q must not be too close together, since close primes allow fast factoring. Larger keys are stronger but slower, and there are many other constraints, so never implement RSA yourself for production.
Q7

Name and briefly describe the five approaches to attacking RSA.

Answer: (1) Brute force: trying all possible private keys, feasible only against small keys. (2) Mathematical attacks: several approaches, all equivalent in effort to factoring the product of two primes. (3) Timing attacks: they depend on the running time of the decryption algorithm. (4) Hardware fault-based attacks: inducing hardware faults in the processor generating digital signatures. (5) Chosen ciphertext attacks: exploiting properties of the algorithm, such as malleability. Only the mathematical attack targets the number theory; the rest attack implementation or structure.
Q8

Explain RSA malleability, derive why the attack works, and classify the attack.

Answer: Malleability means an attacker can modify a ciphertext in a predictable way so the decrypted plaintext changes predictably, without the private key. Eve intercepts c and sends c' ≡ c · r^e mod n to the receiver, who decrypts it to r·m. Derivation: (c')^d = (c × r^e)^d = (m^e × r^e)^d = m^(e×d) × r^(e×d) = m × r, since (m^e)^d mod n = m mod n. The result looks valid, so the receiver cannot detect the alteration, and Eve recovers m by dividing by r. This is a chosen ciphertext attack (CCA): it assumes the attacker can get c' decrypted.
Q9

Why does textbook RSA lack semantic security, and how does padding fix it?

Answer: Textbook RSA is deterministic: the same plaintext with the same public key always produces the same ciphertext, and there is no randomness. An adversary can forward-compute likely messages and compare them against a ciphertext, a chosen plaintext attack, so the ciphertext leaks information and the scheme is not semantically secure. The fix is sophisticated padding, which adds randomness on encryption and removes it on decryption, so the same plaintext encrypts differently every time. The modern standard is OAEP (Optimal Asymmetric Encryption Padding).
Q10

What are RSA's two practical problems, and how does hybrid encryption solve them? Give the four steps.

Answer: Problem 1: public-key cryptography is slow, especially with long keys; RSA is roughly 100 to 1000 times slower than AES. Problem 2: it requires a mechanism to map characters to numbers to be practical. Hybrid encryption uses public-key encryption only to establish a symmetric key, then encrypts the data symmetrically. Steps: (1) generate a random symmetric key k; (2) encrypt the message, c_m = Enc_k(m); (3) encrypt the key with the receiver's public key, c_k = Enc_PK(k); (4) send the pair (c_k, c_m). Almost all public-key encryption in practice is hybrid.
Q11

Describe the Diffie-Hellman exchange, show both sides reach the same key, and explain the person-in-the-middle attack and its fix.

Answer: Alice and Bob share public p and g. Alice picks private a < p, computes X = g^a mod p and sends X; Bob picks private b < p, computes Y = g^b mod p and sends Y. Alice computes k = Y^a mod p and Bob computes k = X^b mod p; they agree because Y^a = (g^b)^a = g^(ab) = (g^a)^b = X^b. A passive attacker who knows p, g, X, Y must solve the discrete logarithm to find a or b, infeasible for large primes. But an active attacker chooses two key pairs (c, d), sends forged X' = g^c and Y' = g^d, and runs two separate exchanges, sharing one key with each party; this works because DH does not authenticate participants. The fix is digital signatures and public-key certificates (signed Diffie-Hellman).
Q12

How does ECC differ from classical Diffie-Hellman, and how do Shor's and Grover's algorithms affect asymmetric versus symmetric cryptography? (ECC is non-examinable.)

Answer: ECC keeps the same trapdoor idea in a different Abelian group. Instead of the multiplicative group modulo p with repeated multiplication a^k mod p, it uses points on a curve y^2 = x^3 + ax + b over a finite field, with point addition and scalar multiplication kP. The hard problem is the ECDLP (find k given P and Q = kP), harder per bit than the classical DLP, so ECC reaches the same security with much shorter keys, typically 256 or 384 bits versus RSA's 2048. ECDH computes public points n_A G and n_B G and both reach n_A·P_B = n_B·P_A. On quantum threats: Shor's algorithm efficiently factors large numbers and computes discrete logarithms, so RSA, Diffie-Hellman and ECC become vulnerable (Australia plans to retire RSA by 2030). Grover's algorithm gives only a quadratic speedup against symmetric ciphers, halving the effective security level, so a 256-bit key matches 128 bits and doubling key sizes is the mitigation. PQC candidates include lattice-based, code-based and hash-based cryptography.
