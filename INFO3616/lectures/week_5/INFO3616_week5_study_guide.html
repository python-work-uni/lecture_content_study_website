Two Keys, One Secret: How Asymmetric Cryptography Works

This week we leave shared-secret cryptography behind and meet a new paradigm: every user owns a public key that anyone can see and a private key only they know. We build RSA out of prime numbers, use it to protect messages and prove who sent them, exchange keys with Diffie-Hellman, then finish with elliptic curves and the quantum threat on the horizon.

Read this first: Hold one mental model — asymmetric cryptography is a trapdoor. Going one way through the door is easy for everyone; coming back the other way is impossible unless you know the secret latch (the private key). RSA, Diffie-Hellman and elliptic curves are three different "doors", but they all rest on a maths problem that is easy to compute forwards and believed to be infeasible to reverse.

Why Asymmetric Cryptography?

One shared key becomes two linked keys — a public one anyone may use and a private one only you hold.

So far in this unit, cryptography has been symmetric: Alice and Bob share one secret key and use the same key to encrypt and decrypt. Symmetric ciphers achieve their security through confusion (substitution) and diffusion (permutation). That model works well, but it has a famous weakness — how do two people who have never met agree on the shared key in the first place?

Public-key cryptography answers that question by changing the paradigm in two important ways.

  1. Each participant has a key pair. A public key that is distributed openly, and a private key that is kept secret.
  2. Encryption and decryption use different keys. Anyone may use the receiver's public key to encrypt a message, but only the receiver — the owner of the private key — can decrypt it.

Because the two keys are different, this is also called asymmetric cryptography ("a-symmetric" = not symmetric).

Asymmetric (public-key) cryptography — a form of cryptography that uses two distinct but mathematically related keys: a public key for one direction and a private key for the other. It relies on mathematical functions with special properties, beyond simple substitution and permutation.

Symmetric cryptography

  • One shared key for both encryption and decryption.
  • Security from substitution (confusion) and permutation (diffusion).
  • Fast, but key distribution is a problem.

Asymmetric cryptography

  • Two keys: a public key and a private key.
  • Security from mathematical problems with special properties.
  • Slower, but solves key distribution.
💡
Why this matters: public-key cryptography is built on mathematical problems that are believed to have the right properties. A number of such problems are thought to work, but there is no proof yet that they are truly hard. Security here is a well-tested belief, not a theorem.
🤔
Pause & predict: If anyone can use your public key to encrypt a message to you, why can't an eavesdropper simply use the same public key to decrypt it? (Hold that thought — the answer is the trapdoor in the next few sections.)

Two Directions of Trust

Swap which key does the locking and you get a completely different security service.

Because there are two keys, there are two useful ways to combine them. Think of the key you use to lock (encrypt) as separate from the key you use to unlock (decrypt).

🔒 Confidentiality

Encrypt with the public key, decrypt with the private key. Anyone can encrypt a message for the receiver, but only the receiver can decrypt it, because only they hold the private key. This keeps the message secret.

✍️ Origin Authentication

Encrypt with the private key, decrypt with the public key. Anyone can decrypt, but only the true owner could have encrypted it, because only they hold the private key. This proves who sent the message.

Origin authentication is the idea behind digital signatures, a key application of public-key cryptography. With a signature, not only the intended recipient but anyone with access to the sender's public key can verify the origin of the message.

⚠️
Conceptual, not literal: the confidentiality and origin-authentication descriptions show the concept of key usage. In practice we do not use the same key pair simultaneously for both purposes — real systems use separate keys for encryption and for signing.

What each algorithm can do

Overall, all participants can see each other's public keys, while each keeps their private key confidential. Different public-key algorithms offer different services:

Memory hook: Diffie-Hellman is the specialist — it only does key exchange. DSS is the specialist that only signs. RSA and Elliptic Curve are the all-rounders that can do all three.

Trapdoor One-Way Functions

Easy to compute forwards, infeasible to reverse — unless you hold the secret information that springs the trap.

To build a public-key system, we need a very particular kind of function. It must be:

  • Computationally fast to compute the function value f(x) = y.
  • Computationally infeasible to compute the inverse f−1(y) = x.
  • Unless you possess a piece of information that lets you reverse it dramatically faster.

That secret piece of information is the trapdoor, and the function is called a trapdoor function.

Trapdoor one-way function
Y = fk(X)  →  easy when k and X are known
X = fk−1(Y)  →  easy when k and Y are known
X = fk−1(Y)  →  infeasible when k is unknown
One-way function — a function that maps a domain into a range such that every value has a unique inverse, where computing the function is easy but computing the inverse is infeasible.
Trapdoor one-way function — a function that is easy to compute in one direction but hard to invert without additional information called the "trapdoor".
💡
Corollary (and the whole point): it must be computationally infeasible to compute the private key from the public key without the trapdoor information. That is what lets you publish your public key to the whole world safely.

Requirements for public-key cryptography

Any algorithm used for public-key cryptography should satisfy these conditions. Here B is the key owner and A is a sender.

  1. It is computationally easy for B to generate a key pair (public key PUb, private key PRb).
  2. It is computationally easy for a sender A, knowing the public key and the message M, to generate the ciphertext: C = E(PUb, M).
  3. It is computationally easy for the receiver B to decrypt using the private key: M = D(PRb, C) = D[PRb, E(PUb, M)].
  4. It is computationally infeasible for an adversary who knows PUb to determine the private key PRb.
  5. It is computationally infeasible for an adversary who knows PUb and a ciphertext C to recover the original message M without knowing PRb.
  6. (Optional, sixth requirement) The two keys can be applied in either order — which is what enables signatures as well as confidentiality.

All of these requirements can be summarised as the requirement of a trapdoor one-way function.

Classic trapdoor candidate problems

Two mathematical problems are believed to have the desired trapdoor properties.

📐 Discrete Logarithms in Modular Arithmetic

It is computationally infeasible to compute the discrete logarithm modulo p, for certain primes p. (Diffie and Hellman, 1976)

DLP: Given y, p, g satisfying y = gx mod p — where p is prime and g is a primitive root of p — how do you find x?

🔑 The RSA Problem

It is computationally infeasible to compute the eth root of an integer modulo n, for certain n.

RSA problem: When c = me mod n and c, e and n are known, can you find m?

Both the discrete logarithm problem and the RSA problem have the property "computationally infeasible". However, they become easy to compute with additional information — namely the private key.

✅
Exam tip: be ready to write both problems out symbolically and state exactly which values are given and which are unknown. The DLP gives you y, p and g and asks for x; the RSA problem gives you c, e and n and asks for m.

Number Theory Toolkit

Three small ideas — coprimes, the set ℤ*n, and Euler's phi function — unlock all of RSA.

Coprime numbers

Two numbers are coprime (or relatively prime) if they share only one divisor, and that divisor is 1.

ℹ️
Example: 8 and 27 are coprime. Factorising, 8 = 2 · 2 · 2 and 27 = 3 · 3 · 3. They have no prime factor in common, so their only common divisor is 1.

The set ℤ*n and Euler's totient

We define ℤ*n as all the non-negative integers less than n that are coprime to n.

ℹ️
Example: let n = 12. The numbers less than 12 and coprime to 12 are 1, 5, 7 and 11 — so ℤ*12 = {1, 5, 7, 11}. The set is useful because it forms an Abelian group under multiplication.

Euler's Phi function (also called the totient function, written ɸ) counts how many elements are in ℤ*n. For example, ɸ(12) = 4.

When n is a product of two distinct primes
If n = p · q, where p and q are prime and p ≠ q, then
ɸ(n) = (p − 1)(q − 1)

This shortcut is the engine room of RSA: because n is the product of two primes, ɸ(n) is trivial to compute if you know p and q — but effectively impossible if you only know n.

🤔
Pause & predict: If p = 7 and q = 11, what is n, and what is ɸ(n)? (You will use both numbers in the RSA toy example in two sections' time.)

RSA Key Generation

Pick two primes, multiply them, then choose an exponent and its modular inverse. That inverse is your private key.

RSA (Rivest–Shamir–Adleman) was developed in 1977 by Ron Rivest, Adi Shamir and Len Adleman at MIT. It is the most widely accepted and implemented general-purpose approach to public-key encryption, and it encrypts plaintext in blocks, each block having a binary value less than n.

Here is the full key-generation recipe. The steps are numbered so you can follow the worked examples.

  1. Let p and q, with p ≠ q, be prime. In practice these are very large numbers.
  2. Define n = p · q. We call n the modulus.
  3. Use Euler's totient function: ɸ(n) = (p − 1)(q − 1).
  4. Choose e such that 1 < e < ɸ(n) and gcd(e, ɸ(n)) = 1 — that is, e is coprime with ɸ(n). One way is to choose e > max(p, q) and prime; testing whether an integer is prime is fast.
  5. Calculate d such that d ≡ e−1 mod ɸ(n). In words, d is the modular inverse of e modulo ɸ(n).
  6. Now we have the keys:
    • (e, n) is the public key.
    • (d, n) is the private key.

At this point we delete p, q and ɸ(n) permanently. Anyone who knew p and q could compute d, so they must never be stored or shared.

💡
Why delete p and q? The whole security of RSA rests on n being hard to factor. If p and q leaked, an attacker would compute ɸ(n) = (p − 1)(q − 1), then invert e to find d, and every message would be readable.

Worked example: key generation with p = 7, q = 11

StepWorkingResult
1Choose primes p = 7, q = 11p ≠ q ✓
2n = p · q = 7 × 11n = 77
3ɸ(n) = (7 − 1)(11 − 1) = 6 × 10ɸ(n) = 60
4Choose e = 13 (less than 60 and coprime with 60)e = 13
5Find d such that 13d mod 60 = 1d = 37
6Public key (e, n); private key (d, n)(13, 77) and (37, 77)
✅
Check your d: verify the modular inverse by multiplying back. Here 13 × 37 = 481 = (8 × 60) + 1, so 13 × 37 ≡ 1 mod 60. If your d does not give remainder 1, it is wrong.

RSA Encryption and Decryption

Encryption raises the message to the power e; decryption raises the ciphertext to the power d. The maths cancels perfectly.

Once the keys exist, using them is beautifully simple. Let m be the plaintext and c the ciphertext.

RSA encryption and decryption
Encryption: c = me mod n
Decryption: m = cd mod n

Worked example: encrypting 3 with (13, 77)

  1. Plaintext m = 3; public key (e, n) = (13, 77).
  2. Encrypt: c = 313 mod 77 = 38.
  3. Decrypt with the private key (d, n) = (37, 77): m = 3837 mod 77 = 3.

The message comes back exactly. In practice, of course, p and q are very large, so n, e and d are enormous.

Worked example from the notes: p = 17, q = 11

Public exponentChoose e = 7 (coprime to 160 and less than it)e = 7
Private exponentd × 7 ≡ 1 mod 160; note 23 × 7 = 161 = (1 × 160) + 1d = 23

Why RSA works over ℤ/nℤ

RSA encryption is defined as a function from ℤ/nℤ to ℤ/nℤ:

RSA as a function
RSA : ℤ/nℤ → ℤ/nℤ

Recall that ℤ/nℤ is a commutative ring, and note that n is not prime but the product of two primes. There was a very good reason to work here:

  • Exponentiation in ℤ/nℤ is fast to compute (using exponentiation by squaring). In other words, computing c = me mod n is very efficient.
  • But getting the eth root of c to recover the original m is believed to be infeasible without d.
⚠️
Important limitation: RSA cannot uniquely encrypt values greater than n. Such values are reduced modulo n, so decryption returns a value less than n, not the original input. This is why plaintext is split into blocks smaller than n.

Because of its mathematical nature, RSA can encrypt only numbers — more specifically, only numbers in ℤ/nℤ. So sender and receiver must use a mapping from characters to numbers to make it useful: for example a ⇒ 1, b ⇒ 2, and so on.

🧠
Memory hook: e for encrypt (public), d for decrypt (private), n for the modulus shared by both keys. Encryption is public knowledge; decryption needs the secret.

Security of RSA

RSA is only as strong as two hard problems — taking e-th roots and factoring n — plus a long list of practical cautions.

The security of RSA rests on two beliefs:

  • Obtaining the eth root of a number in ℤ/nℤ is computationally infeasible unless you know d.
  • Factoring n = p · q, for very large p and q, is computationally infeasible. If you could factor n, you could easily calculate d.
💡
Why it matters: the defence against brute-forcing d is to use a large key space. The more bits in d, the more secure the system — but the slower it becomes, because key generation, encryption and decryption all involve more complex calculations.

Practical rules for choosing p and q

  • p and q (with p ≠ q) must be very large. Encoding n needs thousands of bits — typical RSA key lengths are 2048 bits and more.
  • p and q must not be too close together, because that allows forms of fast factoring.
  • In practice there are many more limiting factors — not every key is a good key.
  • Never implement RSA yourself and use it in production. Use well-tested libraries.
⚠️
Quantum risks later: RSA is secure "for now". Quantum computers running Shor's algorithm would break it, and Australia plans to get rid of RSA by 2030. We return to this in the final section.
🤔
Pause & predict: If an attacker somehow learned p and q, which one line of working would hand them your private key d? (Answer: they would compute ɸ(n) = (p − 1)(q − 1), then find d = e−1 mod ɸ(n).)

Five Ways to Attack RSA

Brute force, mathematics, timing, hardware faults and chosen ciphertext — know the family tree.

Never Use RSA Without Padding

Vanilla RSA preserves structure, so an attacker can tamper with a ciphertext and predictably bend the plaintext. Randomness is the fix.

Plain ("vanilla", or "textbook") RSA is not secure on its own. Two related problems show why.

Problem 1: Malleability (a chosen ciphertext attack)

Malleability — in RSA, the property that an attacker can modify a ciphertext in a predictable way so that the decrypted plaintext also changes in a related, predictable way, without knowing the private key.

Here is the attack. Eve intercepts a ciphertext c and computes a modified ciphertext c′ by multiplying by a value raised to e:

The malleability trick
c′ ≡ c · 2e mod n
(c′)d mod n ≡ (c · 2e mod n)d mod n ≡ 2m
  1. Eve intercepts the ciphertext c.
  2. She computes the modified ciphertext c′ ≡ c · 2e mod n and sends it to the receiver.
  3. The receiver decrypts c′ and obtains 2m — a valid-looking result, not random garbage.
  4. Because the result is valid-looking, the receiver cannot detect that the message was altered.
  5. Eve recovers the original plaintext by dividing by 2 (or more generally by the value she used).

Key idea: vanilla RSA preserves structure, so tampering yields a predictable, manipulated plaintext rather than garbage. This is a generic result — the scalar multiplication can be any number, not just 2. Because the attacker gets a chosen ciphertext decrypted, this is a Chosen Ciphertext Attack (CCA).

Problem 2: No semantic security (a chosen plaintext attack)

  • An attacker can forward-compute likely messages and see whether any matches a given ciphertext.
  • RSA is deterministic: the same plaintext encrypted with the same public key always produces the same ciphertext. There is no randomness.
  • Because encryption is deterministic and the public key is out in the open, RSA is vulnerable to Chosen Plaintext Attacks (CPA).
Semantic security — a cryptosystem is semantically secure when only a small amount of information about the plaintext can be extracted from the ciphertext. Textbook RSA has none, because it lacks randomness.

The solution: padding

Modern RSA implementations add sophisticated padding, which adds randomness on encryption and removes it on decryption. This ensures that the same plaintext encrypted multiple times produces different ciphertexts. Padding is crucial, but non-trivial: today we use OAEP (Optimal Asymmetric Encryption Padding).

⚠️
Never use RSA without padding. Unpadded RSA is malleable (vulnerable to CCA) and deterministic (vulnerable to CPA). Padding with OAEP is what makes RSA semantically secure.

Hybrid Encryption

Use slow public-key crypto once, to share a fast symmetric key. Then switch to the fast lane.

RSA has two key problems in practice.

🐌 Problem 1: Public-key crypto is slow

Long keys make it slow. RSA is 100–1000 times slower than AES.

🔢 Problem 2: It needs a character-to-number mapping

RSA encrypts numbers, so a mapping from characters to numbers is needed to make it useful for real messages.

The solution is hybrid encryption. In general we do not use RSA continuously. Instead, we use RSA briefly to establish a symmetric key, then secure the actual conversation with fast symmetric encryption. Almost all public-key encryption uses hybrid encryption in practice.

Generate random symmetric key k→ Encrypt message: cm = Enck(m)→ Encrypt k: ck = EncPK(k)→ Send (ck, cm)
  1. Generate a random symmetric key k.
  2. Encrypt the actual message as cm = Enck(m) using the symmetric key.
  3. Encrypt k as ck = EncPK(k) using the receiver's public key.
  4. Send (ck, cm) — the encrypted key and the encrypted message.

The receiver decrypts ck with their private key to recover k, then uses k to decrypt cm. The heavy lifting is done by the fast symmetric cipher; the public-key cipher only ever handles the small session key.

🧠
Memory hook: public-key crypto is the courier who delivers the key; symmetric crypto is the fast car that carries the cargo. You would not send the courier for every parcel.
🤔
Pause & predict: In hybrid encryption, why is it safe to send ck and cm together over an insecure channel? (Because k is encrypted under the receiver's public key, so only the receiver can unwrap it.)

Diffie-Hellman Key Exchange

Two strangers publicly swap numbers and quietly arrive at the same secret — without ever sending it.

There are many public-key cryptosystems besides RSA. One of the best known is not used for encryption, but for key exchange. The question it solves is: can Alice and Bob establish a shared symmetric key without a purely listening attacker being able to obtain it? Finite fields come to our aid.

Diffie-Hellman is the first published algorithm that implemented the public-key (trapdoor) principle. It became the basis for:

  • Diffie-Hellman Key Exchange
  • ElGamal encryption/decryption
  • The Digital Signature Standard (DSA/DSS)

The Discrete Logarithm Problem

Just as with factorisation and the eth root before, there is another trapdoor problem. It is computationally infeasible to compute a logarithm over a finite field, if the prime number used to construct the field is large enough.

Discrete Logarithm Problem (DLP)
Given y, p, g with y = gx mod p,
where p is prime and g is a primitive root of p,
find x.

But if you have one extra piece of information (the "private key"), it suddenly becomes easy. How do we make use of that?

Finite fields revisited: primitive roots

Let p be prime. We know ℤ/pℤ is a finite field, with elements {0, 1, ..., p − 1}. We can define a new group over the non-zero numbers, ℤp* = {1, ..., p − 1}, under multiplication.

It can be shown that there is a special element g ∈ ℤp such that every number a ∈ ℤp* is a power of g. So:

The group generated by g
ℤp* = {g0 = 1, g1, ..., gp−2}

The element g is called a primitive root (or generator) of ℤp.

The algorithm

Let p be prime and g a generator for ℤp*. Both values are publicly known.

Alice picks a < p→ Computes X = ga mod p→ Sends X to Bob
Bob picks b < p→ Computes Y = gb mod p→ Sends Y to Alice
  1. Alice chooses a random private value a < p and computes X = ga mod p, then sends X to Bob.
  2. Bob chooses a random private value b < p and computes Y = gb mod p, then sends Y to Alice.
  3. Alice computes k = Ya mod p.
  4. Bob computes k = Xb mod p.

Both sides get the same k, because the exponents commute:

Why both keys match
Ya mod p = (gb)a = gab = (ga)b = Xb mod p

Here a and b are the private keys; X and Y are the public keys. An adversary who only passively observes the exchange knows p, g, X and Y, and is forced to solve a discrete logarithm (find b such that Y = gb mod p) to get the key. For large primes this is computationally infeasible. So DH allows key establishment over an insecure channel — under a passive attacker.

ℹ️
Why the shared k is secret: the eavesdropper sees g, p, ga and gb, but recovering gab from those values is exactly the hard problem. This is sometimes called the computational Diffie-Hellman assumption.

Person-in-the-Middle Attack

DH has no idea who it is talking to. An active attacker can sit in the middle and hold two separate keys.

When the attacker is active, standard DH key exchange is not secure. The attacker, Mallory, does not just listen — she intercepts and replaces messages, running two independent key exchanges at once.

Alice → X→ Mallory intercepts→ Bob sees X′
Bob → Y→ Mallory intercepts→ Alice sees Y′
  1. Mallory chooses random private values c < p and d < p, and computes public values X′ = gc mod p and Y′ = gd mod p.
  2. When Alice sends X, Mallory keeps it and sends X′ to Bob instead.
  3. When Bob sends Y, Mallory keeps it and sends Y′ to Alice instead.
  4. Alice computes k1 = (Y′)a mod p; Bob computes k2 = (X′)b mod p.
  5. Mallory computes k1 = Xc mod p (shared with Alice) and k2 = Yd mod p (shared with Bob).

Now Alice and Bob each think they share a key with the other, but in reality Alice shares k1 with Mallory and Bob shares k2 with Mallory. Mallory can decrypt, read, modify and re-encrypt every future message — a person-in-the-middle attack.

💡
Root cause: the protocol does not authenticate the participants. DH proves you agreed on a key, not who you agreed with.
✅
Solution: use digital signatures and public-key certificates — each party signs their public key with their private key, and the other party verifies it with the corresponding public key, ensuring the exchanged keys have not been tampered with. This is the signed Diffie-Hellman variant, and we discuss signatures and certificates in the next lecture.
🤔
Pause & predict: DH is secure against a passive attacker but not an active one. Why can a signature fix this, when the key exchange maths itself is unchanged? (Because it binds each public key to an authenticated identity.)

Elliptic Curve Cryptography: Same Idea, Different Group

Replace modular multiplication with adding points on a curve and you get the same trapdoor with much shorter keys. This topic is non-examinable — for information only.

ℹ️
Scope note: the following is a very brief introduction to elliptic curve cryptography (ECC). It is marked non-examinable (for information only) in the slides, but it is worth understanding because it is where modern cryptography is heading.

Our schemes so far are defined for rings and fields built with the help of the mod operation — that is, modular arithmetic. Elliptic curves E(a, b) are defined by equations of the form:

An elliptic curve
y2 = x3 + ax + b

When defined over a finite field, an elliptic curve produces a finite set of points. A group can be defined over these points using point addition. This lets us define a Discrete Logarithm Problem for elliptic curves (ECDLP), and ECDLP is harder per bit than the classical DLP.

💡
Why that matters: because the problem is harder per bit, ECC achieves the same security with much shorter keys. Typical ECC keys are 256 bits (very common) or 384 bits (high security) — far smaller than RSA's 2048+ bits.

Key transition: classical DH versus ECC

Diffie-Hellman (classical)

  • Group: ℤp*
  • Operation: multiplication mod p
  • Computation: ak mod p (repeated multiplication)
  • Security from: the Discrete Logarithm Problem

Elliptic Curve Cryptography

  • Elements: points on a curve over a finite field ℤp
  • Operation: point addition, kP = P + P + ⋯ + P
  • Hard problem: given P and Q = kP, recover k
  • Note: all arithmetic is done modulo p (implicitly)

Geometric intuition

Consider E(1, 1), which is y2 = x3 + x + 1. We define O, the point at infinity, which acts as the identity element — an imaginary point added to make the maths complete.

Point addition works like this:

  1. Take two points P and Q on the curve.
  2. Draw the line through P and Q.
  3. The line intersects the curve at a third point.
  4. Reflect that third point across the x-axis. The result is P + Q.

Two key properties follow:

  • The negative of a point is −P = (x, −y) — a reflection across the x-axis.
  • Three points on a line sum to zero: P + Q + R = 0.
🧠
Special case — doubling: what if P = Q? Then use the tangent line at P. The tangent intersects the curve at another point; reflect it across the x-axis and you get 2P. This is how repeated addition (scalar multiplication) is defined.

Elliptic Curves over Finite Fields

Modular arithmetic makes the smooth curve become a scattered set of points — and polynomials can replace numbers entirely.

Curves over ℤp

We now define elliptic curves over a finite field ℤp. The curve equation becomes Ep(a, b):

Elliptic curve over ℤp
y2 = x3 + ax + b (mod p)

Example curve over ℤ23: consider E23(1, 1), that is y2 = x3 + x + 1 (mod 23). Check whether the point (x, y) = (9, 7) lies on the curve:

Testing a point
72 ≡ 93 + 1·9 + 1 (mod 23)
49 ≡ 739 (mod 23)
3 ≡ 3 ✓

Since both sides agree, (9, 7) is on the curve. The curve consists of all pairs (x, y) satisfying the equation, plus O, the point at infinity. This forms a finite set of points.

Curves over a binary field GF(2m)

Previously we used prime fields ℤp. Now we define curves over binary fields GF(2m) — we did something similar in AES. Here the elements are polynomials with coefficients in GF(2), i.e. bit strings, and arithmetic is done modulo an irreducible polynomial.

Curve equation over GF(2m)
y2 + xy = x3 + ax2 + b

Addition and multiplication happen in GF(2m). Let g be a primitive element (generator) of GF(24). Every non-zero field element can be expressed as a power of g:

The multiplicative group GF(24)*
GF(24)* = {g0, g1, g2, ..., g14}

Example curve and point over GF(24)

Consider the curve y2 + xy = x3 + ax2 + b where a = g4 and b = 1. Test the point (x, y) = (g5, g3):

Verification
y2 + xy = x3 + ax2 + b
(g3)2 + g5g3 = (g5)3 + g4(g5)2 + 1
g6 + g8 = g15 + g14 + 1

Converting each side to binary and remembering that addition in GF(2) is XOR:

In bits
1100 + 0101 = 0001 + 1001 + 001
1001 = 1001 ✓

Both sides equal 1001, so the point (x, y) = (g5, g3) is on the curve.

Properties of GF(24)

We select f(x) = x4 + x + 1 as the irreducible polynomial and g as 0010 (that is, g = x). Now we can develop powers of g. For example, to calculate g4 which is x4: since x4 is a higher degree than the largest polynomial supported by 4 bits (which is x3), we reduce it modulo the irreducible polynomial.

Reducing x4
x4 = x4 mod (x4 + x + 1)
= x4 − (x4 + x + 1) = x4 + (x4 + x + 1) = x + 1
so g4 = 0011
ℹ️
Two GF(2) rules to remember: (1) in GF(2), addition and subtraction are the same thing — both are XOR; (2) adding the same element twice gives zero (a + a = 0). That is why x4 − (x4 + x + 1) and x4 + (x4 + x + 1) give the same answer, x + 1.
🤔
Pause & predict: Using g = 0010 and reduction by x4 + x + 1, what is g5? (Multiply g4 = 0011 by g = 0010: x(x + 1) = x2 + x = 0110.)

ECC in Practice: ECDLP, ECDH and EC ElGamal

The same three tricks — hard problem, key exchange, encryption — now played on a group of curve points.

The elliptic curve discrete logarithm problem

Consider the equation Q = kP, where Q and P are points in Ep(a, b) and k < p. It is hard to determine k given P and Q — this is the discrete logarithm problem for elliptic curves.

ℹ️
Worked example: consider the group E23(9, 17), defined by y2 mod 23 = (x3 + 9x + 17) mod 23. Find the discrete logarithm k of Q = (4, 5) to base P = (16, 5). The only way is brute force:
P = (16, 5) ⇒ 2P = (20, 20) ⇒ 3P = (14, 14) ⇒ 4P = (19, 20) ⇒ 5P = (13, 10) ⇒ 6P = (7, 3) ⇒ 7P = (8, 7) ⇒ 8P = (12, 17) ⇒ 9P = (4, 5). Since 9P = Q, k = 9.

In practice k would be very large, so brute force is infeasible. That hardness is the security of ECC.

Elliptic Curve Diffie-Hellman (ECDH)

Both users A and B — and any attacker — know the system-wide public parameters a, b, q, G and n. Here G is a base point (generator) on the curve, and n is the order of G, meaning nG = O (usually n is chosen to be a large prime).

  1. Each user computes a public key by scalar multiplication: PA = nA × G and PB = nB × G. This scalar multiplication is efficient.
  2. The private keys nA and nB are kept secret.
  3. Even knowing PA and G, an attacker cannot compute nA — that is the ECDLP.
  4. Both parties compute the same shared key:
    ECDH shared secret
    nA × PB = nA × (nB × G) = nB × (nA × G) = nB × PA

Security relies on the hardness of the Elliptic Curve Discrete Logarithm Problem.

EC ElGamal encryption

Public parameters: an elliptic curve Eq(a, b), a generator point G with large order n, and the message encoded as a curve point Pm.

👩 Alice (sender)

  1. Select private key nA where nA < n.
  2. Compute public key PA = nA × G.
  3. Choose a random integer k (new for each message).
  4. Send ciphertext: Cm = {kG, Pm + kPB}.

👨 Bob (receiver)

  1. Select private key nB where nB < n.
  2. Compute public key PB = nB × G (shared publicly).
  3. Receive Cm = {kG, Pm + kPB}.
  4. Recover: Pm = (Pm + kPB) − nB × (kG).

Here kPB acts as a one-time mask on Pm — the embedded ECDH shared secret. It works because nB × (kG) = k × (nBG) = kPB, so the mask cancels out.

⚠️
Why k must be random and fresh each time: reusing k for two different messages leaks information. An attacker can XOR the two ciphertexts and eliminate the mask, exposing the relationship between the messages. A fresh k per message prevents this.
ℹ️
Worked example: global parameters E257(0, −4): y2 = x3 − 4, with G(2, 2). Bob's private key nB = 101 gives public key PB = 101(2, 2) = (197, 167). Alice wants to send Pm = (112, 26) and chooses k = 41. She computes kG = 41(2, 2) = (136, 128) and kPB = 41(197, 167) = (68, 84), so Pm + kPB = (112, 26) + (68, 84) = (246, 174). She sends Cm = {(136, 128), (246, 174)}. Bob recovers (246, 174) − 101(136, 128) = (246, 174) − (68, 84) = (112, 26) = Pm.

Security of ECC and key sizes

The security of ECC depends on how difficult it is to determine k given kP — the elliptic curve logarithm problem. Comparison tables of algorithms show comparable key sizes in terms of the computational effort needed for cryptanalysis. The headline point to remember is the key length difference between RSA and ECC: to reach the same security level, ECC needs far fewer bits than RSA.

Post-Quantum Cryptography

Quantum computers break asymmetric crypto outright and merely weaken symmetric crypto — so we halve the damage by doubling key sizes and design new algorithms.

Breaking asymmetric cryptography

  • Shor's algorithm can efficiently factor large numbers and compute discrete logarithms.
  • Therefore RSA, Diffie-Hellman key exchange and ECC will all be vulnerable once a sufficiently powerful quantum computer exists.

Symmetric cryptography is more resilient

  • Grover's algorithm provides only a quadratic speedup for brute-forcing the keys of symmetric ciphers.
  • So a symmetric key's effective security level is halved: a 256-bit key would offer security comparable to a 128-bit key against a quantum adversary.
  • The solution is doubling key sizes.

Asymmetric under quantum attack

  • Broken by Shor's algorithm.
  • RSA, DH and ECC all vulnerable.
  • No easy fix by enlarging keys.

Symmetric under quantum attack

  • Weakened (not broken) by Grover's algorithm.
  • Effective security is halved.
  • Fix: double the key length.

Post-quantum cryptography (PQC)

PQC focuses on developing algorithms that remain secure even in the presence of quantum computational power. Key families include:

🧱 Lattice-based

Based on the hardness of problems related to lattice structures in high-dimensional spaces.

🧮 Code-based

Relies on the hardness of decoding random linear codes.

#️⃣ Hash-based

Leverages the security properties of hash functions for cryptographic tasks.

🧠
Memory hook: Shor shatters asymmetric crypto; Grover only halves symmetric crypto. "Shor = shatter, Grover = halve."
🤔
Pause & predict: A 128-bit symmetric key would have how much effective security against a quantum adversary? (About 64 bits — so you would double it to 256 bits.)

Key Takeaways

If you remember nothing else, remember this.

1

Public-key (asymmetric) cryptography uses two keys: a public key anyone may use and a private key only the owner holds. It is built on mathematical problems with special properties — but there is no proof they are hard.

2

Two directions of trust: encrypt with the public key and decrypt with the private key for confidentiality; encrypt with the private key and decrypt with the public key for origin authentication and digital signatures.

3

RSA and Elliptic Curve do all three jobs (encryption, signatures, key exchange); Diffie-Hellman only does key exchange; DSS only signs.

4

A trapdoor one-way function is easy forwards, infeasible to reverse, and easy to reverse with the trapdoor. The classic candidates are the Discrete Logarithm Problem and the RSA problem.

5

Number theory toolkit: coprimes share only 1; ℤ*n is the set of integers less than n coprime to n; Euler's totient ɸ counts them, and for n = p · q, ɸ(n) = (p − 1)(q − 1).

6

RSA key generation: pick primes p ≠ q; n = p · q; ɸ(n) = (p − 1)(q − 1); choose e coprime to ɸ(n); find d = e−1 mod ɸ(n). Public key (e, n), private key (d, n), then delete p, q and ɸ(n).

7

RSA encryption is c = me mod n and decryption is m = cd mod n. It works over ℤ/nℤ because exponentiation there is fast, while the eth root is infeasible. RSA only encrypts numbers, so characters must be mapped to numbers.

8

RSA security rests on the infeasibility of eth roots and of factoring n. Use very large, well-separated primes (2048+ bits), never implement RSA yourself, and note that Australia plans to phase it out by 2030.

9

Five attacks on RSA: brute force, mathematical (≈ factoring), timing, hardware fault-based, and chosen ciphertext (malleability).

10

Never use RSA without padding. Vanilla RSA is malleable (a CCA) and deterministic (a CPA, no semantic security). Padding with OAEP adds randomness and makes it secure.

11

Hybrid encryption uses RSA to share a fast symmetric key, then encrypts the message symmetrically. Almost all real public-key encryption works this way.

12

Diffie-Hellman lets two parties agree on a shared key using finite fields and the DLP. It is secure against passive attackers but not person-in-the-middle attacks; digital signatures and certificates (signed DH) fix that. ECC achieves the same security with far shorter keys, and Shor's algorithm threatens RSA, DH and ECC alike.

Glossary

Every term you need to speak this week's language.

Symmetric cryptography
Cryptography that uses the same shared key for both encryption and decryption, relying on substitution (confusion) and permutation (diffusion) to secure data.
Asymmetric (public-key) cryptography
Cryptography that uses two distinct but related keys — a public key and a private key — and relies on mathematical functions with special properties beyond substitution and permutation.
Public key
The key that is distributed openly to everyone. Anyone may use it to encrypt a message to its owner, or to verify the owner's signature.
Private key
The companion key that is kept secret. Only its owner can use it to decrypt a message encrypted with the public key, or to create a signature.
Confidentiality
The security service achieved by encrypting with the receiver's public key and decrypting with their private key. Anyone can encrypt; only the receiver can decrypt.
Origin authentication
The security service achieved by encrypting (signing) with the sender's private key and decrypting (verifying) with their public key. Anyone can verify, but only the true owner could have produced it.
Digital signature
A key application of public-key cryptography in which a sender signs with their private key so that anyone with the public key can verify the origin of a message.
Trapdoor one-way function
A function that is easy to compute in one direction but computationally difficult to invert without additional information called the trapdoor (the private key).
Coprime
Two numbers are coprime if they share only one divisor, and that divisor is 1. For example, 8 and 27.
Euler's totient function (ɸ)
Also called the phi function, it counts the number of elements in ℤ*n. When n = p · q with p ≠ q prime, ɸ(n) = (p − 1)(q − 1).
Discrete Logarithm Problem (DLP)
Given y, p and g satisfying y = gx mod p, where p is prime and g is a primitive root of p, find x. It is believed infeasible for large p.
RSA problem
Given c = me mod n and the known values c, e and n, find m. It is equivalent in difficulty to taking an eth root modulo n.
Modulus (n)
In RSA, the value n = p · q that both the public and private keys share. Its hardness to factor is what protects the scheme.
RSA
The Rivest–Shamir–Adleman scheme, developed in 1977 at MIT. It encrypts plaintext in blocks with a binary value less than n, using c = me mod n and m = cd mod n.
Malleability
In RSA, the property that an attacker can modify a ciphertext in a predictable way so the decrypted plaintext changes predictably, without knowing the private key. It enables chosen ciphertext attacks.
Semantic security
A cryptosystem is semantically secure when only a small amount of information about the plaintext can be extracted from the ciphertext. Textbook RSA lacks it because it has no randomness.
Chosen ciphertext attack (CCA)
An attack where the adversary can get chosen ciphertexts decrypted. RSA's malleability makes unpadded RSA vulnerable to it.
Chosen plaintext attack (CPA)
An attack where the adversary can encrypt likely messages and compare the results to a given ciphertext. RSA's determinism makes it vulnerable.
OAEP (Optimal Asymmetric Encryption Padding)
The modern padding scheme for RSA. It adds randomness on encryption and removes it on decryption, giving semantic security.
Hybrid encryption
Using public-key encryption to share a fast symmetric key, then encrypting the actual message symmetrically. Almost all public-key encryption in practice works this way.
Diffie-Hellman key exchange
The first published public-key algorithm (1976). It lets two parties agree on a shared secret over an insecure channel using finite fields and the DLP, without ever transmitting the secret.
Primitive root (generator)
An element g of ℤp such that every non-zero element of the field is a power of g. So ℤp* = {g0, g1, ..., gp−2}.
Finite field
A field with a finite number of elements, such as ℤ/pℤ for prime p. Diffie-Hellman is based on finite fields.
Person-in-the-middle attack
An active attack on Diffie-Hellman where the adversary intercepts and replaces public values, running two separate key exchanges and establishing separate keys with each party.
Signed Diffie-Hellman
A modified Diffie-Hellman exchange in which each party signs their public key with their private key, so the other party can verify authenticity and resist person-in-the-middle attacks.
Elliptic curve
A curve defined by y2 = x3 + ax + b. Over a finite field it yields a finite set of points on which a group can be defined using point addition.
Point at infinity (O)
The imaginary identity element of the elliptic curve group, added so that three collinear points sum to zero and the group is complete.
Point addition
The elliptic curve group operation. To add P and Q, draw the line through them, find the third intersection with the curve, and reflect it across the x-axis. If P = Q, use the tangent at P to get 2P.
ECDLP
The Elliptic Curve Discrete Logarithm Problem: given points P and Q = kP, recover k. It is harder per bit than the classical DLP, which is why ECC keys are shorter.
ECDH
Elliptic Curve Diffie-Hellman: the curve-based analogue of DH, where public keys are PA = nA × G and PB = nB × G, and both sides compute the same shared secret.
EC ElGamal
An elliptic curve encryption scheme in which the ciphertext is Cm = {kG, Pm + kPB}, with kPB acting as a one-time mask that Bob can cancel using his private key.
Post-quantum cryptography (PQC)
Algorithms designed to remain secure against quantum computers. Families include lattice-based, code-based and hash-based cryptography.

Practice Questions

Look away from the page first — retrieval is what builds memory.

Answer, reveal, then tick “Mastered”. Your progress is saved.
Q1

How does public-key cryptography differ from symmetric cryptography, and why is it also called asymmetric cryptography?

Answer: Symmetric cryptography uses one shared key for both encryption and decryption, relying on substitution (confusion) and permutation (diffusion). Public-key cryptography uses two distinct but related keys: each participant has a public key (distributed openly) and a private key (kept secret). Anyone may encrypt with the receiver's public key, but only the receiver — who holds the private key — can decrypt. Because the two keys differ, it is also called asymmetric cryptography.
Q2

Contrast confidentiality and origin authentication in public-key cryptography. Which key does what in each case?

Answer: For confidentiality, encrypt with the receiver's public key and decrypt with the receiver's private key: anyone can encrypt, but only the receiver can decrypt. For origin authentication, encrypt (sign) with the sender's private key and decrypt (verify) with the sender's public key: anyone can verify, but only the true owner could have created it. In practice we do not use the same key pair for both purposes — separate keys are used.
Q3

Which public-key algorithms can do encryption/decryption, digital signatures and key exchange? Give the table from memory.

Answer: RSA: yes to all three. Elliptic Curve: yes to all three. Diffie-Hellman: key exchange only (no encryption, no signatures). DSS (Digital Signature Standard): digital signature only (no encryption, no key exchange).
Q4

Define a trapdoor one-way function and state the two classic trapdoor candidate problems with their equations.

Answer: A trapdoor one-way function is easy to compute forwards but infeasible to invert without extra information (the trapdoor). Formally, Y = fk(X) is easy, X = fk−1(Y) is easy if k is known, and infeasible if k is unknown. The two classic problems are the Discrete Logarithm Problem — given y, p, g with y = gx mod p, find x — and the RSA problem — given c = me mod n and known c, e, n, find m. Both become easy with the private key.
Q5

What does ℤ*n mean, what is Euler's totient function, and how do you compute ɸ(n) when n is a product of two distinct primes?

Answer: ℤ*n is the set of all non-negative integers less than n that are coprime to n; it forms an Abelian group under multiplication. Euler's totient function ɸ counts the number of elements in ℤ*n. For example ℤ*12 = {1, 5, 7, 11}, so ɸ(12) = 4. When n = p · q with p and q distinct primes, ɸ(n) = (p − 1)(q − 1).
Q6

Generate RSA keys for p = 7 and q = 11 with e = 13. Give n, ɸ(n), d, the public key and the private key.

Answer: n = p · q = 7 × 11 = 77. ɸ(n) = (7 − 1)(11 − 1) = 6 × 10 = 60. Choose e = 13 (less than 60 and coprime with it). Find d such that 13d mod 60 = 1: d = 37 (since 13 × 37 = 481 = 8 × 60 + 1). Public key (e, n) = (13, 77); private key (d, n) = (37, 77). Then delete p, q and ɸ(n).
Q7

Using p = 7, q = 11, e = 13, encrypt the plaintext m = 3 and then decrypt it.

Answer: Encryption: c = me mod n = 313 mod 77 = 38. Decryption: m = cd mod n = 3837 mod 77 = 3. The plaintext comes back exactly. Note that RSA can only encrypt numbers, so characters must be mapped to numbers first.
Q8

For p = 11, q = 17 and e = 7, find the ciphertext for plaintext M = 88. (From the practice quiz.)

Answer: n = p · q = 11 × 17 = 187. ɸ(n) = (11 − 1)(17 − 1) = 160 (we do not need it here, since e is given, but note e < ɸ(n)). Encrypt: C = Me mod n = 887 mod 187 = 11. So the ciphertext is 11.
Q9

In an RSA system the public key is e = 31, n = 3599. What is the private key d? (From the practice quiz.)

Answer: Factor n = 3599 into p = 59 and q = 61 (n = pq). Then ɸ(n) = (59 − 1)(61 − 1) = 58 × 60 = 3480. We need ed ≡ 1 mod ɸ(n), i.e. 31d ≡ 1 mod 3480. Checking the options, 31 × 3031 mod 3480 = 1, so d = 3031. (For comparison, 31 × 2412 mod 3480 = 1692, which is not 1.)
Q10

State the five possible approaches to attacking RSA, and explain why timing and hardware fault attacks are different in kind from the others.

Answer: (1) Brute force — trying all private keys, feasible only for small keys. (2) Mathematical attacks — all equivalent in effort to factoring n. (3) Timing attacks — depend on the running time of the decryption algorithm. (4) Hardware fault-based attacks — induce faults in the processor generating signatures. (5) Chosen ciphertext attacks — exploit properties like malleability. Timing and hardware fault attacks are side-channel attacks: they exploit how the implementation behaves physically, not weaknesses in the underlying mathematics.
Q11

Explain RSA malleability with the c′ = c · 2e mod n example, and explain why padding is needed.

Answer: Malleability means an attacker can modify a ciphertext so the decrypted plaintext changes predictably. Eve intercepts c, computes c′ ≡ c · 2e mod n and gets the receiver to decrypt it, obtaining (c′)d ≡ (c · 2e)d ≡ 2m. Because the result is valid-looking rather than random, the receiver cannot detect the tampering, and Eve recovers m by dividing by 2. This is a chosen ciphertext attack, and the scalar can be any number, not just 2. Padding is needed because vanilla RSA is also deterministic — the same plaintext always gives the same ciphertext — so it has no semantic security and is vulnerable to chosen plaintext attacks. Modern RSA uses OAEP padding, which adds randomness on encryption and removes it on decryption.
Q12

Explain hybrid encryption: why it is used, and the four steps of the process.

Answer: Public-key cryptography is slow (RSA is 100–1000 times slower than AES) and needs a character-to-number mapping. Hybrid encryption uses RSA only to establish a fast symmetric key. Steps: (1) generate a random symmetric key k; (2) encrypt the actual message as cm = Enck(m); (3) encrypt k as ck = EncPK(k) using the receiver's public key; (4) send (ck, cm). The receiver decrypts ck with their private key to recover k, then decrypts cm. Almost all public-key encryption uses hybrid encryption in practice.
Q13

Describe Diffie-Hellman key exchange, show that both parties compute the same key, and explain the person-in-the-middle attack and its fix.

Answer: With prime p and generator g public, Alice picks a < p and computes X = ga mod p; Bob picks b < p and computes Y = gb mod p. They exchange X and Y. Alice computes Ya mod p and Bob computes Xb mod p. These are equal because Ya = (gb)a = gab = (ga)b = Xb, so both share k. A passive attacker knows p, g, X, Y and must solve the DLP, which is infeasible for large primes. But an active person-in-the-middle attacker chooses c and d, computes X′ = gc and Y′ = gd, sends X′ to Bob and Y′ to Alice, and establishes separate keys k1 with Alice and k2 with Bob. The protocol is vulnerable because it does not authenticate the participants. The fix is digital signatures and public-key certificates — signed Diffie-Hellman — where each party signs their public key so the other can verify authenticity.
Q14

Why do RSA and ECC need different key sizes for the same security, and how do Shor's and Grover's algorithms change the picture?

Answer: RSA's security rests on the difficulty of factoring n and taking eth roots, so it needs very large keys (2048 bits and more). ECC rests on the Elliptic Curve Discrete Logarithm Problem, which is harder per bit than the classical DLP, so ECC achieves the same security with much shorter keys — typically 256 bits (very common) or 384 bits (high security). Quantum computing changes the picture: Shor's algorithm can efficiently factor large numbers and compute discrete logarithms, so RSA, Diffie-Hellman and ECC all become vulnerable. Symmetric cryptography is more resilient — Grover's algorithm gives only a quadratic speedup, halving the effective security of a symmetric key, so a 256-bit key is comparable to a 128-bit key and the fix is to double key sizes. Post-quantum cryptography develops lattice-based, code-based and hash-based algorithms that stay secure.
