Why Asymmetric Cryptography? (The Motivation)

In symmetric cryptography, N users who wish to communicate securely pairwise require (N(N-1))/(2) shared secret keys. Moreover, symmetric crypto requires a secure out-of-band channel to distribute the secret key before communication begins.

Asymmetric (Public-Key) Cryptography solves this:

  • Each entity creates a key pair:
    • Public Key (PK): Distributed openly to anyone.
    • Private Key (SK): Kept strictly confidential by the owner.
  • For N users, only 2N keys are needed in total.
  • Encryption use case: Anyone encrypts with the recipient's PK; only the recipient can decrypt with their SK.
  • Signature use case: Sender signs with their SK; anyone can verify with the sender's PK.

One-Way Functions & Trapdoors

At the heart of asymmetric cryptography is the Trapdoor One-Way Function:

  • One-Way Function y = f(x): Easy to compute in the forward direction for any x, but computationally infeasible to invert (x = f⁻¹(y)) given only y.
  • Trapdoor: A special piece of secret information K. Without K, inverting f(y) is computationally infeasible. With K, inverting f(y) becomes fast and trivial:
    x = g(y, K)

The Two Classic Mathematical Trapdoors:

  1. Integer Factorisation / RSA Problem:
    • Multiplying two large prime numbers p × q = n is computationally trivial (O(bits²)).
    • Finding p and q given only the composite modulus n is computationally intractable for sufficiently large keys (≥ 2048 bits).
  2. Discrete Logarithm Problem (DLP):
    • Given base g, prime p, and exponent x, calculating y ≡ gˣ (mod p) via modular exponentiation is fast (O(log x)).
    • Given g, p, and y, finding the exponent x such that y ≡ gˣ (mod p) is computationally infeasible for large p.

Mathematical Foundations: Totient & Euler's Theorem

  • Coprime: Integers a and b are coprime if their greatest common divisor gcd(a, b) = 1.
  • Euler's Totient Function φ(n): The number of positive integers less than n that are coprime to n.
    • If p is prime: φ(p) = p - 1.
    • Since φ is multiplicative for coprime factors: for n = p · q (where p and q are distinct primes):
      φ(n) = (p - 1)(q - 1)
  • Euler's Theorem: If gcd(a, n) = 1, then:
    a^(φ(n)) ≡ 1 (mod n)
    • Corollary: a^(k · φ(n) + 1) ≡ a (mod n). This corollary is the exact mathematical reason why RSA decryption works!

RSA Algorithm: Step-by-Step Mechanics

A. Key Generation (Must Know for Calculation Questions)

  1. Select two large distinct primes: p and q.
  2. Compute modulus: n = p · q.
  3. Compute totient: φ(n) = (p - 1)(q - 1).
  4. Choose public exponent e: Select e such that 1 < e < φ(n) and gcd(e, φ(n)) = 1. (In practice, e = 65537 = 2¹⁶ + 1 is standard).
  5. Compute private exponent d: Solve the modular multiplicative inverse:
    e · d ≡ 1 (mod φ(n)) ⇔ d ≡ e⁻¹ (mod φ(n))
    (Computed using the Extended Euclidean Algorithm).
  6. Output Keys:
    • Public Key: (e, n)
    • Private Key: (d, n) (or (d, p, q))

B. Encryption and Decryption

  • Plaintext Message: Represented as an integer M where 0 ≤ M < n.
  • Encryption (Sender uses recipient's Public Key):
    C ≡ Mᵉ (mod n)
  • Decryption (Recipient uses their Private Key):
    M ≡ Cᵈ (mod n)

C. Worked Mini-Example (Toy Numbers)

  • Pick p = 11, q = 17.
  • Modulus: n = 11 × 17 = 187.
  • Totient: φ(n) = (11 - 1)(17 - 1) = 10 × 16 = 160.
  • Choose e = 7 (check: gcd(7, 160) = 1).
  • Find d: 7d ≡ 1 (mod 160) ⟹ 7 × 23 = 161 = 1 × 160 + 1 ⟹ d = 23.
  • Encrypt M = 88:
    C ≡ 88⁷ (mod 187) = 11
  • Decrypt C = 11:
    M ≡ 11²³ (mod 187) = 88

Critical Vulnerabilities of "Textbook" RSA & Why Padding is Mandatory

"Textbook" (unpadded) RSA is mathematically elegant but completely insecure in practice:

  1. Deterministic Encryption (No Semantic Security / IND-CPA):
    • If an attacker knows the plaintext is either "YES" or "NO", they encrypt both with the public key e and compare the result to ciphertext C.
  2. Malleability (Homomorphic Property):
    • Multiplying two ciphertexts multiplies the underlying plaintexts:
      C₁ · C₂ ≡ (M₁)ᵉ · (M₂)ᵉ ≡ (M₁ · M₂)ᵉ (mod n)
    • An active attacker can manipulate ciphertext without decrypting it.
  3. Small Message / Small Exponent Attacks:
    • If Mᵉ < n (e.g., e=3 and M is small), C = M³ over standard integers, so M = ∛(C) without using modulo arithmetic at all!
  4. Poor Prime Selection Pitfalls:
    • If p and q are chosen too close to each other (p ≈ q ≈ √(n)), Fermat's factorisation method can factor n in a few iterations.
    • If private exponent d is too small (d < (1)/(3)n^(1/4)), Wiener's attack factors n.
    • Modern requirement: Key size must be ≥ 2048 bits.

The Fix: OAEP (Optimal Asymmetric Encryption Padding)

To achieve semantic security (indistinguishability under chosen-ciphertext attack, IND-CCA2), RSA is never used raw. It must use OAEP:

  • Injects random padding bytes into the plaintext block prior to exponentiation.
  • Ensures that encrypting the exact same message twice produces completely different ciphertexts.
  • Destroys the algebraic multiplicative structure, stopping malleability.

Diffie-Hellman (DH) Key Exchange

Diffie-Hellman allows two parties to establish a shared symmetric secret key over an unencrypted, public channel without transmitting the secret itself.

The Protocol Flow:

  1. Public Setup: A large prime p and a primitive root (generator) g modulo p.
  2. Alice's Move:
    • Picks a secret random integer a (1 < a < p).
    • Computes public value A = gᵃ (mod p).
    • Sends A across the network to Bob.
  3. Bob's Move:
    • Picks a secret random integer b (1 < b < p).
    • Computes public value B = gᵇ (mod p).
    • Sends B across the network to Alice.
  4. Key Derivation:
    • Alice computes: K = Bᵃ (mod p) = (gᵇ)ᵃ (mod p) = gᵃᵇ (mod p).
    • Bob computes: K = Aᵇ (mod p) = (gᵃ)ᵇ (mod p) = gᵃᵇ (mod p).
    • Both now share K = gᵃᵇ (mod p).

The Fatal Flaw: Person-in-the-Middle (PitM) Attack

  • Vanilla Diffie-Hellman provides no authentication of the endpoints.
  • An attacker (Mallory) intercepts Alice's public value A and sends her gᵐ; intercepts Bob's public value B and sends him gᵐ.
  • Mallory establishes shared secret K₁ = gᵃᵐ with Alice and K₂ = gᵇᵐ with Bob.
  • Mallory decrypts, reads, alters, and re-encrypts all communications transparently.
  • The Defense: Authenticate the public values using Digital Signatures / Public-Key Certificates (PKI).

Hybrid Encryption (Putting It Together)

  • Problem: Asymmetric operations (modular exponentiation of 2048-bit numbers) are ~1000× slower than symmetric algorithms (like AES).
  • Practical Architecture:
    1. Generate a temporary, random symmetric session key Kₛₑₛₛᵢₒₙ (e.g., 256-bit AES key).
    2. Encrypt the large message payload using Kₛₑₛₛᵢₒₙ with AES-GCM (fast bulk encryption).
    3. Encrypt Kₛₑₛₛᵢₒₙ using the recipient's asymmetric public key (RSA-OAEP) or derive it via Diffie-Hellman (ECDHE).
    4. Transmit both the encrypted session key and the ciphertext payload.

Exam Self-Check (Test Yourself)

Answer, reveal, then tick "Mastered". Your progress is saved.
Q1

Why does Euler's theorem guarantee Mᵉᵈ ≡ M (mod n)?

Answer: Because ed = 1 + kφ(n), so Mᵉᵈ = M · (M^(φ(n)))ᵏ ≡ M · (1)ᵏ = M (mod n).
Q2

Can RSA encrypt a message M where M ≥ n?

Answer: No. Plaintext values must strictly lie in the interval 0 ≤ M < n. Larger messages must be chunked or handled via hybrid encryption.
Q3

What is the primary difference between Diffie-Hellman and RSA?

Answer: Diffie-Hellman is strictly a key exchange/agreement protocol (cannot directly encrypt arbitrary data); RSA can perform both encryption and digital signatures.
Q4

Why is padding (OAEP) required for RSA?

Answer: To provide semantic security (preventing dictionary/guessing attacks on deterministic ciphertexts) and prevent homomorphic malleability.
